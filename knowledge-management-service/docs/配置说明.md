# 配置说明

## 环境变量配置位置

**知识库管理服务**支持从**项目根目录的 `.env` 文件**统一读取配置。

### 配置优先级

1. **命令行参数**（最高优先级）
2. **项目根目录的 `.env` 文件**（`AIdoctor/.env`）
3. **服务目录的 `.env` 文件**（`knowledge-management-service/.env`，备选）
4. **配置文件默认值**（`app/config/settings.py`，最低优先级）

## 配置方式

### 方式1：项目根目录的 .env 文件（推荐）

在项目根目录（`AIdoctor`）创建或编辑 `.env` 文件：

```env
# Neo4j配置
NEO4J_URI=bolt://localhost:7687
NEO4J_USER=neo4j
NEO4J_PASSWORD=your_password_here
NEO4J_MAX_CONNECTION_LIFETIME=3600
NEO4J_MAX_CONNECTION_POOL_SIZE=50
NEO4J_CONNECTION_TIMEOUT=60

# 服务配置
HOST=0.0.0.0
PORT=8094

# 数据目录配置
DATA_DIR=data
SOURCE_DIR=data/source
PROCESSED_DIR=data/processed

# 日志配置
LOG_LEVEL=INFO
LOG_FILE=logs/app.log
```

### 方式2：服务目录的 .env 文件（备选）

如果根目录没有 `.env` 文件，可以在 `knowledge-management-service/.env` 中配置（仅用于此服务）。

### 方式3：命令行参数（CLI脚本）

使用 CLI 脚本时，可以通过参数覆盖：

```bash
python scripts/setup_schema.py \
  --uri bolt://localhost:7687 \
  --user neo4j \
  --password your_password
```

## 配置项说明

### Neo4j配置

| 配置项 | 环境变量 | 默认值 | 说明 |
|--------|---------|--------|------|
| 连接URI | `NEO4J_URI` | `bolt://localhost:7687` | Neo4j连接地址 |
| 用户名 | `NEO4J_USER` | `neo4j` | Neo4j用户名 |
| 密码 | `NEO4J_PASSWORD` | `password` | Neo4j密码（必需） |
| 连接最大生存时间 | `NEO4J_MAX_CONNECTION_LIFETIME` | `3600` | 秒 |
| 连接池大小 | `NEO4J_MAX_CONNECTION_POOL_SIZE` | `50` | 最大连接数 |
| 连接超时 | `NEO4J_CONNECTION_TIMEOUT` | `60` | 秒 |

### 服务配置

| 配置项 | 环境变量 | 默认值 | 说明 |
|--------|---------|--------|------|
| 主机地址 | `HOST` | `0.0.0.0` | 服务监听地址 |
| 端口 | `PORT` | `8094` | 服务端口 |

### 数据目录配置

| 配置项 | 环境变量 | 默认值 | 说明 |
|--------|---------|--------|------|
| 数据目录 | `DATA_DIR` | `data` | 数据存储根目录 |
| 源数据目录 | `SOURCE_DIR` | `data/source` | 源数据目录 |
| 处理后目录 | `PROCESSED_DIR` | `data/processed` | 处理后数据目录 |

### 日志配置

| 配置项 | 环境变量 | 默认值 | 说明 |
|--------|---------|--------|------|
| 日志级别 | `LOG_LEVEL` | `INFO` | DEBUG, INFO, WARNING, ERROR |
| 日志文件 | `LOG_FILE` | `logs/app.log` | 日志文件路径 |

## 自动加载机制

### 启动脚本自动加载

`run.py` 和 `scripts/setup_schema.py` 会自动：
1. 查找项目根目录的 `.env` 文件并加载
2. 如果根目录没有，查找服务目录的 `.env` 文件并加载
3. 将环境变量传递给 `pydantic_settings`

### 使用方式

**方式1：通过 run.py 启动（推荐）**

```bash
cd knowledge-management-service
python run.py
```

**方式2：通过 uvicorn 直接启动**

```bash
# 需要先加载环境变量
export $(cat ../.env | grep -v '^#' | xargs)
uvicorn app.main:app --host 0.0.0.0 --port 8094
```

**方式3：通过 CLI 脚本**

```bash
cd knowledge-management-service
python scripts/setup_schema.py --password password
```

## 注意事项

1. **`.env` 文件不要提交到Git**
   - `.env` 文件已在 `.gitignore` 中
   - 只提交 `.env.example` 作为模板（如果有）

2. **配置优先级**
   - 命令行参数 > 环境变量 > 配置文件默认值
   - 项目根目录的 `.env` 会被优先加载

3. **密码安全**
   - 不要在代码中硬编码密码
   - 使用环境变量或 `.env` 文件管理敏感信息

## 验证配置

启动服务后，查看日志确认配置是否正确加载：

```bash
# 查看日志
tail -f logs/app.log

# 应该看到类似输出：
# 已加载环境变量文件: E:\pycharmProject\AIdoctor\.env
# Neo4j客户端初始化完成: bolt://localhost:7687
```

如果配置未正确加载，检查：
1. `.env` 文件是否存在
2. 环境变量名称是否正确（大小写敏感）
3. 启动脚本是否正确加载了 `.env` 文件
