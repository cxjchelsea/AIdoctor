# 执行追踪功能说明

## 功能概述

执行追踪功能是一个管理端功能，用于可视化地管理和监控诊断流程的执行路径。类似于RAGFlow，可以实时查看当前问题走了什么通路来实现。

## 功能特性

1. **自动追踪**：通过AOP和装饰器自动追踪服务调用
2. **跨语言支持**：支持Java和Python服务
3. **实时推送**：通过WebSocket实时推送执行事件
4. **数据存储**：详细数据存储在数据库，摘要存储在CDP
5. **可配置**：通过配置开关控制是否启用

## 架构设计

### 数据存储

- **详细数据**：存储在`execution_trace`表
- **摘要数据**：存储在CDP的`executionTrace`字段（JSON格式）

### 追踪机制

1. **Java服务**：
   - 使用AOP切面自动追踪标记了`@TraceExecution`的方法
   - 使用Feign拦截器追踪服务间调用

2. **Python服务**：
   - 使用装饰器`@trace_execution`追踪方法
   - 使用中间件自动提取CDP ID

## 配置说明

### 启用追踪

在`application.yml`或`application-mysql.yml`中配置：

```yaml
execution:
  trace:
    enabled: true  # 是否启用追踪
    async:
      core-pool-size: 5
      max-pool-size: 10
      queue-capacity: 1000
    data-retention-days: 30  # 数据保留天数
    trace-input: true  # 是否记录输入数据
    trace-output: true  # 是否记录输出数据
```

### 禁用追踪

设置`execution.trace.enabled=false`即可完全禁用追踪功能，不影响主业务流程。

## 使用方法

### Java服务

在需要追踪的方法上添加注解：

```java
@TraceExecution(service = "diagnosis-service", module = "orchestration")
public CDP executeDiagnosisWorkflow(CDP cdp) {
    // 设置追踪上下文
    TraceContext.setCdpId(cdp.getId());
    try {
        // 业务逻辑
    } finally {
        TraceContext.clear();
    }
}
```

### Python服务

1. **安装公共库**：
```bash
cd common/aidoctor_trace
pip install -e .
```

2. **在FastAPI应用中添加中间件**：
```python
from aidoctor_trace import TraceMiddleware

app = FastAPI()
app.add_middleware(TraceMiddleware)
```

3. **在服务方法上添加装饰器**：
```python
from aidoctor_trace import trace_execution

@trace_execution(service="clinical-parsing-service", module="concept_normalizer")
async def normalize_concepts(self, text: str) -> Dict:
    # 业务逻辑
    pass
```

## API接口

### 查询追踪记录

```
GET /api/admin/trace/cdp/{cdpId}
```

返回指定CDP的所有追踪记录。

### 接收追踪事件（供Python服务调用）

```
POST /api/admin/trace/events
Content-Type: application/json

{
  "cdpId": "cdp_123456",
  "traceId": "trace_xxx",
  "type": "SERVICE_CALL_START",
  "service": "clinical-parsing-service",
  "module": "concept_normalizer",
  "method": "normalize",
  "timestamp": 1234567890
}
```

## WebSocket实时推送

### 连接地址

```
ws://localhost:8084/api/admin/trace/ws
```

### 订阅CDP追踪

```javascript
// 使用SockJS和STOMP
const socket = new SockJS('http://localhost:8084/api/admin/trace/ws');
const stompClient = Stomp.over(socket);

stompClient.connect({}, function() {
    // 订阅CDP的追踪事件
    stompClient.subscribe('/topic/trace/{cdpId}', function(message) {
        const event = JSON.parse(message.body);
        console.log('追踪事件:', event);
    });
});
```

## 数据库表结构

### execution_trace表

| 字段 | 类型 | 说明 |
|------|------|------|
| id | BIGINT | 主键 |
| cdp_id | VARCHAR(64) | CDP ID |
| trace_id | VARCHAR(64) | 追踪ID |
| event_type | VARCHAR(50) | 事件类型 |
| service | VARCHAR(100) | 服务名称 |
| module | VARCHAR(100) | 模块名称 |
| method | VARCHAR(100) | 方法名称 |
| step | VARCHAR(200) | 步骤名称 |
| status | VARCHAR(20) | 状态 |
| duration | BIGINT | 执行时长（毫秒） |
| timestamp | DATETIME(6) | 时间戳 |
| input_data | TEXT | 输入数据（JSON） |
| output_data | TEXT | 输出数据（JSON） |
| error_message | TEXT | 错误信息 |
| request_url | VARCHAR(500) | 请求URL |

## 注意事项

1. **性能影响**：追踪功能是异步的，不会阻塞主业务流程
2. **数据量**：建议定期清理历史数据，避免数据量过大
3. **敏感数据**：输入输出数据默认只记录类型，不记录具体值（可配置）
4. **生产环境**：生产环境建议关闭追踪功能或限制数据记录范围
