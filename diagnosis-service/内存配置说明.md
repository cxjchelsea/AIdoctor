# 诊断服务内存配置说明

## 问题描述

如果启动时遇到以下错误：
```
Error occurred during initialization of VM
Could not reserve enough space for 1048576KB object heap
```

这表示系统无法为Java虚拟机分配足够的堆内存。

## 解决方案

### 方案1：使用修改后的配置（推荐）

我已经将`pom.xml`中的最大堆内存从1GB（1024MB）减少到512MB。现在可以重新启动服务：

```bash
mvn spring-boot:run
```

### 方案2：进一步减少内存（如果512MB仍然不够）

如果512MB仍然不够，可以修改`pom.xml`中的配置：

```xml
<jvmArguments>
    -Xms128m -Xmx256m -XX:+UseG1GC -XX:MaxGCPauseMillis=200
</jvmArguments>
```

或者更小的配置：
```xml
<jvmArguments>
    -Xms128m -Xmx384m -XX:+UseG1GC -XX:MaxGCPauseMillis=200
</jvmArguments>
```

### 方案3：通过环境变量覆盖（灵活控制）

可以通过设置`MAVEN_OPTS`环境变量来覆盖pom.xml中的配置：

**Windows (PowerShell):**
```powershell
$env:MAVEN_OPTS="-Xms128m -Xmx256m"
mvn spring-boot:run
```

**Windows (CMD):**
```cmd
set MAVEN_OPTS=-Xms128m -Xmx256m
mvn spring-boot:run
```

**Linux/Mac:**
```bash
export MAVEN_OPTS="-Xms128m -Xmx256m"
mvn spring-boot:run
```

### 方案4：使用IDE运行（IntelliJ IDEA）

如果使用IntelliJ IDEA运行，可以在运行配置中设置：

1. 打开运行配置（Run -> Edit Configurations）
2. 找到诊断服务的运行配置
3. 在"VM options"中添加：
   ```
   -Xms128m -Xmx256m -XX:+UseG1GC
   ```

## 内存配置说明

- **-Xms**: 初始堆内存大小（启动时分配）
- **-Xmx**: 最大堆内存大小（运行时最大可用）
- **-XX:+UseG1GC**: 使用G1垃圾回收器（适合大内存应用）
- **-XX:MaxGCPauseMillis**: 最大GC暂停时间（毫秒）

## 推荐配置

根据系统内存情况选择：

| 系统可用内存 | 推荐配置 |
|------------|---------|
| < 2GB | `-Xms128m -Xmx256m` |
| 2-4GB | `-Xms256m -Xmx512m` |
| 4-8GB | `-Xms256m -Xmx1024m` |
| > 8GB | `-Xms512m -Xmx2048m` |

## 检查系统内存

**Windows:**
```cmd
wmic OS get TotalVisibleMemorySize,FreePhysicalMemory
```

**Linux:**
```bash
free -h
```

**Mac:**
```bash
vm_stat
```

## 注意事项

1. **不要设置过小的内存**：如果内存太小，可能导致频繁GC，影响性能
2. **留出系统内存**：不要将所有内存都分配给Java，系统本身也需要内存
3. **监控内存使用**：如果服务运行后频繁出现OutOfMemoryError，需要增加内存

## 如果问题仍然存在

1. 关闭其他占用内存的程序
2. 检查是否有其他Java进程在运行
3. 考虑增加系统内存（物理内存）
4. 检查是否有32位JVM限制（应该使用64位JVM）
