# 智能健康管理平台 - 系统设计方案

> **文档说明**：本文档描述智能健康管理平台的系统设计方案，包括整体架构、模块关系、数据流转等。  
> **技术实现方案**：请参考《智能健康管理平台-技术实现方案.md》

## 一、系统概述

### 1.1 系统定位

**智能健康管理平台**是一个面向家庭用户的综合性健康管理平台，整合了8个核心模块，为用户提供从健康监测、风险评估、健康管理到专业诊断的全方位健康服务。

### 1.2 系统目标

- **全生命周期健康管理**：覆盖健康监测、风险评估、健康管理、专业诊断等全流程
- **模块化设计**：8个模块相互独立，内部完整，可独立开发和部署
- **统一平台**：8个模块在统一平台上运行，数据共享，功能互补
- **智能化服务**：基于AI技术，提供智能化、个性化的健康服务

### 1.3 八大核心模块

1. **健康中心**：用户健康档案管理、健康数据汇总
2. **健康监测**：实时健康数据监测、设备数据采集
3. **抗衰管理**：抗衰老管理、健康维护
4. **风险评估**：健康风险评估、风险预警
5. **健康科普**：健康知识科普、健康教育
6. **健康商城**：健康产品商城、服务购买
7. **智能家庭医生**：全科医生服务、日常健康管理（新增）
8. **智能诊断**：专科医生服务、专业诊断分析（新增）

## 三、新增模块集成方案

### 3.1 集成策略

**方案**：标准微服务集成 + 共享数据库

- **新模块作为独立微服务**：`family-doctor-service`（端口8087）、`diagnosis-service`（端口8088）
- **注册到Nacos**：通过服务注册中心进行服务发现
- **API网关统一路由**：通过Spring Cloud Gateway统一路由
- **共享数据库**：连接同一数据库实例，共享用户表、健康档案表等
- **服务间调用**：通过OpenFeign调用现有服务获取数据

### 3.3 模块关系

#### 3.3.1 智能家庭医生模块

**定位**：全科医生服务

**核心功能**：
- 9大模块的全生命周期健康管理
- 日常健康咨询
- 健康评估与建档
- 预防与健康促进
- 筛查与早期预警
- 症状评估与分诊
- 诊断支持与鉴别（基础版）
- 预测与预后管理
- 诊疗路径与治疗支持
- 护理与照护路径
- 康复与功能维护

**与其他模块的关系**：
- **获取数据**：从健康中心、健康监测、风险评估获取数据
- **提供数据**：健康档案更新、诊断结果反馈

#### 3.3.2 智能诊断模块

**定位**：专科医生服务

**核心功能**：
- 专业诊断分析（五引擎融合）
- 健康检查服务
- 检查报告解读
- 诊断历史管理

**与其他模块的关系**：
- **获取数据**：从健康中心、健康监测、风险评估获取数据
- **提供数据**：诊断结果反馈给健康中心、风险评估、智能家庭医生

### 3.4 数据共享策略

#### 3.4.1 共享数据库设计

**共享表**（所有服务共享）：
- 用户表（users）
- 健康档案表（health_profiles）
- 监测数据表（monitoring_data）
- 风险标签表（risk_tags）

**新模块独有表**（新服务直接访问）：
- 对话记录表（conversation_records）- 智能家庭医生
- 诊断记录表（diagnosis_records）- 智能诊断
- 检查报告表（examination_reports）- 智能诊断

#### 3.4.2 数据访问方式

**共享数据访问**：
- 通过OpenFeign调用现有服务获取（推荐）
- 或直接访问共享数据库（需要谨慎，注意数据一致性）

**新模块独有数据**：
- 新服务直接访问数据库
