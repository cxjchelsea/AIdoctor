# Oasis 项目架构说明文档

## 一、整体架构概述

这是一个基于**Apache Dubbo**的**微服务架构**项目，采用**Maven 多模块**管理，使用**Spring Boot 2.7.8**作为基础框架。

## 二、核心技术栈

### 2.1 核心框架

- **Spring Boot**: 2.7.8
- **Apache Dubbo**: 3.2.10 (微服务 RPC 框架)
- **Java 版本**: JDK 8

### 2.2 数据存储

- **数据库**: Oracle (使用 ojdbc8 驱动)
- **ORM 框架**: MyBatis Plus 3.5.1
- **缓存**: Redis (使用 Redisson 3.19.1 作为客户端)
- **文件存储**: SeaweedFS (分布式文件系统)

### 2.3 服务治理

- **服务注册中心**: Zookeeper
- **分布式事务**: Seata 2.0 (使用 Kryo 序列化)
- **序列化**: Kryo 5.0.0

### 2.4 日志与监控

- **日志收集**: Logstash 7.17.3
- **日志存储**: Elasticsearch 7.10.1
- **日志可视化**: Kibana 7.17.3
- **日志框架**: Log4j2 (使用 GELF 格式)

### 2.5 其他技术

- **API 文档**: Knife4j 4.0.0 (基于 Swagger)
- **工具库**: Hutool 5.8.16
- **对象映射**: MapStruct 1.5.5
- **Excel 处理**: EasyExcel 3.2.1
- **支付集成**: 支付宝 SDK、微信支付 SDK
- **容器化**: Docker + Docker Compose

## 三、项目模块结构

### 3.1 根目录结构

```
oasis-app-v4/
├── pom.xml                    # 父POM，统一管理依赖版本
├── docker-compose.yml         # Docker编排配置
├── oasis-model/              # 数据模型模块（实体类、DTO、VO等）
├── oasis-common/             # 公共工具模块（工具类、常量、异常等）
├── oasis-starter/            # Starter模块（自定义Spring Boot Starter）
│   ├── oasis-starter-redis/
│   ├── oasis-starter-seaweedfs/
│   └── oasis-starter-esign/
├── oasis-service/            # 业务服务模块集合
└── oasis-alpha-app/          # 应用层（Consumer和Provider）
└── oasis-alpha-wms/          # WMS服务层
```

### 3.2 服务模块结构（每个业务服务都遵循此结构）

每个业务服务（如`oasis-healthArchives`）都分为**三个子模块**：

```
oasis-{service-name}/
├── oasis-{service-name}-api/        # API模块：定义服务接口
│   └── src/main/java/
│       └── com/inshine/oasis/.../api/
│           └── {Service}Api.java    # 服务接口定义
│
├── oasis-{service-name}-provider/   # Provider模块：服务提供者（实现业务逻辑）
│   └── src/main/java/
│       └── com/inshine/oasis/.../provider/
│           ├── serviceImpl/         # 服务实现类
│           ├── mapper/             # MyBatis Mapper
│           └── config/             # 配置类
│   └── src/main/resources/
│       ├── application-*.yaml       # 多环境配置
│       └── mapper/*.xml            # MyBatis XML映射文件
│
└── oasis-{service-name}-consumer/   # Consumer模块：服务消费者（对外提供HTTP接口）
    └── src/main/java/
        └── com/inshine/oasis/.../consumer/
            └── controller/         # RESTful API控制器
    └── src/main/resources/
        └── application-*.yaml      # 多环境配置
```

### 3.3 模块职责说明

#### API 模块 (`-api`)

- **作用**: 定义服务接口契约
- **内容**:
  - 服务接口定义（使用`@DubboService`或接口定义）
  - 相关的 DTO、VO 类（可选，通常放在 model 模块）
- **依赖**: 只依赖`oasis-common`模块

#### Provider 模块 (`-provider`)

- **作用**: 实现业务逻辑，提供服务实现
- **内容**:
  - 服务实现类（实现 API 模块定义的接口）
  - 数据访问层（Mapper、Entity）
  - 业务逻辑处理
- **依赖**:
  - 依赖对应的`-api`模块
  - 依赖`oasis-model`（实体类）
  - 依赖`oasis-common`（工具类）
  - 依赖`oasis-starter-*`（如需要）
  - 可能依赖其他服务的`-provider`模块（服务间调用）

#### Consumer 模块 (`-consumer`)

- **作用**: 对外提供 HTTP RESTful 接口，调用 Provider 服务
- **内容**:
  - Controller 层（RESTful API）
  - 参数校验
  - 调用 Provider 服务（通过 Dubbo）
- **依赖**:
  - 依赖对应的`-api`模块
  - 依赖`oasis-model`（DTO、VO）
  - 依赖`oasis-common`（工具类）
  - **不依赖数据库**（通过 Dubbo 调用 Provider）

## 五、Dubbo 配置说明

### 5.1 Provider 配置示例

```yaml
dubbo:
  application:
    name: {service-name}-provider
  protocol:
    name: dubbo
    port: -1                    # 自动分配端口
    iothreads: 200
    accepts: 1000
    payload: 104857600          # 100MB
  registry:
    address: zookeeper://127.0.0.1:2181
  provider:
    filter: dubboContextFilter
```

### 5.2 Consumer 配置示例

```yaml
dubbo:
  application:
    name: {service-name}-consumer
    qos-port: 33333
  protocol:
    name: dubbo
    port: -1
  registry:
    address: zookeeper://127.0.0.1:2181
  consumer:
    check: false                # 启动时不检查服务提供者
    filter: dubboConsumerFilter
```

## 十二、关键设计模式

1. **三层架构**: API 层（接口定义） → Provider 层（业务实现） → Consumer 层（HTTP 接口）
2. **服务拆分**: 按业务领域拆分微服务
3. **接口契约**: 通过 API 模块定义服务接口，实现接口与实现分离
4. **依赖管理**: 通过父 POM 统一管理依赖版本
5. **Starter 模式**: 自定义 Starter 封装通用功能（Redis、SeaweedFS 等）

## 十四、向其他 AI 描述时的关键点

### 14.1 架构类型

**基于 Apache Dubbo 的微服务架构，采用三层模块设计（API-Provider-Consumer）**

### 14.2 核心特点

1. **服务拆分**: 每个业务服务独立，包含 api、provider、consumer 三个模块
2. **接口契约**: API 模块定义服务接口，实现接口与实现分离
3. **服务治理**: 使用 Zookeeper 作为注册中心，Dubbo 进行服务调用
4. **分布式事务**: 使用 Seata 管理分布式事务
5. **多环境支持**: 通过 profile 区分不同环境配置

### 14.3 技术选型理由

- **Dubbo**: 高性能 RPC 框架，适合微服务场景
- **Zookeeper**: 成熟稳定的注册中心
- **Seata**: 阿里开源的分布式事务解决方案
- **MyBatis Plus**: 简化数据库操作
- **Oracle**: 企业级数据库（根据业务需求）
- **SeaweedFS**: 轻量级分布式文件系统

### 14.4 模块依赖关系

```
Consumer → API ← Provider
    ↓       ↓       ↓
  Model ← Common → Starter
```

## 十五、关键代码实现细节

### 15.1 包命名规范

所有模块遵循统一的包命名规范：

- **API 模块**: `com.inshine.oasis.{service}.api`
  - 例如：`com.inshine.oasis.archives.api`
- **Provider 模块**: `com.inshine.oasis.{service}.provider`
  - 例如：`com.inshine.oasis.archives.provider`
  - 子包：`serviceImpl`、`mapper`、`config`
- **Consumer 模块**: `com.inshine.oasis.{service}.consumer`
  - 例如：`com.inshine.oasis.archives.consumer`
  - 子包：`controller`、`service`（可选）

### 15.2 API 模块接口定义

API 模块中定义的是**普通 Java 接口**，不使用任何注解：

```java
package com.inshine.oasis.archives.api;

import com.inshine.oasis.model.common.dto.ResultTemplate;
import java.util.Date;

public interface HealthArchivesService {
    ResultTemplate<?> getDiseaseData(Long page, Integer pageSize,
                                     String catalogId, String userId,
                                     Date startTime, Date endTime);
    // 其他方法...
}
```

### 15.3 Provider 模块实现

Provider 模块中实现接口，使用`@DubboService`注解：

```java
package com.inshine.oasis.archives.provider.serviceImpl;

import com.inshine.oasis.archives.api.HealthArchivesService;
import org.apache.dubbo.config.annotation.DubboService;
import javax.annotation.Resource;

@DubboService(timeout = 20000)
public class HealthArchivesServiceImpl implements HealthArchivesService {

    @Resource
    private HealthArchivesMapper mapper;

    @Override
    public ResultTemplate<?> getDiseaseData(...) {
        // 业务逻辑实现
    }
}
```

### 15.4 Consumer 模块 Controller

Consumer 模块中使用`@DubboReference`注入服务，提供 HTTP 接口：

```java
package com.inshine.oasis.archives.consumer.controller;

import com.inshine.oasis.archives.api.HealthArchivesService;
import org.apache.dubbo.config.annotation.DubboReference;
import org.springframework.web.bind.annotation.*;

@RestController
@RequestMapping("/app/v1/archives")
public class HealthArchivesController {

    @DubboReference
    private HealthArchivesService healthArchivesService;

    @GetMapping("/disease")
    public ResultTemplate<?> getDiseaseData(
            @RequestParam Long page,
            @RequestParam Integer pageSize,
            // 其他参数...
    ) {
        return healthArchivesService.getDiseaseData(page, pageSize, ...);
    }
}
```

### 15.5 启动类配置

#### Provider 启动类

```java
package com.inshine.oasis.app.provider;

import org.apache.dubbo.config.spring.context.annotation.EnableDubbo;
import org.mybatis.spring.annotation.MapperScan;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.boot.autoconfigure.gson.GsonAutoConfiguration;
import org.springframework.cache.annotation.EnableCaching;
import org.springframework.retry.annotation.EnableRetry;
import org.springframework.scheduling.annotation.EnableScheduling;
import org.springframework.transaction.annotation.EnableTransactionManagement;

@SpringBootApplication(scanBasePackages = {"com.inshine.oasis"},
                       exclude = {GsonAutoConfiguration.class})
@EnableDubbo(scanBasePackages = {"com.inshine.oasis"})
@MapperScan(basePackages = {"com.inshine.oasis.*.provider.mapper"})
@EnableCaching
@EnableScheduling
@EnableTransactionManagement
@EnableRetry
public class APPProviderApplication {
    public static void main(String[] args) {
        SpringApplication.run(APPProviderApplication.class, args);
    }
}
```

#### Consumer 启动类

```java
package com.inshine.oasis.app.consumer;

import org.apache.dubbo.config.spring.context.annotation.EnableDubbo;
import org.springframework.boot.SpringApplication;
import org.springframework.boot.autoconfigure.SpringBootApplication;
import org.springframework.boot.autoconfigure.gson.GsonAutoConfiguration;
import org.springframework.scheduling.annotation.EnableScheduling;

@SpringBootApplication(scanBasePackages = {"com.inshine.oasis"},
                       exclude = {GsonAutoConfiguration.class})
@EnableDubbo
@EnableScheduling
public class APPConsumerApplication {
    public static void main(String[] args) {
        SpringApplication.run(APPConsumerApplication.class, args);
    }
}
```

**关键点**：

- `scanBasePackages = {"com.inshine.oasis"}` - 扫描整个项目包
- Provider 需要`@MapperScan`扫描 Mapper 接口
- Provider 需要启用缓存、事务、重试等
- Consumer 不需要数据库相关配置

### 15.6 应用聚合层（alpha-app）

项目有一个特殊的聚合层`oasis-alpha-app`，它聚合了所有服务的 Provider 和 Consumer：

```
oasis-alpha-app/
├── oasis-app-provider/    # 聚合所有provider模块
│   └── pom.xml            # 依赖所有*-provider模块
└── oasis-app-consumer/    # 聚合所有consumer模块
    └── pom.xml            # 依赖所有*-consumer模块
```

这样设计的好处：

- 可以统一启动所有服务
- 便于整体部署
- 便于服务间调用（Provider 可以依赖其他 Provider）

## 十六、创建新服务的详细步骤

1. **在`oasis-service`下创建服务目录**：`oasis-{service-name}`
2. **创建父 POM**：`oasis-{service-name}/pom.xml`（packaging 为 pom）
3. **创建三个子模块**：
   - `oasis-{service-name}-api`
   - `oasis-{service-name}-provider`
   - `oasis-{service-name}-consumer`
4. **在 API 模块中定义服务接口**（普通 Java 接口）
5. **在 Provider 模块中实现接口**（使用`@DubboService`）
6. **在 Consumer 模块中创建 Controller**（使用`@DubboReference`）
7. **配置启动类**（Provider 需要`@MapperScan`）
8. **配置 application.yaml**（Dubbo、数据库等）
9. **在父 POM 中注册新模块**：
   - `oasis-service/pom.xml`中添加模块
   - `oasis-alpha-app/oasis-app-provider/pom.xml`中添加 provider 依赖
   - `oasis-alpha-app/oasis-app-consumer/pom.xml`中添加 consumer 依赖

### 17.4 配置说明

#### 17.4.1 Dubbo 配置项说明

| 配置项                     | 说明           | 默认值/建议值                      |
| -------------------------- | -------------- | ---------------------------------- |
| `dubbo.application.name`   | 应用名称       | `{service-name}-provider/consumer` |
| `dubbo.protocol.port`      | 服务端口       | `-1`（自动分配）                   |
| `dubbo.protocol.iothreads` | IO 线程数      | `200`                              |
| `dubbo.protocol.accepts`   | 最大连接数     | `1000`                             |
| `dubbo.protocol.payload`   | 最大数据包大小 | `104857600`（100MB）               |
| `dubbo.registry.address`   | 注册中心地址   | `zookeeper://127.0.0.1:2181`       |
| `dubbo.registry.group`     | 服务分组       | 根据环境设置（dev/test/prod）      |
| `dubbo.consumer.check`     | 启动时检查服务 | `false`（避免启动失败）            |

#### 17.4.2 数据库配置说明

- **驱动**: `oracle.jdbc.driver.OracleDriver`
- **URL 格式**: `jdbc:oracle:thin:@host:port/database?serverTimezone=Asia/Shanghai`
- **时区**: 必须设置`serverTimezone=Asia/Shanghai`

#### 17.4.3 Redis 配置说明

- **连接池配置**: 根据环境调整连接数
  - 开发环境: `max-active: 8`
  - 生产环境: `max-active: 20`（可适当增加）
- **超时时间**: `timeout: 30000`（30 秒）

#### 17.4.4 Seata 配置说明

- **序列化方式**: `kryo`（高性能）
- **事务组**: `tx-service-group: app`
- **注册中心**: 使用 Zookeeper，与 Dubbo 共用
- **数据源代理模式**: `AT`（自动模式）
- **超时配置**:
  - `session-timeout: 10000`
  - `connect-timeout: 10000`

#### 17.4.5 MyBatis Plus 配置说明

- **枚举包扫描**: `com.inshine.oasis.model.*`
- **Mapper XML 位置**: `classpath:/mapper/*.xml`
- **SQL 日志**:
  - 开发环境: 开启（`log-impl: org.apache.ibatis.logging.stdout.StdOutImpl`）
  - 生产环境: 关闭（注释掉或删除）

#### 17.4.6 SeaweedFS 配置说明

- **Master 节点**: 配置主机和端口
- **默认端口**: `9333`

## 十八、重要注意事项

### 18.1 包扫描配置

- 所有启动类必须配置`scanBasePackages = {"com.inshine.oasis"}`
- 确保能扫描到所有模块的类

### 18.2 Mapper 扫描

- Provider 启动类必须配置`@MapperScan(basePackages = {"com.inshine.oasis.*.provider.mapper"})`
- 支持多模块 Mapper 扫描

### 18.3 服务间调用

- Provider 可以依赖其他 Provider 模块（直接调用）
- Consumer 通过`@DubboReference`调用 Provider 服务
- 避免循环依赖

### 18.4 数据库配置

- **只有 Provider 模块配置数据库**
- Consumer 模块排除数据库自动配置

### 18.5 多环境配置

- 使用`application-{profile}.yaml`区分环境
- 启动时通过`--spring.profiles.active={profile}`指定

---

**总结**: 这是一个典型的**企业级微服务架构**项目，采用**Dubbo + Spring Boot**技术栈，通过**API-Provider-Consumer 三层模块设计**实现服务拆分和接口契约管理，使用**Zookeeper**进行服务注册发现，**Seata**管理分布式事务，支持多环境部署和容器化。

**关键实现要点**：

1. API 模块定义普通接口（无注解）
2. Provider 使用`@DubboService`实现接口
3. Consumer 使用`@DubboReference`注入服务
4. 启动类统一包扫描`com.inshine.oasis`
5. Provider 需要`@MapperScan`扫描 Mapper
6. alpha-app 层聚合所有服务便于统一部署
