## 一、设计目标与愿景

### 1.1 核心目标

将现有的**健康打卡模块**和**合理用药模块**升级为：
- **智能家庭医生**（替代健康打卡模块）
- **智能诊断医生**（替代合理用药模块）

最终实现：**让设备像一个人一样，所有模块都联动起来，作为智能医生解决问题**

### 1.2 设计原则

1. **类人思维**：采用五脑架构，模拟真实医生的思维过程
2. **全局联动**：所有模块通过五脑中枢协调，形成统一智能体
3. **闭环控制**：感知→认知→预测→决策→执行→再感知的完整闭环
4. **主动智能**：系统主动识别问题、主动提供建议、主动调整策略

### 1.3 核心思想

**五脑架构的本质**：让系统像真实医生一样思考和行动

真实医生的工作流程：
1. **观察患者**（感知）→ 看、听、问、查
2. **理解问题**（认知）→ 这些信息意味着什么？
3. **预判风险**（预测）→ 如果不管，会怎样？
4. **做出决策**（决策）→ 现在应该做什么？
5. **确保执行**（执行）→ 你真的做了吗？效果如何？

## 二、五脑架构核心设计

### 2.1 五脑系统总架构

```
┌─────────────────────────────────────────────────────────────┐
│                    对话中枢（统一表达层）                      │
│  负责：理解用户意图、调度五脑、翻译医学语言为用户语言          │
└─────────────────────────────────────────────────────────────┘
                            ↕ 调度与翻译
┌─────────────────────────────────────────────────────────────┐
│                    五脑协同系统                                │
│  ┌──────────┐  ┌──────────┐  ┌──────────┐  ┌──────────┐  │
│  │ 感知脑   │→ │ 认知脑   │→ │ 预测脑   │→ │ 决策脑   │  │
│  │Perception│  │Cognition │  │Prediction│  │Decision  │  │
│  │采集事实  │  │构建问题  │  │时间演化  │  │★控制中心★│  │
│  └──────────┘  └──────────┘  └──────────┘  └──────────┘  │
│       ↕              ↕              ↕              ↓        │
│  ┌──────────────────────────────────────────────────────┐  │
│  │              执行脑（Execution）                      │  │
│  │          任务拆解、行为引导、执行监测、结果回流      │  │
│  └──────────────────────────────────────────────────────┘  │
└─────────────────────────────────────────────────────────────┘
                            ↕ 数据流
┌─────────────────────────────────────────────────────────────┐
│                    数据与知识层                                │
│  健康档案库 | 知识库 | 规则库 | 模型库 | 执行记录库          │
└─────────────────────────────────────────────────────────────┘
```

### 2.2 五脑关系图

```
现实世界（用户的身体、行为、数据）
    ↓
【感知脑】"现在发生了什么？"
    ↓ 原始事实
【认知脑】"这些事情意味着什么？"
    ↓ 问题结构
【预测脑】"如果不变，会走向哪里？"
    ↓ 风险排序
【决策脑】"现在应该做哪件事？" ★唯一控制中心★
    ↓ 行动方案
【执行脑】"这件事有没有真的改变现实？"
    ↓ 执行结果
现实世界发生变化
    ↺（再次被感知，形成闭环）
```

### 2.3 对话中枢的作用

**对话中枢不是第六个脑，而是五脑的"翻译官"和"调度员"**

```
用户 ↔ 对话中枢 ↔ 五脑系统
```

- **用户说话** → 对话中枢理解意图 → 调度对应的脑处理
- **五脑输出** → 对话中枢翻译成用户语言 → 说给用户听

**关键原则**：五脑不直接和用户说话，只有对话中枢能说话

## 三、五脑详细设计

### 3.1 感知脑（Perception Brain）

#### 3.1.1 感知脑的本质

**感知脑 = 替代医生完成第一轮持续观察与问诊的系统**

不是简单的"数据采集器"，而是"有医学意图的感知系统"

#### 3.1.2 五大感知子系统

##### 3.1.2.1 身份感知（Context Perception）

**作用**：让系统知道"我在和什么样的身体对话"

**包含内容**：
- **基础信息**：年龄、性别、身高、体重
- **病史信息**：慢病史、手术史、家族史
- **用药信息**：当前用药、用药史、过敏史
- **风险标签**：高血压风险人群、糖尿病风险人群等

**工作方式**：
- 不是一次性填表，而是"用问诊和使用过程慢慢补全"
- 例如：系统会问"你目前是否长期服用某些药物？如果有，我可以在解读检测结果时一并考虑。"

**为什么重要**：
- 身份感知是感知脑的"滤镜"
- 同样的数据，不同身份的人，意义完全不同
- 例如：血压140/90对55岁有家族史的人，和对25岁健康年轻人的意义完全不同

**与现有模块映射**：
- 健康档案 → 身份感知
- 基本信息 → 身份感知

##### 3.1.2.2 主诉感知（Subjective Perception）

**作用**：采集用户主动说的"不舒服"

**包含内容**：
- **症状**：头痛、胸闷、乏力等
- **部位**：头部、胸部、腹部等
- **时间**：什么时候开始的、持续多久
- **程度**：疼痛评分0-10分、严重程度

**工作方式**：
- **自然语言输入**：用户说"我最近总是很累"
- **结构化抽取**：系统提取"疲劳"、"最近"、"持续"
- **关键原则**：**主诉不是结论，是信号**

**为什么重要**：
- 主诉是医生了解问题的第一入口
- 也是智能问诊的真正归属地
- 主诉感知的质量直接影响后续认知和决策

**与现有模块映射**：
- 智能问诊 → 主诉感知
- AI导诊/症状自查 → 主诉感知

##### 3.1.2.3 行为感知（Behavioral Perception）

**作用**：了解用户的日常生活方式

**包含内容**：
- **睡眠**：睡眠时长、睡眠质量、入睡时间
- **运动**：运动类型、运动频率、运动强度
- **饮食**：饮食习惯、饮食规律、特殊饮食
- **情绪**：情绪状态、压力水平
- **依从性**：是否按建议做、完成度如何

**工作方式**：
- **不是"打卡型KPI"**（不是用来评价用户）
- **而是"风险背景"**（用来解释身体变化）
- 例如：血压升高 + 睡眠不足 → 可能是睡眠问题导致的

**为什么重要**：
- 行为数据不是用来"评价用户"
- 而是用来"解释身体变化"
- 行为感知帮助系统理解"为什么会有这个变化"

**与现有模块映射**：
- 健康记录 → 行为感知
- 健康打卡 → 依从性感知

##### 3.1.2.4 生理感知（Physiological Perception）

**作用**：采集客观的生理指标

**包含内容**：
- **生命体征**：血压、心率、体温、血氧
- **试纸检测**：血糖、尿常规、便常规等
- **可穿戴设备**：步数、心率、睡眠监测
- **检查报告**：医院体检报告、化验单等

**工作方式**：
- 每个检测必须有"医学意图"（不是越多越好）
- 检测必须被解释（否则等于噪音）
- 例如："这项检测是为了更好判断你最近的状态变化。"

**为什么重要**：
- 检测不是感知脑的核心
- 检测只是感知脑的一种手段
- 每个检测都要有明确的医学目的

**与现有模块映射**：
- 健康监测 → 生理感知
- 设备检测 → 生理感知
- 数据导入 → 生理感知

##### 3.1.2.5 连续性感知（Temporal Perception）

**作用**：感知时间序列的变化趋势

**包含内容**：
- **时间序列**：近7天、近30天、近90天的数据
- **趋势分析**：上升、下降、波动
- **变化速度**：快速变化、缓慢变化

**工作方式**：
- **不强调"单次异常"**（一次血压高可能是偶然）
- **强调"连续偏离"**（连续3天血压高值得关注）
- **强调"反复波动"**（反复波动可能不稳定）
- **强调"趋势改变"**（从稳定到不稳定）

**为什么重要**：
- 连续性感知是家庭医生和医院医生的最大区别
- 也是感知脑最有价值的能力
- 家庭医生关注的是"趋势"，不是"单次"

**与现有模块映射**：
- 健康记录 → 连续性感知
- 健康周期总览 → 连续性感知

#### 3.1.3 感知脑的工作特点

##### 特点1：有计划地感知

**不是被动收集，而是主动设计感知任务**

工作流程：
```
预测/决策脑提出需求
    ↓
感知脑设计感知任务
    ↓
用户完成检测
    ↓
感知脑更新状态
```

例如：
- 决策脑说"需要了解你的睡眠情况"
- 感知脑就会设计"连续7天记录睡眠"的任务
- 用户完成后，感知脑更新状态

##### 特点2：医学意图明确

每个感知任务都有明确的医学目的：
- "为什么需要这个检测？"
- "这个检测能解决什么问题？"
- "检测结果如何解释？"

#### 3.1.4 感知脑的输出

感知脑输出的是**原始事实**，不是结论：
- 血压：140/90 mmHg
- 睡眠：最近7天平均5小时
- 主诉：头痛2天，疼痛6分

这些事实会传递给认知脑，由认知脑来判断意义

### 3.2 认知脑（Cognition Brain）

#### 3.2.1 认知脑的本质

**认知脑 = 把感知到的信息转化为医学意义和问题结构的系统**

不是"下诊断的系统"，而是"理解问题的系统"

#### 3.2.2 四层认知结构

##### 3.2.2.1 信息理解层（Meaning Layer）

**作用**：给每一条信息贴上医学语义标签

**工作方式**：
- 指标 → 正常/偏高/偏低
- 症状 → 医学术语映射
- 行为 → 风险相关行为

**举例**：
- "睡不好" → 睡眠质量下降
- "饭后犯困" → 餐后血糖波动可能
- "空腹血糖 6.3" → 轻度异常区间

**关键**：这一步不做判断，只做"理解"

**与现有模块映射**：
- 智能测算 → 信息理解层
- 报告解读 → 信息理解层

##### 3.2.2.2 异常识别层（Abnormality Layer）

**作用**：识别哪些信息值得医生注意

**工作方式**：
- 标记异常
- 标记"可能是偶然的"
- 标记"需要持续关注的"

**判断原则**：
- **单点异常 ≠ 问题**（一次血压高可能是偶然）
- **趋势异常 > 单次异常**（连续3天血压高值得关注）
- **多维异常 > 单一异常**（血压高 + 睡眠差 + 体重增加）

**举例**：
- 单次血糖偏高 → 观察
- 连续偏高 + 睡眠差 → 关注

**关键**：认知脑开始"收缩信息"，过滤噪音

**与现有模块映射**：
- 智能测算 → 异常识别层
- 筛查与早期预警 → 异常识别层

##### 3.2.2.3 模式组合层（Pattern Layer）

**作用**：把"散的信息"拼成"像病一样的结构"

**工作方式**：
- **多指标联合**：血压 + 血糖 + 腰围
- **症状 + 行为 + 检测**：头痛 + 睡眠不足 + 血压高
- **连续时间窗口**：近7天的趋势

**举例**：
```
模式A：代谢压力上升
- 空腹血糖轻高
- 腰围增加
- 睡眠不足
```

**关键**：
- 这是"医生的经验被结构化"的地方
- 也是系统的护城河
- 模式识别是认知脑的核心能力

**与现有模块映射**：
- 报告解读 → 模式组合层
- 健康评估 → 模式组合层

##### 3.2.2.4 问题建模层（Problem Layer）

**作用**：把模式转化为"医学关注点"

**工作方式**：
- 问题 ≠ 诊断
- 问题 = 医学关注点

**输出形式**：
```
当前健康问题列表
├ 主要问题：糖代谢调节能力下降倾向
├ 次要问题：睡眠节律紊乱
└ 观察中问题：体重变化趋势
```

**关键**：这是给预测脑和决策脑用的"输入语言"

**与现有模块映射**：
- 健康评估 → 问题建模层
- 诊断支持 → 问题建模层

#### 3.2.3 认知脑的工作特点

##### 特点1：不下诊断

认知脑不说"你得了什么病"，而是说"你目前存在哪些医学上值得关注的问题"

##### 特点2：模式识别

认知脑的核心能力是识别"模式"：
- 代谢异常模式
- 睡眠-情绪耦合模式
- 体能下降模式
- 早期衰弱模式

##### 特点3：问题结构化

认知脑输出的不是散乱的信息，而是结构化的"问题列表"，便于后续处理

#### 3.2.4 认知脑的输出

认知脑输出的是**问题结构**：
- 问题列表：主要问题、次要问题、观察中问题
- 问题描述：用医学术语描述
- 问题证据：支持这个问题的证据

这些结构会传递给预测脑，由预测脑来评估风险

### 3.3 预测脑（Prediction Brain）

#### 3.3.1 预测脑的本质

**预测脑 = 基于当前问题状态，对未来风险进行排序和时间化的系统**

不是"算命系统"，而是"风险评估和时间规划系统"

#### 3.3.2 四层预测结构

##### 3.3.2.1 风险映射层（Risk Mapping）

**作用**：把"当前问题"映射到"未来风险"

**工作方式**：
- 问题 → 风险的医学映射

**举例**：
- 代谢异常模式 → 糖尿病风险、心血管风险
- 睡眠紊乱 + 情绪低落 → 抑郁风险、认知功能下降风险
- 肌力下降 → 跌倒风险、衰弱风险

**关键**：风险 ≠ 疾病诊断，风险是"方向"，不是"结论"

**与现有模块映射**：
- 疾病预测 → 风险映射层

##### 3.3.2.2 时间演化层（Time Horizon）

**作用**：判断"这些风险大概什么时候值得担心？"

**工作方式**：
- 把风险拆成时间窗口

**时间轴**：
```
风险时间轴
├ 近期风险（0-3个月）：跌倒风险、急性事件
├ 中期风险（3-24个月）：糖代谢疾病、心血管风险
└ 长期风险（2年以上）：衰老相关问题、慢性并发症
```

**举例**：
- 跌倒风险 → 近期（随时可能发生）
- 糖代谢疾病 → 中期（3-24个月内）
- 衰老相关问题 → 长期（2年以上）

**关键**：时间感是预测脑区别于认知脑的关键

**与现有模块映射**：
- 疾病预测 → 时间演化层

##### 3.3.2.3 可逆性判断层（Reversibility）

**作用**：判断"这个风险现在还能不能扭转？"

**工作方式**：
- **高可逆**：生活方式即可改善（睡眠紊乱）
- **中可逆**：需长期管理（代谢异常）
- **低可逆**：重在监测（年龄相关衰弱）

**举例**：
- 睡眠紊乱 → 高可逆（现在改还来得及）
- 代谢异常 → 中可逆（需长期管理）
- 年龄相关衰弱 → 低可逆（只能减缓）

**关键**：这是预测脑为"决策脑"服务的关键输出

##### 3.3.2.4 风险优先级层（Prioritization）

**作用**：对多个风险进行排序

**排序依据**：
- 时间紧不紧（近期风险优先）
- 后果重不重（严重后果优先）
- 能不能干预（可干预的优先）
- 用户能不能配合（能配合的优先）

**输出形式**：
```
个人风险清单（排序后）
1️⃣ 需优先干预的风险：跌倒风险（近期、可干预）
2️⃣ 需持续关注的风险：代谢异常（中期、需管理）
3️⃣ 当前观察即可的风险：衰老相关问题（长期、低可逆）
```

**关键**：预测脑的终极价值 = 排序

**与现有模块映射**：
- 风险评估 → 风险优先级层

#### 3.3.3 预测脑的工作特点

##### 特点1：时间感

预测脑不说"有风险"，而是说"什么时候值得担心"

##### 特点2：可逆性

预测脑判断哪些风险"现在改还来得及"，哪些"只能减缓"

##### 特点3：排序

预测脑的终极价值是"排序"，告诉决策脑"先管哪个"

#### 3.3.4 预测脑的输出

预测脑输出的是**风险清单**：
- 风险列表：按优先级排序
- 时间窗口：近期/中期/长期
- 可逆性：高可逆/中可逆/低可逆

这些风险会传递给决策脑，由决策脑来决定行动

---

### 3.4 决策脑（Decision Brain）★最重要★

#### 3.4.1 决策脑的本质

**决策脑 = 决定"在当前情况下，最合理的下一步行动是什么"的系统**

**唯一有控制权的脑**：只有决策脑可以决定"做什么"

#### 3.4.2 五模块决策结构

##### 3.4.2.1 问题优先级决策（Priority Decision）

**作用**：决定"这么多问题，先管哪个？"

**决策依据**：
- **紧急程度**：是否紧急
- **潜在后果**：后果是否严重
- **可逆性**：是否可逆
- **当前阶段**：是否适合现在处理

**输出形式**：
```
本周期管理重点
1️⃣ 当前优先处理：跌倒风险（紧急、可干预）
2️⃣ 同步观察：代谢异常（中期、需持续关注）
3️⃣ 暂缓处理：衰老相关问题（长期、低可逆）
```

**关键**：这是决策脑"像医生"的第一步

##### 3.4.2.2 行动类型决策（Action Type）

**作用**：决定"这个问题，靠什么方式来处理？"

**行动类型**：
- **继续观察**：暂时不需要干预
- **补充检测**：需要更多信息
- **生活方式干预**：通过改变生活方式
- **健康管理计划**：制定长期管理计划
- **转人工医生**：超出系统能力

**关键**：
- 这是合规最关键的一层
- 没有"直接治疗疾病"
- 没有"直接开处方"

**与现有模块映射**：
- 今日建议 → 行动类型决策
- AI导诊/症状自查 → 行动类型决策

##### 3.4.2.3 路径组合决策（Care Pathway）

**作用**：决定"不是单一动作，而是分阶段管理路径"

**工作方式**：
- 不是给一个动作，而是给一条路径
- 路径分阶段：阶段1 → 阶段2 → 阶段3

**举例**（代谢风险）：
```
阶段1：睡眠与饮食调整 + 监测（近期）
阶段2：2-4周复测（中期）
阶段3：必要时建议线下就医（长期）
```

**关键**：路径感 = 决策脑与"内容推荐"的本质区别

**与现有模块映射**：
- 干预方案中心 → 路径组合决策

##### 3.4.2.4 风险与边界控制（Safety & Compliance）

**作用**：决定"哪些话不能说？哪些事不能做？"

**工作方式**：
- 自动识别红旗信号
- 自动识别高风险组合
- 自动识别超出系统能力的问题

**决策结果**：
```
⚠️ 当前情况不适合自行管理
建议尽快联系医生
```

**关键**：这是系统"可信"的来源

**与现有模块映射**：
- AI导诊/症状自查 → 风险与边界控制

##### 3.4.2.5 执行可行性校验（Feasibility）

**作用**：决定"这个方案，用户真的能做吗？"

**考虑因素**：
- **用户年龄**：老年人不能做高强度运动
- **依从性历史**：历史完成率低，降低难度
- **设备条件**：没有设备，调整方案
- **行为负担**：任务太多，减少任务

**决策原则**：**宁可少做，但要做得到**

**与现有模块映射**：
- 今日建议 → 执行可行性校验

#### 3.4.3 决策脑的工作特点

##### 特点1：唯一控制权

**决策脑是唯一有控制权的脑**

其他脑的角色：
- 感知脑：输入层（Input）
- 认知脑：状态建模层（State Modeling）
- 预测脑：仿真与评估层（Simulation）
- 决策脑：**控制器（Controller）** ★
- 执行脑：执行器（Actuator）

##### 特点2：合规边界

**不做医疗诊断，不替代医生处方**

只做：
- 健康管理决策
- 医嘱前决策

##### 特点3：路径感

**不是给一个动作，而是给一条路径**

路径特点：
- 分阶段
- 可升级
- 可调整

#### 3.4.4 决策脑的输出

决策脑输出的是**行动方案**：
- 管理路径：分阶段的健康管理路径
- 行动清单：立即做什么、24小时做什么、长期做什么
- 任务列表：具体的可执行任务

这些方案会传递给执行脑，由执行脑来拆解和执行

---

### 3.5 执行脑（Execution Brain）

#### 3.5.1 执行脑的本质

**执行脑 = 确保医生决策真正发生在用户生活中的系统**

不是"提醒系统"，而是"执行支持系统"

#### 3.5.2 五模块执行结构

##### 3.5.2.1 任务拆解与生成（Task Generation）

**作用**：把"抽象建议"拆成"具体可做的事"

**工作方式**：
- 决策脑说："建议你改善睡眠并监测血糖"
- 执行脑拆成：
  - 今天 22:30 前入睡
  - 连续 7 天记录睡眠
  - 本周完成 2 次血糖检测

**关键**：没有拆解，就没有执行

**与现有模块映射**：
- 健康打卡（任务执行） → 任务拆解

##### 3.5.2.2 行为引导与协助（Guidance）

**作用**：不是"叫你做"，而是"带你做"

**引导方式**：
- **步骤化**：一步一步告诉你怎么做
- **情境化**：在合适的时间、场景提醒
- **心理负担降低**：告诉你"这件事很简单、不用担心"

**举例**：
- "这个检测只需要 3 分钟，我可以现在带你完成。"
- "控盐很简单，每天减少一勺盐就可以了。"

**关键**：这是执行脑最体现"家庭医生"的地方

**与现有模块映射**：
- 合理用药（用药提醒） → 行为引导

##### 3.5.2.3 执行监测与反馈（Monitoring）

**作用**：监测"你到底做没做？"

**监测内容**：
- 是否完成
- 是否按时
- 是否连续
- 是否中断

**监测指标**：
```
执行状态
├ 已完成
├ 延迟
├ 中断
└ 放弃
```

**关键**：执行失败不是用户的问题，是系统需要调整的信号

**与现有模块映射**：
- 健康打卡（打卡记录） → 执行监测

##### 3.5.2.4 结果回流与调整（Feedback Loop）

**作用**：执行失败 → 反馈给决策脑 → 重新计算路径

**工作流程**：
```
执行脑：发现执行困难 / 效果不足
    ↓
回流给决策脑
    ↓
决策脑：调整路径
    ↓
执行脑：重新拆解任务
```

**举例**：
- 用户多次未完成晨练
- 执行脑反馈"执行负担过高"
- 决策脑改为"晚间轻活动"

**关键**：执行脑不是死命催，而是会"认输并换方案"

**与现有模块映射**：
- 健康打卡（打卡记录） → 结果回流

##### 3.5.2.5 支持资源与工具（Support）

**作用**：提供执行所需的工具和资源

**包含内容**：
- 健康商城：推荐相关产品
- 内容科普：解释为什么要做
- 设备试纸：提供检测工具

**关键定位**：**不是卖东西，是"为医嘱提供工具"**

**与现有模块映射**：
- 健康商城 → 支持资源与工具
- 健康科普 → 支持资源与工具

#### 3.5.3 执行脑的工作特点

##### 特点1：陪伴型

**不是管理用户，而是"陪用户把事情做完"**

语气特点：
- 陪伴型
- 支持型
- 调整型

不是：
- KPI
- 监督
- 责备

##### 特点2：自适应

**执行失败不是用户的问题，是系统需要调整的信号**

工作方式：
- 执行失败 → 反馈给决策脑
- 决策脑调整路径
- 执行脑重新拆解

##### 特点3：唯一落地的实脑

**前四脑都是"虚脑"，执行脑是"长在地面上"的**

- 感知脑：虚（数据）
- 认知脑：虚（问题）
- 预测脑：虚（风险）
- 决策脑：虚（方案）
- **执行脑：实（真的做了）**

#### 3.5.4 执行脑的输出

执行脑输出的是**执行结果**：
- 完成情况：已完成/延迟/中断/放弃
- 执行质量：完成度、及时性
- 反馈信息：执行困难、效果不足

这些结果会反馈给感知脑，形成闭环

### 3.6 对话中枢（Dialogue Hub）

#### 3.6.1 对话中枢的本质

**对话中枢 = 五脑的"翻译官"和"调度员"**

不是第六个脑，而是位于五脑之上的统一表达与交互层

#### 3.6.2 三层职责

##### 3.6.2.1 理解用户（入口层）

**作用**：理解用户说的话

**工作方式**：
- 用户说："我最近总是很累"
- 对话中枢：
  - 意图识别：用户想了解原因
  - 上下文判断：当前在哪个健康阶段
  - 是否需要调用五脑：需要调用认知脑

**关键**：对话中枢 ≠ 聊天，而是**调度中心**

##### 3.6.2.2 调度五脑（中枢层）

**作用**：判断"需要谁来想"，然后调用对应的脑

**工作方式**：
- 对话中枢从不"自己想医学问题"
- 而是判断"需要谁来想" → 调用对应的脑 → 获得结构化结果

**调度规则**：
| 用户说 | 调用 |
|--------|------|
| "我哪里不舒服" | 感知脑 |
| "这正常吗" | 认知脑 |
| "会不会越来越严重" | 预测脑 |
| "我该怎么做" | 决策脑 |
| "我忘了做检测" | 执行脑 |

**关键**：对话中枢不懂医学，但懂"该问谁"

##### 3.6.2.3 翻译与表达（出口层）

**作用**：把五脑的医学语言翻译成用户可理解的语言

**翻译过程**：
```
医学语言
    ↓ 去专业术语
医生脑内语言
    ↓ 去概率/模型
患者可理解语言
    ↓ 去恐吓/过度确定
医生式表达
```

**举例**：
- 认知脑输出："存在代谢异常模式"
- 对话中枢翻译："从你目前的一些指标组合来看，你的身体正在承受一定的代谢压力。这还不是疾病，但如果长期这样，中期内可能需要更多关注。现在开始调整，会比较有帮助。"

**关键**：没有脑名、没有模型、没有概率，只有医生式表达

#### 3.6.3 对话中枢的工作特点

##### 特点1：五脑不直接说话

**只有对话中枢能和人说话，五脑只和系统说话**

##### 特点2：角色切换

**根据调用不同脑，切换不同对话角色**

| 脑 | 对话角色 | 说什么 |
|---|---------|--------|
| 感知脑 | 问诊者 | 为什么要了解 |
| 认知脑 | 解释者 | 目前关注点 |
| 预测脑 | 提醒者 | 时间+趋势 |
| 决策脑 | 建议者 | 路径与选择 |
| 执行脑 | 陪伴者 | 提醒与协助 |

##### 特点3：四种对话类型

- **采集型对话**（感知）：问你情况、帮你补信息
- **解释型对话**（认知）：帮你理解现状
- **预警型对话**（预测）：提醒风险与时间
- **行动型对话**（决策+执行）：告诉你下一步、陪你完成

#### 3.6.4 对话中枢的输出

对话中枢输出的是**用户可见的对话**：
- 自然语言表达
- 医生式语气
- 可理解的内容

**与现有模块映射**：
- 数字人问答 → 对话中枢
- 智能问诊 → 对话中枢 + 感知脑 + 认知脑

## 四、五脑联动机制设计

### 4.1 标准闭环流程

```
现实世界（用户行为/生理数据）
    ↓
【感知脑】采集事实
    ↓ 原始状态
【认知脑】构建问题模型
    ↓ 当前问题状态
【预测脑】时间演化/风险
    ↓ 风险 + 紧迫性
【决策脑】★行动选择/优先级★
    ↓ 行动方案
【执行脑】行为落地
    ↓ 行为结果
现实世界发生变化
    ↺（再次被感知，形成闭环）
```

### 4.2 三条关键控制回路

#### 4.2.1 回路一：基础现实回路（最重要）

```
执行脑 → 现实变化 → 感知脑
```

**含义**：
- 做了什么？
- 身体有没有变化？
- 行为有没有发生？

**为什么重要**：这是"对现实负责"的回路

#### 4.2.2 回路二：预测校验回路（医生经验来源）

```
预测脑 → 执行/观察 → 感知 → 认知 → 预测
```

**含义**：
- 之前的判断对不对？
- 风险有没有按预期变化？

**为什么重要**：这是系统"越来越像医生"的来源

#### 4.2.3 回路三：执行失败回路（系统成熟度关键）

```
执行失败 → 执行脑 → 决策脑 → 路径重算
```

**含义**：
- 不是"用户不行"
- 而是"方案不适合"

**为什么重要**：这是和"打卡型健康App"的本质区别

### 4.3 时间维度分工

五脑不是"同时工作"，而是**分时间尺度控制**：

| 脑 | 时间尺度 | 说明 |
|---|---------|------|
| 感知脑 | 秒-天 | 实时变化 |
| 认知脑 | 天-周 | 问题形成 |
| 预测脑 | 月-年 | 风险趋势 |
| 决策脑 | 时点决策 | 任意时点 |
| 执行脑 | 天-月 | 行为改变 |

**为什么重要**：这保证了系统既稳定，又能快速反应

### 4.4 事件驱动机制

**五脑通过事件总线联动**：

1. **感知脑**采集到数据 → 发布"感知事件"
2. **认知脑**订阅感知事件 → 处理 → 发布"认知事件"
3. **预测脑**订阅认知事件 → 处理 → 发布"预测事件"
4. **决策脑**订阅预测事件 → 处理 → 发布"决策事件"
5. **执行脑**订阅决策事件 → 处理 → 发布"执行事件"
6. **感知脑**订阅执行事件 → 感知变化 → 形成闭环

**为什么重要**：事件驱动让五脑解耦，各自独立工作，通过事件协调

## 五、模块替换与升级方案

### 5.1 健康打卡模块 → 智能家庭医生

#### 5.1.1 原有功能分析

**健康打卡模块（T1-M5）包含**：
- T1-M5-L1：干预方案中心
- T1-M5-L2：任务执行
- T1-M5-L3：打卡记录

**核心问题**：
- ❌ **被动记录**：用户主动打卡，系统被动记录
- ❌ **缺乏智能**：没有主动识别风险、主动推送建议
- ❌ **孤立运行**：与其他模块缺乏联动

#### 5.1.2 升级为智能家庭医生

**新架构**：基于五脑架构的主动型智能家庭医生

**功能映射**：

| 原有功能 | 五脑归属 | 新功能定位 |
|---------|---------|-----------|
| 干预方案中心 | 决策脑（路径组合决策） | 智能生成分阶段健康管理路径 |
| 任务执行 | 执行脑（任务拆解与生成） | 主动拆解任务、引导执行 |
| 打卡记录 | 执行脑（执行监测与反馈） | 智能监测、结果回流、自动调整 |

**新增能力**：
1. **主动感知**：根据决策脑需求，主动设计感知任务
2. **智能认知**：识别健康问题模式，构建问题结构
3. **风险预测**：预测未来风险，提前干预
4. **智能决策**：综合多源信息，生成个性化管理路径
5. **自适应执行**：根据执行反馈，自动调整方案

#### 5.1.3 实现路径

**Phase 1：基础五脑框架**

- 搭建五脑基础架构
- 实现感知脑（整合健康监测数据）
- 实现认知脑（基础问题识别）
- 实现决策脑（基础路径生成）
- 实现执行脑（任务拆解与监测）

**Phase 2：智能增强**

- 实现预测脑（风险预测）
- 增强认知脑（模式识别）
- 增强决策脑（多源融合决策）
- 增强执行脑（自适应调整）

**Phase 3：对话中枢**

- 实现对话中枢
- 统一表达与交互
- 角色切换与翻译

### 5.2 合理用药模块 → 智能诊断医生

#### 5.2.1 原有功能分析

**合理用药模块（T1-M6）包含**：
- T1-M6-L1：家庭药箱（电子药箱 + 用药提醒）

**核心问题**：
- ❌ **功能单一**：主要是用药提醒和库存管理
- ❌ **缺乏诊断能力**：不能解读检查报告、不能辅助诊断
- ❌ **缺乏联动**：与健康监测、健康评估缺乏深度联动

#### 5.2.2 升级为智能诊断医生

**新架构**：基于五脑架构的智能诊断支持系统

**功能映射**：

| 原有功能 | 五脑归属 | 新功能定位 |
|---------|---------|-----------|
| 家庭药箱 | 执行脑（支持资源与工具） | 用药执行支持 |
| 用药提醒 | 执行脑（行为引导与协助） | 智能用药管理 |

**新增能力**：
1. **报告解读**：认知脑（模式组合层）识别异常组合模式
2. **诊断支持**：认知脑（问题建模层）构建诊断方向
3. **鉴别诊断**：认知脑输出可能方向、支持点、反对点
4. **用药决策**：决策脑（行动类型决策）决定用药方案
5. **用药监测**：执行脑监测用药依从性、不良反应

#### 5.2.3 实现路径

- 增强执行脑（用药执行支持）
- 增强感知脑（用药依从性感知）
- 增强认知脑（用药风险识别）

   - 模式组合：血压异常 + 睡眠不足（从行为感知得知）→ 代谢压力模式

4. 【决策脑】接收预测事件，做出决策
   - 问题优先级：当前优先处理

   ↓ 触发事件：task_executed
   
6. 【感知脑】接收执行事件，感知结果

### 6.4 如何实现"所有模块都联动起来"

#### 6.4.1 核心机制

**所有模块通过五脑中枢协调，形成统一智能体**

**模块映射关系**：
- 健康监测模块 → 感知脑（生理感知）

#### 6.4.2 联动方式

1. 模块A触发事件 → 事件总线
2. 事件总线分发 → 相关模块
3. 相关模块处理 → 触发新事件
4. 形成联动链条

#### 6.4.3 统一表达

**所有模块的结果通过对话中枢统一表达**：

- 用户看到的不是"多个模块"
- 而是"一个智能医生"
- 所有模块的结果都通过对话中枢翻译成统一的医生式表达

- 当前血压：140/90 mmHg
- 连续3天偏高

- 睡眠情况：最近7天平均5小时

**认知脑接收**：感知脑的原始事实

**认知脑工作**：
- **信息理解**：140/90 → 轻度异常
- **异常识别**：连续3天偏高 → 值得关注（不是偶然）
- **模式组合**：血压异常 + 睡眠不足 → 代谢压力模式

**认知脑输出**：问题结构
- 主要问题：血压控制不稳定
- 问题证据：连续3天偏高、睡眠不足
- 问题模式：代谢压力模式

#### Step 3：预测脑工作

**预测脑接收**：认知脑的问题结构

**预测脑工作**：
- **风险映射**：血压控制不稳定 → 心血管风险

**预测脑输出**：风险清单
- 风险：心血管风险
- 时间：中期（3-24个月）
- 可逆性：中可逆
- 优先级：需持续关注

#### Step 4：决策脑工作

**决策脑接收**：预测脑的风险清单

**决策脑工作**：
- **问题优先级**：当前优先处理
- **行动类型**：生活方式干预 + 补充检测
- **路径组合**：
  - 阶段1：控盐+监测（近期）
  - 阶段2：复评（2-4周）
  - 阶段3：必要时就医（长期）
- **边界控制**：无红旗信号，可自行管理
- **可行性校验**：用户年龄55岁，可以执行

**决策脑输出**：行动方案
- 管理路径：分阶段健康管理路径
- 行动清单：立即控盐、24小时内复测、如持续偏高建议就医

#### Step 5：执行脑工作

**执行脑接收**：决策脑的行动方案

**执行脑工作**：
- **任务拆解**：
  - 今天控盐<6g
  - 明天早上8点复测血压
  - 连续7天记录
- **行为引导**："这个检测只需要3分钟，我可以现在带你完成"

**执行脑输出**：执行结果
- 任务已生成
- 提醒已设置
- 支持资源已推荐

#### Step 6：对话中枢工作

**对话中枢工作**：
- **理解用户**：用户可能问"我的血压怎么样？"
- **调度五脑**：调用认知脑、预测脑、决策脑
- **翻译表达**："您的血压连续3天偏高，建议复测。这还不是疾病，但如果长期这样，中期内可能需要更多关注。现在开始控盐，会比较有帮助。"

**对话中枢输出**：用户可见的对话

#### Step 7：闭环反馈

**执行脑监测**：用户完成了控盐任务，但未完成复测

**执行脑反馈**：通过事件总线反馈给决策脑

**决策脑调整**：降低任务难度，改为"3天内完成复测即可"

**执行脑重新拆解**：调整任务时间

**感知脑感知**：监测到用户执行情况，更新状态

## 十、关键设计原则总结

### 10.1 决策脑是唯一控制中心

- 只有决策脑可以决定"做什么"
- 其他脑都不能决定"要不要做事"
- 这是"医生权威"的所在

### 10.2 五脑不直接说话

- 只有对话中枢能和人说话
- 五脑只和系统说话
- 如果用户能感知到"你背后有多少个脑"，那这套系统就是失败的

### 10.3 闭环控制

- 感知→认知→预测→决策→执行→再感知
- 形成完整的反馈回路
- 这是"对现实负责"的保证

### 10.4 事件驱动

- 通过事件总线实现五脑联动
- 五脑解耦，各自独立工作
- 通过事件协调，形成统一智能体

### 10.5 时间维度分工

- 五脑分时间尺度控制
- 既稳定，又能快速反应
- 这是系统稳定性的来源
