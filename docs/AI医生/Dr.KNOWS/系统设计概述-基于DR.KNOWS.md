# AI医生系统设计概述 - 基于DR.KNOWS论文

> **一句话总结**：系统设计基于DR.KNOWS论文的核心方法，并扩展为完整的AI医生能力。

---

## 一、DR.KNOWS论文的核心方法（3分钟理解）

### 核心思想
**"路径是核心产物，诊断文本是最后的表达层"**

DR.KNOWS不是让LLM自由生成诊断，而是**先找到医学推理路径，再用路径约束LLM生成诊断**。

### 核心流程（论文方法）

```
患者描述症状
    ↓
【步骤1】医学概念识别 → 提取"胸痛"、"出汗"等概念
    ↓
【步骤2】知识图谱检索 → 从Neo4j中找推理路径
    例：胸痛 → 心血管疾病 → 心绞痛
    ↓
【步骤3】路径评分排序 → 用SGIN+注意力机制评分，选出Top-10路径
    ↓
【步骤4】路径注入LLM → 把路径作为上下文给LLM
    ↓
【步骤5】LLM生成诊断 → 在路径约束下生成诊断，减少幻觉
    ↓
诊断结果 + 推理路径（可解释）
```

### 关键技术点

1. **知识图谱路径检索**：Neo4j图遍历，找症状→疾病的推理路径
2. **路径评分**：SGIN生成节点嵌入 + 注意力机制计算相似度
3. **路径注入**：将排序后的路径作为上下文注入prompt
4. **受控生成**：LLM在路径约束下生成，避免自由联想

## 二、系统设计如何基于论文扩展（核心对应关系）

### 2.1 论文方法 → 系统设计的直接对应

| DR.KNOWS论文 | 系统设计（工具） | 技术实现 |
|-------------|----------------|---------|
| **医学概念识别** | 工具A：病例理解与结构化 | QuickUMLS / 中文医学NER |
| **知识图谱路径检索** | 工具C：鉴别诊断引擎（知识图谱引擎） | Neo4j图遍历 + Cypher查询 |
| **路径评分排序** | 工具C：鉴别诊断引擎 | SGIN + 注意力机制 |
| **路径注入LLM** | 工具C：鉴别诊断引擎（大模型引擎） | 路径格式化 + Prompt注入 |
| **诊断预测生成** | 工具C：鉴别诊断引擎（多引擎融合） | LLM + 多引擎加权融合 |

**核心要点**：系统**完全采用**DR.KNOWS的路径检索+路径注入方法作为核心推理引擎。

---

### 2.2 系统设计的扩展（论文没有的部分）

DR.KNOWS论文只解决**"是什么病"**的问题，系统扩展为**完整的AI医生能力**：

#### 扩展1：主动问诊能力（工具B）
- **论文**：被动接收病历文本
- **系统**：主动询问关键信息，智能追问
- **价值**：像真人医生一样主动收集信息

#### 扩展2：多引擎融合（工具C）
- **论文**：只用知识图谱+LLM
- **系统**：规则引擎 + 知识图谱 + 统计模型 + 大模型 + 鉴别诊断
- **价值**：提高准确性和可靠性

#### 扩展3：检查建议（工具D）
- **论文**：不涉及检查建议
- **系统**：基于DDx建议检查，评估检查价值
- **价值**：完整的诊断流程

#### 扩展4：治疗建议（工具E）
- **论文**：不涉及治疗
- **系统**：基于诊断推理治疗方案
- **价值**：完整的医疗闭环

#### 扩展5：风险评估（工具F）
- **论文**：不涉及风险评估
- **系统**：识别高危情况，紧急程度分级
- **价值**：安全性保障

#### 扩展6：可解释性（工具G）
- **论文**：有推理路径，但不够完整
- **系统**：完整的证据链、支持/反对证据、终点结论包
- **价值**：可追溯、可审核

## 三、系统设计的核心技术架构

```
┌─────────────────────────────────┐
│  通道1：结构化推理通道（核心）    │
│  决定"该往哪想" - 临床逻辑        │
│  ├─ 工具A：病例理解              │
│  ├─ 工具C：知识图谱路径检索       │ ← DR.KNOWS核心
│  ├─ 工具C：路径评分排序           │ ← DR.KNOWS核心
│  ├─ 工具C：多引擎融合             │
│  └─ 工具C：路径注入LLM            │ ← DR.KNOWS核心
└─────────────────────────────────┘
            ↓
       CDP（临床决策包）
            ↓
┌─────────────────────────────────┐
│  通道2：语言与策略通道           │
│  决定"怎么说、怎么问"             │
│  ├─ 工具B：主动问诊              │
│  └─ 工具G：可解释性生成          │
└─────────────────────────────────┘
```

**核心原则**：
- **通道1（结构化推理）**：决定"该往哪想" → 使用DR.KNOWS方法
- **通道2（语言表达）**：决定"怎么说" → LLM生成自然语言
