# 健康判定服务 - 架构与逻辑整理

> **文档定位**：本文档全面整理健康状态判定服务（health-state-assessment-service）的系统架构、核心逻辑、数据流程和技术实现细节。  
> **服务定位**：AI医生系统的脑区0，系统入口服务，负责判断"这个人，现在需要被当成'病人'对待吗？"  

**文档内容说明**：
- ✅ **完整实现**：已完整实现，符合设计规范的功能
- 🟡 **简化实现**：采用简化实现方式，功能可用但需要进一步优化的功能
- 📋 **设计目标**：设计文档中定义的目标，当前未完全实现

---

## 一、服务概述

### 1.1 服务定位

- **对应脑区**：脑区0（健康状态判定）
- **在架构中的位置**：系统入口服务，所有用户请求的第一站
- **服务职责**：
  1. 执行入口判定流程（P0模块，Step 1-5）
  2. 工作态判定（健康管理态/临床诊疗态）
  3. 危险信号检查（安全兜底，所有用户都要过一次）
  4. 健康管理计划生成（健康管理态时）
  5. CDP创建（可选，或由diagnosis-service创建）

### 1.2 核心价值

- **系统入口判定**：决定用户进入哪个路径（健康筛查路径A / 症状诊断路径B）
- **安全兜底**：识别危险信号并提示就医，避免线上诊断处理紧急情况
- **工作态判定**：区分健康管理和临床诊疗场景，提供不同的服务流程
- **风险分级**：对用户进行风险等级评估，为后续流程提供依据

## 三、核心业务流程

### 3.1 完整流程概览

```
用户输入
   │
   ▼
┌─────────────────────────────────────┐
│  入口判定流程（P0模块，Step 1-5）    │
├─────────────────────────────────────┤
│ Step 1: 接收用户输入                │
│ Step 2: 识别症状/困扰               │
│ Step 3: 方向澄清（仅情况C）         │
│ Step 4: 危险信号检查（所有用户）     │
│ Step 5: 路径选择                    │
└─────────────────────────────────────┘
   │
   ├─→ 危险信号命中 → 退出流程（提示就医）
   │
   ├─→ 路径A（健康筛查） → 健康管理态
   │
   └─→ 路径B（症状诊断） → 临床诊疗态
```

### 3.2 入口判定流程（P0模块）详细逻辑

#### Step 1: 接收用户输入

**功能**：
- 接收用户自然语言输入
- 支持自然语言理解（NLU）
- 允许混合诉求（既想体检又有轻微不适）
- 不依赖选择题入口

**设计实现**（参考《health-state-assessment-service - 服务实现方案.md》）：
1. **自然语言理解（NLU）**
   - **设计方案**：可选集成LLM API（如OpenAI）进行NLU，支持医疗领域NER模型（医疗BERT、BioBERT）
   - **当前实现**：使用关键词匹配和正则表达式（简化实现）
   - **优化方向**：
     - 集成医疗领域NER模型（医疗BERT、BioBERT）
     - 实体链接到医学知识库（UMLS、ICD-10）
     - 同义词扩展和实体归一化

2. **意图识别**
   - 识别筛查意图关键词（体检、筛查、检查、健康管理、预防等）
   - 识别症状关键词（痛、疼、不适、难受、不舒服、异常等）
   - 判断意图类型：
     - `screening`：纯筛查意图
     - `diagnosis`：症状咨询意图
     - `mixed`：混合诉求
     - `unknown`：不确定

3. **实体提取**
   - 提取症状实体（症状、需求等）
   - 提取基本信息（年龄、性别、BMI等）
   - 支持同义词识别和实体归一化（设计目标）

**输出**：
```python
{
    "original_input": str,          # 原始输入
    "intent": str,                  # 用户意图
    "entities": list,               # 提取的实体
    "has_symptoms": bool,           # 是否包含症状描述
    "has_screening_intent": bool,   # 是否包含筛查意图
    "basic_info": dict,             # 基本信息
    "provided_symptoms": list       # 提供的症状列表
}
```

#### Step 2: 识别症状/困扰

**功能**：
- 识别用户是否"有症状/困扰"
- 轻微问题也算"有困扰"，不要求严重程度
- 能识别"明确无症状"的表达

**判断结果**：
- **情况A**：明确无症状（纯筛查/体检规划）→ `no_symptom`
- **情况B**：存在症状/困扰（不论轻重）→ `has_symptom`
- **情况C**：不确定/模糊/混合诉求 → `uncertain`

**处理逻辑**：
1. 从Step 1的输出中提取症状实体
2. 根据意图和症状存在性判断情况
3. 提取困扰（心理、功能变化等）

**输出**：
```python
{
    "status": str,          # "no_symptom" | "has_symptom" | "uncertain"
    "symptoms": list,       # 识别的症状列表
    "concerns": list,       # 识别的困扰列表
    "confidence": float,    # 识别置信度
    "intent": str,          # 意图
    "original_input": str   # 原始输入
}
```

#### Step 3: 方向澄清

**功能**：
- 仅对"情况C"（不确定/模糊/混合诉求）触发
- 生成最小澄清问题
- 根据用户回答确定方向（A或B）

**设计实现**（参考《health-state-assessment-service - 服务实现方案.md》）：
1. **触发条件**：检查是否为情况C（`status == "uncertain"`）

2. **澄清问题生成**
   - **设计方案**：使用LLM生成澄清问题（可选），提供选项按钮方便用户快速选择
   - **当前实现**：自动推断，不等待用户回答（简化实现）
   - **优化方向**：
     - 返回澄清问题给前端，等待用户回答
     - 实现异步澄清流程
     - 使用LLM生成更自然的澄清问题

3. **方向确定**
   - 根据用户回答确定方向（A或B）
   - 支持用户选择健康筛查（A）或症状咨询（B）

**注意**：当前实现采用自动推断方式，不符合设计规范中的"方向澄清"要求，后续需要优化为异步澄清流程。

**输出**：
```python
{
    "clarified": bool,      # 是否已澄清
    "direction": str,       # "A" | "B"
    "clarification_question": str,  # 澄清问题
    "user_response": str    # 用户回答
}
```

#### Step 4: 危险信号检查

**功能**：
- **所有用户都要过一次**（安全兜底）
- 使用红旗信号库匹配
- 检查高危症状组合
- 如果命中危险信号，退出线上流程

**处理逻辑**：
1. 使用红旗信号库（0.3）匹配症状
2. 检查高危症状组合：
   - 心梗三联征：胸痛 + 气短 + 出汗
   - 脑出血可能：剧烈头痛 + 恶心 + 呕吐
   - 肺栓塞可能：呼吸困难 + 胸痛 + 晕厥
   - 急性心梗可能：胸痛 + 大汗 + 恶心
3. 如果命中危险信号，标记为需要退出流程

**输出**：
```python
{
    "red_flags_hit": bool,      # 是否命中危险信号
    "red_flags": list,          # 检测到的危险信号列表
    "safety_message": str       # 安全提示信息
}
```

#### Step 5: 路径选择

**功能**：
- 根据前面的判断结果确定路径
- 输出路径选择结果

**路径选择规则**：
1. **危险信号命中** → 退出线上流程（`exit`）
2. **情况A（明确无症状）** → 进入健康筛查路径（`A`）
3. **情况B（存在症状/困扰）** → 进入症状诊断路径（`B`）
4. **情况C（不确定）** → 默认进入B路径（安全优先）

**输出**：
```python
{
    "path": str,            # "A" | "B" | "exit"
    "path_name": str,       # 路径名称
    "next_step": str,       # 下一步骤
    "cdp_id": str,          # CDP ID
    "reason": str,          # 选择原因
    "message": str          # 提示信息
}
```

### 3.3 健康状态判定流程

#### 3.3.1 主流程

```
入口判定结果
   │
   ├─→ 危险信号命中 → 直接返回（L1风险，临床诊疗态）
   │
   └─→ 正常流程
        │
        ├─→ 症状严重程度评估
        ├─→ 风险早筛
        ├─→ 红旗信号识别（与入口判定结果合并）
        ├─→ 工作态判定
        ├─→ 风险等级计算
        └─→ 健康管理计划生成（仅健康管理态）
```

#### 3.3.2 症状严重程度评估

**使用规则库**：症状严重程度判定规则库（0.1）

**严重程度等级**：
- `NORMAL`：正常范围（无症状）
- `LOW`：轻度
- `MODERATE`：中度
- `HIGH`：重度

**评估逻辑**：
1. 检查是否包含高危症状（胸痛、呼吸困难、意识不清、剧烈头痛、大出血、高热）
2. 检查是否包含中等严重症状（胸痛、腹痛、头痛、发热、咳嗽、气短、乏力、恶心、呕吐、腹泻）
3. 根据症状数量和类型计算严重程度分数（0-1）
4. 映射到严重程度等级

#### 3.3.3 风险早筛

**使用规则库**：早期风险信号识别库（0.2）

**识别内容**：
- 家族史（高血压、糖尿病、心血管疾病等）
- 行为风险（高盐饮食、肥胖、缺乏运动、吸烟、饮酒等）
- 慢性暴露风险

**输出**：
```python
{
    "risk_factors": list,       # 风险因素列表
    "lifestyle_risks": list,    # 生活方式风险
    "risk_level": str,          # 风险等级（L1/L2/L3/L4）
    "family_history": dict      # 家族史信息
}
```

#### 3.3.4 红旗信号识别

**使用规则库**：红旗信号库（0.3）

**识别内容**：
- 高危症状（胸痛、呼吸困难、意识不清、剧烈头痛、大出血、高热）
- 高危症状组合（心梗三联征、脑出血可能、肺栓塞可能、急性心梗可能）

**与入口判定结果合并**：
- 合并入口判定（Step 4）和健康状态判定中的红旗信号检测结果
- 去重后返回完整的红旗信号列表

#### 3.3.5 工作态判定

**使用规则库**：工作态判定规则库（0.4）

**工作态类型**：
- `clinical_mode`：临床诊疗态
- `wellness_mode`：健康管理态

**设计实现**（参考《health-state-assessment-service - 服务实现方案.md》和《AI医生系统-技术架构设计.md》）：

**判定规则**（优先级从高到低）：
1. **规则1**：出现红旗信号 → 立即进入临床诊疗态
2. **规则2**：检查生命体征异常 → 进入临床诊疗态
   - 高血压危象：收缩压 ≥ 180 或 舒张压 ≥ 120
   - 低血压休克：收缩压 < 90
   - 心动过速或过缓：心率 ≥ 120 或 ≤ 50
3. **规则3**：症状严重程度高 → 进入临床诊疗态
4. **规则4**：风险等级 ≥ L2 → 进入临床诊疗态
5. **规则5**：症状严重程度中 + 风险等级L3 → 进入临床诊疗态
6. **规则6**：症状在正常范围且风险等级低（L3/L4） → 进入健康管理态
7. **规则7**：不确定时，优先进入临床诊疗态（宁可误报，不能漏报）

**入口判定路径选择的影响**：
- **设计意图**：入口判定（P0模块）的路径选择结果（A/B）应该作为工作态判定的重要依据，但不是唯一依据
- **设计逻辑**：
  - 如果入口判定选择了路径A（健康筛查），且满足规则6的条件，则进入健康管理态
  - 如果入口判定选择了路径B（症状诊断），则优先考虑进入临床诊疗态
  - 但即使选择了路径A，如果出现红旗信号、生命体征异常、症状严重程度高等情况，仍应进入临床诊疗态（安全优先）
- **当前实现**：代码中简化实现为直接根据路径选择结果确定工作态，后续需要优化为按照规则1-7进行综合判定

#### 3.3.6 风险等级计算

**风险等级定义**：
- **L1**：极高风险（需立即处理）- 有红旗信号 + 生命体征异常
- **L2**：高风险（需尽快处理）- 有红旗信号或症状严重程度高
- **L3**：中风险（建议关注）- 症状严重程度中等或存在风险因素
- **L4**：低风险（正常管理）- 症状在正常范围

**计算逻辑**：
1. 有红旗信号 + 生命体征异常 → L1
2. 有红旗信号 → L2
3. 症状严重程度高 → L2
4. 症状严重程度中 + 风险等级L2 → L2
5. 症状严重程度中 + 风险等级L3 → L3
6. 症状严重程度低 + 高风险因素 → L3
7. 症状严重程度低 + 低风险因素 → L4
8. 正常范围 → L4

#### 3.3.7 健康管理计划生成

**使用规则库**：健康管理计划生成规则（0.5）

**生成时机**：仅在健康管理态时生成

**生成内容**：
1. **风险识别**：识别到的风险因素
2. **生活方式建议**：根据风险因素提供个性化建议
3. **随访计划**：根据风险等级制定随访计划

**输出**：
```python
{
    "riskManagement": str,      # 风险识别
    "lifestyleAdvice": str,     # 生活方式建议
    "followUpPlan": str         # 随访计划
}
```

## 四、数据模型

### 4.1 请求模型

```python
class HealthStateAssessmentRequest(BaseModel):
    """健康状态判定请求"""
    userId: str                          # 用户ID（必填）
    cdpId: Optional[str] = None          # CDP ID（可选）
    userInput: Optional[str] = None      # 用户原始输入文本
    basicInfo: Optional[Dict[str, Any]] = None  # 基本信息：age, gender, bmi等
    symptoms: Optional[List[str]] = None # 症状列表
    vitalSigns: Optional[Dict[str, Any]] = None  # 生命体征：bp, heartRate等
```

### 4.2 响应模型

```python
class WellnessPlan(BaseModel):
    """健康管理计划"""
    riskManagement: str                  # 风险识别
    lifestyleAdvice: str                 # 生活方式建议
    followUpPlan: str                   # 随访计划

class HealthStateAssessmentResponse(BaseModel):
```

## 六、规则库

### 6.1 症状严重程度判定规则库（0.1）

**文件位置**：`app/rules/severity_rules.py`

**功能**：判定症状的严重程度等级

**严重程度等级**：
- `NORMAL`：正常范围（无症状）
- `LOW`：轻度
- `MODERATE`：中度
- `HIGH`：重度

**判定规则**：
1. 检查是否包含高危症状（胸痛、呼吸困难、意识不清、剧烈头痛、大出血、高热）
2. 检查是否包含中等严重症状（胸痛、腹痛、头痛、发热、咳嗽、气短、乏力、恶心、呕吐、腹泻）
3. 根据症状数量和类型计算严重程度分数（0-1）
4. 映射到严重程度等级

### 6.2 早期风险信号识别库（0.2）

**文件位置**：`app/rules/risk_screening_rules.py`

**功能**：识别早期风险信号，用于健康管理

**识别内容**：
- 家族史（高血压、糖尿病、心血管疾病等）
- 行为风险（高盐饮食、肥胖、缺乏运动、吸烟、饮酒等）
- 慢性暴露风险

**输出**：
- 风险因素列表
- 生活方式风险
- 风险等级（L1/L2/L3/L4）
- 家族史信息

### 6.3 红旗信号库（0.3）

**文件位置**：`app/rules/red_flag_rules.py`

**功能**：识别危险信号，用于安全兜底

**高危症状**：
- 胸痛
- 呼吸困难
- 意识不清
- 剧烈头痛
- 大出血
- 高热

**高危症状组合**：
- 心梗三联征：胸痛 + 气短 + 出汗
- 脑出血可能：剧烈头痛 + 恶心 + 呕吐
- 肺栓塞可能：呼吸困难 + 胸痛 + 晕厥
- 急性心梗可能：胸痛 + 大汗 + 恶心

### 6.4 工作态判定规则库（0.4）

**文件位置**：`app/rules/work_mode_rules.py`

**功能**：判定工作态（健康管理态/临床诊疗态）

**工作态类型**：
- `clinical_mode`：临床诊疗态
- `wellness_mode`：健康管理态

**判定规则**（优先级从高到低）：
1. 出现红旗信号 → 立即进入临床诊疗态
2. 检查生命体征异常 → 进入临床诊疗态
3. 症状严重程度高 → 进入临床诊疗态
4. 风险等级 ≥ L2 → 进入临床诊疗态
5. 症状严重程度中 + 风险等级L3 → 进入临床诊疗态
6. 症状在正常范围且风险等级低（L3/L4） → 进入健康管理态
7. 不确定时，优先进入临床诊疗态（宁可误报，不能漏报）

### 6.5 健康管理计划生成规则（0.5）

**文件位置**：`app/rules/wellness_plan_rules.py`

**功能**：生成健康管理计划

**生成内容**：
1. **风险识别**：识别到的风险因素
2. **生活方式建议**：根据风险因素提供个性化建议
3. **随访计划**：根据风险等级制定随访计划

## 八、服务实现

### 8.1 主服务类

**文件位置**：`app/services/health_state_assessment.py`

**类名**：`HealthStateAssessmentService`

**核心方法**：
- `assess(request: HealthStateAssessmentRequest) -> HealthStateAssessmentResponse`：执行健康状态判定

**处理流程**：
1. 执行入口判定（P0模块，Step 1-5）
2. 如果命中危险信号，直接返回退出结果
3. 基于入口判定结果进行健康状态判定：
   - 症状严重程度评估
   - 风险早筛
   - 红旗信号识别（与入口判定结果合并）
   - 工作态判定
   - 风险等级计算
   - 健康管理计划生成（仅健康管理态）

### 8.2 入口判定流程服务

**文件位置**：`app/services/entry_assessment/`

**功能**：执行入口判定流程（P0模块，Step 1-5）

**模块组成**：
- `step1_receive_input.py`：Step 1: 接收用户输入
- `step2_identify_symptom.py`：Step 2: 识别症状/困扰
- `step3_clarification.py`：Step 3: 方向澄清
- `step4_red_flag_check.py`：Step 4: 危险信号检查
- `step5_path_selection.py`：Step 5: 路径选择

**入口函数**：
- `perform_entry_assessment(user_input_dict: Dict) -> Dict`：执行完整的入口判定流程

### 8.3 健康管理计划生成服务

**文件位置**：`app/services/wellness_plan_generator.py`

**功能**：生成健康管理计划

**主要函数**：
- `generate_wellness_plan(risk_level: str, risk_factors: List, basic_info: Dict) -> WellnessPlan`：生成健康管理计划

### 8.4 健康筛查流程服务

**文件位置**：`app/services/wellness_screening_service.py`

**功能**：执行健康筛查流程（A路径）

**主要方法**：
- `a1_demand_classification(request: Dict) -> Dict`：A1: 需求分类
- `a2_health_profile_collection(request: Dict) -> Dict`：A2: 收集健康画像
- `a3_branch_execution(request: Dict) -> Dict`：A3: 执行分支
- `a4_unified_result_generation(request: Dict) -> Dict`：A4: 生成统一结果
