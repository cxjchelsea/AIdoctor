# AI医生系统 - 工具调用协议

> **文档定位**：本文档详细定义AI医生系统的工具调用协议，包括ToolContext（工具调用上下文）和ToolResult（工具返回结果）的详细规范。这是开发工具时的必读文档。

## 一、工具调用协议概述

### 1.1 协议定位

**工具调用协议定位**：
- **统一接口规范**：定义主Agent与工具之间的统一接口规范
- **ToolContext**：主Agent调用工具时传递的上下文信息
- **ToolResult**：工具执行后返回给主Agent的结果
- **可追溯**：所有工具调用都通过trace_id关联，记录到AuditTrail

### 1.2 调用流程

**工具调用流程**：

```
主Agent决定调用工具
    ↓
生成ToolContext（包含CDP引用、AgentState摘要、约束等）
    ↓
调用工具（通过REST API或内部调用）
    ↓
工具执行（从CDP读取数据，执行逻辑，生成结果）
    ↓
工具返回ToolResult（包含payload、evidence、quality、suggestedWrites）
    ↓
主Agent评估ToolResult
    ↓
决定是否写回CDP
```

## 二、ToolContext（工具调用上下文）

### 2.1 ToolContext定位

**ToolContext定位**：
- **工具调用上下文**：ToolContext是主Agent调用工具时传递的上下文信息
- **工具输入来源**：工具通过ToolContext获取CDP引用、AgentState摘要、约束等信息
- **不可修改**：工具不能修改ToolContext，只能读取

### 2.2 ToolContext字段结构

**ToolContext字段结构**：

| 字段路径 | 数据类型 | 说明 | 必填 |
|---------|---------|------|------|
| `tool_context.trace_id` | String | 追踪ID（用于审计和调试） | 是 |
| `tool_context.cdp_reference` | JSON | CDP引用 | 是 |
| `tool_context.cdp_reference.cdp_id` | String | CDP ID | 是 |
| `tool_context.cdp_reference.version` | Integer | CDP版本号 | 是 |
| `tool_context.cdp_reference.read_fields` | Array | 工具需要读取的CDP字段路径 | 是 |
| `tool_context.agent_state_summary` | JSON | AgentState摘要 | 是 |
| `tool_context.agent_state_summary.current_step` | Integer | 当前诊断步骤（1-5） | 是 |
| `tool_context.agent_state_summary.work_mode` | String | 工作态（wellness_mode/clinical_mode） | 是 |
| `tool_context.constraints` | JSON | 约束（成本/时间/风险） | 是 |
| `tool_context.constraints.max_time_seconds` | Integer | 最大执行时间（秒） | 是 |
| `tool_context.constraints.max_cost` | Float | 最大成本 | 是 |
| `tool_context.constraints.risk_level_limit` | String | 风险等级限制（L1/L2/L3/L4） | 否 |
| `tool_context.call_params` | JSON | 工具调用参数（工具特定） | 否 |

### 2.3 ToolContext JSON示例

**ToolContext JSON示例**：

```json
{
  "trace_id": "trace_1234567890",
  "cdp_reference": {
    "cdp_id": "cdp_001",
    "version": 2,
    "read_fields": [
      "cdp.patient_state",
      "cdp.ddx"
    ]
  },
  "agent_state_summary": {
    "current_step": 3,
    "work_mode": "clinical_mode"
  },
  "constraints": {
    "max_time_seconds": 30,
    "max_cost": 10.0,
    "risk_level_limit": "L3"
  },
  "call_params": {
    "mode": "normal",
    "options": {
      "include_reasoning_paths": true
    }
  }
}
```

### 2.4 ToolContext生成规则

**ToolContext生成规则**：
- 主Agent在调用工具前生成ToolContext
- 根据工具的输入依赖（从CDP读取哪些字段路径）设置`cdp_reference.read_fields`
- 根据AgentState生成`agent_state_summary`
- 根据当前状态和工具特性设置`constraints`
- 生成唯一的`trace_id`，用于关联ToolContext和ToolResult

## 三、ToolResult（工具返回结果）

### 3.1 ToolResult定位

**ToolResult定位**：
- **工具返回结果**：ToolResult是工具执行后返回给主Agent的结果
- **结构化输出**：ToolResult包含status、payload、evidence、quality、suggestedWrites、errors等字段
- **主Agent决策依据**：主Agent根据ToolResult决定是否写回CDP、是否继续调用其他工具

### 3.2 ToolResult字段结构

**ToolResult字段结构**：

| 字段路径 | 数据类型 | 说明 | 必填 |
|---------|---------|------|------|
| `tool_result.trace_id` | String | 追踪ID（与ToolContext中的trace_id一致） | 是 |
| `tool_result.tool_id` | String | 工具ID | 是 |
| `tool_result.status` | String | 执行状态（success/partial_success/failure/timeout） | 是 |
| `tool_result.payload` | JSON | 输出payload（工具特定结构） | 是 |
| `tool_result.evidence` | Array | 证据引用 | 是 |
| `tool_result.evidence[].source` | String | 证据来源（knowledge_base/kg_path/rule/llm） | 是 |
| `tool_result.evidence[].reference` | String | 证据引用（CUI/路径ID/规则ID/LLM prompt） | 是 |
| `tool_result.evidence[].strength` | String | 证据强度（strong/medium/weak） | 是 |
| `tool_result.quality` | JSON | 质量指标 | 是 |
| `tool_result.quality.confidence` | Float | 置信度（0.0-1.0） | 是 |
| `tool_result.quality.completeness` | Float | 完整度（0.0-1.0） | 是 |
| `tool_result.quality.accuracy` | Float | 准确度（0.0-1.0，如可评估） | 否 |
| `tool_result.suggested_writes` | Array | 建议写回CDP的字段路径 | 是 |
| `tool_result.suggested_writes[].field_path` | String | 字段路径（如`cdp.ddx`） | 是 |
| `tool_result.suggested_writes[].value` | JSON | 字段值 | 是 |
| `tool_result.suggested_writes[].reason` | String | 写回原因 | 是 |
| `tool_result.errors` | Array | 错误信息 | 否 |
| `tool_result.errors[].error_type` | String | 错误类型（timeout/validation_error/runtime_error） | 是 |
| `tool_result.errors[].error_message` | String | 错误消息 | 是 |
| `tool_result.errors[].error_details` | JSON | 错误详情 | 否 |
| `tool_result.duration_ms` | Integer | 执行时间（毫秒） | 是 |
| `tool_result.metadata` | JSON | 元数据（工具特定） | 否 |

### 3.4 ToolResult状态说明

**ToolResult状态说明**：

| 状态 | 说明 | 主Agent处理策略 |
|------|------|----------------|
| `success` | 工具执行成功，输出完整 | 评估quality，决定是否写回CDP |
| `partial_success` | 工具执行部分成功，输出不完整 | 评估quality和errors，决定是否写回CDP或重试 |
| `failure` | 工具执行失败 | 根据错误类型决定是否重试或使用降级策略 |
| `timeout` | 工具执行超时 | 根据工具重要性决定是否重试或使用降级策略 |

## 四、工具调用REST API规范

### 4.1 API端点

**工具调用REST API端点**：

```http
POST /api/v1/tools/{tool_id}/invoke
```

**请求头**：
```
Content-Type: application/json
X-Trace-Id: {trace_id}  # 可选，如果未提供，服务端会生成
```

**请求体**：ToolContext JSON

**响应体**：ToolResult JSON

### 4.2 API示例

**请求示例**：

```http
POST /api/v1/tools/tool_3/invoke
Content-Type: application/json

{
  "trace_id": "trace_1234567890",
  "cdp_reference": {
    "cdp_id": "cdp_001",
    "version": 2,
    "read_fields": [
      "cdp.patient_state",
      "cdp.ddx"
    ]
  },
  "agent_state_summary": {
    "current_step": 3,
    "work_mode": "clinical_mode"
  },
  "constraints": {
    "max_time_seconds": 30,
    "max_cost": 10.0
  },
  "call_params": {}
}
```

**响应示例（成功）**：

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "trace_id": "trace_1234567890",
  "tool_id": "tool_3",
  "status": "success",
  "payload": {...},
  "evidence": [...],
  "quality": {...},
  "suggested_writes": [...],
  "errors": [],
  "duration_ms": 2500
}
```

**响应示例（失败）**：

```http
HTTP/1.1 200 OK
Content-Type: application/json

{
  "trace_id": "trace_1234567890",
  "tool_id": "tool_3",
  "status": "failure",
  "payload": {},
  "evidence": [],
  "quality": {
    "confidence": 0.0,
    "completeness": 0.0
  },
  "suggested_writes": [],
  "errors": [
    {
      "error_type": "timeout",
      "error_message": "工具执行超时",
      "error_details": {
        "timeout_seconds": 30
      }
    }
  ],
  "duration_ms": 30000
}
```

### 4.3 错误响应

**HTTP错误响应**：

```http
HTTP/1.1 400 Bad Request
Content-Type: application/json

{
  "error": {
    "error_code": "INVALID_TOOL_CONTEXT",
    "error_message": "ToolContext格式错误",
    "error_details": {
      "missing_fields": ["cdp_reference"]
    }
  }
}
```

**常见错误码**：
- `INVALID_TOOL_CONTEXT`：ToolContext格式错误
- `TOOL_NOT_FOUND`：工具不存在
- `CDP_NOT_FOUND`：CDP不存在
- `CDP_VERSION_MISMATCH`：CDP版本不匹配
- `TOOL_TIMEOUT`：工具执行超时
- `TOOL_INTERNAL_ERROR`：工具内部错误

## 五、工具调用约束

### 5.1 时间约束

**时间约束**：
- 每个工具都有最大执行时间限制（通过`constraints.max_time_seconds`传递）
- 如果工具执行时间超过限制，返回`timeout`状态
- 主Agent根据工具重要性决定是否重试

### 5.2 成本约束

**成本约束**：
- 每个工具都有最大成本限制（通过`constraints.max_cost`传递）
- 工具需要估算LLM调用成本，不能超过限制
- 如果成本超过限制，工具应该返回`failure`状态

### 5.3 风险约束

**风险约束**：
- 每个工具都有风险等级限制（通过`constraints.risk_level_limit`传递）
- 工具不能产生超过限制的风险等级
- 如果识别到超过限制的风险，工具应该返回`failure`状态或触发升级

## 六、工具调用审计

### 6.1 审计记录

**审计记录**：
- 所有工具调用都记录到AuditTrail
- 记录ToolContext和ToolResult的完整信息
- 通过`trace_id`关联ToolContext和ToolResult

### 6.2 审计字段

**审计字段**：
- `trace_id`：追踪ID
- `tool_id`：工具ID
- `cdp_id`：CDP ID
- `cdp_version`：CDP版本号
- `input`：ToolContext摘要
- `output`：ToolResult摘要
- `duration_ms`：执行时间
- `timestamp`：时间戳
