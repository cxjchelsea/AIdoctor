## 一、微服务部署架构

### 1.1 整体架构

```
┌─────────────────┐
│   API Gateway   │
└────────┬────────┘
         │
    ┌────┴────┐
    │         │
┌───▼───┐ ┌──▼────┐
│ Java  │ │Python │
│Services│ │Services│
│       │ │       │
│       │ │  ┌────▼──────┐
│       │ │  │Knowledge  │
│       │ │  │Query Svc  │
│       │ │  │(在线层)    │
│       │ │  └────┬──────┘
└───┬───┘ └──┬────┘
    │         │
    └────┬────┘
         │
┌────────▼────────┐
│   Data Layer    │
│ MySQL/Oracle/   │
│ Neo4j/Redis   │
└─────────────────┘
         │
┌────────▼────────┐
│Knowledge Ops   │
│Service          │
│(离线层)         │
└─────────────────┘
```

### 1.2 服务分类

#### 1.2.1 在线服务（实时响应诊断请求）

**Java服务**：
- `diagnosis-service`：主Agent服务（端口：8080）
- `examination-service`：检查服务（端口：8081）

**Python服务**：
- `health-state-assessment-service`：健康状态判定服务（tool_0，端口：8090）
- `clinical-parsing-service`：病例理解服务（tool_1，端口：8091）
- `dialog-service`：主动问诊服务（tool_2，端口：8092）
- `diagnosis-engine-service`：鉴别诊断服务（tool_3，端口：8093）
- `workup-planner-service`：检查建议服务（tool_4，端口：8094）
- `treatment-engine-service`：治疗建议服务（tool_5，端口：8095）
- `risk-assessment-service`：风险评估服务（tool_6，端口：8096）
- `explanation-service`：证据链服务（tool_7，端口：8097）
- `knowledge-query-service`：知识查询服务（在线层，端口：8098）
- `ocr-service`：OCR服务（端口：8099）

**部署策略**：
- 高可用部署，支持负载均衡
- 支持自动扩缩容
- 支持健康检查和故障转移

#### 1.2.2 离线服务（异步知识演化）

**Python服务**：
- `knowledge-ops-service`：知识运维服务（离线层，端口：8100）

**服务职责**：
- 知识抽取（Extractor Agent）
- 知识验证（Verifier Agent）
- 冲突处理（Conflict Resolver Agent）
- 候选构建（Release Builder Agent）
- 回归评测（Shadow Evaluator Agent）
- 发布门禁（Publish Gate）
- 监控与回滚（Rollback & Drift Monitor Agent）

**部署策略**：
- 独立部署，不阻塞在线诊断流程
- 支持异步任务队列（Redis）
- 单实例部署（离线服务）

## 二、容器化部署

### 2.1 Docker容器化

**所有服务**：
- 每个服务都有独立的Dockerfile
- 支持多阶段构建，减小镜像体积
- 使用.dockerignore排除不必要的文件

**示例Dockerfile（Python服务）**：
```dockerfile
FROM python:3.9-slim

WORKDIR /app

# 安装依赖
COPY requirements.txt .
RUN pip install --no-cache-dir -r requirements.txt

# 复制代码
COPY . .

# 启动服务
CMD ["uvicorn", "app.main:app", "--host", "0.0.0.0", "--port", "8090"]
```

**示例Dockerfile（Java服务）**：
```dockerfile
FROM openjdk:17-jdk-slim

WORKDIR /app

# 复制jar包
COPY target/diagnosis-service.jar app.jar

# 启动服务
ENTRYPOINT ["java", "-jar", "app.jar"]
```

### 2.2 Kubernetes编排

**部署配置**：
- 使用Deployment管理服务实例
- 使用Service暴露服务端口
- 使用ConfigMap管理配置
- 使用Secret管理敏感信息

**示例Deployment（Python服务）**：
```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: health-state-assessment-service
spec:
  replicas: 2
  selector:
    matchLabels:
      app: health-state-assessment-service
  template:
    metadata:
      labels:
        app: health-state-assessment-service
    spec:
      containers:
      - name: health-state-assessment-service
        image: aidoctor/health-state-assessment-service:latest
        ports:
        - containerPort: 8090
        env:
        - name: MYSQL_HOST
          valueFrom:
            configMapKeyRef:
              name: app-config
              key: mysql.host
        - name: REDIS_HOST
          valueFrom:
            configMapKeyRef:
              name: app-config
              key: redis.host
```

**示例Service**：
```yaml
apiVersion: v1
kind: Service
metadata:
  name: health-state-assessment-service
spec:
  selector:
    app: health-state-assessment-service
  ports:
  - port: 8090
    targetPort: 8090
  type: LoadBalancer
```

### 2.3 服务网格（可选）

**技术选型**：Istio

**功能**：

- 服务间通信加密

## 三、知识演化服务部署

### 3.1 知识查询服务（Knowledge Query Service）

**部署方式**：
- **服务类型**：Python服务（FastAPI）
- **端口**：8098
- **部署模式**：在线服务，高可用部署
- **依赖**：Neo4j（知识图谱）、MySQL/Oracle（知识库元数据）

**服务职责**：
- 知识库优先查询（主诉知识图谱、疾病知识图谱）
- Neo4j路径检索验证
- 路径约束推理
- 版本化知识访问

**部署配置**：
```yaml
knowledge-query-service:
  image: aidoctor/knowledge-query-service:latest
  ports:
    - "8098:8098"
  environment:
    - NEO4J_URI=neo4j://neo4j:7687
    - MYSQL_HOST=mysql
    - MYSQL_PORT=3306
  depends_on:
    - neo4j
    - mysql
  replicas: 2  # 高可用部署
```

### 3.2 知识运维服务（Knowledge Operations Service）

**部署方式**：
- **服务类型**：Python服务（FastAPI + 异步任务队列）
- **端口**：8100
- **部署模式**：离线服务，独立部署
- **依赖**：Neo4j（三个知识库区）、MySQL/Oracle（元数据）、Redis（任务队列）

**服务职责**：
- 知识抽取（Extractor Agent）
- 知识验证（Verifier Agent）
- 冲突处理（Conflict Resolver Agent）
- 候选构建（Release Builder Agent）
- 回归评测（Shadow Evaluator Agent）
- 发布门禁（Publish Gate）
- 监控与回滚（Rollback & Drift Monitor Agent）

**部署配置**：
```yaml
knowledge-ops-service:
  image: aidoctor/knowledge-ops-service:latest
  ports:
    - "8100:8100"
  environment:
    - NEO4J_URI=neo4j://neo4j:7687
    - MYSQL_HOST=mysql
    - MYSQL_PORT=3306
    - REDIS_HOST=redis
    - REDIS_PORT=6379
    - WORK_MODE=offline  # 离线模式
  depends_on:
    - neo4j
    - mysql
    - redis
  replicas: 1  # 单实例部署（离线服务）
```

**Agent部署**：
- 所有Agent作为knowledge-ops-service的内部模块
- 通过消息队列（Redis）异步执行任务
- 支持任务调度、重试、限流

### 3.3 知识库存储部署

#### 3.3.1 Neo4j部署

**存储方案**：
- 一套Neo4j + release/label分区 + current_release指针
- 通过label实现Sandbox/Staging/Production分区
- 通过release_id字段区分不同版本

**部署配置**：
```yaml
neo4j:
  image: neo4j:5.0
  ports:
    - "7474:7474"  # HTTP
    - "7687:7687"  # Bolt
  environment:
    - NEO4J_AUTH=neo4j/password
    - NEO4J_dbms_memory_heap_max__size=4G
  volumes:
    - neo4j_data:/data
    - neo4j_logs:/logs
```

#### 3.3.2 元数据存储（MySQL/Oracle）

**表结构**：
- `ReleaseMetadata`表：存储release元数据（release_id、is_current等）
- `KnowledgeObjectMetadata`表：存储KO元数据
- `Proposal`表：存储知识演化提案

## 四、工作态切换机制

### 4.1 健康管理态 → 临床诊疗态升级

**升级条件**：
- 症状加重
- 新症状出现
- 风险信号检测

**实现**：
```python
class WorkModeUpgrader:
    def check_upgrade_conditions(self, cdp: CDP) -> bool:
        """
        检查是否需要从健康管理态升级到临床诊疗态
        """
        # 检查升级条件
        if self.symptom_worsened(cdp):
            return True
        if self.new_symptoms_appeared(cdp):
            return True
        if self.risk_signals_detected(cdp):
            return True
        
        return False
    
    def upgrade_to_clinical_mode(self, cdp: CDP):
        """
        升级到临床诊疗态
        """
        cdp.health_state_assessment.work_mode = "clinical_mode"
        cdp.health_state_assessment.needs_clinical_mode = True
        # 启动诊断流程
        self.start_diagnosis_workflow(cdp)
```

## 五、部署环境

### 5.1 开发环境

**部署方式**：
- Docker Compose本地部署
- 所有服务运行在同一台机器
- 使用MySQL作为数据库

**配置文件**：`docker-compose.yml`

### 5.2 生产环境

**部署方式**：
- Kubernetes集群部署
- 服务分布在多个节点
- 使用Oracle作为数据库
- 支持自动扩缩容和故障转移

**配置管理**：
- 使用ConfigMap管理配置
- 使用Secret管理敏感信息
- 支持环境变量注入

## 六、监控与日志

### 6.1 监控

**监控指标**：
- 服务健康状态
- 请求响应时间
- 错误率
- 资源使用率（CPU、内存、磁盘）

- Prometheus + Grafana
- Kubernetes内置监控

**日志收集**：
- 使用ELK Stack（Elasticsearch + Logstash + Kibana）
- 或使用Fluentd + Elasticsearch

**日志级别**：
- DEBUG：开发调试
- INFO：正常信息
- WARN：警告信息
- ERROR：错误信息

## 七、总结

### 7.1 部署架构特点

1. **微服务架构**：服务独立部署，职责单一
2. **容器化部署**：Docker + Kubernetes
3. **在线/离线分离**：在线服务高可用，离线服务独立部署
4. **知识库分区**：Sandbox/Staging/Production三个知识库区

### 7.2 部署原则

1. **高可用**：在线服务支持多实例部署和故障转移
2. **可扩展**：支持水平扩展和自动扩缩容
3. **可观测**：完善的监控和日志系统
4. **安全性**：服务间通信加密，敏感信息加密存储
