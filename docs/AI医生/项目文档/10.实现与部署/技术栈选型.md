## 一、后端技术栈

### 1.1 Java服务层（业务服务）

**适用场景**：
- 主Agent服务（diagnosis-service）
- 检查服务（examination-service）
- 其他业务服务

**技术选型**：
- **Web框架**：Spring Boot 2.7.8
- **服务治理**：Spring Cloud Gateway + Nacos（可选）
- **ORM**：JPA / Hibernate
- **服务调用**：OpenFeign
- **数据库**：MySQL 8.0（本地开发）/ Oracle（生产环境）

**选择理由**：
- Spring Boot生态成熟，适合复杂业务逻辑
- 与现有Java技术栈兼容
- 支持微服务架构

### 1.2 Python服务层（AI服务）

**适用场景**：
- 所有工具服务（tool_0-tool_7）
- 知识查询服务（knowledge-query-service）
- 知识运维服务（knowledge-ops-service）
- OCR服务

**技术选型**：
- **Web框架**：FastAPI
- **异步框架**：asyncio + aiohttp
- **NLP**：transformers（BERT/ClinicalBERT）、spaCy
- **图神经网络**：PyTorch Geometric（SGIN实现）
- **机器学习**：scikit-learn、XGBoost/LightGBM

**选择理由**：
- FastAPI性能优秀，支持异步处理
- Python生态在AI/ML领域成熟
- 便于集成各种AI模型和工具

## 二、数据存储

### 2.1 关系型数据库

**技术选型**：
- **本地开发**：MySQL 8.0
- **生产环境**：Oracle（与同事共同使用）

**用途**：
- CDP存储
- 诊断记录
- 检查记录
- 健康状态判定记录
- 健康筛查记录
- 知识库元数据（主诉知识图谱、疾病知识图谱）

**选择理由**：
- MySQL适合本地开发，轻量级
- Oracle适合生产环境，性能稳定
- 支持复杂查询和事务处理

### 2.2 图数据库

**技术选型**：Neo4j 5

**用途**：
- 知识图谱存储（UMLS或自定义医学知识图谱）
- DR.KNOWS路径检索
- 知识演化存储（Sandbox/Staging/Production三个知识库区）

**选择理由**：
- Neo4j是成熟的图数据库，支持复杂图查询
- Cypher查询语言适合路径检索
- 支持大规模知识图谱（450万概念，1500万关系）

### 2.3 缓存

**技术选型**：Redis 7

**用途**：
- CDP临时状态缓存
- 会话管理
- 路径缓存（常用路径）
- Prompt缓存（常用prompt模板）
- 任务队列（知识演化服务）

**选择理由**：
- Redis性能优秀，支持多种数据结构
- 适合缓存和会话管理
- 支持分布式部署

## 三、模型与工具

### 3.1 医学概念识别

**技术选型**：
- **英文**：QuickUMLS / cTAKES
- **中文**：中文医学NER模型

**用途**：
- 从患者描述中提取医学概念（症状、体征、疾病等）
- 归一化到标准术语（CUI/ICD/SNOMED）

**选择理由**：
- QuickUMLS和cTAKES是成熟的医学实体识别工具
- 支持UMLS标准术语归一化
- 中文医学NER模型支持中文医学文本处理

### 3.2 大语言模型

**技术选型**：
- T5 / ChatGPT / 医学专用LLM

**用途**：
- 路径注入LLM（路径约束推理）
- 自然语言生成（NLG）
- 诊断推理

**选择理由**：
- T5适合文本生成任务
- ChatGPT性能优秀，支持对话
- 医学专用LLM针对医学领域优化

### 3.3 图遍历算法

**技术选型**：
- Neo4j Cypher查询 + 图遍历算法（DR.KNOWS方法）

**用途**：
- 多跳推理路径检索
- 路径结构特征分析
- 路径验证

**选择理由**：
- Cypher查询语言适合图遍历
- DR.KNOWS方法经过验证，适合医学推理

### 3.4 OCR

**技术选型**：
- PaddleOCR / Tesseract

**用途**：
- 检查报告OCR识别
- 医学影像文字识别

**选择理由**：
- PaddleOCR对中文支持好
- Tesseract成熟稳定

## 四、性能优化相关技术

### 4.1 路径检索优化

**技术**：
- **路径缓存**：Redis缓存常用路径
- **并行计算**：多症状路径并行搜索
- **智能剪枝**：基于关系权重的路径过滤

### 4.2 CDP性能优化

**技术**：
- **CDP缓存**：Redis缓存CDP临时状态
- **版本管理优化**：只保存关键版本，不保存每次更新
- **批量更新**：合并多个字段更新为一次操作

### 4.3 LLM推理优化

**技术**：
- **Prompt缓存**：缓存常用prompt模板
- **批量推理**：批量处理多个请求
- **模型量化**：使用量化模型减少推理时间
- **路径约束**：通过知识图谱路径约束LLM生成，减少无效推理

## 五、部署相关技术

### 5.1 容器化

**技术选型**：
- **Docker**：容器化所有服务
- **Kubernetes**：容器编排和自动扩缩容
- **服务网格**：Istio（可选，用于服务治理）

**选择理由**：
- Docker便于服务打包和部署
- Kubernetes支持自动扩缩容和服务治理
- Istio提供高级服务治理能力

### 5.2 服务治理

**技术选型**：
- **API Gateway**：Spring Cloud Gateway
- **服务注册与发现**：Nacos（可选）
- **负载均衡**：Kubernetes内置 / Nginx

**选择理由**：
- Spring Cloud Gateway适合微服务架构
- Nacos提供服务注册与发现能力
- Kubernetes内置负载均衡

## 七、总结

### 7.1 技术栈特点

1. **混合技术栈**：Java用于业务服务，Python用于AI服务
2. **多数据库**：MySQL/Oracle用于业务数据，Neo4j用于知识图谱，Redis用于缓存
3. **AI技术栈**：FastAPI + transformers + PyTorch Geometric
4. **容器化部署**：Docker + Kubernetes

### 7.2 技术选型原则

1. **成熟稳定**：选择成熟的技术栈，降低技术风险
2. **性能优先**：选择性能优秀的技术，满足实时诊断需求
3. **生态兼容**：选择与现有技术栈兼容的技术
4. **可扩展性**：选择支持水平扩展的技术
