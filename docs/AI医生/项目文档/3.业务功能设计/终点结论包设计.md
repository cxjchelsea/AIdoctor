# AI医生系统 - 终点结论包设计

> **文档定位**：本文档详细设计AI医生系统的终点结论包（Conclusion Package）设计，包括四要素结构、健康管理态输出格式、临床诊疗态输出格式等。这是理解系统输出格式的必读文档。

## 一、终点结论包概述

### 1.1 设计定位

**终点结论包设计定位**：
- **核心职责**：确保所有诊断结果输出都包含四个要素，保证可行动、可审计
- **设计原则**：
  - **可行动**：用户能够根据结论包采取明确的行动
  - **可审计**：所有结论都有明确的证据支持，可追溯
  - **可迭代**：支持复评和回退机制

### 1.2 四要素结构

**终点结论包四要素**：

1. **结论（Conclusion）**：诊断结论或最可能方向
2. **必须排除项状态（Must-Exclude Status）**：高危诊断的排除状态
3. **关键依据（Key Evidence）**：支持诊断的证据链
4. **行动与随访（Action & Follow-up）**：立即行动、复评时间窗、升级触发条件

---

## 二、要素1：结论（Conclusion）

### 2.1 可确证结论

**可确证结论特点**：
- 证据达到明确诊断标准
- 路径完整且一致
- 输出具体疾病诊断（或最可能诊断）

**结论结构**：

```json
{
  "type": "可确证",
  "diagnosis": "具体疾病名称",
  "confidence": "高/中/低",
  "severity": "轻度/中度/重度",
  "evidence_chain": [
    "证据1",
    "证据2",
    "证据3"
  ]
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | String | 结论类型：可确证/不可确证 |
| `diagnosis` | String | 具体疾病诊断名称 |
| `confidence` | String | 诊断置信度：高/中/低 |
| `severity` | String | 疾病严重程度：轻度/中度/重度 |
| `evidence_chain` | Array | 支持证据链（至少3条） |

### 2.2 不可确证结论

**不可确证结论特点**：
- 证据不足以确证
- 但路径指向明确方向
- 输出最可能方向或最可能诊断倾向

**结论结构**：

```json
{
  "type": "不可确证",
  "most_likely_direction": "最可能方向",
  "most_likely_diagnosis": "最可能诊断倾向",
  "uncertainty_source": "为什么无法明确判断",
  "missing_evidence": [
    "缺失的关键证据1",
    "缺失的关键证据2"
  ]
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `type` | String | 结论类型：可确证/不可确证 |
| `most_likely_direction` | String | 最可能方向 |
| `most_likely_diagnosis` | String | 最可能诊断倾向 |
| `uncertainty_source` | String | 不确定性来源：为什么无法明确判断 |
| `missing_evidence` | Array | 缺失的关键证据：需要哪些证据来明确 |

## 三、要素2：必须排除项状态（Must-Exclude Status）

### 3.1 状态类型

**状态类型**：

1. **已排除**：已通过验证明确排除的高危诊断
   - 排除理由：为什么已排除
2. **未排除**：未完成排除，必须保留在候选清单中
   - 未排除原因：为什么未排除
3. **需线下排除**：需要线下检查才能排除的高危诊断
   - 排除建议：需要做什么检查才能排除

### 3.2 关键原则

**关键原则**：
- **未完成排除则必须保留**：不能因为可能性低就忽略
- **必须明确告知患者**：必须排除项的状态必须明确告知患者

### 3.3 状态结构

**状态结构**：

```json
{
  "excluded": [
    {
      "diagnosis": "已排除的高危诊断",
      "status": "已排除",
      "reason": "排除理由"
    }
  ],
  "not_excluded": [
    {
      "diagnosis": "未排除的高危诊断",
      "status": "未排除",
      "reason": "未排除原因"
    }
  ],
  "need_offline_exclude": [
    {
      "diagnosis": "需线下排除的高危诊断",
      "status": "需线下排除",
      "exclude_suggestion": "需要做什么检查才能排除"
    }
  ]
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `excluded` | Array | 已排除的高危诊断列表 |
| `not_excluded` | Array | 未排除的高危诊断列表 |
| `need_offline_exclude` | Array | 需线下排除的高危诊断列表 |

## 四、要素3：关键依据（Key Evidence）

### 4.1 证据要求

**证据要求**：
- **至少三条证据**，明确哪些是阳性证据，哪些是关键阴性证据
- **阳性证据**：支持诊断的证据（至少3条）
- **阴性证据**：排除其他诊断的证据
- **检查结果**：支持诊断的检查结果

### 4.2 证据结构

**证据结构**：

```json
{
  "positive_evidence": [
    {
      "evidence": "证据名称",
      "source": "证据来源",
      "strength": "强证据/中证据/弱证据"
    }
  ],
  "negative_evidence": [
    {
      "evidence": "证据名称",
      "excluded_direction": "排除的诊断方向"
    }
  ],
  "check_results": [
    {
      "check_name": "检查名称",
      "result": "检查结果",
      "support_direction": "支持的诊断方向"
    }
  ]
}
```

**字段说明**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `positive_evidence` | Array | 阳性证据列表（至少3条） |
| `negative_evidence` | Array | 阴性证据列表 |
| `check_results` | Array | 检查结果列表 |

### 4.3 证据强度分级

**证据强度分级**：

- **强证据**：直接支持诊断的证据，如典型症状、典型检查结果
- **中证据**：间接支持诊断的证据，如相关症状、相关检查结果
- **弱证据**：可能支持诊断的证据，如非典型症状、非典型检查结果

## 五、要素4：行动与随访（Action & Follow-up）

### 5.1 立即行动

**立即行动内容**：
- **就医建议**：科室、时间、需带资料
- **检查建议**：如需进一步确诊
- **治疗方向**：治疗方案方向，不给出具体用药剂量
- **紧急情况处理建议**：如出现紧急情况如何处理

**立即行动结构**：

```json
{
  "immediate_action": {
    "medical_advice": "就医建议",
    "examinations": ["检查建议1", "检查建议2"],
    "treatment_direction": "治疗方向",
    "urgent_conditions": "紧急情况处理建议"
  }
}
```

### 5.2 复评时间窗

**复评时间窗内容**：
- **默认复评时间**：根据疾病类型设定
- **提前复评条件**：症状加重、出现新症状等
- **延迟复评条件**：症状完全缓解等

**复评时间窗结构**：

```json
{
  "review_time_window": {
    "default_time": "默认复评时间",
    "early_review_conditions": ["提前复评条件1", "提前复评条件2"],
    "delay_review_conditions": ["延迟复评条件1", "延迟复评条件2"]
  }
}
```

### 5.3 升级触发条件

**升级触发条件内容**：
- 出现哪些情况必须立即升级（立即就医）
- 例如：症状突然加重、出现高危症状、处理无效等

**升级触发条件结构**：

```json
{
  "upgrade_conditions": [
    "升级触发条件1",
    "升级触发条件2",
    "升级触发条件3"
  ]
}
```

## 七、健康管理态输出格式

### 7.1 健康管理态输出特点

**健康管理态输出特点**：
- 不包含诊断结论（因为用户无症状）
- 包含健康筛查建议、健康目标管理建议、随访计划等
- 输出格式与临床诊疗态不同

### 7.2 健康管理态输出结构

**健康管理态输出结构**：

```json
{
  "wellness_plan": {
    "screening_recommendations": [
      {
        "screening_type": "筛查类型",
        "recommended_age": "推荐年龄",
        "frequency": "筛查频率",
        "reason": "推荐理由"
      }
    ],
    "health_goals": [
      {
        "goal_type": "目标类型",
        "current_status": "当前状态",
        "target": "目标",
        "action_plan": "行动计划"
      }
    ],
    "follow_up_plan": {
      "next_review_time": "下次复评时间",
      "review_conditions": ["复评条件1", "复评条件2"]
    }
  }
}
```

## 八、临床诊疗态输出格式

### 8.1 临床诊疗态输出特点

**临床诊疗态输出特点**：
- 包含完整的终点结论包四要素
- 包含诊断结论、必须排除项状态、关键依据、行动与随访
- 输出格式严格遵循四要素结构

### 8.2 临床诊疗态输出结构

**临床诊疗态输出结构**：

```json
{
  "conclusion_package": {
    "conclusion": { /* 要素1 */ },
    "must_exclude_status": { /* 要素2 */ },
    "key_evidence": { /* 要素3 */ },
    "action_and_followup": { /* 要素4 */ }
  },
  "ddx": {
    "tier1_most_likely": [ /* 最可能方向 */ ],
    "tier2_must_exclude": [ /* 必须排除方向 */ ],
    "tier3_active_alternatives": [ /* 积极备选方向 */ ]
  },
  "evidence_graph": [ /* 证据图 */ ],
  "reasoning_paths": [ /* 推理路径 */ ]
}
```

## 九、输出格式验证规则

### 9.1 验证规则

**验证规则**：

1. **四要素完整性验证**：
   - 结论包必须包含四个要素
   - 每个要素必须包含必填字段

2. **证据数量验证**：
   - 阳性证据至少3条
   - 关键依据必须包含至少3条证据

3. **必须排除项验证**：
   - 如果存在Tier2候选，必须明确排除状态
   - 未排除的高危诊断必须明确告知

4. **行动建议验证**：
   - 必须包含立即行动建议
   - 必须包含复评时间窗
   - 必须包含升级触发条件

### 9.2 验证失败处理

**验证失败处理**：
- 如果验证失败，系统应标记为"需要人工审核"
- 不应输出不完整的结论包
- 应记录验证失败的原因
