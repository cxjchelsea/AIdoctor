## 一、临床诊疗态流程概述

### 1.1 流程定位

**临床诊疗态流程定位**：
- **面向对象**：疑似/明确有病的人
- **核心任务**：
  - 鉴别诊断（DDx）
  - 检查/处置建议
  - 推理与证据链
- **使用技术**：
  - DR.KNOWS方法
  - 知识图谱路径推理
  - 强结构化推理

### 1.2 5步AI循证诊断流程

临床诊疗态采用**5步AI循证诊断流程**：

```
Step 1: 识别问题
  ↓
Step 2: 构建鉴别诊断候选集并分层
  ↓
Step 3: 组织候选集并建立分流路径
  ↓
Step 4: 采集关键证据并形成排序与验证计划
  ↓
Step 5: 回填证据并输出终点结论包
```

**流程特点**：
- **可推理**：每个步骤都有明确的推理逻辑和依据
- **可复用**：问题清单、候选集、分流路径等可沉淀为模板库
- **可审计**：每个步骤的输出都有结构化记录，支持追溯和验证
- **可回退**：支持回退到任意步骤，确保系统不会在错误结论上"锁死"

## 二、Step 1：识别问题

### 2.1 目标

把用户的自然语言描述，转化成可推理、可复用、可审计的结构化"问题清单"，作为后续候选方向生成与分流问诊的唯一输入。

### 2.2 核心任务

1. **概念归一化（明确用户在说什么）**
   - 把"原话"翻译为医学可用的标准概念
   - 处理同义表达与歧义表达
   - 避免误解主诉含义

2. **形成完整问题清单**
   - 不仅记录主诉，还要同步记录伴随问题与关键背景
   - 进行分组组织，保证后续推理不会漏关键信息

3. **标记信息缺口（决定能不能进入下一步）**
   - 明确"当前已知什么、还缺什么、缺了会造成什么推理风险"
   - 按缺口等级决定是否允许进入 Step 2

### 2.3 输出标准

**结构化问题清单**：

```json
{
  "主要问题": {
    "主诉名称": "归一化后的主诉",
    "持续时间": "持续时间与起病方式（突然/渐进）",
    "严重程度": "当前严重程度（对活动/睡眠/功能影响）"
  },
  "伴随问题": [
    {
      "症状名称": "与主诉同窗出现的关键伴随症状",
      "出现时间": "时间",
      "分流价值": "是否具有分流价值"
    }
  ],
  "关键背景": {
    "年龄": "年龄",
    "性别": "性别",
    "既往史": ["与当前主诉相关的重大疾病史"],
    "当前用药": ["会改变风险或表现者"],
    "过敏史": ["会改变风险或表现者"],
    "生理状态": "妊娠、近期手术、久坐久卧、感染接触等",
    "家族史": ["与主诉高度相关者"]
  },
  "信息缺口": {
    "必填缺口": ["缺失则不能进入 Step 2"],
    "重要缺口": ["可进入但必须提示不确定性与风险"],
    "可选缺口": ["可在后续步骤补充"]
  }
}
```

### 2.4 参与工具

- **工具1：病例理解工具** - 执行概念归一化和结构化提取
- **工具2：主动问诊工具** - 识别信息缺口并生成追问

### 2.5 完成条件

- 必填缺口已补齐，或已明确标记为"重要缺口"并提示风险
- 问题清单结构化完成，可进入 Step 2

### 2.6 示例

**用户原话**："我这两天胸口闷，走几步就喘，昨天还出汗，有点恶心。"

**输出问题清单**：

```json
{
  "主要问题": {
    "主诉名称": "胸闷样不适",
    "持续时间": "2天，活动后加重",
    "严重程度": "活动受限"
  },
  "伴随问题": [
    {"症状名称": "活动后气促", "出现时间": "2天"},
    {"症状名称": "出汗", "出现时间": "昨天"},
    {"症状名称": "恶心", "出现时间": "昨天"}
  ],
  "关键背景": {
    "年龄": "待补",

    "既往史": ["待补：高血压/糖尿病/血脂异常/冠心病史"],
    "当前用药": ["待补"],
    "过敏史": ["待补"],
    "生理状态": "待补：血栓风险（久坐久卧、下肢肿痛、近期手术等）"
  },
  "信息缺口": {
    "必填缺口": [
      "症状性质与强度、是否放射",

  }
```

## 三、Step 2：构建鉴别诊断候选集并分层

### 3.1 目标

在 Step 1 的"问题清单"基础上，建立该主诉的鉴别诊断全集，并按临床风险与证据强度分成三层，形成后续问诊分流与检查决策的"候选集合"。

### 3.2 核心原则

**知识库优先，DR.KNOWS路径用于验证和补充**

优先使用知识库中的权威医学内容（主诉知识图谱、疾病知识图谱），DR.KNOWS路径用于验证和补充。

### 3.3 核心任务

1. **知识库候选集检索阶段（优先）**
   - 从主诉知识图谱检索三层候选：根据主诉标准名，从主诉表5（三层候选总览表）检索Tier1/Tier2/Tier3候选疾病
   - 从主诉表6（候选疾病明细表）检索详细信息：
     - 默认层级（Tier1/Tier2/Tier3）
     - 入选依据（来自知识库的权威依据）
     - 当前支持线索（关键支持证据条目ID列表）
     - 当前反对线索（关键反对证据条目ID列表）
     - 待补齐缺口（必须补齐的关键信息条目ID列表）
   - 从疾病知识图谱检索疾病详细信息：
     - 典型表现模式
     - 关键支持证据条目ID列表
     - 关键反对证据条目ID列表
     - 必须补齐的关键信息条目ID列表
     - 易混疾病ID列表
     - 关键鉴别点
     - 分流路径中的位置（Tier1/Tier2/Tier3）
     - 推理子组归属

2. **DR.KNOWS路径检索阶段（验证和补充）**
   - 提取症状CUI：从问题清单中提取所有症状的CUI编码
   - 执行路径检索：从Neo4j知识图谱检索所有从症状到疾病的推理路径（支持2-4跳）
   - 路径与知识库候选匹配：
     - 检查检索到的路径是否指向知识库候选集中的疾病
     - 如果路径指向知识库候选，标记为"已验证"
     - 如果路径指向知识库候选外的疾病，标记为"补充候选"（用于知识库完善）

3. **候选集整合与验证阶段**
   - 知识库候选优先：
     - 直接使用知识库中的候选集作为主要候选
     - 使用知识库中的默认层级（Tier1/Tier2/Tier3）作为初始分层
     - 使用知识库中的入选依据作为候选的入选依据
   - DR.KNOWS路径验证：
     - 为每个知识库候选匹配对应的DR.KNOWS路径
     - 如果知识库候选有对应的路径，标记为"路径已验证"
     - 如果知识库候选没有对应的路径，标记为"路径缺失"（但不影响候选入选，因为知识库是权威来源）

4. **三层分层阶段（基于知识库权威内容）**
   - **Tier2（必须优先除外）选择**：
     - 直接使用知识库中的Tier2候选（主诉表5、主诉表6中的默认层级为Tier2的疾病）
     - 使用知识库中的入选依据（如"漏诊后果严重且符合现有表现"）
     - 使用知识库中的支持线索和反对线索
   - **Tier1（最可能）选择**：
     - 直接使用知识库中的Tier1候选（主诉表5、主诉表6中的默认层级为Tier1的疾病）
     - 使用知识库中的入选依据（如"常见方向组"）
     - 使用知识库中的支持线索和反对线索
     - 根据当前患者信息匹配知识库中的支持线索
   - **Tier3（积极备选）选择**：
     - 直接使用知识库中的Tier3候选（主诉表5、主诉表6中的默认层级为Tier3的疾病）
     - 使用知识库中的入选依据（如"易混淆组"）
     - 使用知识库中的支持线索和反对线索

5. **信息缺口标记（基于知识库）**
   - 优先使用知识库中的待补齐缺口：
     - 从主诉表6（候选疾病明细表）中获取"待补齐缺口"（必须补齐的关键信息条目ID列表）
     - 从疾病知识图谱中获取"必须补齐的关键信息条目ID列表"
     - 这些是知识库中定义的权威缺口清单
   - DR.KNOWS路径补充缺口（可选）：
     - 如果知识库中的缺口清单不完整，可以从DR.KNOWS路径中提取中间节点作为补充
     - 但知识库中的缺口清单优先

### 3.4 输出标准

**必交付内容**：

1. **鉴别诊断分层清单**（基于知识库权威内容）：
   - **Tier1（最可能）**（1个）
     - 疾病名称（来自知识库）
     - 入选依据（来自知识库的权威依据，如"常见方向组"）
     - 当前支持线索（来自知识库的关键支持证据条目ID列表）
     - 当前反对线索（来自知识库的关键反对证据条目ID列表）
     - 当前信息缺口（来自知识库的待补齐缺口）
     - DR.KNOWS路径列表（如果存在，用于验证和追溯）
   - **Tier2（必须优先除外）**（0-1个）
     - 疾病名称（来自知识库）
     - 入选依据（来自知识库的权威依据，如"漏诊后果严重且符合现有表现"）
     - 当前支持线索（来自知识库的关键支持证据条目ID列表）
     - 当前反对线索（来自知识库的关键反对证据条目ID列表）
     - 当前信息缺口（来自知识库的待补齐缺口，必须补齐才能排除）
     - DR.KNOWS路径列表（如果存在，用于验证和追溯）
   - **Tier3（积极备选）**（1-2个）
     - 疾病名称（来自知识库）
     - 入选依据（来自知识库的权威依据，如"易混淆组"）
     - 当前支持线索（来自知识库的关键支持证据条目ID列表）
     - 当前反对线索（来自知识库的关键反对证据条目ID列表）
     - 当前信息缺口（来自知识库的待补齐缺口）
     - DR.KNOWS路径列表（如果存在，用于验证和追溯）

2. **推理路径库**（用于后续步骤的验证和回填）：
   - 已验证路径（指向知识库候选的路径）
   - 补充候选路径（指向知识库候选外的路径，用于知识库完善）

3. **下一步分流入口**：
   - 对Tier2和Tier3候选，标记关键澄清点
   - 关键澄清点优先来自知识库（主诉表8：关键差异点配置表）
   - 如果知识库中没有，可以从DR.KNOWS路径中的中间节点补充

### 3.5 参与工具

- **工具3：鉴别诊断工具** - 生成鉴别诊断全集并进行三层分层
- **工具6：风险评估工具** - 识别必须排除的高危诊断

### 3.6 完成条件

- 鉴别诊断全集已生成
- 三层分层已完成（至少有一个首要假设）
- 每个方向都有明确的入选依据

## 四、Step 3：组织候选集并建立分流路径

### 4.1 目标

把 Step 2 的"分层候选清单"组织成可推进的推理结构，并提炼出能在问诊与基础测量中快速收缩范围的分流路径，确保后续收缩不是"随便问"，而是沿着明确的逻辑分叉推进。

### 4.2 核心原则

**优先使用知识库中的推理子组和关键差异点**，DR.KNOWS路径用于验证和补充。

### 4.3 核心任务

1. **关键差异点提取（基于知识库）**
   - 优先使用知识库中的关键差异点：
     - 从主诉表8（关键差异点配置表）中获取关键差异点
     - 这些是知识库中定义的权威差异点，包含标准问法、答案选项、影响子组/疾病、动作等
   - DR.KNOWS路径补充差异点（可选）：
     - 如果知识库中的差异点不完整，可以从DR.KNOWS路径中提取中间节点作为补充
     - 但知识库中的差异点优先
   - 差异点分类（基于知识库）：
     - 系统来源差异点（心血管/呼吸/消化等）
     - 病程差异点（急性/慢性）
     - 诱因差异点（活动/体位/进食等）
     - 分布差异点（局部/全身、单侧/双侧）

2. **推理子组组织（基于知识库）**
   - 优先使用知识库中的推理子组：
     - 从主诉表7（推理子组清单表）中获取推理子组
     - 这些是知识库中定义的权威子组，包含子组名称、覆盖疾病、子组进入触发、推进目标等
   - 从疾病知识图谱获取推理子组归属：
     - 从疾病知识图谱中获取"推理子组归属"字段
     - 确定每个疾病属于哪个推理子组
   - 子组的高危触发条件（基于知识库）：
     - 从疾病知识图谱中获取"升级触发条件（疾病级红旗）"
     - 从主诉表1中获取"危险信号清单引用"

3. **分流路径设计**
   - 第一层分叉问题设计：
     - 基于关键差异点设计第一层分叉问题
     - 例如：是否静息也发作（区分急性/慢性）
     - 例如：是否伴发热（区分感染/非感染）
   - 高危路径设计：
     - 识别高危触发条件
     - 设计高危路径：一旦命中高危条件，直接进入验证/升级
   - 分流路径结构：
     - 第一层分叉问题 → 子组筛选
     - 高危触发条件 → 高危路径
     - 未命中高危 → 继续收缩方向

4. **主诉关键线索库构建**
   - 从路径中提取线索：
     - 路径中的节点就是线索
     - 路径中的关系就是线索类型
   - 线索分类：
     - 关键差异点线索（用于区分方向）
     - 阳性线索（支持某一方向）
     - 关键阴性线索（排除某一方向）
   - 线索标准化：
     - 线索名称（中文）
     - 线索类型（差异点/阳性/阴性）
     - 获取方式（追问/观察/测量）
     - 标准问法与答案选项
     - 判定规则（支持/不支持/不确定）
     - 推理动作（命中后：哪个方向上移/后移/触发高危路径）

5. **形成分流问题清单（供下一步证据采集使用）**
   - 把差异点转换为结构化问题（固定问法、固定选项、固定记录字段）
   - 输出为 Step 4 的证据采集入口

### 4.4 输出标准

**必交付内容**：

1. **推理结构表**：
   - 子组名称与包含的候选方向（优先来自知识库）
   - 子组入选依据（对应问题清单和推理路径）
   - 子组的关键差异点（1-2条，优先来自知识库）
   - 子组的高危触发条件（如适用，来自知识库）

2. **分流路径清单**：
   - 第一层分叉问题（用于快速分流子组）
   - 命中高危时的处理指引（进入验证/升级的入口条件）
   - 未命中高危时的继续收缩方向（进入下一步证据采集）

3. **主诉关键线索库**：
   - 关键差异点线索（优先来自知识库）
   - 阳性线索
   - 关键阴性线索

### 4.5 参与工具

- **工具3：鉴别诊断工具** - 组织推理子组和分流路径
- **工具2：主动问诊工具** - 生成分流问题清单

### 4.6 完成条件

- 推理子组结构已建立
- 关键差异点已提炼
- 分流路径清单已生成

## 五、Step 4：采集关键证据并形成排序与验证计划

### 5.1 目标

沿着 Step 3 的分流路径，系统采集能够"推动排序变化"的关键证据，形成稳定的三层清单，并制定验证计划，明确下一步要用什么证据把"方向"推进到"可确认/可排除/需升级"。

### 5.2 核心原则

使用DR.KNOWS路径约束推理，指导证据采集和排序。

### 5.3 核心任务

1. **证据提取**
   - 从路径中提取需要采集的证据：
     - 路径中的节点就是需要采集的证据
     - 如果路径中的节点在当前证据中缺失，标记为需要采集
   - 证据分类：
     - 阳性线索证据（路径中支持某一方向的节点）
     - 关键阴性线索证据（路径中排除某一方向的节点）
   - 证据采集顺序（基于知识库，非优先级）：
     - 优先采集知识库中标记为"必须补齐"的信息（来自知识库的待补齐缺口）
     - 优先采集Tier2候选路径中的证据（必须优先除外）
     - 优先采集Tier1候选路径中的证据（最可能）
     - 优先采集Tier3候选路径中的证据（积极备选）

2. **路径约束推理**
   - 选择Top-N路径（基于知识库候选，非路径结构特征）：
     - 排序依据是知识库中的内容（Tier1/Tier2/Tier3），不是路径长度、数量、风险评估等级
     - 优先选择指向Tier1候选的路径
     - 优先选择指向Tier2候选的路径
     - 优先选择指向Tier3候选的路径
     - 总共选择Top-10路径用于约束LLM推理
   - 构建路径约束Prompt：
     - 将Top-N路径格式化为自然语言描述
     - 将路径作为上下文注入Prompt
     - 明确要求LLM：必须基于提供的路径推理，不得引入路径外的自由联想
   - LLM推理：
     - LLM在路径约束下进行推理
     - 分析每个疾病的支持证据（必须来自路径）
     - 分析每个疾病的反对证据（必须来自路径）
     - 识别还需要哪些信息来进一步判断（路径中缺失的节点）
   - 推理结果验证（关键步骤）：
     - 路径一致性验证：检查LLM输出的诊断是否在路径中
     - 证据来源验证：检查LLM输出的证据是否来自路径
     - 路径完整性验证：检查LLM是否使用了所有Top-N路径
     - 医学逻辑验证：检查LLM的推理是否符合医学逻辑
     - 降级策略：如果验证失败，使用路径本身作为推理结果，并标记为"需要人工审核"

3. **证据采集执行**
   - 按采集顺序采集证据（基于知识库，非优先级）：
     - 优先采集知识库中标记为"必须补齐"的信息（来自知识库的待补齐缺口）
     - 优先采集Tier2候选路径中的证据（必须优先除外）
     - 优先采集Tier1候选路径中的证据（最可能）
     - 优先采集Tier3候选路径中的证据（积极备选）
   - 证据采集方式：
     - 追问：路径中的症状节点
     - 观察：路径中的体征节点
     - 测量：路径中的检查节点
   - 证据记录：
     - 记录证据项名称
     - 记录证据来源（追问/观察/测量）
     - 记录证据结果
     - 记录证据方向（支持/不支持/不确定）
     - 记录影响对象（推动哪个方向前移或后移）

4. **三层排序形成**（基于知识库权威内容，非路径结构特征）
   - 基于知识库中的权威内容排序：
     - Tier2（必须排除方向）：知识库中的Tier2候选，如果未完成排除则保留
     - Tier1（最可能方向）：知识库中的Tier1候选，根据当前支持线索和反对线索匹配情况
     - Tier3（积极备选方向）：知识库中的Tier3候选，需要进一步区分
   - 路径用于验证候选：
     - 如果新证据支持某一方向的路径，验证该方向的知识库候选仍然有效
     - 如果新证据反对某一方向的路径，标记该方向的知识库候选为"需要重新评估"
     - 但排序不依赖路径数量，而是基于知识库中的权威内容
   - 排序依据标注：
     - 每个方向必须写清"一句话依据"
     - 依据优先来自知识库（知识库中的入选依据、支持线索、反对线索）
     - 路径作为补充依据（用于追溯和验证）

5. **验证计划制定**
   - 优先使用知识库中的验证计划：
     - 从疾病知识图谱中获取"必须补齐的关键信息条目ID列表"
     - 从主诉表6（候选疾病明细表）中获取"待补齐缺口"（必须补齐的关键信息条目ID列表）
     - 这些是知识库中定义的权威验证计划
   - DR.KNOWS路径补充验证计划（可选）：
     - 如果知识库中的验证计划不完整，可以从路径中提取检查节点作为补充
     - 但知识库中的验证计划优先
   - 验证计划设计：
     - 验证目的（确认/排除/升级判定）
     - 验证动作（补问/观察/测量/检查或就医）
     - 判定标准（什么结果支持/不支持）
     - 结果回填规则（结果出现后如何更新三层排序）
   - 验证计划执行顺序（基于知识库，非优先级）：
     - 优先执行Tier2候选的验证计划（必须优先除外）
     - 优先执行Tier1候选的验证计划（最可能）
     - 优先执行Tier3候选的验证计划（积极备选）

6. **路径更新与知识库验证**
   - 将新证据回填到路径：
     - 如果新证据匹配路径中的节点，标记为已采集
     - 如果新证据支持路径，标记路径为"支持"
     - 如果新证据反对路径，标记路径为"反对"
   - 路径支持状态更新：
     - 被支持的路径：保留，路径支持状态更新为"支持"
     - 被反对的路径：如果强烈反对，标记为"被反对"，但不移除（保留用于审计）
   - 路径用于验证知识库候选（关键作用）：
     - 检查被支持的路径是否指向知识库中的候选疾病
     - 如果路径支持知识库候选，验证候选仍然有效
     - 如果路径强烈反对知识库候选，标记候选为"需要重新评估"
     - 但知识库候选的排序不依赖路径数量，而是基于知识库中的权威内容

### 5.4 输出标准

**必交付内容**：

1. **证据清单**：
   - 每条证据包含：名称、来源、结果、方向、影响对象、相关路径

2. **三层排序清单**：
   - 最可能方向（1个）+ 一句话依据 + 推理路径
   - 必须排除方向（0-1个）+ 一句话依据 + 排除状态 + 推理路径
   - 积极备选方向（1-2个）+ 一句话依据 + 推理路径

3. **验证计划**：
   - 每项验证包含：目的、动作、判定标准、回填规则、相关路径

4. **更新后的推理路径**：
   - 包含新证据的路径
   - 重分析后的路径验证状态（路径支持状态，用于验证知识库候选）

### 5.5 参与工具

- **工具2：主动问诊工具** - 采集关键证据
- **工具3：鉴别诊断工具** - 固化三层排序
- **工具4：检查建议工具** - 制定验证计划

### 5.6 完成条件

- 关键证据已采集（至少覆盖主要差异点）
- 三层排序已固化
- 验证计划已制定（针对最可能和必须排除方向）

## 六、Step 5：回填证据并输出终点结论包

### 6.1 目标

将 Step 4 的验证结果回填到证据清单与问题清单中，更新三层排序，并输出可行动、可审计的终点结论包。该结论包既能对用户形成明确的"下一步怎么做"，也能对内部形成可追溯的证据链与复评规则，保证诊断过程可迭代。

### 6.2 核心原则

使用DR.KNOWS路径生成证据链和结论包。

### 6.3 核心任务

1. **证据回填**
   - 回填新增证据：
     - 将Step 4验证计划的结果回填到证据清单
     - 将新增问诊、测量、检查结果回填
   - 证据标记：
     - 标记每条证据对各方向的作用（支持/不支持/不确定）
     - 标记每条证据来自哪个推理路径
   - 证据审计记录：
     - 记录证据项
     - 记录来源（追问/观察/测量/检查）
     - 记录结果
     - 记录作用（支持/不支持/不确定）
     - 记录影响（推动哪个方向前移或后移）

2. **路径更新与知识库候选验证**
   - 将新证据回填到路径：
     - 如果新证据匹配路径中的节点，标记为已采集
     - 如果新证据支持路径，标记路径为"支持"
     - 如果新证据反对路径，标记路径为"反对"
   - 路径用于验证知识库候选（关键作用）：
     - 检查被支持的路径是否指向知识库中的候选疾病
     - 如果路径支持知识库候选，验证候选仍然有效
     - 如果路径强烈反对知识库候选，标记候选为"需要重新评估"
     - 但知识库候选的排序不依赖路径数量，而是基于知识库中的权威内容
   - 路径筛选（用于证据链生成）：
     - 保留被支持的路径（用于证据链生成）
     - 保留指向知识库候选的路径（用于验证和追溯）
     - 保留Top-N路径（用于证据链生成）

3. **三层排序更新（基于知识库）**
   - 基于知识库候选更新排序：
     - Tier2（必须排除方向）：知识库中的Tier2候选，如果未完成排除则保留
     - Tier1（最可能方向）：知识库中的Tier1候选，根据当前支持线索和反对线索匹配情况
     - Tier3（积极备选方向）：知识库中的Tier3候选，需要进一步区分
   - 路径用于验证候选：
     - 如果路径支持知识库候选，验证候选仍然有效
     - 如果路径强烈反对知识库候选，标记候选为"需要重新评估"
     - 但排序不依赖路径数量，而是基于知识库中的权威内容
   - 排序依据更新：
     - 更新每个方向的"一句话依据"
     - 依据优先来自知识库（知识库中的入选依据、支持线索、反对线索）
     - 路径作为补充依据（用于追溯和验证）

4. **证据链生成（基于知识库和路径）**
   - 优先使用知识库中的证据链：
     - 从疾病知识图谱中获取"证据链构建规则"（输出解释时证据如何选取与排序）
     - 从疾病知识图谱中获取"关键支持证据条目ID列表"和"关键反对证据条目ID列表"
     - 这些是知识库中定义的权威证据链
   - DR.KNOWS路径补充证据链：
     - 选择被支持的路径（指向知识库候选的路径）
     - 将路径格式化为证据链描述
     - 例如：症状A → 系统来源B → 疾病C
     - 路径作为知识库证据链的补充和验证
   - 证据链完整性检查：
     - 检查知识库中的证据链是否完整（关键支持证据是否都有证据支持）
     - 检查路径是否与知识库中的证据链一致
     - 如果路径与知识库证据链一致，验证证据链有效
   - 证据链标注（基于知识库和路径）：
     - 标注哪些是阳性证据（优先来自知识库的关键支持证据，路径作为补充）
     - 标注哪些是关键阴性证据（优先来自知识库的关键反对证据，路径作为补充）
     - 标注证据来源（知识库/路径）

5. **终点结论包生成**
   - 终点分类：
     - **可确证终点**：证据达到明确诊断标准，路径完整且一致
     - **不可确证终点**：证据不足以确证，但路径指向明确方向
   - 结论生成：
     - **可确证**：输出具体疾病诊断（基于Top路径）
     - **不可确证**：输出最可能方向或最可能诊断倾向（基于Top路径）
   - 必须排除项状态：
     - 已排除：路径被强烈反对，证据充分
     - 未排除：路径仍存在，证据不足
     - 需线下排除：需要线下检查才能排除
   - 关键依据：
     - 至少三条证据（来自Top路径）
     - 明确哪些是阳性证据
     - 明确哪些是关键阴性证据
     - 每条证据都对应推理路径
   - 行动与随访：
     - 立即行动（基于路径中的检查节点）
     - 复评时间窗（基于路径中的随访节点）
     - 升级触发条件（基于路径中的高危节点）

6. **复评与回退机制**
   - 回退触发条件：
     - 证据冲突：新证据与现有路径强烈冲突
     - 症状演变：症状变化导致现有路径不再适用
     - 处理无效：按路径建议处理无效
   - 回退目标确定：
     - 如果路径被强烈反对，回退到Step 2（重新检索路径）
     - 如果证据不足，回退到Step 4（重新采集证据）
     - 如果排序不稳定，回退到Step 3（重新组织分流路径）
   - 回退执行：
     - 清除被反对的路径
     - 保留仍有效的路径
     - 重新执行相应步骤

### 6.4 输出标准

**必交付内容**：

1. **证据回填记录**：
   - 每条证据包含：名称、来源、结果、作用、影响、相关路径

2. **更新后的三层清单**：
   - 最可能方向（1个）+ 一句话依据 + 推理路径
   - 必须排除方向（0-1个）+ 排除状态 + 推理路径
   - 积极备选方向（1-2个）+ 一句话依据 + 推理路径

3. **终点结论包（四要素）**：
   - **结论**：可确证（具体疾病）/ 不可确证（最可能方向）
   - **必须排除项状态**：已排除/未排除/需线下排除 + 理由
   - **关键依据**：至少三条证据（来自推理路径）
   - **行动与随访**：立即行动 + 复评时间窗 + 升级触发条件

4. **推理路径（Top-5）**：
   - 每条路径包含：路径描述、证据支持、强度、相关疾病

5. **回退决策**（如适用）：
   - 回退原因、回退目标、保留的路径

### 6.5 参与工具

- **工具1：病例理解工具** - 回填证据到问题清单
- **工具3：鉴别诊断工具** - 更新三层排序
- **工具4：检查建议工具** - 回填检查结果
- **工具5：治疗建议工具** - 生成行动建议
- **工具6：风险评估工具** - 生成升级触发条件
- **工具7：证据链工具** - 生成终点结论包

### 6.6 完成条件

- 证据已回填
- 三层排序已更新
- 终点结论包已生成（包含四要素）

## 七、流程迭代与回退机制

### 7.1 概述

临床诊疗态流程支持动态迭代和回退，当出现证据冲突、症状演变或处理无效时，系统可以回退到之前的步骤重新处理，确保不会在错误结论上"锁死"。

### 7.2 回退机制说明

**回退机制特点**：
- 系统支持回退到任意步骤（Step 1-5 或阶段0）
- 回退触发条件包括：证据冲突、症状演变、治疗无效、必须排除项未完成等
- 回退遵循医疗理论原则：假设可修正性、证据优先性、风险优先性、可追溯性

### 7.3 回退触发条件

**回退触发条件**：

1. **证据冲突**：
   - 新证据与现有路径强烈冲突
   - 多个工具返回的结果不一致
   - 证据融合过程中识别到无法解决的冲突

2. **症状演变**：
   - 症状变化导致现有路径不再适用
   - 新症状出现，需要重新评估

3. **处理无效**：
   - 按路径建议处理无效
   - 患者反馈症状未改善或加重

4. **必须排除项未完成**：
   - Tier2候选（必须排除方向）未完成排除
   - 关键证据缺失，无法完成排除

### 7.4 回退目标确定

**回退目标确定规则**：

- **如果路径被强烈反对** → 回退到Step 2（重新检索路径）
- **如果证据不足** → 回退到Step 4（重新采集证据）
- **如果排序不稳定** → 回退到Step 3（重新组织分流路径）
- **如果问题清单不完整** → 回退到Step 1（重新识别问题）

### 7.5 回退执行

**回退执行步骤**：

1. **清除被反对的路径**：
   - 标记被强烈反对的路径为"已排除"
   - 保留路径记录用于审计

2. **保留仍有效的路径**：
   - 保留被支持的路径
   - 保留指向知识库候选的路径

3. **重新执行相应步骤**：
   - 根据回退目标，重新执行相应的步骤
   - 使用保留的路径和证据作为输入
