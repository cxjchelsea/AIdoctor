## 一、健康管理态流程概述

### 1.1 流程定位

**目标**：面向无症状的健康人群，提供健康筛查、体检规划、健康管理等服务

**适用场景**：
- 用户无症状或不确定健康状态
- 用户希望进行健康筛查、体检规划
- 用户希望进行健康目标管理
- 用户有明确的计划性健康需求（备孕、疫苗、差旅等）

### 1.2 流程结构

```
A1｜需求分类 → A2｜通用最小健康档案 → A3｜进入对应分支执行 → A4｜统一结果页输出 → A5｜随访闭环
```

**核心原则**：
- 用户无症状或不确定健康状态
- 采集最低必要信息（缺失不阻塞）
- 按需求类型进入固定分支
- 所有分支收敛为统一结果展示结构

## 二、A1｜需求分类

### 2.1 功能目标

把用户需求归入三类之一，后续严格对齐分支流程。

### 2.2 需求类型

1. **筛查建议**：用户无症状，只想知道"应该做哪些筛查/多久一次"
2. **健康目标管理**：用户无症状，但希望改善健康状态（减脂/睡眠/运动/精力）
3. **计划性健康需求**：用户无症状，但有明确场景任务（备孕/疫苗/差旅/材料等）

### 2.3 处理流程

1. 三选一归类需求
2. 输出需求类型（1/2/3）

### 2.4 需求清单

- **四类需求选项文案**
- **用户常见表达归类示例**
- **不确定时的引导话术**

### 2.5 业务逻辑示例

```java
/**
 * A1｜需求分类服务
 */
@Service
public class DemandClassificationService {
    
    /**
     * 需求分类
     */
    public DemandClassificationResult classify(String userId, String userInput, CDP cdp) {
        // 1. 意图识别（使用NLU引擎）
        NLUResult nluResult = nluEngine.parse(userInput);
        String intent = nluResult.getIntent();
        
        // 2. 需求分类（根据意图匹配到3个分支之一）
        DemandType demandType = determineDemandType(intent, nluResult);
        // demandType: SCREENING_RECOMMENDATION | HEALTH_GOAL_MANAGEMENT | PLANNED_HEALTH_NEEDS
        
        // 3. 提取关键信息
        Map<String, Object> extractedInfo = extractKeyInformation(nluResult, demandType);
        
        // 4. 更新CDP
        cdpManager.updateCDP(cdp.getId(), Map.of(
            "demandType", demandType.name(),
            "extractedInfo", extractedInfo,
            "stage", "A1_DEMAND_CLASSIFICATION"
        ));
        
        return DemandClassificationResult.builder()
            .demandType(demandType)
            .extractedInfo(extractedInfo)
            .nextStep("A2｜收集健康画像")
            .build();
    }
}
```

## 三、A2｜通用最小健康档案

### 3.1 功能目标

采集最低必要信息，为后续建议提供依据（缺失不阻塞）。

### 3.2 处理流程

1. 采集最小健康档案字段
2. 输出健康档案卡 + 可选补充的缺失字段清单

### 3.3 健康档案字段

- **基本信息**：年龄、性别、身高、体重
- **既往史**：疾病史、手术史、过敏史
- **家族史**：遗传疾病史
- **生活习惯**：吸烟、饮酒、运动、饮食
- **用药史**：当前用药、既往用药

### 3.4 需求清单

- **健康档案采集字段清单**
- **低信息模式兜底话术**（缺失不阻塞仍能输出）
- **缺失字段提示与补充策略**（可选）

### 3.5 业务逻辑示例

```java
/**
 * A2｜收集健康画像服务
 */
@Service
public class HealthProfileCollectionService {
    
    /**
     * 收集健康画像
     */
    public HealthProfile collectHealthProfile(String userId, CDP cdp, Map<String, Object> initialData) {
        // 1. 从CDP获取已有信息
        Map<String, Object> cdpData = cdpManager.getCDPData(cdp.getId());
        
        // 2. 构建健康画像结构
        HealthProfile profile = HealthProfile.builder()
            .userId(userId)
            .basicInfo(extractBasicInfo(cdpData, initialData))
            .healthHistory(extractHealthHistory(cdpData, initialData))
            .familyHistory(extractFamilyHistory(cdpData, initialData))
            .lifestyle(extractLifestyle(cdpData, initialData))
            .medicationHistory(extractMedicationHistory(cdpData, initialData))
            .allergyHistory(extractAllergyHistory(cdpData, initialData))
            .build();
        
        // 3. 识别缺失信息
        InformationGaps gaps = identifyMissingInformation(profile);
        
        // 4. 生成补充提问（仅对必填项）
        List<String> followUpQuestions = generateFollowUpQuestions(gaps.getRequiredGaps());
        
        // 5. 如果还有必填项缺失，返回需要补充的信息
        if (!gaps.getRequiredGaps().isEmpty()) {
            return HealthProfile.builder()
                .profile(profile)
                .completeness(calculateCompleteness(profile))
                .missingRequiredFields(gaps.getRequiredGaps())
                .followUpQuestions(followUpQuestions)
                .isComplete(false)
                .build();
        }
        
        // 6. 画像完整，更新CDP并进入下一步
        cdpManager.updateCDP(cdp.getId(), Map.of(
            "healthProfile", profile,
            "stage", "A2_HEALTH_PROFILE_COLLECTED"
        ));
        
        return HealthProfile.builder()
            .profile(profile)
            .completeness(1.0)
            .isComplete(true)
            .nextStep("A3｜执行分支")
            .build();
    }
}
```

## 四、A3｜进入对应分支执行

### 4.1 功能目标

按需求类型进入固定分支，输出该分支的标准结果。

### 4.2 分支结构

#### A3-1｜筛查建议分支（对应需求1）

**目标**：用户无症状，只想知道"应该做哪些筛查/多久一次"

**处理流程**：
1. **补充追问**（仅问会影响筛查决策的关键信息）
   - 年龄、性别、既往史、家族史等关键信息
   - 避免过度追问

2. **规则化生成两张清单**：
   - **推荐做的筛查清单**：
     - 按年龄段、性别、风险因素推荐筛查项目
     - 包含筛查频率和时机
   - **不建议做的筛查清单**：
     - 反过度筛查理由
     - 替代建议

3. **输出分支结果**：
   - 推荐筛查清单 + 频率/时机
   - 不建议筛查清单 + 理由
   - 下次更新时间点
   - 随访节奏

**需求清单**：
- **额外追问清单**（仅筛查决策关键项）
- **输出数量与排序规则**（推荐/不推荐各输出多少条）
- **条件触发筛查规则库**（什么条件→建议哪些筛查→大致频率/时机）
- **不推荐筛查清单**（反过度筛查理由与替代建议）
- **强烈要求检查时的标准回应话术**

#### A3-2｜健康目标管理分支（对应需求2）

**目标**：用户无症状，但希望改善健康状态（减脂/睡眠/运动/精力）

**处理流程**：
1. **固定追问**（目标/现状/资源/周期）
   - 目标：想要改善的具体目标（减脂/睡眠/运动/精力等）
   - 现状：当前状态和基线数据
   - 资源：可用的时间、精力、经济资源
   - 周期：期望的改善周期

2. **生成可执行行动计划**：
   - 行动计划：具体的行动步骤
   - 追踪指标：2-3个关键指标（如体重、睡眠时长）
   - 复盘节点：定期回顾和调整时间点

3. **输出分支结果**：
   - 行动计划 + 追踪指标 + 复盘节点
   - 随访节奏

**需求清单**：
- **固定追问清单**（目标/现状/资源/周期）
- **目标计划模板库**（按目标类型复用）
- **追踪指标建议库**（2–3个即可）
- **失败兜底调整话术**

#### A3-4｜计划性健康需求分支（对应需求4）

**目标**：用户无症状，但有明确场景任务（备孕/疫苗/差旅/材料等）

**处理流程**：
1. **追问场景必要信息**（场景/时间点/禁忌信息）
   - 场景：具体的场景任务（备孕/疫苗/差旅/材料等）
   - 时间点：任务的时间节点
   - 禁忌信息：是否有禁忌症或特殊情况

2. **输出清单 + 时间表 + 注意事项**：
   - 检查清单：需要完成的检查项目
   - 时间表：检查的时间安排
   - 注意事项：需要特别注意的事项

3. **输出分支结果**：
   - 清单 + 时间表 + 注意事项
   - 随访节奏

**需求清单**：
- **固定追问清单**（场景/时间点/禁忌信息）
- **场景清单库**（清单+时间表+注意事项）
- **场景节点提醒规则**（什么时候提醒更新）

### 4.3 业务逻辑示例

```java
/**
 * A3｜执行分支服务
 */
@Service
public class BranchExecutionService {
    
    /**
     * 执行分支
     */
    public BranchExecutionResult executeBranch(String userId, CDP cdp, DemandType demandType, HealthProfile profile) {
        BranchExecutionResult result;
        
        switch (demandType) {
            case SCREENING_RECOMMENDATION:
                result = executeScreeningRecommendation(userId, profile, cdp);
                break;
            case HEALTH_GOAL_MANAGEMENT:
                result = executeHealthGoalManagement(userId, profile, cdp);
                break;
            case PLANNED_HEALTH_NEEDS:
                result = executePlannedHealthNeeds(userId, profile, cdp);
                break;
            default:
                throw new IllegalArgumentException("Unknown demand type: " + demandType);
        }
        
        // 更新CDP
        cdpManager.updateCDP(cdp.getId(), Map.of(
            "branchResult", result,
            "stage", "A3_BRANCH_EXECUTED"
        ));
        
        return result;
    }
}
```

## 五、A4｜统一结果页输出

### 5.1 功能目标

所有分支收敛为同一种结果展示结构。

### 5.2 结果展示结构

1. **一句话总结**：总结本次咨询的核心建议
2. **现在建议做的事（清单）**：明确建议用户执行的事项
3. **暂时不建议做的事（清单）**：明确不建议的事项及理由
4. **下一次复查/更新时间点**：明确的随访时间
5. **退出A路径条件提示**：出现不适/危险信号→线下评估

### 5.3 需求清单

- **一句话总结模板**（按需求类型）
- **推荐/不推荐展示话术模板**
- **退出A路径提醒文案**（出现不适/危险信号→线下评估）

### 5.4 业务逻辑示例

```java
/**
 * A4｜生成统一结果服务
 */
@Service
public class UnifiedResultGeneratorService {
    
    /**
     * 生成统一结果
     */
    public UnifiedResult generateUnifiedResult(CDP cdp, BranchExecutionResult branchResult) {
        // 1. 提取分支结果
        DemandType demandType = branchResult.getDemandType();
        
        // 2. 构建统一结果结构
        UnifiedResult result = UnifiedResult.builder()
            .cdpId(cdp.getId())
            .demandType(demandType)
            .summary(generateSummary(branchResult))
            .mainContent(buildMainContent(branchResult))
            .recommendations(buildRecommendations(branchResult))
            .nextSteps(buildNextSteps(branchResult))
            .build();
        
        // 3. 更新CDP
        cdpManager.updateCDP(cdp.getId(), Map.of(
            "unifiedResult", result,
            "stage", "A4_UNIFIED_RESULT_GENERATED"
        ));
        
        return result;
    }
}
```

## 六、A5｜随访闭环

### 6.1 功能目标

给出明确随访节奏，形成流程结束点与再次进入入口。

### 6.2 随访节奏规则（按需求类型）

1. **筛查建议**：周期性更新档案
   - 按筛查项目的时间间隔提醒用户更新
   - 定期回顾健康档案

2. **健康目标管理**：按复盘节点回访更新
   - 按行动计划中的复盘节点提醒用户
   - 评估进展并调整计划

3. **计划性需求**：按场景节点提醒更新/完成任务
   - 按时间表提醒用户完成检查
   - 任务完成后关闭提醒

### 6.3 需求清单

- **随访节奏规则**（按需求类型）
- **随访提醒话术**（按节点提醒用户更新/复查/复盘）

### 6.4 业务逻辑示例

```java
/**
 * A5｜设置随访服务
 */
@Service
public class FollowUpSetupService {
    
    /**
     * 设置随访
     */
    public FollowUpPlan setupFollowUp(String userId, CDP cdp, UnifiedResult unifiedResult) {
        // 1. 计算随访周期（基于风险等级、需求类型等）
        int followUpDays = calculateFollowUpDays(unifiedResult);
        
        // 2. 生成随访提醒内容
        String reminderContent = generateReminderContent(unifiedResult);
        
        // 3. 创建随访计划
        FollowUpPlan plan = FollowUpPlan.builder()
            .userId(userId)
            .cdpId(cdp.getId())
            .followUpDate(LocalDate.now().plusDays(followUpDays))
            .reminderContent(reminderContent)
            .isActive(true)
            .build();
        
        // 4. 保存随访计划
        followUpManager.saveFollowUpPlan(plan);
        
        // 5. 更新CDP
        cdpManager.updateCDP(cdp.getId(), Map.of(
            "followUpPlan", plan,
            "stage", "A5_FOLLOW_UP_SETUP"
        ));
        
        return plan;
    }
}
```

## 八、健康管理态升级触发

### 8.1 触发条件

- 症状加重或持续不缓解
- 出现新症状
- 识别到风险信号（红旗信号）
- 随访中发现异常

### 8.2 升级动作

- 更新 `health_state_assessment.work_mode` = clinical_mode
- 启动诊断流程
- 主Agent重新调用相关工具
