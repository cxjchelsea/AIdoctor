## 一、核心概念详细说明

### 1.1 CDP（Clinical Decision Package）

**定义**：临床决策包，系统内部一切推理的核心数据结构。

**特点**：
- **唯一事实源**：CDP是病例事实的唯一事实源，所有工具从CDP读取，建议写回CDP
- **结构化存储**：CDP以结构化JSON格式存储，支持版本管理和状态转换
- **不可变历史**：CDP采用写时复制机制，每次更新创建新版本，历史版本不可修改

**主要字段**：
- `health_state_assessment`：健康状态判定结果
- `wellness_plan`：健康管理计划
- `patient_state`：患者状态
- `ddx`：鉴别诊断列表
- `evidence_graph`：证据图
- `workup_plan`：检查计划
- `management_plan`：治疗计划
- `triage`：风险评估
- `uncertainty`：不确定性信息
- `audit`：审计信息

> **详细设计**：请参考《6.数据模型设计/CDP数据结构设计.md》

### 1.2 主Agent（Clinical Agent Brain）

**定义**：负责运行循环、工具调用、决策提交的核心Agent。

**职责**：
- **唯一决策者**：主Agent是唯一"最终结论提交者"，所有诊断结论、检查建议、治疗方案都由主Agent最终决定
- **自主调用工具**：主Agent根据当前CDP状态和AgentState，自主决定调用哪些工具、调用顺序、调用参数
- **停止/升级/拒答能力**：主Agent具备停止条件判断、升级策略执行、拒答边界判断的能力
- **证据融合**：主Agent内部融合多个工具返回的证据，进行冲突解决和一致性检查
- **策略状态管理**：主Agent维护AgentState，包括阈值、预算、失败回退、已尝试工具等

**运行循环**：
```
Observe（观察）→ Plan（规划）→ Act（执行）→ Update（更新）→ Evaluate（评估）→ Stop/Escalate（停止/升级）
```

> **详细设计**：请参考《5.主Agent设计/主Agent运行循环设计.md》

### 1.3 工具（Tools）

**定义**：将AI医生的能力拆解为8个"临床工具"，每个工具都可以单独训练、评测、替换。

**特点**：
- **无独立目标**：工具不拥有独立的诊断目标或治疗目标，只按主Agent调用执行
- **无长期策略状态**：工具不维护长期状态，每次调用都是独立的
- **结构化输出**：工具返回结构化的payload、evidence、quality、suggestedWrites
- **证据引用**：工具必须提供evidence引用，说明输出结果的依据来源

**八大工具**：
- tool_0：健康状态判定工具
- tool_1：病例理解工具
- tool_2：主动问诊工具
- tool_3：鉴别诊断工具
- tool_4：检查建议工具
- tool_5：治疗建议工具
- tool_6：风险评估工具
- tool_7：证据链工具

> **详细设计**：请参考《4.工具设计/工具接口规范.md》

### 1.4 双通道推理架构

**定义**：将推理过程分为两个通道：结构化推理通道和语言与策略通道。

**通道1：结构化推理通道**（决定"该往哪想" - 临床逻辑）
- 医学概念标准化（CUI/ICD/SNOMED）
- 知识图谱路径检索与排序（DR.KNOWS方法）
- 规则/概率/贝叶斯/评分量表（可插拔）
- 知识库优先诊断
- 输出：DDx候选 + 证据结构 + 推理路径

**通道2：语言与策略通道**（决定"怎么说、怎么问" - 医生表达）
- 问诊对话生成（问什么、怎么问）
- 解释与沟通（把结构化结果讲成人话）
- 生成处置方案草案（在受控证据基础上）
- 自然语言生成（NLG）
- 输出：自然语言问诊、解释、建议

**核心原则**：
> **让结构化通道决定"该往哪想"，让LLM决定"怎么说、怎么问、怎么组织方案"**

> **详细设计**：请参考《2.架构设计/双通道推理架构.md》

### 1.5 DR.KNOWS方法

**定义**：基于知识图谱的医学诊断方法，通过多跳推理路径检索进行诊断。

**核心步骤**：
1. **医学概念识别与归一化**：将用户输入的症状、体征等转换为标准医学概念（CUI/ICD/SNOMED）
2. **多跳推理路径检索**：从Neo4j知识图谱中检索2-4跳的推理路径
3. **路径结构特征分析**：分析路径的结构特征（非数值评分）
4. **路径验证**：验证路径是否指向知识库候选
5. **路径约束推理**：在路径约束下使用LLM进行推理
6. **推理结果验证**：验证推理结果是否符合路径约束

> **详细设计**：请参考《13.技术细节/DR.KNOWS路径推理设计.md》

### 1.6 知识演化

**定义**：知识库的持续更新和维护机制。

**三个知识库区**：
- **Sandbox（实验/构建区）**：用于实验和构建新知识
- **Staging（候选验证区）**：用于验证候选知识
- **Production（生产知识库）**：用于生产环境，只读

**知识演化Agent集群**：
- Extractor Agent（抽取Agent）
- Verifier Agent（验证Agent）
- Conflict Resolver Agent（冲突解决Agent）
- Release Builder Agent（打包发布候选Agent）
- Shadow Evaluator Agent（影子评测Agent）
- Rollback & Drift Monitor Agent（回滚与漂移监控）

**Publish Gate（发布门禁）**：
- Gate-1: 结构合法性检查
- Gate-2: 证据可追溯性检查
- Gate-3: 回归评测与影子评测
- Gate-4: 风险分级审批

> **详细设计**：请参考《9.知识演化设计/知识演化架构设计.md》

## 二、概念关系图

### 2.1 核心概念关系

```
主Agent（Clinical Agent Brain）
    ├─→ 管理 CDP（唯一事实源）
    ├─→ 管理 AgentState（策略状态）
    ├─→ 管理 AuditTrail（审计轨迹）
    ├─→ 调用 工具（Tools）
    │       ├─→ tool_0：健康状态判定工具
    │       ├─→ tool_1：病例理解工具
    │       ├─→ tool_2：主动问诊工具
    │       ├─→ tool_3：鉴别诊断工具（使用DR.KNOWS方法）
    │       ├─→ tool_4：检查建议工具
    │       ├─→ tool_5：治疗建议工具
    │       ├─→ tool_6：风险评估工具
    │       └─→ tool_7：证据链工具
    │
    └─→ 双通道推理
            ├─→ 通道1：结构化推理通道（决定"该往哪想"）
            └─→ 通道2：语言与策略通道（决定"怎么说、怎么问"）
```

### 2.2 数据流关系

```
用户输入
    ↓
创建CDP（初始版本）
    ↓
主Agent运行循环
    ├─→ 调用工具（从CDP读取）
    ├─→ 工具返回结果（建议写回CDP）
    ├─→ 证据融合与冲突解决
    ├─→ 更新CDP（新版本）
    └─→ 更新AgentState
            ↓
    记录到AuditTrail
            ↓
    继续运行循环...
            ↓
    最终CDP（包含完整诊断结果）
```
