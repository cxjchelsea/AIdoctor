# AI医生系统 - 入口设计规范

> **文档定位**：本文档详细说明AI医生系统所有入口的设计规范，包括用户进入系统、工作态判定、路径选择等入口设计。  
> **设计理念**：对话为主，无感判定，渐进式收集，像医生一样问诊

---

## 📖 术语表

| 术语 | 定义 |
|------|------|
| **入口判定** | 系统判断用户应该进入哪个路径的流程（P0模块） |
| **工作态** | 系统的工作模式：健康管理态（wellness_mode）和临床诊疗态（clinical_mode） |
| **健康管理态** | 面向"没病或不确定健康状态"的人，负责风险管理与随访 |
| **临床诊疗态** | 面向"疑似/明确有病"的人，执行受控、可解释的临床推理与决策支持 |
| **无感判定** | 在对话过程中自然完成判定，用户无需感知流程切换 |
| **渐进式收集** | 按需逐步收集信息，而非一次性填写大量信息 |

---

## 一、入口设计核心原则

### 1.1 设计理念

1. **对话为主，不填表**
   - 用户直接进入对话界面，用自然语言描述问题
   - 不依赖选择题入口，不要求先填表
   - 支持自然语言理解（NLU），允许混合诉求

2. **无感判定，自然切换**
   - 入口判定流程在对话中无感完成
   - 用户输入第一句话后，系统在后台完成判定
   - 判定完成后，系统在对话中自然引导用户

3. **渐进式收集，缺失不阻塞**
   - 按需逐步收集信息，而非一次性填写大量信息
   - 基本信息是可选的，不影响判定
   - 缺失信息不阻塞流程，可在后续补充

4. **像医生一样问诊**
   - 界面温暖、专业，像真正的医生问诊
   - 系统主动引导用户，而不是被动等待
   - 支持多模态输入（文字、图片、语音）

### 1.2 设计原则

| 原则 | 说明 | 反例 |
|------|------|------|
| **低门槛** | 用户无需理解复杂流程，直接描述问题即可 | ❌ 要求用户先选择"健康筛查"或"症状诊断" |
| **无感切换** | 判定在后台完成，用户无感知 | ❌ 显示明显的"正在评估"页面 |
| **自然流畅** | 对话自然继续，像真实医生问诊 | ❌ 填表收集大量信息后再开始问诊 |
| **灵活性强** | 支持复杂、混合诉求 | ❌ 只能选择单一诉求类型 |

## 二、系统入口设计

### 2.1 用户首次进入系统

#### 2.1.1 用户看到的初始界面

**对话区域**：
- 系统欢迎消息（医生头像 + 消息气泡）：
  ```
  您好，我是智能诊断助手。请描述您的问题或需求，我会根据您提供的信息为您提供帮助。
  ```

**信息面板**：
- 顶部操作区：
  - "开始新诊断"按钮（默认状态，点击清空当前对话）
  - "我的病例"按钮（查看历史病例）
  - "健康档案"按钮（查看/编辑健康档案）
- 信息完整度卡片（初始为空）
- 快速操作区：
  - "上传检查报告"按钮
  - "补充体征数据"按钮

#### 2.1.2 用户操作

**用户可以直接**：
1. 在输入框中输入问题或需求（文字、图片、语音）
2. 点击快捷输入提示（可选）：
   - "我最近不舒服"
   - "我想做个体检"
   - "帮我看看这个报告"
3. 点击信息面板的按钮（开始新诊断、我的病例、健康档案）

**用户不需要**：
- ❌ 先选择"健康筛查"或"症状诊断"
- ❌ 先填写基本信息表单
- ❌ 先选择诉求类型

## 三、入口判定流程设计（P0模块）

### 3.1 流程概述

**设计理念**：入口判定流程（P0模块）不在独立界面中完成，而是在对话过程中无感完成。用户直接进入对话界面，系统在前几轮对话中自然完成工作态判定，然后无感进入相应的推理流程。

**流程概览**：
```
用户输入第一句话
    ↓
系统在后台完成入口判定（Step 1-5）
    ↓
如果需要，系统在对话中自然询问
    ↓
判定完成后，无感进入相应流程
```

### 3.2 五个步骤详细设计

#### Step 1：接收用户输入

**功能**：接收用户自然语言描述本次来访目的

**输入要求**：
- ✅ 用户自然语言输入（文本/语音）
- ✅ 基本信息（可选）：年龄、性别等
- ✅ 健康档案（可选）：如有历史档案

**处理逻辑**：
- 支持自然语言理解（NLU）
- 允许混合诉求（既想体检又有轻微不适）
- 不依赖选择题入口

**输出**：结构化的用户意图表达

**UI表现**：
- 用户输入后，系统立即响应（不显示"正在分析"）
- 如果输入包含图片，系统显示"正在识别图片内容..."

**示例**：
```
用户：我最近胸痛，想咨询一下
系统：[后台处理，不显示处理状态]
```

#### Step 2：识别用户是否"有症状/困扰"

**功能**：系统对用户输入做一次判断，识别用户是否有症状/困扰

**判断结果**：

**情况 A：明确无症状**
- 用户表达的是"健康管理/体检规划/筛查/预防"
- 且没有任何不适描述
- **处理**：进入 Step 4（危险信号兜底）后，准备进入健康筛查路径（A）

**情况 B：存在症状/困扰**
- 用户描述任何身体不适、异常感觉、功能变化、心理困扰等（不论轻重）
- **处理**：进入 Step 4（危险信号兜底）后，准备进入症状诊断路径（B）

**情况 C：不确定/模糊/混合诉求**
- 用户说不清是否算不适
- 或同时说"想体检 + 有点不舒服"
- **处理**：进入 Step 3 做一次方向澄清

**UI表现**：
- 系统在后台分析，不显示分析过程
- 如果明确（情况A或B），直接进入下一步
- 如果不明确（情况C），进入 Step 3

**示例**：
```
用户：我想做个体检
系统：[后台判定为情况A，无症状]
      [无感进入健康筛查路径]

用户：我最近胸痛
系统：[后台判定为情况B，有症状]
      [无感进入症状诊断路径]

用户：我想体检，但最近有点不舒服
系统：[后台判定为情况C，不确定]
      [进入Step 3，在对话中询问]
```

#### Step 3：方向澄清（仅对"情况C"触发一次）

**功能**：通过最小澄清确认用户当前的主要目标

**触发条件**：仅当 Step 2 判断为"情况C"时触发

**澄清目标**：确认用户主要目标是：
- **A**：健康筛查/体检规划
- **B**：症状咨询/问题排查

**处理原则**：
- 澄清后不得反复追问，避免入口卡顿
- 澄清结果只能落到两类：进入 A 或进入 B
- 仅询问一次，不重复询问

**UI表现**：
- 系统在对话中自然询问：
  ```
  系统：请确认一下，您主要是想进行健康筛查/体检规划，还是想咨询症状问题？
  ```
- 提供选项按钮，方便用户快速选择：
  - [健康筛查/体检规划]
  - [症状咨询/问题排查]
- 用户也可以直接文字回答

**示例**：
```
用户：我想体检，但最近有点不舒服
系统：请确认一下，您主要是想进行健康筛查/体检规划，还是想咨询症状问题？
      [健康筛查/体检规划]  [症状咨询/问题排查]

用户：[点击"症状咨询/问题排查"]
系统：[判定为情况B，进入症状诊断路径]
```

#### Step 4：危险信号检查（安全兜底，所有用户都要过一次）

**功能**：无论用户走 A 还是 B，都必须判断是否存在危险信号

**检查逻辑**：
- **如果命中危险信号**：
  - 不进入线上流程
  - 输出"优先线下就医/急诊"的安全提示（结束）

- **如果未命中危险信号**：
  - 进入 Step 5 输出选路结果

**危险信号库**：维护一份危险信号清单（红旗库）

**检查原则**：
- 入口判定阶段只做"是否命中"，不做解释诊断
- 命中后输出固定的安全提示并结束线上流程

**UI表现**：
- 如果命中危险信号，系统在对话中提示：
  ```
  系统：[警告图标] 检测到以下危险信号：胸痛伴大汗、呼吸困难
        建议您立即到急诊科就诊，或拨打120急救电话。
        线上诊断无法处理此类紧急情况，请优先线下就医。
  ```
- 如果未命中，继续正常流程（不显示检查过程）

**示例**：
```
用户：我胸痛，还出汗，感觉喘不上气
系统：[后台检查危险信号，命中]
      [警告图标] 检测到以下危险信号：胸痛伴大汗、呼吸困难
      建议您立即到急诊科就诊，或拨打120急救电话。
      线上诊断无法处理此类紧急情况，请优先线下就医。
```

#### Step 5：输出路径结果并跳转

**功能**：根据前面的判断结果，输出明确的路径选择并跳转

**输出规则**：
- **无症状 + 无危险信号** → 进入健康筛查路径（A）
- **有症状/困扰 + 无危险信号** → 进入症状诊断路径（B）
- **危险信号命中** → 退出线上流程（安全提示）

**跳转规则**：
- 跳转到对应路径的第一个步骤
- **A路径**：进入健康筛查流程的起点（A1｜需求分类）
- **B路径**：进入症状诊断流程的起点（阶段1｜问诊）

**UI表现**：
- 系统无感进入相应流程，在对话中自然引导用户
- 不显示明显的"路径切换"提示
- 用户无需感知流程切换，对话自然继续

**示例**：
```
用户：我想做个体检
系统：[后台完成判定，无感进入健康筛查路径]
      好的，我来帮您规划体检方案。请问您的年龄和性别是？
      [用户看到的是自然的对话继续，无感知路径切换]

用户：我最近胸痛
系统：[后台完成判定，无感进入症状诊断路径]
      我了解了，胸痛需要重视。请问疼痛持续多久了？
      [用户看到的是自然的对话继续，无感知路径切换]
```

## 四、工作态判定设计

### 4.1 工作态判定流程

**设计理念**：工作态判定通过入口判定流程（P0模块）完成，在对话中无感完成，用户无需感知。

**判定依据**：
- 用户描述的症状/不适（初始主诉）
- 基本信息（年龄、性别等，可选）
- 健康档案（如有，可选）

**判定结果**：
- `needsClinicalMode`：true/false
- `workMode`：wellness_mode / clinical_mode
- `riskLevel`：L1/L2/L3/L4
- `assessmentReason`：判定依据

> **说明**：以上为**对外API（camelCase）**字段；对应的 **CDP内部JSON** 字段使用 `snake_case`（如 `needs_clinical_mode` / `work_mode` / `risk_level` / `assessment_reason`），由网关/服务层完成映射。

### 4.2 工作态判定规则

| 工作态 | 判定条件 | 路径 |
|--------|---------|------|
| **健康管理态** | 明确无症状 + 无危险信号 | 健康筛查路径（A） |
| **临床诊疗态** | 存在症状/困扰 + 无危险信号 | 症状诊断路径（B） |
| **紧急处理** | 命中危险信号 | 退出线上流程，建议立即就医 |

### 4.3 UI表现

**健康管理态**：
- 系统在对话中自然引导：
  ```
  系统：好的，我来帮您规划体检方案。请问您的年龄和性别是？
  ```
- 信息面板显示"健康筛查"标签

**临床诊疗态**：
- 系统在对话中自然引导：
  ```
  系统：我了解了，胸痛需要重视。请问疼痛持续多久了？
  ```
- 信息面板显示"症状诊断"标签
- 显示5步AI循证诊断流程进度指示器

## 五、健康筛查路径入口设计（A路径）

### 5.1 入口条件

- 入口判定结果：无症状 + 无危险信号
- 工作态：健康管理态（wellness_mode）

### 5.2 入口后的第一个步骤：A1｜需求分类

**功能**：把用户需求归入四类之一

**需求类型**：
1. **筛查建议**：用户无症状，只想知道"应该做哪些筛查/多久一次"
2. **健康目标管理**：用户无症状，但希望改善健康状态（减脂/睡眠/运动/精力）
3. **计划性健康需求**：用户无症状，但有明确场景任务（备孕/疫苗/差旅/材料等）

**UI表现**：
- 系统在对话中询问或自动识别：
  ```
  系统：请问您主要是想了解筛查建议、管理健康目标，还是有其他计划性健康需求？
      [筛查建议]  [目标管理]  [计划性需求]
  ```
- 如果用户输入中已包含明确需求，系统自动识别，无需询问

**示例**：
```
用户：我想做个体检
系统：[自动识别为"筛查建议"]
      好的，我来帮您规划体检方案。请问您的年龄和性别是？
```

### 5.3 后续流程

- A2｜通用最小健康档案（通过对话收集，缺失不阻塞）
- A3｜进入对应分支执行
- A4｜统一结果页输出
- A5｜随访闭环

## 六、症状诊断路径入口设计（B路径）

### 6.1 入口条件

- 入口判定结果：有症状/困扰 + 无危险信号
- 工作态：临床诊疗态（clinical_mode）

### 6.2 入口后的第一个步骤：阶段1｜问诊

**功能**：通过对话收集关键信息，进行5步AI循证诊断流程

**UI表现**：
- 系统在对话中自然引导：
  ```
  系统：我了解了，胸痛需要重视。请问疼痛持续多久了？
  ```
- 信息面板显示：
  - 5步AI循证诊断流程进度指示器
  - 信息完整度进度条
  - 已收集信息摘要

**追问方式**：
- 系统主动追问关键信息
- 提供选项按钮，方便用户快速选择：
  ```
  系统：症状是突然出现的还是慢慢加重的？
      [突然出现]  [慢慢加重]  [不确定]
  ```
- 用户也可以直接文字回答

**示例**：
```
用户：我最近胸痛
系统：我了解了，胸痛需要重视。请问疼痛持续多久了？

用户：2天了
系统：症状是突然出现的还是慢慢加重的？
      [突然出现]  [慢慢加重]  [不确定]

用户：[点击"突然出现"]
系统：疼痛时是否伴有出汗、恶心等症状？
      [是]  [否]  [不确定]
```

### 6.3 后续流程

- 阶段2：检查推断（Workup Inference）
- 阶段3：鉴别诊断（DDx）
- 阶段4：决策与处置
- 阶段5：随访与复盘

## 七、特殊场景入口设计

### 7.1 危险信号场景

**触发条件**：Step 4 检查到危险信号

**UI表现**：
```
系统：[警告图标] 检测到以下危险信号：[危险信号列表]
      建议您立即到急诊科就诊，或拨打120急救电话。
      线上诊断无法处理此类紧急情况，请优先线下就医。
```

**后续操作**：
- 不进入线上流程
- 提供"拨打120"快捷按钮（移动端）
- 提供"查找附近医院"功能（可选）

### 7.2 路径切换场景

**触发条件**：
- 用户在健康筛查流程中后续出现症状描述
- 用户在症状诊断流程中明确只是想筛查

**UI表现**：
```
系统：您刚才提到了症状，是否需要切换到症状诊断流程？
      [切换到症状诊断]  [继续健康筛查]

系统：您主要是想进行健康筛查，是否需要切换到健康筛查流程？
      [切换到健康筛查]  [继续症状诊断]
```

### 7.3 历史病例入口

**入口位置**：信息面板顶部"我的病例"按钮

**功能**：
- 查看历史病例列表
- 点击"查看结果"查看已完成诊断
- 点击"继续诊断"继续未完成诊断

**UI表现**：
- 点击后打开抽屉（移动端）或侧边栏（PC端）
- 显示病例列表，按时间倒序排列
- 每个病例显示：时间、主诉、诊断结果、状态

### 7.4 健康档案入口

**入口位置**：信息面板顶部"健康档案"按钮

**功能**：
- 查看健康档案详情
- 编辑健康档案（可选，非强制）

**UI表现**：
- 点击后打开抽屉（移动端）或侧边栏（PC端）
- 显示健康档案信息
- 提供"编辑"按钮（可选）

## 八、UI/UX设计要点

### 8.1 对话界面设计

**核心原则**：
- 像医生一样：温暖、专业
- 对话为主：自然流畅
- 无感切换：用户无感知流程切换

**设计要点**：
1. **医生头像和身份标识**
   - 显示医生头像（温暖、专业）
   - 显示"智能诊断助手"身份
   - 显示在线状态

2. **消息气泡设计**
   - 系统消息：左侧，医生头像 + 消息气泡

## 九、技术实现要点

### 9.1 前端实现

**核心组件**：
- `EntryAssessmentFlow`：入口判定流程组件
- `DiagnosisChatPanel`：诊断对话面板
- `WellnessScreeningFlow`：健康筛查流程组件
- `InformationPanel`：信息面板组件

**状态管理**：
- 使用 Zustand 管理全局状态
- 状态包括：工作态、CDP ID、对话消息、信息完整度等

**API调用**：
- 健康状态判定API（整合入口判定Step 1-5）：`POST /api/v1/health-state-assessment/assess`
- 入口判定在后台完成，前端无需感知

### 9.2 后端实现

**核心服务**：
- `HealthStateAssessmentService`：健康状态判定服务
- `EntryAssessmentService`：入口判定服务（P0模块）

**处理流程**：
1. 接收用户输入（自然语言）
2. 执行入口判定（Step 1-5）
3. 返回判定结果（工作态、路径选择等）
4. 前端根据结果无感进入相应流程

**性能优化**：
- 入口判定在后台快速完成（通常<1秒）
- 使用缓存减少重复计算
- 异步处理，不阻塞用户操作
