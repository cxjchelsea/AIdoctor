## 一、双通道推理架构概述

### 1.1 设计理念

基于GPT建议和DR.KNOWS论文，采用**双通道推理架构**：

```
┌─────────────────────────────────────────────────────────────┐
│                    通道1：结构化推理通道                      │
│              （决定"该往哪想" - 临床逻辑）                    │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  医学概念标准化（CUI/ICD/SNOMED）                      │  │
│  │  知识图谱路径检索与排序（DR.KNOWS方法）                │  │
│  │  规则/概率/贝叶斯/评分量表（可插拔）                   │  │
│  │  知识库优先诊断                                         │  │
│  └──────────────────────────────────────────────────────┘  │
│  输出：DDx候选 + 证据结构 + 推理路径                         │
└─────────────────────────────────────────────────────────────┘
                            ↓
                    CDP（Clinical Decision Package）
                            ↓
┌─────────────────────────────────────────────────────────────┐
│                    通道2：语言与策略通道                      │
│            （决定"怎么说、怎么问" - 医生表达）               │
│  ┌──────────────────────────────────────────────────────┐  │
│  │  问诊对话生成（问什么、怎么问）                        │  │
│  │  解释与沟通（把结构化结果讲成人话）                    │  │
│  │  生成处置方案草案（在受控证据基础上）                  │  │
│  │  自然语言生成（NLG）                                   │  │
│  └──────────────────────────────────────────────────────┘  │
│  输出：自然语言问诊、解释、建议                              │
└─────────────────────────────────────────────────────────────┘
```

**核心原则**：
> **让结构化通道决定"该往哪想"，让LLM决定"怎么说、怎么问、怎么组织方案"**

### 1.2 架构优势

**职责分离**：
- **通道1**：专注于临床逻辑推理，确保诊断的准确性和可解释性
- **通道2**：专注于自然语言表达，确保用户体验和沟通效果

**可维护性**：
- 两个通道可以独立优化和升级
- 通道1的改进不影响通道2，反之亦然

**可解释性**：
- 通道1提供结构化的推理路径和证据
- 通道2基于结构化结果生成可解释的自然语言表达

**可扩展性**：
- 通道1可以集成多种推理引擎（规则、概率、贝叶斯等）
- 通道2可以集成多种NLG模型和对话策略

## 二、通道1：结构化推理通道

### 2.1 通道定位

**职责**：决定"该往哪想" - 临床逻辑推理

**核心任务**：
- 医学概念标准化（CUI/ICD/SNOMED）
- 知识图谱路径检索与排序（DR.KNOWS方法）
- 规则/概率/贝叶斯/评分量表（可插拔）
- 知识库优先诊断

**输出**：DDx候选 + 证据结构 + 推理路径（写入CDP）

### 2.2 主要工具

**通道1工具**：

| 工具ID | 工具名称 | 主要职责 | 技术实现 |
|--------|---------|---------|---------|
| tool_0 | 健康状态判定工具 | 判断工作态、入口判定流程 | 规则推理、风险评估 |
| tool_1 | 病例理解工具 | 概念归一化、结构化提取 | 医学概念标准化（CUI/ICD/SNOMED） |
| tool_3 | 鉴别诊断工具 | 多引擎融合诊断、DDx生成 | 知识库优先 + DR.KNOWS路径验证、路径约束推理 |
| tool_4 | 检查建议工具 | 检查价值评估、验证计划 | 检查价值评估、信息增益计算 |
| tool_5 | 治疗建议工具 | 治疗方案推理、药物推荐 | 治疗方案推理、药物推荐 |
| tool_6 | 风险评估工具 | 高危识别、紧急程度评估 | 风险识别、紧急程度评估 |

### 2.3 技术实现

**知识库优先（Knowledge Base First）**：
- **主诉知识图谱**：基于主诉检索候选疾病（Tier1/Tier2/Tier3）
- **疾病知识图谱**：检索疾病详细信息（症状、体征、检查、治疗等）

**DR.KNOWS路径检索与验证**：
- **多跳推理路径检索**：从Neo4j知识图谱中检索2-4跳的推理路径
- **路径结构特征分析**：分析路径的结构特征（非数值评分）
- **路径验证**：验证路径是否指向知识库候选

**路径约束推理**：
- **路径约束LLM推理**：在路径约束下使用LLM进行推理
- **推理结果验证**：验证推理结果是否符合路径约束（路径一致性/证据来源）
- **降级策略**：验证失败时使用路径本身作为推理结果

**医学概念标准化**：
- **CUI（Concept Unique Identifier）**：UMLS统一医学语言系统的概念编码
- **ICD（International Classification of Diseases）**：国际疾病分类编码
- **SNOMED（Systematized Nomenclature of Medicine）**：系统化医学术语命名法

**多引擎融合**：
- **规则引擎**：基于医学规则进行推理
- **概率引擎**：基于概率模型进行推理
- **贝叶斯引擎**：基于贝叶斯网络进行推理
- **评分量表**：基于评分量表进行推理

### 2.4 输出格式

**结构化输出**（写入CDP）：

```json
{
  "ddx": {
    "rank_list": [...],
    "tier1_most_likely": [...],
    "tier2_must_exclude": [...],
    "tier3_active_alternatives": [...]
  },
  "evidence_graph": {
    "supporting_evidence": [...],
    "contradicting_evidence": [...],
    "missing_evidence": [...]
  },
  "workup_plan": {
    "workup_items": [...],
    "verification_plans": [...]
  },
  "management_plan": {
    "treatment_plan": {...},
    "medication_suggestions": [...]
  },
  "triage": {
    "risk_level": "L1/L2/L3/L4",
    "red_flags": [...],
    "urgency_level": "..."
  }
}
```

## 三、通道2：语言与策略通道

### 3.1 通道定位

**职责**：决定"怎么说、怎么问" - 医生表达

**核心任务**：
- 问诊对话生成（问什么、怎么问）
- 解释与沟通（把结构化结果讲成人话）
- 生成处置方案草案（在受控证据基础上）
- 自然语言生成（NLG）

**输出**：自然语言问诊、解释、建议

### 3.2 主要工具

**通道2工具**：

| 工具ID | 工具名称 | 主要职责 | 技术实现 |
|--------|---------|---------|---------|
| tool_2 | 主动问诊工具 | 信息缺口识别、问诊生成 | 信息缺口识别、智能追问生成、自然语言生成 |
| tool_7 | 证据链工具 | 证据链构建、解释生成 | 证据链格式化、推理路径可视化、自然语言解释生成 |
| tool_5 | 治疗建议工具 | 治疗方案推理、药物推荐 | 治疗方案的自然语言表达 |

### 3.3 技术实现

**自然语言理解（NLU）**：
- **用户输入理解**：理解用户的自然语言输入
- **意图识别**：识别用户的意图（问诊、咨询、上传报告等）
- **实体抽取**：从用户输入中抽取医学实体（症状、体征、疾病等）

**自然语言生成（NLG）**：
- **问诊问题生成**：基于信息缺口生成问诊问题
- **解释生成**：将结构化结果转换为自然语言解释
- **方案生成**：生成治疗方案的自然语言表达

**对话管理**：
- **对话上下文管理**：维护对话历史和上下文
- **信息缺口识别**：识别缺失的关键信息
- **智能追问**：基于DDx和证据链生成智能追问

**解释生成**：
- **证据链格式化**：将结构化的证据链格式化为可读的文本
- **推理路径可视化**：将推理路径可视化为自然语言描述
- **自然语言解释**：生成完整的自然语言解释

### 3.4 输出格式

**自然语言输出**：

```json
{
  "next_question": "您是否有发热？",
  "question_reason": "需要确认是否有发热症状，以区分感染性疾病和非感染性疾病",
  "explanation_text": "根据您的主诉和症状，我考虑可能是...",
  "treatment_plan_text": "建议您...",
  "evidence_summary": "支持诊断的证据包括..."
}
```

## 四、双通道协作机制

### 4.1 协作流程

```
通道1工具（结构化推理）
    ↓
生成结构化结果（DDx、检查建议等）
    ↓
写入CDP（结构化数据）
    ↓
主Agent读取CDP
    ↓
通道2工具（语言与策略）
    ↓
读取CDP
    ↓
生成自然语言表达
    ↓
输出给用户
```

### 4.2 关键原则

**通道1决定"该往哪想"**：
- 结构化推理工具负责临床逻辑推理
- 生成结构化的诊断、检查、治疗建议
- 确保推理的准确性和可解释性

**通道2决定"怎么说"**：
- 语言与策略工具负责将结构化结果转换为自然语言
- 生成问诊问题、解释说明
- 确保用户体验和沟通效果

**CDP作为桥梁**：
- 通道1的输出写入CDP
- 通道2基于CDP生成自然语言表达
- CDP是唯一的事实源，确保两个通道的一致性

**主Agent统一决策**：
- 主Agent统一管理两个通道的工具调用
- 确保推理过程可追溯、可审计
- 协调两个通道的工作，避免冲突

### 4.3 协作示例

**示例1：诊断流程**

```
1. 通道1（tool_1）：病例理解
   - 输入：用户自然语言输入
   - 输出：结构化的患者状态（症状、体征等）
   - 写入CDP：cdp.patient_state

2. 通道1（tool_3）：鉴别诊断
   - 输入：cdp.patient_state
   - 输出：DDx列表（tier1/tier2/tier3）
   - 写入CDP：cdp.ddx

3. 通道2（tool_2）：主动问诊
   - 输入：cdp.ddx、cdp.uncertainty.missing_critical_info
   - 输出：问诊问题（自然语言）
   - 输出给用户："您是否有发热？"

4. 用户回答："有发热，38.5度"

5. 通道1（tool_1）：病例理解
   - 输入：用户回答
   - 输出：更新cdp.patient_state（添加发热症状）

6. 通道1（tool_3）：鉴别诊断
   - 输入：更新后的cdp.patient_state
   - 输出：更新后的DDx列表
   - 写入CDP：cdp.ddx

7. 通道2（tool_7）：证据链工具
   - 输入：cdp.ddx、cdp.evidence_graph
   - 输出：解释文本（自然语言）
   - 输出给用户："根据您的主诉和症状，我考虑可能是..."
```

**示例2：检查建议流程**

```
1. 通道1（tool_4）：检查建议
   - 输入：cdp.ddx、cdp.triage
   - 输出：检查计划（结构化）
   - 写入CDP：cdp.workup_plan

2. 通道2（tool_7）：证据链工具
   - 输入：cdp.workup_plan
   - 输出：检查建议的自然语言表达
   - 输出给用户："建议您进行血常规检查，以排除感染性疾病..."
```

## 五、技术实现细节

### 5.1 通道1技术栈

**知识图谱**：
- **Neo4j**：存储医学知识图谱
- **Cypher查询**：检索推理路径
- **路径分析**：分析路径结构特征

**概念标准化**：
- **UMLS**：统一医学语言系统
- **CUI映射**：医学概念到CUI的映射
- **ICD/SNOMED编码**：疾病和症状的标准化编码

**推理引擎**：
- **规则引擎**：基于医学规则的推理
- **概率引擎**：基于概率模型的推理
- **贝叶斯引擎**：基于贝叶斯网络的推理
- **评分量表**：基于评分量表的推理

**DR.KNOWS方法**：
- **路径检索**：多跳推理路径检索（2-4跳）
- **路径验证**：验证路径是否指向知识库候选
- **路径约束推理**：在路径约束下使用LLM进行推理

### 5.2 通道2技术栈

**自然语言处理**：
- **LLM（大语言模型）**：用于自然语言生成和理解
- **NLU（自然语言理解）**：理解用户输入
- **NLG（自然语言生成）**：生成自然语言输出

**对话管理**：
- **对话上下文管理**：维护对话历史和上下文
- **信息缺口识别**：识别缺失的关键信息
- **智能追问生成**：基于DDx和证据链生成智能追问

**解释生成**：
- **证据链格式化**：将结构化的证据链格式化为可读的文本
- **推理路径可视化**：将推理路径可视化为自然语言描述
- **自然语言解释**：生成完整的自然语言解释
