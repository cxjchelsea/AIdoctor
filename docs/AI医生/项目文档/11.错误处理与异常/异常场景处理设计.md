# AI医生系统 - 异常场景处理设计

> **文档定位**：本文档详细说明AI医生系统在异常场景下的处理方案，包括工具连续失败、预算耗尽、证据严重不足、诊断候选集为空、系统资源耗尽等异常场景的处理策略。

> - [错误处理规范](./错误处理规范.md)：请参考《错误处理规范》了解错误处理的具体规范

## 一、异常场景概述

### 1.1 异常场景分类

**异常场景类型**：
- **工具连续失败场景**：多个工具连续失败，系统无法继续执行
- **预算耗尽场景**：AgentState中的budget耗尽（max_tool_calls、max_time_seconds、max_cost）
- **证据严重不足场景**：证据数量严重不足（evidence_count < 2），且无法通过工具补充
- **诊断候选集为空场景**：tool_3（鉴别诊断工具）返回的候选集为空
- **系统资源耗尽场景**：系统资源耗尽（内存、CPU、磁盘等）

### 1.2 异常场景处理原则

**核心原则**：
1. **安全第一**：宁可误报，不能漏报，确保患者安全
2. **优雅降级**：系统在异常时能够优雅降级，不崩溃
3. **数据保护**：异常场景下保护关键数据（CDP、AgentState、AuditTrail）
4. **用户友好**：异常提示对用户友好，明确指导用户下一步操作

## 二、工具连续失败场景

### 2.1 场景描述

**场景**：多个工具连续失败，系统无法继续执行

**触发条件**：
- 检查 tried_tools 中的失败记录
- 如果关键工具连续失败3次以上，标记为"系统不可用"

### 2.2 处理策略

**处理流程**：

```
1. 检测工具连续失败
   - 检查 tried_tools 中的失败记录
   - 如果关键工具连续失败3次以上，标记为"系统不可用"

2. 系统不可用处理
   - 触发升级策略：建议用户咨询专业医生
   - 记录系统不可用状态
   - 通知运维团队

3. 数据保护
   - 保存当前CDP状态到数据库
   - 保存AgentState状态
   - 保存AuditTrail记录

4. 用户通知
   - 通知用户系统暂时不可用
   - 建议用户稍后重试或咨询专业医生

5. 记录到AuditTrail
   - 记录系统不可用
   - 记录工具连续失败情况
```

### 2.3 关键工具定义

**关键工具**：
- **tool_0（健康状态判定）**：判断是否需要进入诊疗流程
- **tool_3（鉴别诊断）**：生成诊断候选集
- **tool_6（风险评估）**：识别高危情况

**非关键工具**：
- **tool_2（主动问诊）**：可以跳过，使用已有信息
- **tool_5（治疗建议）**：可以跳过，只提供诊断
- **tool_7（证据链）**：可以跳过，不影响核心诊断

## 三、预算耗尽场景

### 3.1 场景描述

**场景**：AgentState中的budget耗尽（max_tool_calls、max_time_seconds、max_cost）

**触发条件**：
- 检查 current_tool_calls >= max_tool_calls
- 检查 current_time_seconds >= max_time_seconds
- 检查 current_cost >= max_cost

### 3.2 处理策略

**处理流程**：

```
1. 检测预算耗尽
   - 检查 current_tool_calls >= max_tool_calls
   - 检查 current_time_seconds >= max_time_seconds
   - 检查 current_cost >= max_cost

2. 预算耗尽处理
   - 如果预算耗尽：停止运行循环，触发升级或拒答
   - 记录预算耗尽原因
   - 保存当前CDP状态

3. 用户通知
   - 通知用户诊断过程耗时较长，建议咨询专业医生
   - 提供当前诊断结果（如有）

4. 记录到AuditTrail
   - 记录预算耗尽
   - 记录预算使用情况

5. 优化建议
   - 分析预算耗尽原因
   - 提供优化建议（增加预算、优化算法等）
```

### 3.3 预算类型

**预算类型**：
- **max_tool_calls**：最大工具调用次数（默认：20次）
- **max_time_seconds**：最大执行时间（默认：300秒）
- **max_cost**：最大成本（默认：根据LLM调用成本计算）

**预算调整策略**：
- 根据诊断复杂度动态调整预算
- 高危情况增加预算
- 简单情况减少预算

## 四、证据严重不足场景

### 4.1 场景描述

**场景**：证据数量严重不足（evidence_count < 2），且无法通过工具补充

**触发条件**：
- 检查 evidence_count < 2
- 检查是否已尝试所有相关工具
- 检查工具是否连续失败

### 4.2 处理策略

**处理流程**：

```
1. 检测证据严重不足
   - 检查 evidence_count < 2
   - 检查是否已尝试所有相关工具
   - 检查工具是否连续失败

2. 证据严重不足处理
   - 如果证据严重不足且无法补充：触发拒答策略
   - 记录证据不足原因
   - 保存当前CDP状态

3. 用户通知
   - 通知用户证据不足，无法完成诊断
   - 建议用户提供更多信息或咨询专业医生

4. 记录到AuditTrail
   - 记录证据严重不足
   - 记录证据不足原因

5. 优化建议
   - 分析证据不足原因
   - 提供优化建议（改进问诊策略、扩展知识库等）
```

### 4.3 证据补充策略

**证据补充策略**：
1. **主动问诊**：调用tool_2（主动问诊工具）获取更多信息
2. **检查建议**：调用tool_4（检查建议工具）建议进行相关检查
3. **扩展检索**：放宽检索条件，扩大候选范围

**如果证据补充失败**：
- 触发拒答策略
- 建议用户咨询专业医生
- 提供当前已有信息

## 五、诊断候选集为空场景

### 5.1 场景描述

**场景**：tool_3（鉴别诊断工具）返回的候选集为空

**触发条件**：
- 检查 cdp.ddx.rank_list 是否为空
- 检查是否已尝试扩展检索

### 5.2 处理策略

**处理流程**：

```
1. 检测诊断候选集为空
   - 检查 cdp.ddx.rank_list 是否为空
   - 检查是否已尝试扩展检索

2. 诊断候选集为空处理
   - 如果候选集为空：触发扩展检索
   - 如果扩展检索仍为空：触发升级或拒答

3. 扩展检索策略
   - 调用 tool_3（鉴别诊断工具）- 扩展检索模式
   - 放宽检索条件（增加症状范围、减少路径长度限制等）

4. 如果扩展检索仍为空
   - 触发升级策略：建议用户咨询专业医生
   - 记录诊断候选集为空原因

5. 记录到AuditTrail
   - 记录诊断候选集为空
   - 记录扩展检索结果
```

### 5.3 扩展检索策略

**扩展检索条件**：
- **增加症状范围**：包含更多相关症状
- **减少路径长度限制**：允许更长的推理路径
- **放宽知识库匹配**：降低匹配阈值
- **使用补充候选**：使用DR.KNOWS路径补充候选

**如果扩展检索仍为空**：
- 触发升级策略
- 建议用户咨询专业医生
- 记录为"超出系统诊断范围"

## 六、系统资源耗尽场景

### 6.1 场景描述

**场景**：系统资源耗尽（内存、CPU、磁盘等）

**触发条件**：
- 检查内存使用率 > 90%
- 检查CPU使用率 > 90%
- 检查磁盘使用率 > 90%

### 6.2 处理策略

**处理流程**：

```
1. 检测系统资源耗尽
   - 检查内存使用率
   - 检查CPU使用率
   - 检查磁盘使用率

2. 系统资源耗尽处理
   - 触发资源清理：清理缓存、释放连接、终止非关键任务
   - 如果资源仍不足：触发升级或拒答

3. 数据保护
   - 保存当前CDP状态到数据库
   - 保存AgentState状态
   - 保存AuditTrail记录

4. 用户通知
   - 通知用户系统资源不足，建议稍后重试

5. 记录到AuditTrail
   - 记录系统资源耗尽
   - 记录资源使用情况

6. 通知运维
   - 通知运维团队系统资源耗尽
   - 记录资源使用情况
```

### 6.3 资源清理策略

**资源清理优先级**：
1. **清理缓存**：清理非关键缓存（路径缓存、Prompt缓存等）
2. **释放连接**：释放非关键数据库连接、HTTP连接
3. **终止非关键任务**：终止非关键的后台任务
4. **拒绝新请求**：如果资源仍不足，拒绝新的诊断请求

**如果资源清理失败**：
- 触发升级或拒答
- 通知运维团队
- 记录资源使用情况

## 七、异常场景处理总结

### 7.1 异常场景处理流程

**通用处理流程**：

```
异常场景检测
  ↓
异常场景分类
  ↓
  ├─→ 工具连续失败
  │     ↓
  │   触发升级策略
  │     ↓
  │   数据保护
  │     ↓
  │   用户通知
  │
  ├─→ 预算耗尽
  │     ↓
  │   停止运行循环
  │     ↓
  │   触发升级或拒答
  │     ↓
  │   用户通知
  │
  ├─→ 证据严重不足
  │     ↓
  │   触发拒答策略
  │     ↓
  │   用户通知
  │
  ├─→ 诊断候选集为空
  │     ↓
  │   扩展检索
  │     ↓
  │   如果仍为空 → 触发升级或拒答
  │
  └─→ 系统资源耗尽
        ↓
      资源清理
        ↓
      如果仍不足 → 触发升级或拒答
```

### 7.2 异常场景处理原则

**处理原则**：
1. **安全第一**：所有异常场景都遵循"安全第一"原则
2. **数据保护**：异常场景下保护关键数据
3. **用户友好**：异常提示对用户友好，明确指导用户下一步操作
4. **可追溯**：所有异常场景都记录到AuditTrail

### 7.3 异常场景升级策略

**升级策略**：
- **升级到人工**：建议用户咨询专业医生
- **拒答策略**：明确说明无法完成诊断，建议咨询专业医生
- **部分结果**：如果已有部分结果，提供部分结果并说明局限性
