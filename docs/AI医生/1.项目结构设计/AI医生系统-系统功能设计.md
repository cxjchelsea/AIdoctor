# AI医生系统 - 系统功能设计

> **文档定位**：本文档是AI医生系统的**系统功能设计**，专注于业务功能、临床流程、能力模块等业务层面的设计。  
> **技术实现**：请参考《AI医生系统-技术架构设计.md》  
> **核心目标**：构建一个能够代替真人医生的AI医生系统，具备完整的医学推理能力、主动交互能力、可解释性和安全性。  
> **参考论文**：Leveraging Medical Knowledge Graphs Into Large Language Models for Diagnosis Prediction (JMIR AI 2025)

## 📖 术语表（Glossary）

> **说明**：本文档中使用的关键术语定义，便于快速理解核心概念。

| 术语 | 英文 | 定义 | 首次出现章节 |
|------|------|------|------------|
| **CDP** | Clinical Decision Package | 临床决策包，系统内部一切推理的核心数据结构，包含患者状态、诊断列表、证据链等信息 | 1.3 |
| **DDx** | Differential Diagnosis | 鉴别诊断，指对同一症状或体征可能对应的多种疾病的诊断列表 | 2.3 |
| **工作态** | Work Mode | 系统的工作模式，包括健康管理态（wellness_mode）和临床诊疗态（clinical_mode） | 1.1 |
| **健康管理态** | Wellness Mode | 面向"没病或不确定健康状态"的人，负责风险管理与随访的工作态 | 1.1 |
| **临床诊疗态** | Clinical Mode | 面向"疑似/明确有病"的人，执行受控、可解释的临床推理与决策支持的工作态 | 1.1 |
| **脑区** | Brain Region | 将AI医生的能力拆解为8个"临床脑区"，每个脑区都可以单独训练、评测、替换 | 1.2 |
| **主诉** | Chief Complaint | 患者主要症状或不适的描述，是诊断的起点 | 2.0 |
| **红旗信号** | Red Flag | 危险信号，需要立即就医的高危症状或体征 | 2.0.1 |
| **证据链** | Evidence Chain | 支持诊断结论的完整证据序列，包括支持证据、反对证据、缺失证据 | 2.7 |
| **三层分层** | Three-Layer Classification | 将鉴别诊断分为三层：首要假设、主要备选诊断、必须排除的高危诊断 | 2.3 |
| **推理子组** | Reasoning Subgroup | 将候选诊断按系统分类、病理生理机制等维度组织为推理子组 | 2.3.1 |
| **分流路径** | Triage Path | 基于关键差异点形成的可执行的分流路径，用于快速收缩诊断范围 | 2.3.2 |
| **验证计划** | Verification Plan | 针对"最可能方向"和"必须排除方向"制定的验证计划，回答查不查、查什么、用什么标准判定 | 2.4.1 |
| **终点结论包** | Conclusion Package | 诊断流程的最终输出，包含结论、必须排除项状态、关键依据、行动与随访四要素 | 3.5 |
| **回退机制** | Rollback Mechanism | 当出现证据冲突、症状演变或处理无效时，系统回退到之前的步骤重新处理 | 3.4.7 |
| **CUI** | Concept Unique Identifier | 概念唯一标识符，UMLS（统一医学语言系统）中的医学概念编码 | 2.1 |
| **ICD** | International Classification of Diseases | 国际疾病分类编码 | 2.1 |
| **SNOMED** | Systematized Nomenclature of Medicine | 系统化医学术语命名法 | 2.1 |
| **DR.KNOWS** | - | 基于知识图谱的医学诊断方法，通过多跳推理路径检索进行诊断 | 2.3 |

## 一、系统定位与核心理念

### 1.1 系统定位

> **医生面对的，从来不是"有没有病"的人群，而是"不知道自己有没有病"的人群。**

**AI医生系统**必须同时面向"有病的人"和"没病的人"，否则它就不配叫医生，只能叫"诊断工具"。

**核心定位**：
- **不是假设用户是病人**，而是从"健康状态不确定"的人出发
- **先判断是否需要进入医学诊疗流程**
- **对未进入诊疗流程的人**，负责风险管理与随访
- **对进入诊疗流程的人**，执行受控、可解释的临床推理与决策支持

**两种工作态**：

#### 🟢 工作态一：健康管理态（Wellness / Monitoring Mode）

- **面向**：没病 or 不确定健康状态的人
- **核心任务**：
  - 判断是否需要升级到临床诊疗态
  - 管理风险与趋势（早期风险识别）
  - 主动问询与随访
  - 健康建议与生活方式指导
- **允许**：
  - 不下诊断
  - 只给观察建议
  - 提供安抚与解释

#### 🔴 工作态二：临床诊疗态（Clinical Reasoning Mode）

- **面向**：疑似/明确有病的人
- **核心任务**：
  - 鉴别诊断（DDx）
  - 检查/处置建议
  - 推理与证据链
- **使用**：
  - DR.KNOWS方法
  - 知识图谱路径推理
  - 强结构化推理

> **这不是两个系统，而是一个系统的两个"工作态"。**

### 1.2 核心设计原则

> **"医生的第一职责不是'下诊断'，而是'判断要不要下诊断'"**

系统设计遵循医生的工作流程，将AI医生的能力拆解为8个"临床脑区"，每个脑区都可以单独训练、评测、替换：

0. **健康状态判定**（Health State Assessment）- **新增，关键分叉点**
1. **病例理解与结构化**（Clinical Parsing）
2. **主动问诊与信息补全**（Interview / Gap-Filling）
3. **鉴别诊断引擎**（Differential Diagnosis, DDx）
4. **检查/检验建议与价值评估**（Workup Planner）
5. **治疗/处置建议引擎**（Management Planner）
6. **风险与急症识别**（Triage / Safety Brain）
7. **可解释性与证据链**（Evidence & Rationale）

### 1.3 核心数据结构：Clinical Decision Package (CDP)

## 二、八大临床脑区功能设计

### 2.0 脑区0：健康状态判定（Health State Assessment）- **关键分叉点**

> **对应技术架构文档**：4.0 智能体0：健康状态判定智能体 + 1.3 health-state-assessment-service  
> **技术实现详情**：请参考《AI医生系统-技术架构设计.md》第4.0节和第1.3节

**职责**：判断"这个人，现在需要被当成'病人'对待吗？"

> **这是医生的第一职责，发生在"诊断之前"**

**输入**：
- 用户描述的症状/不适（初始主诉）
- 基本信息（年龄、性别等）
- 健康档案（如有）

**输出**：健康状态判定
- 是否需要进入诊疗流程（`needs_clinical_mode`：true/false）
- 工作态选择（`work_mode`：wellness_mode / clinical_mode）
- 风险等级（L1/L2/L3/L4）
- 判定依据（`assessment_reason`）

#### 2.0.1 AI诊断入口判定流程（P0模块）

**流程概述**：入口判定模块通过五个步骤完成用户意图识别、症状识别、方向澄清、危险信号检查和路径输出。

**Step 1｜接收用户输入**

**功能**：接收用户自然语言描述本次来访目的

**输入**：用户自然语言输入（文本/语音）

**处理**：
- 支持自然语言理解（NLU）
- 允许混合诉求（既想体检又有轻微不适）
- 不依赖选择题入口

**输出**：结构化的用户意图表达

**需求清单**：
- **输入接收能力**：
  - 支持用户用自然语言描述需求（不依赖选择题入口）
  - 允许用户输入"混合诉求"（既想体检又有轻微不适）

**Step 2｜识别用户是否"有症状/困扰"**

**功能**：系统对用户输入做一次判断，识别用户是否有症状/困扰

**判断结果**：

**情况 A：明确无症状**
- 用户表达的是"健康管理/体检规划/筛查/预防"
- 且没有任何不适描述
- **处理**：进入 Step 4（危险信号兜底）后，准备进入健康筛查路径（A）

**情况 B：存在症状/困扰**
- 用户描述任何身体不适、异常感觉、功能变化、心理困扰等（不论轻重）
- **处理**：进入 Step 4（危险信号兜底）后，准备进入症状诊断路径（B）

**情况 C：不确定/模糊/混合诉求**
- 用户说不清是否算不适
- 或同时说"想体检 + 有点不舒服"
- **处理**：进入 Step 3 做一次方向澄清

**需求清单**：
- **症状/困扰识别规则**：
  - 能识别"症状/不适/困扰/异常感觉/功能变化"等表达
  - 轻微问题也算"有困扰"，不要求严重程度
  - 能识别"明确无症状"的表达（纯筛查/纯体检规划）

**Step 3｜方向澄清（仅对"情况C"触发一次）**

**功能**：通过最小澄清确认用户当前的主要目标

**触发条件**：仅当 Step 2 判断为"情况C"时触发

**澄清目标**：确认用户主要目标是：
- **A**：健康筛查/体检规划
- **B**：症状咨询/问题排查

**处理原则**：
- 澄清后不得反复追问，避免入口卡顿
- 澄清结果只能落到两类：进入 A 或进入 B

**处理流程**：
- 生成最小澄清问题（仅一次）
- 根据用户回答确定方向（A 或 B）
- 澄清完成后，继续进入 Step 4

**需求清单**：
- **方向澄清机制（仅一次）**：
  - 当用户表达模糊或混合诉求时，触发一次澄清
  - 澄清结果只能落到两类：进入 A 或进入 B
  - 澄清后不得反复追问，避免入口卡顿

**Step 4｜危险信号检查（安全兜底，所有用户都要过一次）**

**功能**：无论用户走 A 还是 B，都必须判断是否存在危险信号

**检查逻辑**：
- **如果命中危险信号**：
  - 不进入线上流程
  - 输出"优先线下就医/急诊"的安全提示（结束）

- **如果未命中危险信号**：
  - 进入 Step 5 输出选路结果

**危险信号库**：维护一份危险信号清单（红旗库）

**检查原则**：
- 入口判定阶段只做"是否命中"，不做解释诊断
- 命中后输出固定的安全提示并结束线上流程

**需求清单**：
- **危险信号检查机制**：
  - 维护一份危险信号清单（红旗库）
  - 入口判定阶段只做"是否命中"，不做解释诊断
  - 命中后输出固定的安全提示并结束线上流程

**Step 5｜输出路径结果并跳转**

**功能**：根据前面的判断结果，输出明确的路径选择并跳转

**输出规则**：
- **无症状 + 无危险信号** → 进入健康筛查路径（A）
- **有症状/困扰 + 无危险信号** → 进入症状诊断路径（B）
- **危险信号命中** → 退出线上流程（安全提示）

**跳转规则**：
- 跳转到对应路径的第一个步骤
- **A路径**：进入健康筛查流程的起点（A1｜需求分类）
- **B路径**：进入症状诊断流程的起点（阶段1｜问诊）

**需求清单**：
- **选路输出与跳转规则**：
  - 输出必须明确：进入 A / 进入 B / 退出线上流程
  - 跳转到对应路径的第一个步骤
  - A：进入健康筛查流程的起点
  - B：进入症状诊断流程的起点

#### 2.0.2 路径切换支持（防止误入）

**功能**：允许用户在路径中切换，防止误入错误路径

**切换规则**：

**A路径 → B路径切换**：
- **触发条件**：若用户在 A 路径中后续出现症状描述
- **处理**：应允许切换到 B（症状诊断路径）

**B路径 → A路径切换**：
- **触发条件**：若用户在 B 路径中明确只是想筛查
- **处理**：应允许切换到 A（健康筛查路径）

**需求清单**：
- **路径切换支持（防止误入）**：
  - 若用户在 A 路径中后续出现症状描述，应允许切换到 B
  - 若用户在 B 路径中明确只是想筛查，应允许切换到 A

**关键原则**：
- **宁可误报，不能漏报**：不确定时优先进入临床诊疗态
- **及时升级**：健康管理态中发现风险信号，立即升级到临床诊疗态

**输入**：
- 当前CDP（特别是 `ddx` 和 `uncertainty.missing_critical_info`）
- 对话历史

**输出**：问诊计划
- 下一问是什么
- 为什么问这个问题（基于临床决策分析）

**核心功能**：
1. **信息缺口识别**：识别缺失的关键信息

4. **自然语言生成**：生成像医生一样的追问问题

**问诊原则**：
- **临床决策价值优先**：优先问能排除高危诊断或区分多个DDx的问题

- **关键信息优先**：优先问对诊断至关重要的信息
- **患者体验**：避免重复提问，避免过于技术化的问题

**2.2.0 临床决策分析驱动的问诊（基于临床决策理论）**

**医疗理论依据**：临床决策分析（Clinical Decision Analysis, CDA）

**核心思想**：
问诊不仅是信息收集，更是临床决策过程。每个问题都应该能够：
1. 改变诊断概率（信息增益）
2. 影响临床决策（风险识别）
3. 考虑成本效益（患者负担）

**临床决策增益计算**：

```python
# 扩展的信息增益计算（基于临床决策理论）
IG_clinical(q|DDx, E) = IG_information(q|DDx, E) 
                      + α · IG_risk(q|DDx, E)
                      + β · IG_cost(q|DDx, E)

其中：
1. IG_information: 信息论的信息增益（原有）
   - 计算方式：IG_information = H(DDx|E) - E[H(DDx|E ∪ {answer})]
   - 衡量：问题能减少多少诊断不确定性

2. IG_risk: 风险相关的信息增益
   - 计算方式：IG_risk = Σ_{d ∈ DDx_high_risk} P(d) · I(q can exclude d)
   - 衡量：问题能排除多少高危诊断
   - 医疗依据：漏诊代价远大于误报代价（λ_FN >> λ_FP）
   - 例如：胸痛时优先问"是否伴出汗"（排除心梗）

3. IG_cost: 成本效益相关的信息增益
   - 计算方式：IG_cost = IG_information / Cost(q)
   - 衡量：问题的成本效益比
   - 考虑：时间成本、患者负担、心理成本
   - 医疗依据：临床决策分析中的"期望效用理论"

权重设置（基于医疗理论）：
- α = 0.5（风险权重较高，因为漏诊代价极大）
- β = 0.2（成本权重较低，但需要考虑患者体验）
- 信息增益权重 = 0.3（基础权重）
```

**医疗理论依据**：
- **临床决策分析**：考虑诊断的敏感性、特异性、预测值
- **期望效用理论**：考虑误诊的代价（漏诊代价 >> 误报代价）
- **诊断决策阈值理论**：优先排除高危诊断（治疗阈值以上的诊断）

**最优问诊策略**：
在临床决策理论下，最优问诊策略是：
```
q* = argmax_{q} [IG_clinical(q|DDx, E)]
```

**理论保证**：
- 优先问能排除高危诊断的问题（风险优先）
- 优先问信息增益高的问题（效率优先）
- 考虑问题的成本效益（患者体验优先）

**输出到CDP**：
- 更新 `uncertainty.missing_critical_info`
- 生成问诊计划（临时字段，不持久化）

### 2.3 脑区C：鉴别诊断引擎（Differential Diagnosis, DDx）

**职责**：生成Top-K鉴别诊断列表，每个诊断包含支持证据、反证、缺失证据

**核心功能**：

**2.3.1 推理子组组织（基于诊断树理论）**

**职责**：将候选方向按最有效的维度组织为推理子组，把清单变成结构

**医疗理论依据**：
1. **诊断树理论**（Diagnostic Tree Theory）- 诊断学中的系统化诊断方法
2. **解剖学分类**（Anatomical Classification）- 基于解剖学/生理学系统的分类
3. **病理生理机制**（Pathophysiological Mechanism）- 基于疾病机制的诊断
4. **时间特征诊断**（Temporal Pattern Diagnosis）- 基于起病方式和病程的诊断

**核心思想**：
将候选诊断组织为树状结构，符合临床医生的思维模式：
- **根节点**：主诉/主要症状（Chief Complaint）
- **第一层**：系统分类（基于解剖学/生理学）- 决定"哪个系统的问题"
- **第二层**：病理生理机制 - 决定"什么类型的疾病"
- **第三层**：具体疾病 - 决定"具体是什么病"
- **叶节点**：最终诊断（Final Diagnosis）

**医疗理论优势**：
- **符合临床思维**：临床医生通常先确定系统，再确定机制，最后确定具体疾病
- **提高诊断效率**：一条关键问题能推动整个系统方向前移或后移
- **减少诊断遗漏**：系统化组织确保不遗漏重要诊断方向
- **支持分层问诊**：按照诊断树的层级进行问诊，逐步缩小诊断范围

**组织维度**（按诊断学优先级）：

1. **系统分类**（第一优先级）- 基于解剖学/生理学系统
   - **分类**：心血管系统、呼吸系统、消化系统、神经系统、代谢系统、心理系统、血液系统、泌尿系统、内分泌系统、免疫系统等
   - **医疗理论依据**：
     - 解剖学分类是诊断的基础（Anatomical Basis of Diagnosis）
     - 符合临床医生的思维习惯（Clinical Thinking Pattern）
     - 系统性疾病通常有特定的症状模式（System-Specific Symptom Patterns）
   - **优势**：
     - 一条关键问题能推动整个系统方向前移或后移
     - 例如："胸痛" → 心血管系统 vs 呼吸系统 vs 消化系统
   - **诊断学依据**：Harrison's Principles of Internal Medicine中的系统分类方法

2. **病理生理机制**（第二优先级）- 基于疾病机制
   - **分类**：炎症性、感染性、肿瘤性、代谢性、免疫性、遗传性、退行性、创伤性、中毒性等
   - **医疗理论依据**：
     - 理解疾病机制有助于诊断和治疗（Mechanism-Based Diagnosis）
     - 机制相同或相似的疾病有相似的临床表现（Mechanism-Clinical Correlation）
     - 病理生理机制决定疾病的自然病程（Natural History of Disease）
   - **优势**：
     - 机制相同或相似的疾病可以一起考虑
     - 例如：缺血性心脏病（心梗、心绞痛）vs 炎症性心脏病（心肌炎）
   - **诊断学依据**：Robbins and Cotran Pathologic Basis of Disease中的机制分类

3. **起病方式与病程**（第三优先级）- 基于时间特征
   - **分类**：
     - 急性（<1周）、亚急性（1-4周）、慢性（>4周）
     - 持续/间歇、进行性/缓解性、复发性
   - **医疗理论依据**：
     - 时间特征是重要的诊断线索（Temporal Pattern as Diagnostic Clue）
     - 不同疾病有不同的起病方式和病程（Disease-Specific Temporal Patterns）
     - 时间特征能帮助区分相似疾病（Differential Diagnosis by Temporal Pattern）
   - **优势**：
     - 时间特征能快速区分疾病类型
     - 例如：急性胸痛（心梗）vs 慢性胸痛（心绞痛）
   - **诊断学依据**：临床诊断学中的时间特征诊断方法

4. **严重程度与风险**（贯穿所有层级）- 基于临床严重性
   - **分类**：高危（必须立即排除）、中危、低危
   - **医疗理论依据**：
     - 风险分层是临床决策的核心（Risk Stratification in Clinical Decision Making）
     - 漏诊高危疾病的代价极大（High Cost of Missing High-Risk Diseases）
     - 风险优先原则（Risk-First Principle）：优先排除高危诊断
   - **优势**：
     - 优先处理高危诊断，避免漏诊
     - 例如：胸痛时优先排除心梗（高危），再考虑心绞痛（中危）
   - **诊断学依据**：急诊医学中的分诊理论（Triage Theory）

**诊断树结构**（基于诊断树理论）：

**医疗理论依据**：
- **诊断树理论**：将诊断过程组织为树状结构，符合临床医生的系统化思维
- **分层诊断**：按照系统→机制→疾病的层次进行诊断，逐步缩小诊断范围
- **关键差异点**：每个系统/机制层级都有关键差异点，用于区分不同方向

**结构说明**：
- **根节点**：主诉/主要症状（Chief Complaint）- 诊断的起点

- **关键差异点**：每个层级的关键问题，用于区分不同方向

**2.3.2 分流路径设计**

**职责**：提炼关键差异点，形成可执行的分流路径，确保后续收缩不是"随便问"，而是沿着明确的逻辑分叉推进

**核心功能**：
1. **提炼关键差异点**：
   - 为每对子组或每个关键方向提炼"能最快区分"的差异点
   - 例如：是否突发、是否静息也出现、是否进行性加重

2. **明确"必须优先处理"的路径**（高危先行）：
   - 对必须排除的高危方向建立优先路径
   - 一旦命中高危差异点或高危线索，直接进入升级/验证动作
   - 避免在高危尚未控制时继续在低危方向上细问

3. **形成分流路径清单**：
   - 第一层分叉问题（用于快速分流子组）
   - 命中高危时的处理指引（进入验证/升级的入口条件）
   - 未命中高危时的继续收缩方向（进入下一步证据采集）

### 2.4 脑区D：检查/检验建议与价值评估（Workup Planner）

> **对应技术架构文档**：4.4 智能体4：检查建议智能体 + 3.4 检查建议引擎  
> **技术实现详情**：请参考《AI医生系统-技术架构设计.md》第4.4节和第3.4节

**职责**：基于当前DDx和已有证据，建议下一步检查，并评估检查的价值

**输入**：
- 当前CDP的 `ddx`
- 已有证据（`patient_state`）
- 风险等级（`triage`）

**输出**：检查建议
- 检查名称
- 检查目的（能确认/排除哪些DDx）
- 优先级（紧急/重要/可选）
- 预期信息增益（能区分哪些DDx）

**核心功能**：
1. **检查必要性评估**：判断是否需要进一步检查
2. **检查价值评估**：评估检查能提供多少信息增益
3. **检查优先级排序**：根据紧急程度和信息增益排序
4. **检查目的明确化**：明确每个检查能确认/排除哪些DDx

**避免"无脑开单"**：
- 必须评估检查的价值
- 优先推荐信息增益高的检查
- 避免重复检查
- 考虑检查的成本和风险

**2.4.1 验证计划制定**

**职责**：针对"最可能方向"和"必须排除方向"制定验证计划，回答三个问题：查不查、查什么、用什么标准判定

**验证计划结构**：
```json
{
  "verification_purpose": "确认/排除/升级判定",
  "verification_action": {
    "type": "补问/观察/测量/检查或就医",
    "content": "具体动作",
    "priority": "优先级"
  },
  "judgment_standard": {
    "if_support": "什么结果支持该方向",
    "if_not_support": "什么结果不支持该方向",
    "if_uncertain": "什么结果需要进一步验证"
  },
  "result_backfill_rule": {
    "if_support": "如何更新三层排序（上移/巩固）",
    "if_not_support": "如何更新三层排序（下移/排除）",
    "if_uncertain": "如何更新三层排序（保留/标记需线下排除）"
  }
}
```

**核心原则**：
- **验证计划必须能改变排序或触发升级处理**，避免"做了也不改变决策"的无效验证
- 针对"最可能方向"：验证计划用于确认诊断
- 针对"必须排除方向"：验证计划用于排除高危诊断

**验证计划类型**：
1. **补问验证**：通过追问关键问题验证
   - 例如："疼痛是否持续不缓解？"用于验证心梗
2. **观察验证**：通过观察体征验证
   - 例如：观察生命体征是否异常
3. **测量验证**：通过设备测量验证
   - 例如：测量血压、心率、体温
4. **检查验证**：通过医学检查验证
   - 例如：心电图、心肌酶等
5. **就医验证**：需要线下就医才能验证
   - 例如：需要专业医生检查才能排除

**输出到CDP**：
- 更新 `workup_plan` 字段（包含验证计划）

### 3.2 健康管理态详细流程

#### 3.2.1 健康人筛查流程（A路径）概述

**目标**：面向无症状的健康人群，提供健康筛查、体检规划、健康管理等服务

**流程结构**：
```
A1｜需求分类 → A2｜通用最小健康档案 → A3｜进入对应分支执行 → A4｜统一结果页输出 → A5｜随访闭环
```

**核心原则**：
- 用户无症状或不确定健康状态
- 采集最低必要信息（缺失不阻塞）
- 按需求类型进入固定分支
- 所有分支收敛为统一结果展示结构

#### 3.2.2 A1｜需求分类

**目标**：把用户需求归入三类之一，后续严格对齐分支流程

**需求类型**：
1. **筛查建议**：用户无症状，只想知道"应该做哪些筛查/多久一次"
2. **健康目标管理**：用户无症状，但希望改善健康状态（减脂/睡眠/运动/精力）
3. **计划性健康需求**：用户无症状，但有明确场景任务（备孕/疫苗/差旅/材料等）

**处理流程**：
1. 三选一归类需求
2. 输出需求类型（1/2/3）

**需求清单**：
- **四类需求选项文案**
- **用户常见表达归类示例**
- **不确定时的引导话术**

#### 3.2.3 A2｜通用最小健康档案

**目标**：采集最低必要信息，为后续建议提供依据（缺失不阻塞）

**处理流程**：
1. 采集最小健康档案字段
2. 输出健康档案卡 + 可选补充的缺失字段清单

**健康档案字段**：
- 基本信息：年龄、性别、身高、体重
- 既往史：疾病史、手术史、过敏史
- 家族史：遗传疾病史
- 生活习惯：吸烟、饮酒、运动、饮食
- 用药史：当前用药、既往用药

**需求清单**：
- **健康档案采集字段清单**
- **低信息模式兜底话术**（缺失不阻塞仍能输出）
- **缺失字段提示与补充策略**（可选）

#### 3.2.4 A3｜进入对应分支执行

**目标**：按需求类型进入固定分支，输出该分支的标准结果

##### A3-1｜筛查建议分支（对应需求1）

**目标**：用户无症状，只想知道"应该做哪些筛查/多久一次"

**处理流程**：
1. **补充追问**（仅问会影响筛查决策的关键信息）
   - 年龄、性别、既往史、家族史等关键信息
   - 避免过度追问

2. **规则化生成两张清单**：
   - **推荐做的筛查清单**：
     - 按年龄段、性别、风险因素推荐筛查项目
     - 包含筛查频率和时机
   - **不建议做的筛查清单**：
     - 反过度筛查理由
     - 替代建议

3. **输出分支结果**：
   - 推荐筛查清单 + 频率/时机
   - 不建议筛查清单 + 理由
   - 下次更新时间点
   - 随访节奏

**需求清单**：
- **额外追问清单**（仅筛查决策关键项）
- **输出数量与排序规则**（推荐/不推荐各输出多少条）
- **条件触发筛查规则库**（什么条件→建议哪些筛查→大致频率/时机）
- **不推荐筛查清单**（反过度筛查理由与替代建议）
- **强烈要求检查时的标准回应话术**

##### A3-2｜健康目标管理分支（对应需求2）

**目标**：用户无症状，但希望改善健康状态（减脂/睡眠/运动/精力）

**处理流程**：
1. **固定追问**（目标/现状/资源/周期）
   - 目标：想要改善的具体目标（减脂/睡眠/运动/精力等）
   - 现状：当前状态和基线数据
   - 资源：可用的时间、精力、经济资源
   - 周期：期望的改善周期

2. **生成可执行行动计划**：
   - 行动计划：具体的行动步骤
   - 追踪指标：2-3个关键指标（如体重、睡眠时长）
   - 复盘节点：定期回顾和调整时间点

3. **输出分支结果**：
   - 行动计划 + 追踪指标 + 复盘节点
   - 随访节奏

**需求清单**：
- **固定追问清单**（目标/现状/资源/周期）
- **目标计划模板库**（按目标类型复用）
- **追踪指标建议库**（2–3个即可）
- **失败兜底调整话术**

##### A3-4｜计划性健康需求分支（对应需求4）

**目标**：用户无症状，但有明确场景任务（备孕/疫苗/差旅/材料等）

**处理流程**：
1. **追问场景必要信息**（场景/时间点/禁忌信息）
   - 场景：具体的场景任务（备孕/疫苗/差旅/材料等）
   - 时间点：任务的时间节点
   - 禁忌信息：是否有禁忌症或特殊情况

2. **输出清单 + 时间表 + 注意事项**：
   - 检查清单：需要完成的检查项目
   - 时间表：检查的时间安排
   - 注意事项：需要特别注意的事项

3. **输出分支结果**：
   - 清单 + 时间表 + 注意事项
   - 随访节奏

**需求清单**：
- **固定追问清单**（场景/时间点/禁忌信息）
- **场景清单库**（清单+时间表+注意事项）
- **场景节点提醒规则**（什么时候提醒更新）

#### 3.2.5 A4｜统一结果页输出

**目标**：所有分支收敛为同一种结果展示结构

**结果展示结构**：
1. **一句话总结**：总结本次咨询的核心建议
2. **现在建议做的事（清单）**：明确建议用户执行的事项
3. **暂时不建议做的事（清单）**：明确不建议的事项及理由
4. **下一次复查/更新时间点**：明确的随访时间
5. **退出A路径条件提示**：出现不适/危险信号→线下评估

**需求清单**：
- **一句话总结模板**（按需求类型）
- **推荐/不推荐展示话术模板**
- **退出A路径提醒文案**（出现不适/危险信号→线下评估）

#### 3.2.6 A5｜随访闭环

**目标**：给出明确随访节奏，形成流程结束点与再次进入入口

**随访节奏规则**（按需求类型）：

1. **筛查建议**：周期性更新档案
   - 按筛查项目的时间间隔提醒用户更新
   - 定期回顾健康档案

   - 轻度异常：3-6个月复查
   - 中度异常：1-3个月复查或进一步评估
   - 重度异常：立即就医，完成后随访

3. **目标管理**：按复盘节点回访更新
   - 按行动计划中的复盘节点提醒用户
   - 评估进展并调整计划

4. **计划性需求**：按场景节点提醒更新/完成任务
   - 按时间表提醒用户完成检查
   - 任务完成后关闭提醒

**需求清单**：
- **随访节奏规则**（按需求类型）
- **随访提醒话术**（按节点提醒用户更新/复查/复盘）

### 3.3 临床诊疗态详细流程（AI循证诊断流程）

> **参考文档**：《智能诊断A路径：AI循证诊断流程.md》  
> **对应技术架构文档**：5.3 临床诊疗态协作流程 + 3.3 5步AI循证诊断流程编排引擎  
> **技术实现详情**：请参考《AI医生系统-技术架构设计.md》第5.3节和第3.3节  
> **核心思想**：将临床诊疗态流程重构为5步AI循证诊断流程，确保诊断过程可推理、可复用、可审计。

#### 3.3.1 流程总览

临床诊疗态采用**5步AI循证诊断流程**：

```
Step 1: 识别问题
  ↓
Step 2: 构建鉴别诊断候选集并分层
  ↓
Step 3: 组织候选集并建立分流路径
  ↓
Step 4: 采集关键证据并形成排序与验证计划
  ↓
Step 5: 回填证据并输出终点结论包
```

**流程特点**：
- **可推理**：每个步骤都有明确的推理逻辑和依据
- **可复用**：问题清单、候选集、分流路径等可沉淀为模板库
- **可审计**：每个步骤的输出都有结构化记录，支持追溯和验证

#### 3.3.2 Step 1：识别问题

**目标**：把用户的自然语言描述，转化成可推理、可复用、可审计的结构化"问题清单"，作为后续候选方向生成与分流问诊的唯一输入。

**核心任务**：

1. **概念归一化（明确用户在说什么）**
   - 把"原话"翻译为医学可用的标准概念
   - 处理同义表达与歧义表达
   - 避免误解主诉含义

2. **形成完整问题清单**
   - 不仅记录主诉，还要同步记录伴随问题与关键背景
   - 进行分组组织，保证后续推理不会漏关键信息

3. **标记信息缺口（决定能不能进入下一步）**
   - 明确"当前已知什么、还缺什么、缺了会造成什么推理风险"
   - 按缺口等级决定是否允许进入 Step 2

**输出标准**：

**结构化问题清单**：

```json
{
  "主要问题": {
    "主诉名称": "归一化后的主诉",
    "持续时间": "持续时间与起病方式（突然/渐进）",
    "严重程度": "当前严重程度（对活动/睡眠/功能影响）"
  },
  "伴随问题": [
    {
      "症状名称": "与主诉同窗出现的关键伴随症状",
      "出现时间": "时间",
      "分流价值": "是否具有分流价值"
    }
  ],
  "关键背景": {
    "年龄": "年龄",
    "性别": "性别",
    "既往史": ["与当前主诉相关的重大疾病史"],
    "当前用药": ["会改变风险或表现者"],
    "过敏史": ["会改变风险或表现者"],
    "生理状态": "妊娠、近期手术、久坐久卧、感染接触等",
    "家族史": ["与主诉高度相关者"]
  },
  "信息缺口": {
    "必填缺口": ["缺失则不能进入 Step 2"],

```

**参与脑区**：
- **脑区A：病例理解与结构化** - 执行概念归一化和结构化提取
- **脑区B：主动问诊与信息补全** - 识别信息缺口并生成追问

**完成条件**：
- 必填缺口已补齐，或已明确标记为"重要缺口"并提示风险
- 问题清单结构化完成，可进入 Step 2

**示例**：

用户原话："我这两天胸口闷，走几步就喘，昨天还出汗，有点恶心。"


#### 3.3.3 Step 2：构建鉴别诊断候选集并分层

**目标**：在 Step 1 的"问题清单"基础上，建立该主诉的鉴别诊断全集，并按临床风险与证据强度分成三层，形成后续问诊分流与检查决策的"候选集合"。

**核心任务**：

1. **生成鉴别诊断全集（先"列全"）**
   - 围绕主要问题、伴随问题与关键背景，列出所有可能方向
   - 要求覆盖：常见原因、易混淆原因、严重但不能漏诊的原因

2. **三层分层（把"可能"变成"可推进"）**
   - **首要假设**：当前信息最能支持、最符合整体表现的方向
   - **主要备选诊断**：与首要假设并列需要对比、仍可能成立的方向
   - **必须排除的高危诊断**：一旦漏诊后果严重，即使概率不高也必须纳入并优先排除

3. **为每个候选方向标注"入选依据"**
   - 每个方向必须写清楚是由问题清单中的哪条线索触发纳入
   - 避免"凭经验堆病名"，保证可审计与可复用

**输出标准**：

**鉴别诊断分层清单**：

```json
{
  "首要假设": [
    {
      "方向名称": "疾病名称",
      "入选依据": "对应问题清单的哪几条线索",
      "当前信息缺口": ["缺什么会导致方向无法推进"],
      "概率": 0.0-1.0
    }
  ],
  "主要备选诊断": [
    {
      "方向名称": "疾病名称",
      "入选依据": "对应问题清单的哪几条线索",
      "当前信息缺口": ["缺什么会导致方向无法推进"],
      "概率": 0.0-1.0
    }
  ],
  "必须排除的高危诊断": [
    {
      "方向名称": "疾病名称",
      "入选依据": "对应问题清单的哪几条线索",
```

#### 3.3.4 Step 3：组织候选集并建立分流路径

**目标**：把 Step 2 的"分层候选清单"组织成可推进的推理结构，并提炼出能在问诊与基础测量中快速收缩范围的分流路径，确保后续收缩不是"随便问"，而是沿着明确的逻辑分叉推进。

**核心任务**：

1. **组织成推理子组（把清单变成结构）**
   - 将候选方向按最有效的维度组织为子组
   - 常用维度：系统来源（心血管/呼吸/代谢/消化/心理等）、起病与病程（急性/亚急/慢性）、诱因与触发场景、分布与对称性
   - 目标：一条关键问题能推动一个子组整体前移或后移

2. **提炼关键差异点（分流用）**
   - 为每对子组或每个关键方向提炼"能最快区分"的差异点
   - 形成分流问题的骨架，例如：是否突发、是否静息也出现、是否进行性加重

3. **明确"必须优先处理"的路径（高危先行）**
   - 对必须排除的高危方向建立优先路径
   - 一旦命中高危差异点或高危线索，直接进入升级/验证动作
   - 避免在高危尚未控制时继续在低危方向上细问

4. **形成分流问题清单（供下一步证据采集使用）**

#### 3.3.5 Step 4：采集关键证据并形成三层排序与验证计划

**核心任务**：

1. **采集关键证据（用证据推动，而不是继续罗列）**
   - **阳性线索**：能显著支持某一方向的证据，出现后应推动该方向前移
   - **关键阴性线索**：能显著削弱某一方向的证据，出现后应推动该方向后移
   - 要求证据必须来自可追问、可观察、可测量、可复核的来源

2. **固化三层排序（把结果输出成稳定结构）**
   - **最可能方向**（1个）：当前证据最能支持的方向
   - **必须排除方向**（0-1个）：未完成排除则必须保留

3. **制定验证计划（让排序进入下一阶段）**

   - 回答三个问题：查不查、查什么、用什么标准判定支持/不支持
   - 验证计划必须能改变排序或触发升级处理

#### 3.3.6 Step 5：回填证据并输出终点结论包

**目标**：将 Step 4 的验证结果回填到证据清单与问题清单中，更新三层排序，并输出可行动、可审计的终点结论包。该结论包既能对用户形成明确的"下一步怎么做"，也能对内部形成可追溯的证据链与复评规则，保证诊断过程可迭代。

**核心任务**：

1. **证据回填（把结果变成可审计记录）**
   - 把新增信息逐条回填，包括：补问得到的新症状/体征信息、设备测量数据、线下检查结果与就医反馈
   - 对每条证据标记其对各方向的作用：支持、不支持、不确定

2. **更新三层排序（根据证据重排）**
   - 根据回填证据重新确定：
     - 最可能方向是否稳定或需要更换
     - 必须排除方向是否已完成排除、是否仍需保留
     - 积极备选方向是否需要上移或下沉
   - 强调"排序可变"，避免一旦形成初步结论就不再修正

3. **输出终点结论包（两类终点）**
   - **可确证终点**：当证据达到明确诊断标准或具备强确认条件时，输出具体疾病诊断
   - **不可确证终点**：当证据不足以确证时，输出最可能方向与下一步行动，并明确不确定性来源、复评窗口与升级触发条件

4. **复评与回退（让流程闭环且可迭代）**
   - 当出现证据冲突、症状演变或处理无效时，触发回退

#### 3.3.7 流程迭代与回退机制

**概述**：临床诊疗态流程支持动态迭代和回退，当出现证据冲突、症状演变或处理无效时，系统可以回退到之前的步骤重新处理，确保不会在错误结论上"锁死"。

**回退机制说明**：
- 系统支持回退到任意步骤（Step 1-5 或阶段0）
- 回退触发条件包括：证据冲突、症状演变、治疗无效、必须排除项未完成等
- 回退遵循医疗理论原则：假设可修正性、证据优先性、风险优先性、可追溯性

> **详细回退机制**：请参考 [3.4.7 回退机制（基于临床推理理论）](#347-回退机制基于临床推理理论) 章节，包含完整的回退条件清单、回退路径、医疗理论依据和理论保证。

### 3.5 终点结论包四要素（关键输出标准）

**职责**：确保所有诊断结果输出都包含四个要素，保证可行动、可审计

**四要素结构**：

#### 要素1：结论（Conclusion）

**可确证结论**：
- 输出具体疾病诊断（或最可能诊断）
- 诊断依据：支持证据链（至少3条）
- 疾病严重程度：轻度/中度/重度
- 诊断置信度：高/中/低

**不可确证结论**：
- 输出最可能方向或最可能诊断倾向
- 不确定性来源：为什么无法明确判断
- 缺失的关键证据：需要哪些证据来明确

#### 要素2：必须排除项状态（Must-Exclude Status）

**状态类型**：
- **已排除**：已通过验证明确排除的高危诊断
  - 排除理由：为什么已排除
- **未排除**：未完成排除，必须保留在候选清单中
  - 未排除原因：为什么未排除
- **需线下排除**：需要线下检查才能排除的高危诊断
  - 排除建议：需要做什么检查才能排除

**关键原则**：
- 未完成排除则必须保留，不能因为可能性低就忽略
- 必须明确告知患者必须排除项的状态

#### 要素3：关键依据（Key Evidence）

**证据要求**：
- **至少三条证据**，明确哪些是阳性证据，哪些是关键阴性证据
- **阳性证据**：支持诊断的证据（至少3条）
- **阴性证据**：排除其他诊断的证据
- **检查结果**：支持诊断的检查结果

**证据结构**：

```json
    }
  ],
  "check_results": [

      "check_name": "检查名称",
      "result": "检查结果",
      "support_direction": "支持的诊断方向"
    }
  ]
}
```

**立即行动**：
- 就医建议（科室、时间、需带资料）
- 检查建议（如需进一步确诊）
- 治疗方向（治疗方案方向，不给出具体用药剂量）
- 紧急情况处理建议

**复评时间窗**：

- 延迟复评条件（症状完全缓解等）

**升级触发条件**：
- 出现哪些情况必须立即升级（立即就医）

### 3.4 关键流程节点

#### 3.4.1 健康状态判定完成

**判定标准**：
- 已收集足够信息进行健康状态判定
- 明确是否需要进入诊疗流程
- 确定工作态（wellness_mode / clinical_mode）

**判定结果**：
- **进入健康管理态**：生成 `wellness_plan`，不生成 `ddx`
- **进入临床诊疗态**：启动诊断流程，生成 `ddx`

#### 3.4.2 健康管理态升级触发

**触发条件**：
- 症状加重或持续不缓解
- 出现新症状
- 识别到风险信号（红旗信号）
- 随访中发现异常

**升级动作**：
- 更新 `health_state_assessment.work_mode` = clinical_mode
- 启动诊断流程
- 重新运行相关脑区

#### 3.4.3 Step 1 完成判断（识别问题）

**判断标准**：
- 问题清单已结构化（主要问题、伴随问题、关键背景）
- 必填缺口已补齐，或已明确标记为"重要缺口"并提示风险
- 概念已归一化，可进入 Step 2

**触发条件**：
- 必填缺口已补齐
- 或已明确标记为"重要缺口"并提示风险
- 问题清单结构化完成

**进入下一步**：
- 进入 Step 2：构建鉴别诊断候选集并分层

#### 3.4.4 Step 2 完成判断（构建鉴别诊断候选集并分层）

**判断标准**：
- 鉴别诊断全集已生成
- 三层分层已完成（至少有一个首要假设）
- 每个方向都有明确的入选依据

**触发条件**：
- 鉴别诊断全集已生成
- 三层分层已完成
- 下一步分流入口已标记

**进入下一步**：
- 进入 Step 3：组织候选集并建立分流路径

#### 3.4.5 Step 3 完成判断（组织候选集并建立分流路径）

**判断标准**：
- 推理子组结构已建立
- 关键差异点已提炼
- 分流路径清单已生成

**触发条件**：
- 推理子组结构已建立
- 关键差异点已提炼
- 分流路径清单已生成

**进入下一步**：
- 进入 Step 4：采集关键证据并形成排序与验证计划

#### 3.4.6 Step 4 完成判断（采集关键证据并形成排序与验证计划）

**判断标准**：
- 关键证据已采集（至少覆盖主要差异点）
- 三层排序已固化
- 验证计划已制定（针对最可能和必须排除方向）

**触发条件**：
- 关键证据已采集
- 三层排序已固化
- 验证计划已制定

**进入下一步**：
- 进入 Step 5：回填证据并输出终点结论包

#### 3.4.7 Step 5 完成判断（回填证据并输出终点结论包）

**判断标准**：
- 证据已回填
- 三层排序已更新
- 终点结论包已生成（包含四要素）

**触发条件**：
- 证据已回填
- 三层排序已更新
- 终点结论包已生成

**流程结束**：
- 输出终点结论包给用户
- 启动随访机制

#### 3.4.8 诊断更新触发（临床诊疗态）

**触发条件**：
- 新信息输入（新的症状、检查结果等）
- 信息冲突（需要重新评估）
- 随访反馈（症状变化）

**更新机制**：
- 根据新信息判断需要回退到哪个 Step
- 重新运行相关脑区
- 更新CDP的相应字段

#### 3.4.5 高危升级触发（临床诊疗态）

**触发条件**：
- 脑区F识别到高危情况
- `triage.risk_level` = L1 或 L2

**升级动作**：
- 立即建议就医
- 明确告知风险等级
- 提供紧急处理建议

#### 3.4.9 回填与重排规则（临床诊疗态）

**职责**：定义新信息出现后如何重新排序诊断方向，以及如何处理证据冲突

**回填与重排规则结构**：
```json
{

    "new_evidence_appears": {
      "if_strong_support": {
        "action": "方向上移（权重+0.3）",
        "example": "心电图ST段抬高 → 急性心梗方向上移"
      },
      "if_strong_oppose": {
        "action": "方向下移（权重-0.2）",
        "example": "心电图正常且持续正常 → 心绞痛方向下移"
      },
      "if_uncertain": {
        "action": "标记为不确定并回退到 Step 4 重新分析"
      }
    },
    "evidence_conflict": {
      "conflict_type": "证据冲突类型",
      "action": "标不确定并回退到 Step 4",
      "backfill_target_step": "Step 4",
      "reason": "需要重新采集证据，重新分析支持/反对证据"
    },
    "three_layer_update": {
      "most_likely": "如何更新最可能方向",
      "must_exclude": "如何更新必须排除方向",
      "active_alternatives": "如何更新积极备选方向"
    }
  }
}
```

**重排规则**：
1. **新证据出现后的重排**：
   - 强支持证据 → 方向上移（权重+0.3）
   - 强反对证据 → 方向下移（权重-0.2）
   - 不确定证据 → 标记为不确定，需要进一步验证

2. **证据冲突时的回退规则**：
   - 如果新证据与原有证据明显冲突 → 标记为不确定并回退到 Step 4
   - 如果症状描述与检查结果冲突 → 回退到 Step 1 重新收集信息
   - 如果信息冲突，需要确认并标记为"待确认"状态

3. **三层排序更新规则**：
   - **最可能方向**：如果新证据强烈支持，巩固；如果新证据不支持，可能需要更换
   - **必须排除方向**：如果验证结果明确排除，标记为"已排除"；如果未排除，必须保留
   - **积极备选方向**：如果新证据支持，可能上移为最可能方向；如果新证据不支持，可能下沉或移除

**强调"排序可变"**：避免一旦形成初步结论就不再修正

#### 3.4.7 回退机制（基于临床推理理论）

> **对应技术架构文档**：6.5 回退机制引擎  
> **技术实现详情**：请参考《AI医生系统-技术架构设计.md》第6.5节

**职责**：当出现证据冲突、症状演变或处理无效时，触发回退，确保系统不会在错误结论上"锁死"

**医疗理论依据**：
1. **假设-验证模型**（Hypothesis-Testing Model）- Elstein的临床推理模型
2. **诊断修正理论**（Diagnostic Revision Theory）
3. **治疗性诊断**（Therapeutic Diagnosis）

**核心思想**：

- 诊断假设能够根据新证据动态调整
- 避免诊断锁定（Diagnostic Lock-in）
- 符合临床医生的思维过程

**回退机制**（基于临床推理理论）：

**医疗理论保证**：
在临床推理理论下，回退机制保证：
- **诊断假设能够根据新证据动态调整**：符合Elstein的假设-验证模型
- **避免诊断锁定（Diagnostic Lock-in）**：防止系统在错误结论上"锁死"
- **符合临床医生的思维过程**：临床诊断是一个动态的、迭代的过程
- **保证诊断的准确性**：通过回退机制及时纠正错误诊断

**回退路径**：

1. **回退到 Step 3**（组织候选集并建立分流路径）
   - **触发条件**：症状演变、新症状出现、新红旗信号
   - **医疗理论依据**：
     - **诊断修正理论**（Diagnostic Revision Theory）：症状变化需要重新组织诊断假设
     - **疾病进展理论**（Disease Progression Theory）：新症状可能提示疾病进展或诊断方向错误
   - **医疗原则**：症状演变提示疾病状态改变，需要重新评估诊断
   - **动作**：重新组织诊断树，重新生成候选诊断集，重新建立分流路径

2. **回退到 Step 4**（采集关键证据并形成排序与验证计划）
   - **触发条件**：假设验证失败、治疗无效、必须排除项未完成、证据冲突
   - **医疗理论依据**：
     - **假设-验证模型**（Hypothesis-Testing Model）：如果假设与证据不符，回退到证据采集阶段
     - **治疗性诊断**（Therapeutic Diagnosis）：治疗无效说明诊断可能错误
     - **风险优先原则**（Risk-First Principle）：高危诊断必须优先排除
   - **医疗原则**：
     - 假设验证失败：需要重新采集证据验证假设
     - 治疗无效：说明诊断方向可能错误，需要重新诊断
     - 必须排除项未完成：高危诊断必须优先处理
   - **动作**：重新采集证据，重新制定验证计划，重新评估诊断概率

3. **回退到 Step 1**（识别问题）
   - **触发条件**：信息冲突、信息不完整、关键信息缺失
   - **医疗理论依据**：
     - **信息完整性原则**（Information Completeness Principle）：诊断需要完整、准确的信息
     - **信息一致性原则**（Information Consistency Principle）：信息冲突需要澄清
   - **医疗原则**：
     - 信息冲突：主观症状与客观体征不一致，需要重新验证
     - 信息不完整：关键信息缺失无法进行可靠诊断
   - **动作**：重新收集信息，澄清冲突，补全关键信息

4. **回退到阶段0**（健康状态判定阶段）
   - **触发条件**：症状突然加重、出现新的高危症状、生命体征异常
   - **医疗理论依据**：
     - **分诊理论**（Triage Theory）：高危情况需要重新评估健康状态
     - **风险升级原则**（Risk Escalation Principle）：症状恶化需要升级处理
   - **医疗原则**：症状突然加重或出现高危症状，需要重新评估是否需要紧急处理
   - **动作**：重新进行健康状态判定，重新评估风险等级，决定是否需要紧急就医

**理论保证**：
- **收敛性保证**：在回退机制下，诊断序列在有限步内收敛到稳定状态
- **误差界保证**：回退机制保证最终诊断的误差上界
- **安全性保证**：回退机制确保高危诊断不会被遗漏

**回退原则**（基于临床推理理论）：

1. **假设可修正性**：诊断假设应该能够根据新证据动态调整
   - 医疗依据：Elstein的假设-验证模型
   - 保证：避免诊断锁定（Diagnostic Lock-in）

2. **证据优先性**：新证据优先于旧假设
   - 医疗依据：循证医学原则
   - 保证：当新证据与旧假设冲突时，优先相信新证据

3. **风险优先性**：高危诊断优先处理
   - 医疗依据：风险优先原则（Risk-First Principle）
   - 保证：漏诊高危疾病的代价极大，必须优先排除

4. **可追溯性**：记录回退原因和动作
   - 医疗依据：临床决策的可审计性
   - 保证：便于审计和验证，支持临床决策的透明度

## 五、评估与验证体系

### 5.1 三类离线评测集

#### 5.1.1 静态病例集（Static Case Set）

**用途**：评估"读病历 → 给DDx/计划"的能力

**输入**：固定的完整病历文本
**输出**：DDx列表、检查建议、处置方案
**评估**：可重复、可对比

**评估指标**：
- DDx Top-K命中率
- 检查建议合理性
- 处置方案合理性

#### 5.1.2 交互问诊集（Interactive Interview Set）

**用途**：评估"问对问题"的能力和问诊效率

**输入**：初始主诉，需要多轮对话
**输出**：问诊问题序列、最终诊断
**评估**：问诊质量、问诊效率

**评估指标**：
- "缺失信息"是否合理（问诊质量）
- 问诊轮次效率（完成诊断所需轮次）
- 信息增益有效性（问的问题是否有助于区分DDx）

#### 5.1.3 轨迹回放集（Trajectory Replay Set）

**用途**：评估"信息逐步揭示时修正DDx"的能力

**输入**：逐步提供信息
- 先给主诉
- 再给体征
- 再给检验
- 再给影像

**输出**：每个阶段的DDx更新
**评估**：是否能随着信息更新修正DDx

**评估指标**：
- DDx修正准确性
- 信息更新后的诊断更新及时性
- 证据链更新完整性

### 5.2 核心评估指标

#### 5.2.1 DDx准确性指标

- **DDx Top-1命中率**：最高可能性诊断是否正确
- **DDx Top-3命中率**：前3个可能性中是否包含正确诊断
- **DDx Top-5命中率**：前5个可能性中是否包含正确诊断

#### 5.2.2 安全性指标

- **红旗识别召回率**：宁可误报，不能漏报
- **高危升级及时性**：识别高危后是否及时建议就医
- **不确定性表达准确性**：低置信度时是否明确表达不确定性

#### 5.2.3 问诊质量指标

- **信息增益有效性**：问的问题是否有助于区分DDx
- **问诊轮次效率**：完成诊断所需轮次
- **缺失信息合理性**：识别的缺失信息是否合理

#### 5.2.4 可解释性指标

- **证据链完整性**：支持证据、反对证据、缺失证据是否完整
- **推理路径可追溯性**：诊断结论是否能追溯到证据
- **方案合理性**：基于路径/证据可解释

#### 5.2.5 健康状态判定指标

- **健康状态判定准确率**：是否正确判断是否需要进入诊疗流程
- **健康管理态升级及时性**：发现风险信号后是否及时升级到临床诊疗态
- **漏诊率**：应该进入临床诊疗态但误判为健康管理态的比例（必须极低）
