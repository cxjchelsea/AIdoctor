# AI医生系统 - 知识图谱两层结构设计

---

## 一、整体架构设计

### 1.1 知识图谱分层架构

```
┌─────────────────────────────────────────────────────────────┐
│                    工程层（Ingestion & Retrieval）            │
│  Document → Chunk → Mention → Evidence → Source → Version   │
│  （数据来源、证据追溯、版本管理）                              │
└─────────────────────────────────────────────────────────────┘
                            ↓ 链接
┌─────────────────────────────────────────────────────────────┐
│                    语义层（Ontology/Concept）                 │
│                                                               │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  第0项：编码规范（节点属性）                            │   │
│  │  Symptom/Disease/Examination等节点的编码属性            │   │
│  └─────────────────────────────────────────────────────┘   │
│                            ↓                                 │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  第3项：标准目录主数据（基础实体）                      │   │
│  │  Symptom, ChiefComplaint, Disease, Examination,        │   │
│  │  Category（基础属性：编号、名称、分类、编码）            │   │
│  └─────────────────────────────────────────────────────┘   │
│                            ↓                                 │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  第5项：主诉模板（扩展）                                │   │
│  │  ChiefComplaint扩展属性 + 关系                         │   │
│  │  DifferentialFrameworkSubclass, DifferentialPoint     │   │
│  └─────────────────────────────────────────────────────┘   │
│                            ↓                                 │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  第6项：疾病模板（扩展）                                │   │
│  │  Disease扩展属性 + 关系                                │   │
│  │  ReasoningSubgroup, DifferentialPoint                 │   │
│  └─────────────────────────────────────────────────────┘   │
│                            ↓                                 │
│  ┌─────────────────────────────────────────────────────┐   │
│  │  第7项：证据条目模板（待设计）                          │   │
│  │  Evidence节点及其关系                                  │   │
│  └─────────────────────────────────────────────────────┘   │
└─────────────────────────────────────────────────────────────┘
```

## 二、双层Schema设计

### 2.1 语义层（Ontology/Concept Schema）

**定义**：语义层定义医学领域的核心概念、实体类型和关系类型，关注临床语义的正确性。

#### 2.1.1 核心实体类型汇总

| 实体类型 | 来源模块 | 说明 |
|---------|---------|------|
| **Symptom** | 第3项 | 标准症状 |
| **ChiefComplaint** | 第3项+第5项 | 标准主诉（第3项基础，第5项扩展） |
| **Disease** | 第3项+第6项 | 标准疾病（第3项基础，第6项扩展） |
| **Examination** | 第3项 | 标准检查 |
| **Evidence** | 第7项（待设计） | 证据条目 |
| **ReasoningSubgroup** | 第6项 | 推理子组 |
| **DifferentialFrameworkSubclass** | 第5项 | 鉴别诊断框架子类 |
| **DifferentialPoint** | 第5项+第6项 | 关键差异点/鉴别点 |
| **Category** | 第3项 | 分类 |
| **Treatment** | 第0项 | 治疗（编码规范） |
| **Sign** | 第0项 | 体征（编码规范） |
| **Indicator** | 第0项 | 指标（编码规范） |
| **Drug** | 第0项 | 药物（编码规范） |

#### 2.1.2 核心关系类型汇总

| 关系类型 | 来源模块 | 说明 |
|---------|---------|------|
| **BELONGS_TO** | 第3项 | 实体属于分类 |
| **HAS_CATEGORY** | 第3项 | 分类包含子分类（分类层级关系） |
| **ALIGNED_WITH** | 第0项 | 编码对齐关系（不同编码体系之间的映射，可选） |
| **HAS_CANDIDATE_DISEASE** | 第5项 | 主诉有候选疾病（三层候选） |
| **HAS_REASONING_SUBGROUP** | 第5项 | 主诉有推理子组 |
| **HAS_DIFFERENTIAL_SUBCLASS** | 第5项 | 主诉有鉴别诊断框架子类 |
| **HAS_DIFFERENTIAL_POINT** | 第5项 | 主诉有关键差异点 |
| **RECOMMENDS_EXAMINATION** | 第5项 | 主诉推荐检查 |
| **SUPPORTED_BY** | 第6项 | 疾病被证据支持 |
| **OPPOSED_BY** | 第6项 | 疾病被证据反对 |
| **REQUIRES** | 第6项 | 疾病需要证据 |
| **DIFFERENTIAL_WITH** | 第6项 | 疾病需要与另一疾病鉴别 |
| **REQUIRES_EXAMINATION** | 第6项 | 疾病需要检查 |
| **BELONGS_TO_SUBGROUP** | 第6项 | 疾病属于推理子组 |
| **HAS_DIFFERENTIAL_POINT** | 第6项 | 疾病有鉴别点 |
| **ESCALATION_TRIGGER** | 第6项 | 疾病升级触发条件（可选） |
| **CONTAINS_DISEASE** | 第5项+第6项 | 子类/子组包含疾病 |
| **AFFECTS** | 第5项 | 差异点影响子组/疾病 |
| **IS_STANDARD_FOR** | 第3项 | 标准目录实体是某个概念的标准术语（可选） |

### 2.2 工程层（Ingestion & Retrieval Schema）

**定义**：工程层定义知识抽取、存储、检索所需的技术结构，关注可追溯性和可维护性。

#### 2.2.1 核心节点类型

| 节点类型 | 说明 | 主要属性 |
|---------|------|---------|
| **Document** | 源文档 | doc_id, name, type, version, source_url |
| **Chunk** | 文档片段（含向量嵌入） | chunk_id, text, embedding, doc_id, chunk_index |
| **Mention** | 实体提及 | mention_id, text, start_pos, end_pos, chunk_id |
| **Evidence** | 证据节点 | evidence_id, chunk_id, confidence |
| **Source** | 数据来源 | source_id, source_type, version, author |
| **Version** | 版本信息 | version_id, version_number, created_at, description |
| **ExtractionRun** | 抽取运行记录 | run_id, model_name, prompt_version, created_at, metrics |

#### 2.2.2 核心关系类型

| 关系类型 | 说明 |
|---------|------|
| **CONTAINS** | 文档包含词块 |
| **CONTAINS** | 词块包含实体提及 |
| **REFERS_TO** | 提及指向实体 |
| **HAS_EVIDENCE** | 关系边链接到证据chunk |
| **FROM_DOC** | 实体/关系链接到来源文档 |
| **HAS_VERSION** | 实体/关系有版本信息 |

### 2.3 两层Schema的关联

**关联方式**：
- 语义层的实体节点通过`Mention`节点链接到工程层的`Chunk`
- 语义层的关系边通过`source_chunk_id`属性链接到工程层的`Chunk`
- 工程层的`Source`和`Version`节点为语义层实体提供来源和版本信息

**示例结构**：
```
语义层：Disease(深静脉血栓) --[SUPPORTED_BY]--> Evidence(单侧肿胀)
         ↓                                    ↓
工程层：Mention --[IN_CHUNK]--> Chunk --[FROM_DOC]--> Document(指南v2.0)
```
