## 存储格式基础概念

### 1 三种存储格式的定义

#### 知识图谱（Knowledge Graph）

**定义**：知识图谱是一种用图结构来表示知识的数据模型，由**节点（实体）**和**边（关系）**组成。节点代表实体（如"胸痛"、"心绞痛"、"心电图"），边代表实体之间的关系（如"引起"、"需要检查"）。

**示例**：

```
节点：胸痛 --[引起]--> 节点：心绞痛
节点：心绞痛 --[需要检查]--> 节点：心电图
```

**特点**：

- 结构化存储：明确表示实体和关系
- 支持推理：可以通过图遍历发现隐含关系
- 查询灵活：支持复杂的图查询语言（如Cypher、SPARQL）

#### 配置文件（Configuration File）

**定义**：配置文件是用结构化文本格式（如JSON、YAML、XML）存储的规则、参数和流程定义。通常采用键值对、列表、嵌套结构等格式。

**示例（JSON格式）**：

```json
{
  "症状到主诉映射规则": {
    "胸痛 + 气短": "心血管疾病",
    "发热 + 咳嗽": "呼吸系统疾病"
  },
  "严重度标准": {
    "轻度": 1,
    "中度": 2,
    "重度": 3
  }
}
```

**特点**：

- 人类可读：易于编辑和维护
- 结构化：有明确的语法规则
- 版本可控：可以用Git等工具管理变更

#### 表格文件（Table File）

**定义**：表格文件是用行列结构存储的数据，常见格式包括CSV、Excel、TSV等。每行代表一条记录，每列代表一个属性。

**示例（CSV格式）**：

```csv
同义词,标准词
胸疼,胸痛
心口疼,胸痛
胸闷,胸痛
```

**特点**：

- 简单直观：易于批量编辑和导入
- 批量操作：适合大量同义词映射
- 数据导入：可以方便地导入到其他系统

### 2 计算机如何理解这些格式

#### 知识图谱

- **存储方式**：通常使用图数据库（如Neo4j、ArangoDB）存储
- **理解方式**：
  - 通过图数据库引擎解析节点和边的结构
  - 使用图查询语言（如Cypher）进行查询和推理
  - 支持图遍历算法发现路径和关系
- **计算机表示**：在内存中表示为图数据结构（邻接表或邻接矩阵）

#### 配置文件

- **存储方式**：以文本文件形式存储（JSON、YAML、XML等）
- **理解方式**：
  - 使用解析器（Parser）将文本解析为数据结构（如字典、列表）
  - 通过键值访问获取配置项
  - 支持嵌套结构和类型转换
- **计算机表示**：解析后转换为内存中的数据结构（如Python的dict、list）

#### 表格文件

- **存储方式**：以文本文件形式存储（CSV、TSV）或二进制格式（Excel）
- **理解方式**：
  - 使用CSV解析器按行读取，按分隔符（逗号、制表符）分割列
  - 第一行通常作为列名（表头）
  - 转换为二维数组或DataFrame结构
- **计算机表示**：解析后转换为二维数组或DataFrame（如pandas DataFrame）

### 3 关于"向量"概念的澄清

#### 3.1 向量的两种含义

**数学中的向量**（有大小和方向）：

- 在数学中，向量确实是有大小和方向的量，如物理中的力、速度等
- 例如：`[3, 4]` 表示一个在x方向3个单位、y方向4个单位的向量，大小为5，方向为53.13度

**计算机科学中的向量（Embedding）**：

- 在AI和计算机科学中，"向量"更多指的是**高维数值数组**，用于表示语义信息
- 例如：`[0.2, -0.5, 0.8, 0.1, ...]`（通常有几百到几千维）
- **关键区别**：这里的"向量"主要表示**语义在向量空间中的位置**，而不是传统意义上的"方向"
- 两个向量的**相似度**（通过余弦相似度、欧氏距离计算）表示语义的相似程度

**关系说明**：

- Embedding向量在数学形式上确实是向量（数组），但它的"方向"和"大小"主要用来表示**语义相似性**，而不是物理空间的方向
- 可以理解为：在语义空间中，相似的词或概念在向量空间中距离更近

#### 3.2 计算机能理解多种格式，不仅仅是向量

**重要澄清**：计算机实际上可以理解多种数据格式，**不仅仅是向量**：

1. **结构化数据**（知识图谱、配置文件、表格）：
   - 计算机通过**解析器（Parser）**理解这些格式
   - 例如：JSON解析器将文本转换为字典和列表；CSV解析器将文本转换为二维数组
   - 这些格式在内存中表示为**数据结构**（图、字典、数组等），计算机可以直接操作

2. **向量数据**（Embedding）：
   - 计算机将向量存储为**浮点数数组**
   - 通过**数学运算**（如向量点积、余弦相似度）来理解语义关系

3. **文本数据**：
   - 计算机通过**字符编码**（如UTF-8）理解文本
   - 可以按字符、单词、句子等不同粒度处理

**核心观点**：

- 计算机的"理解"本质上是**数据结构的解析和操作**
- 不同的存储格式对应不同的**解析方式**和**数据结构**
- **结构化存储**（知识图谱、配置文件、表格）和**向量存储**都是计算机可以理解的格式，只是理解方式不同

### 4 结构化存储与向量存储的区别

| 特性               | 知识图谱/配置文件/表格文件     | 向量存储（Embedding）              |
| ------------------ | ------------------------------ | ---------------------------------- |
| **存储形式**       | 结构化数据（图、键值对、表格） | 数值向量（浮点数数组）             |
| **语义理解**       | 显式语义：直接存储概念和关系   | 隐式语义：通过向量空间中的位置表示 |
| **可解释性**       | 高：可以直接查看和理解         | 低：向量含义不直观                 |
| **查询方式**       | 精确匹配、规则查询、图遍历     | 相似度计算（余弦相似度、欧氏距离） |
| **推理能力**       | 支持逻辑推理和规则推理         | 通过向量相似度进行语义相似性推理   |
| **适用场景**       | 结构化知识、规则、关系         | 语义搜索、相似度匹配、大模型检索   |
| **修改方式**       | 直接编辑结构                   | 需要重新计算向量                   |
| **计算机理解方式** | 通过解析器转换为数据结构       | 通过数学运算（向量计算）           |

**关键区别**：

- **结构化存储**（知识图谱/配置文件/表格）：
  - 存储的是**符号化的知识**，计算机通过**解析语法结构**来理解
  - 语义是**显式的**，例如"胸痛引起心绞痛"这个关系是直接存储的
  - 计算机通过**解析器**将其转换为内存中的数据结构（图、字典、数组），然后直接操作这些结构

- **向量存储**：
  - 存储的是**数值向量**，语义是**隐式的**
  - 通过向量在空间中的位置和距离来表示语义相似性
  - 例如"胸痛"可能被编码为`[0.2, -0.5, 0.8, ...]`这样的向量
  - 计算机通过**数学运算**（向量点积、余弦相似度等）来理解语义关系

**在本系统中的应用**：

- **结构化存储**用于存储**精确的医学知识**（疾病关系、诊断规则），需要可解释性和逻辑推理
- **向量存储**（如果使用）通常用于**语义检索**和**相似度匹配**，如从大量文本中检索相关医学知识

**总结**：

- 计算机可以理解**多种格式**，包括结构化数据（知识图谱、配置文件、表格）和向量数据
- 不同格式有不同的**理解方式**：结构化数据通过解析器，向量数据通过数学运算
- 选择哪种格式取决于**应用场景**：需要精确规则和可解释性用结构化存储，需要语义相似度匹配用向量存储

### 5 本系统是否需要向量存储？

#### 5.1 结论：**不需要**

#### 5.2 为什么当前不需要向量存储？

**1. 核心需求是精确的医学知识，而非语义相似度**

- 本系统的19个知识内容项都是**结构化、精确的医学知识**：
  - 疾病关系（"胸痛引起心绞痛"）是**确定的因果关系**，不是相似度问题
  - 诊断规则（"症状A + 症状B → 疾病C"）是**明确的逻辑规则**，需要精确匹配
  - 编码规范、标准目录是**标准化的数据**，需要精确查找

- **向量存储的局限性**：
  - 向量相似度是**模糊匹配**，可能找到"相似但不准确"的结果
  - 医学诊断需要**精确性**，不能容忍"差不多"的答案
  - 例如：用户说"胸疼"，系统应该精确匹配到"胸痛"（通过归一化词表），而不是通过向量相似度找到"心痛"、"腹痛"等相似词

**2. 需要可解释性和逻辑推理**

- 医学诊断系统必须能够**解释诊断依据**：
  - 医生和患者需要知道"为什么是这个诊断"
  - 知识图谱和配置文件可以直接展示推理路径："胸痛 → 心绞痛 → 需要心电图检查"
  - 向量存储无法提供可解释的推理路径

- **结构化存储的优势**：
  - 知识图谱支持**图遍历推理**，可以找到多跳关系
  - 配置文件支持**规则推理**，可以展示完整的推理链条
  - 向量存储只能给出"相似度分数"，无法解释"为什么相似"

**3. 知识规模相对可控，不需要大规模语义检索**

- 本系统的知识内容：
  - 19个知识内容项，规模相对有限
  - 主要是**标准化的医学概念和规则**，不是海量非结构化文本
  - 可以通过知识图谱和配置文件高效管理

- **向量存储的适用场景**：
  - 通常用于处理**海量非结构化文本**（如医学文献库、病历库）
  - 当需要从**百万级文档**中检索相关内容时，向量检索才有优势
  - 本系统的知识是**结构化、精炼的**，不需要大规模语义检索

**4. 维护成本考虑**

- 结构化存储的维护：
  - 知识图谱、配置文件、表格文件都可以**直接编辑**
  - 医学专家可以直接查看和修改规则
  - 版本控制清晰，变更可追溯

- 向量存储的维护：
  - 需要**重新计算向量**（使用大模型生成embedding）
  - 每次知识更新都需要重新向量化，成本高
  - 向量含义不直观，难以验证正确性
