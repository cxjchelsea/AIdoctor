## 入口判定服务-前端界面完整测试指南

### 一、测试环境准备

1. 启动后端服务：
```bash
cd health-state-assessment-service
python run.py
```
确认服务运行在 `http://localhost:8081`

2. 启动前端服务：
```bash
cd frontend
npm run dev
```
前端通常运行在 `http://localhost:3000` 或 `http://localhost:5173`

3. 配置API代理（如果需要）：
确保前端能正确调用后端API（检查 `vite.config.ts` 或代理配置）

### 二、前端界面测试步骤

#### 测试场景1：无症状用户（健康筛查路径A）

测试目标：验证无症状用户进入健康管理态

操作步骤：
1. 打开前端页面（诊断页面）
2. 在输入框输入："我想做个体检"
3. 点击"发送"按钮

预期界面表现：
- 用户消息显示在对话中
- 系统在后台完成健康状态判定（无感，不显示"正在评估"）
- 出现"健康状态评估"卡片，显示：
  - 工作态：健康管理态（绿色标签）
  - 风险等级：L3 或 L4（蓝色/绿色标签）
  - 路径选择：A路径（健康筛查）（蓝色标签）
  - 症状状态：无症状（绿色标签）
- 出现"健康管理计划"卡片，包含：
  - 风险识别
  - 生活方式建议
  - 随访计划
- 出现"开始健康筛查流程"按钮

验证点：
- [ ] 健康状态评估卡片正确显示
- [ ] 工作态为"健康管理态"
- [ ] 路径选择为"A路径（健康筛查）"
- [ ] 健康管理计划正确显示
- [ ] 无危险信号提示

### 四、常见问题排查

#### 问题1：前端无法调用后端API

检查：
1. 后端服务是否运行（访问 `http://localhost:8081/health`）
2. 前端API配置是否正确（`apiClient.ts` 中的 `baseURL`）
3. 浏览器控制台是否有CORS错误
4. 网络请求是否成功（F12 -> Network）

#### 问题2：健康状态评估卡片不显示

检查：
1. 浏览器控制台是否有错误
2. `performHealthAssessment` 是否被调用
3. API响应是否正确
4. `HealthStateAssessmentCard` 组件是否正确渲染

#### 问题3：工作态不正确

检查：
1. 查看浏览器控制台的API响应
2. 检查 `entryAssessment.pathSelected` 的值
3. 检查后端日志，查看判定逻辑

#### 问题4：危险信号未检测

检查：
1. 输入是否包含危险信号关键词
2. 查看后端日志，检查 `check_red_flags` 的执行
3. 检查 `red_flag_rules.py` 中的规则

### 五、调试技巧

1. 打开浏览器开发者工具（F12）
2. 查看Console标签：检查是否有JavaScript错误
3. 查看Network标签：
   - 找到 `health-state-assessment/assess` 请求
   - 查看Request Payload（发送的数据）
   - 查看Response（返回的数据）
4. 查看后端日志：检查服务端处理过程

### 七、快速验证命令

如果前端无法访问，可以用浏览器直接测试API：

1. 打开浏览器开发者工具（F12）
2. 在Console中输入：

```javascript
// 测试健康状态判定API
fetch('http://localhost:8081/api/v1/health-state-assessment/assess', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json'
  },
  body: JSON.stringify({
    userId: 'test001',
    userInput: '我想做个体检',
    basicInfo: { age: 30, gender: '男' }
  })
})
.then(res => res.json())
.then(data => console.log('结果:', data))
```

这样可以快速验证后端API是否正常工作。
