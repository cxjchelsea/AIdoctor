# 知识图谱设计 - 第3项：标准目录主数据

> **设计目标**：为标准目录主数据设计知识图谱结构，支持标准术语的存储、查询和关系建立。  
> **创建日期**：2026-01-28  
> **文档版本**：v1.0

---

## 📋 设计总览

**第3项的特点**：
- **存储形式**：表格文件（源数据）→ 知识图谱（节点）
- **核心内容**：标准症状词表、标准主诉清单、疾病主数据目录、检验项目目录
- **设计重点**：标准目录作为实体节点存储，只包含基础目录信息

**设计原则**：
- 标准目录作为独立的实体节点存储
- **只包含基础目录信息**：编号、名称、分类、编码等
- 支持分类和层级结构
- 表格文件作为源数据，批量导入到知识图谱

**职责划分**：
- **第3项（标准目录主数据）**：提供基础目录信息（编号、名称、分类、编码）
- **第5项（主诉模板）**：在第3项基础上扩展主诉的详细属性（定义、适用人群、适用场景）和关系（主诉包含症状）
- **第6项（疾病模板）**：在第3项基础上扩展疾病的详细属性（定义、患病率、典型背景）和关系（症状引起疾病、疾病需要检查等）

## 步骤0：双层Schema定义

### 0.1 语义层（Ontology/Concept Schema）

**核心实体类型**：
- **Symptom**（症状）：标准症状词表中的症状实体
- **ChiefComplaint**（主诉）：标准主诉清单中的主诉实体
- **Disease**（疾病）：疾病主数据目录中的疾病实体
- **Examination**（检查/检验）：检验项目目录中的检查实体
- **Category**（分类）：症状、疾病等的分类实体

**关系类型**：
- **BELONGS_TO**：实体属于某个分类
- **HAS_CATEGORY**：分类包含实体
- **IS_STANDARD_FOR**：标准目录实体是某个概念的标准术语

### 0.2 工程层（Ingestion & Retrieval Schema）

**数据来源**：
- **Document**：标准目录文档（表格文件）
- **Chunk**：目录条目的文本片段
- **Source**：目录来源（标准体系、版本等）

**数据追溯**：
- 每个标准目录实体可以链接到来源文档
- 支持目录版本管理和更新历史

### 0.3 两层Schema的关联

**关联方式**：
- 语义层的标准目录实体通过`Source`节点链接到工程层的`Document`
- 目录的更新历史通过`Version`节点管理

```

├── 症状类（Symptom）
```

## 步骤3：抽取设计

### 3.1 数据来源

**主要数据来源**：
1. **标准症状词表**：表格文件，包含所有标准症状
2. **标准主诉清单**：表格文件，包含所有标准主诉

4. **检验项目目录**：表格文件，包含所有标准检验项目

### 3.2 抽取方法

**方法1：表格文件直接导入**
- 从表格文件直接读取标准目录数据
- 批量创建实体节点
- 设置节点属性

**方法2：分类关系建立**
- 根据分类字段建立实体与分类的关系
- 建立分类之间的层级关系

**方法3：编码对齐**
- 与第0项的编码信息对齐
- 建立标准目录实体与编码的关联

### 3.3 抽取流程

```
步骤1：读取表格源数据
  ↓
步骤2：创建分类节点（如果不存在）
  ↓
步骤3：创建实体节点（症状/主诉/疾病/检查）
  ↓
步骤4：设置节点属性（编号、名称、分类、编码等）
  ↓
步骤5：建立分类关系（BELONGS_TO）
  ↓
步骤6：建立分类层级关系（HAS_CATEGORY）
  ↓
步骤7：链接到来源文档
  ↓
步骤8：验证数据完整性
```

## 步骤4：实体归并/去重 + 标准编码对齐

### 4.1 实体归并策略

**归并场景**：
- 同一标准术语在不同表格中可能有不同编号
- 需要归并为同一实体节点

**归并方法**：
1. **名称精确匹配**：完全相同的名称归并为同一实体
2. **编码匹配**：相同编码的实体归并
3. **语义匹配**：语义相似的实体归并

### 4.2 标准编码对齐

**对齐策略**：
- 与第0项的编码信息对齐
- 标准目录实体的编码属性与编码规范对齐
- 支持多编码体系并存

### 4.3 归并对齐流程

```
步骤1：名称归一化
  ↓
步骤2：候选发现（找出可能重复的实体）
  ↓
步骤3：相似度计算
  ↓
步骤4：聚类归并
  ↓
步骤5：标准编码对齐
  ↓
步骤6：生成稳定ID
  ↓
最终实体列表（去重、对齐、有稳定ID）
```

## 📊 设计总结

### 核心设计要点

1. **标准目录作为实体节点**：标准目录作为独立的实体节点存储，支持关系查询和推理
2. **只包含基础目录信息**：第3项只包含编号、名称、分类、编码等基础信息，详细属性（定义、患病率、适用人群等）应在第5、6项中定义
3. **分类结构支持**：支持分类和层级结构，便于组织和管理
4. **与编码规范集成**：与第0项的编码信息集成，支持多编码体系
5. **表格文件导入**：表格文件作为源数据，批量导入到知识图谱

### 与表格文件的协同

- **表格文件**：作为源数据，便于批量管理和导入
- **知识图谱**：标准目录作为实体节点存储，支持关系查询和推理
- **数据流转**：表格文件 → 导入脚本 → 知识图谱实体节点

### 与其他知识内容的关联

- **与第0项的关联**：标准目录实体的编码属性与编码规范对齐
- **与第5项的关联**：标准主诉目录与主诉模板的实体部分对应。第3项提供基础目录信息，第5项在此基础上扩展详细属性（定义、适用人群、适用场景等）和关系（主诉包含症状）
- **与第6项的关联**：标准疾病目录与疾病模板对应。第3项提供基础目录信息，第6项在此基础上扩展详细属性（定义、患病率、典型背景等）和关系（症状引起疾病、疾病需要检查等）
- **与第7项的关联**：标准检查目录与证据条目模板的实体部分对应
