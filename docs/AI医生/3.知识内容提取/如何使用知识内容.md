# 如何使用知识内容

> 总原则：**知识推理负责"关系网络与可解释路径"，规则推理负责"安全与流程决策"，两者缺一不可。**

---

## 1 知识图谱的搭建流程

> **目的**：将交付物（基础层、三模板）转换为可用的Neo4j知识图谱，供系统进行知识推理。

### 1.1 第一步：基础层归一化（建立概念ID映射）

**作用**：确保系统内部每个概念都有唯一标识，用户的各种表达都能被正确理解。

1. **建立概念ID体系**：
   - 从**医学概念本体与编码规范（2.1.1）**读取所有概念的标准名称和编码
   - 为每个概念分配唯一ID（如`SYMPTOM_001`、`DISEASE_042`）
   - 确保同一个概念在不同知识内容中始终使用同一个ID

2. **构建归一化映射表**：
   - 从**归一化词表（2.1.2）**读取同义词/别名/口语化表达与标准术语的映射关系
   - 建立映射表：用户输入 → 标准术语 → 概念ID
   - 例如：用户说"胸口闷" → 映射到"胸闷样不适" → 获取概念ID `SYMPTOM_001`

### 1.2 第二步：构建知识图谱节点（基于模板B）

**作用**：在Neo4j中创建所有概念节点，作为知识图谱的基础。

1. **创建疾病节点**：
   - 从**模板B：疾病模板（2.2.2）**的疾病节点属性表读取每个疾病的信息
   - 在Neo4j中创建节点，节点类型为`Disease`，属性包括：
     - `disease_id`：疾病ID（标准编码，如ICD/SNOMED）
     - `name`：疾病名称（标准术语）
     - `prevalence_<age_group>_<gender>`：患病率（按年龄组/性别，如`prevalence_55_male`）
     - `typical_symptoms`：典型症状组合列表
     - `typical_signs`：典型体征列表
     - `typical_background`：典型背景（年龄、性别、既往史等）

2. **创建其他概念节点**：
   - 创建`Symptom`节点（症状）、`Examination`节点（检查）、`Treatment`节点（治疗）、`Sign`节点（体征）等
   - 节点属性来自**基础层（2.1）**的概念本体

### 1.3 第三步：构建知识图谱关系边（基于模板B）

**作用**：建立概念之间的关系网络，支持多跳推理。

1. **症状-疾病关系**（`CAUSES`或`RELATED_TO`）：
   - 从**模板B：疾病模板（2.2.2）**的关系边表读取
   - 创建关系：`(Symptom)-[:CAUSES {weight: 0.8, confidence: 0.9}]->(Disease)`
   - 权重和置信度来自模板B的关系边表

2. **疾病-检查关系**（`REQUIRES_EXAMINATION`）：
   - 从**模板B：疾病模板（2.2.2）**的关系边表读取
   - 创建关系：`(Disease)-[:REQUIRES_EXAMINATION {sensitivity: 0.9, specificity: 0.95}]->(Examination)`
   - 敏感性和特异性来自模板B的关系边表

3. **疾病-治疗关系**（`REQUIRES_TREATMENT`）：
   - 从**模板B：疾病模板（2.2.2）**的关系边表读取
   - 创建关系：`(Disease)-[:REQUIRES_TREATMENT]->(Treatment)`

4. **疾病-疾病关系**（`DIFFERENTIAL_WITH`）：
   - 从**模板B：疾病模板（2.2.2）**的关系边表读取
   - 创建关系：`(Disease1)-[:DIFFERENTIAL_WITH {diff_points: [...]}]->(Disease2)`
   - 鉴别要点来自模板B的关系边表

5. **证据-疾病关系**（可选，基于模板C）：
   - 从**模板C：证据条目库（2.2.3）**读取证据条目
   - 可以将证据作为节点：`(Evidence)-[:SUPPORTS {strength: 'high'}]->(Disease)`
   - 或者将证据作为关系属性：在症状-疾病关系上添加证据属性

### 1.4 第四步：补充可计算属性（基于模板B和模板C）

**作用**：为疾病节点添加可计算属性，支持概率计算和贝叶斯更新。

1. **先验概率**：
   - 从**模板B：疾病模板（2.2.2）**的患病率数据计算
   - 根据患者年龄、性别、地区，查询对应年龄组/性别的患病率
   - 存储为疾病节点的属性或计算属性

2. **似然评分**：
   - 从**模板C：证据条目库（2.2.3）**读取证据的敏感性/特异性数据
   - 或从**模板B：疾病模板（2.2.2）**的诊断试验敏感性/特异性数据库读取
   - 当患者出现某个证据时，根据敏感性/特异性计算似然评分

3. **后验概率**：
   - 使用**贝叶斯更新规则库（2.3.4）**中的计算公式
   - 基于先验概率和似然评分，计算后验概率

## 2 什么时候用知识推理，什么时候用规则推理

> **核心判断标准**：**知识推理用于"计算和推理"（候选有哪些、概率是多少、路径如何解释），规则推理用于"决策和控制"（什么时候问什么问题、什么时候切换路径、什么时候建议就医）。**

### 2.1 使用知识推理的场景

**知识推理基于知识图谱，用于以下场景：**

| 场景         | 需要解决的问题                       | 使用的知识内容                                           | 输出结果                                   |
| ------------ | ------------------------------------ | -------------------------------------------------------- | ------------------------------------------ |
| **候选生成** | 用户说"胸痛"，系统要知道考虑哪些疾病 | 模板A（主诉级候选集）+ 知识图谱路径推理                  | 三层候选集合（首要假设/主要备选/必须排除） |
| **概率计算** | 根据患者信息，计算每个候选疾病的概率 | 知识图谱（患病率、关系权重）+ 模板C（证据敏感性/特异性） | 候选疾病的概率排序                         |
| **概率更新** | 新证据出现后，如何更新疾病概率       | 知识图谱（贝叶斯更新）+ 模板C（证据条目）                | 更新后的概率排序                           |
| **路径推理** | 从症状到疾病的推理路径是什么         | 知识图谱（多跳关系路径）                                 | 可解释的推理路径                           |
| **关系查询** | 某个疾病需要做什么检查、怎么治疗     | 知识图谱（疾病-检查关系、疾病-治疗关系）                 | 检查/治疗建议                              |

### 2.2 使用规则推理的场景

**规则推理基于规则库，用于以下场景：**

| 场景         | 需要解决的问题                                   | 使用的知识内容                                               | 输出结果                                      |
| ------------ | ------------------------------------------------ | ------------------------------------------------------------ | --------------------------------------------- |
| **入口判定** | 用户想干什么，走A路径还是B路径                   | 入口判定规则库（2.3.1）                                      | 工作态选择（A路径/B路径）                     |
| **安全判断** | 是否出现高危信号，需要立即就医                   | 红旗信号库（2.3.1）、高危识别规则库（2.3.3）                 | 是否触发红旗/高危，是否建议急诊               |
| **流程控制** | 什么时候问什么问题，什么时候切换路径             | 主诉关键字段模板（2.3.1）、分流路径模板（2.2.1）、回退条件清单（2.3.4） | 下一步动作（追问/切换路径/回退）              |
| **信息收集** | 需要收集哪些信息，如何追问                       | 主诉关键字段模板（2.3.1）、智能追问题库（2.3.1）             | 追问问题列表                                  |
| **健康管理** | A路径的完整流程（需求分类、筛查建议、随访等）    | A路径规则库（2.3.2）                                         | 健康管理建议、随访计划                        |
| **风险分级** | 疾病的严重程度、紧急程度如何判定                 | 严重程度评估规则库（2.3.3）、紧急程度分级规则库（2.3.3）     | 严重程度（轻度/中度/重度）、紧急程度（L1-L4） |
| **入口转换** | 用户从家族史/既往史/体检异常入口，如何转换为主诉 | 入口角度统一转换规则库（2.3.5）                              | 转换后的主诉、追问问题                        |

### 2.3 知识推理与规则推理的协同

**两者缺一不可，协同工作：**

- **规则决定"问什么"** → **知识决定"怎么算"**：
  - 规则推理：根据主诉关键字段模板，决定需要问"起病时间"、"严重程度"等
  - 知识推理：根据收集到的信息，计算候选疾病的概率

- **规则决定"走哪条路"** → **知识决定"路上有什么"**：
  - 规则推理：根据分流路径模板，决定问"疼痛是急性还是慢性？"
  - 知识推理：根据答案，通过知识图谱推理，确定哪些疾病方向更可能

- **规则保证"安全"** → **知识保证"准确"**：
  - 规则推理：识别红旗信号，立即建议就医
  - 知识推理：计算疾病概率，提供可解释的诊断依据

## 3 知识推理的使用场景（不同情况如何使用）

### 3.1 场景1：主诉驱动的候选生成

**问题**：用户说"胸痛"，系统要知道考虑哪些疾病。

**使用流程**：

1. **查询模板A**：

   - 从**模板A：主诉级候选集（2.2.1）**读取"胸痛"的三层候选集合
   - 获得：首要假设（心绞痛、胃食管反流）、主要备选（焦虑症、胸膜炎等）、必须排除（急性心肌梗死、主动脉夹层等）

2. **知识图谱路径推理**：

   ```cypher
   // 查询从"胸痛"到候选疾病的路径
   MATCH path = (s:Symptom {id: 'SYMPTOM_CHEST_PAIN'})-[:CAUSES*1..3]->(d:Disease)
   WHERE d.id IN ['DISEASE_ANGINA', 'DISEASE_MI', 'DISEASE_GERD', ...]
   RETURN path, d.name, d.prevalence_55_male
   ORDER BY d.prevalence_55_male DESC
   ```

3. **计算候选概率**：

   - 对每个候选疾病，结合先验概率（患病率）和路径权重，计算初始概率
   - 使用**模板C：证据条目库（2.2.3）**中的证据强度，调整概率

### 3.2 场景2：证据驱动的概率更新

**问题**：患者出现新证据"胸痛伴大汗"，如何更新疾病概率。

**使用流程**：

1. **查询证据条目库**：

   - 从**模板C：证据条目库（2.2.3）**读取该证据的属性：
     - 证据类型：症状组合
     - 证据强度：高
     - 特异性：多见于急性心肌梗死
     - 敏感性/特异性：对急性心肌梗死的敏感性0.7、特异性0.8

2. **贝叶斯更新**：

   - 使用**贝叶斯更新规则库（2.3.4）**中的计算公式
   - 基于先验概率和似然（敏感性/特异性），计算后验概率
   - 更新候选疾病的概率排序

3. **知识图谱路径验证**：

   ```cypher
   // 验证证据与疾病的关联路径
   MATCH (e:Evidence {id: 'EVIDENCE_CHEST_PAIN_WITH_SWEATING'})-[:SUPPORTS]->(d:Disease)
   WHERE d.id = 'DISEASE_MI'
   RETURN e, d, e.sensitivity, e.specificity
   ```

### 3.3 场景3：多跳推理路径解释

**问题**：如何构建从症状到疾病的可解释推理路径。

**使用流程**：

1. **生成推理路径**：

   ```cypher
   // 查询从症状到疾病的完整推理路径
   MATCH path = (s:Symptom)-[:CAUSES]->(d1:Disease)-[:DIFFERENTIAL_WITH]->(d2:Disease)
   WHERE s.id = 'SYMPTOM_CHEST_PAIN'
   RETURN path
   ```

2. **构建可解释路径**：

   - 路径：`胸痛 → 心血管疾病（知识图谱路径） → 急性心肌梗死（支持证据：ST段抬高）`
   - 用于**脑区G：可解释性与证据链服务**的证据链构建

### 3.4 场景4：检查/治疗建议查询

**问题**：某个疾病需要做什么检查、怎么治疗。

**使用流程**：

1. **查询疾病-检查关系**：

   ```cypher
   // 查询疾病需要做的检查
   MATCH (d:Disease {id: 'DISEASE_MI'})-[:REQUIRES_EXAMINATION]->(e:Examination)
   RETURN e.name, e.sensitivity, e.specificity
   ```

2. **查询疾病-治疗关系**：

   ```cypher
   // 查询疾病的治疗方案
   MATCH (d:Disease {id: 'DISEASE_MI'})-[:REQUIRES_TREATMENT]->(t:Treatment)
   RETURN t.name, t.type
   ```

## 4 规则推理的使用场景（不同情况如何使用）

### 4.1 场景1：入口判定与工作态切换

**问题**：用户想干什么，走A路径还是B路径。

**使用流程**：

1. **用户输入识别**：
   - 使用**症状/困扰识别规则库（2.3.1）**判断用户是否有症状/困扰
   - 如果识别到症状关键词 → 标记为"有症状"
   - 如果识别到"想体检"、"想减脂"等 → 标记为"无症状，健康管理需求"

2. **红旗信号检查**：
   - 使用**红旗信号库（2.3.1）**检查是否出现高危症状组合
   - 例如：用户说"胸痛+意识模糊" → 触发红旗条件 → 立即建议急诊，退出线上流程

3. **工作态判定**：
   - 使用**工作态判定规则库（2.3.1）**：
     - 出现红旗信号 → 进入临床诊疗态（B路径）
     - 有症状/困扰 + 无危险信号 → 进入临床诊疗态（B路径）
     - 无症状 + 无危险信号 → 进入健康管理态（A路径）

4. **方向澄清**（如果需要）：
   - 如果用户表达模糊（如"想体检 + 有点不舒服"），使用**方向澄清模板库（2.3.1）**生成澄清问题
   - 根据用户回答，使用**入口判定路径选择规则库（2.3.1）**确定路径

### 4.2 场景2：A路径（健康管理态）完整流程

**问题**：用户走A路径，从需求分类到结果输出、随访闭环。

**使用流程**：

1. **A1需求分类**：
   - 使用**需求分类规则库（2.3.2）**将用户需求归入四类之一
   - 例如：用户说"我想做个体检" → 匹配到"筛查建议"需求

2. **A2健康档案采集**：
   - 使用**健康档案字段清单（2.3.2）**确定需要采集的字段
   - 按字段清单逐一询问，缺失字段使用低信息模式兜底话术

3. **A3分支处理**（根据需求类型）：
   - **A3-1筛查建议**：使用**筛查建议规则库（2.3.2）**，根据年龄段/性别/风险因素推荐筛查项目
   - **A3-2体检异常解读**：使用**体检异常分级规则库（2.3.2）**，判定异常等级（轻度/中度/重度）并给出对应建议
   - **A3-3健康目标管理**：使用**健康目标管理模板库（2.3.2）**，生成行动计划
   - **A3-4计划性健康需求**：使用**计划性健康需求场景库（2.3.2）**，提供检查清单和时间表

4. **A4结果页输出**：
   - 使用**统一结果页模板库（2.3.2）**生成结果页，包含：一句话总结、现在建议做的事、暂时不建议做的事、下一次复查/更新时间点、退出A路径条件提示

5. **A5随访闭环**：
   - 使用**健康管理态随访规则库（2.3.2）**，根据需求类型设置随访节奏
   - 在随访节点提醒用户更新/复查/复盘

6. **A→B升级监控**：
   - 持续使用**健康管理态升级条件库（2.3.2）**监控升级触发条件
   - 如果症状加重、出现新症状、识别到风险信号 → 触发升级，切换到B路径

### 4.3 场景3：B路径（临床诊疗态）完整流程

**问题**：用户走B路径，从主诉收集到诊断分析、结论输出。

**使用流程**：

1. **主诉字段收集**：
   - 使用**主诉关键字段模板（2.3.1）**确定需要收集的字段（起病时间、起病方式、严重程度、症状性质等）
   - 使用**伴随症状清单（2.3.1）**询问伴随症状
   - 使用**关键背景字段（2.1.3）**收集患者背景信息

2. **信息缺口判定**：
   - 使用**信息缺口分级规则（2.3.1）**判定信息完整度
   - 如果必填项缺失 → 使用**智能追问题库（2.3.1）**追问
   - 如果信息完整度≥60%且无必填缺口 → 进入诊断分析

3. **问诊策略计算**（可选）：
   - 使用**临床决策分析驱动的问诊规则库（2.3.1）**计算信息增益、风险增益、成本效益
   - 优先问能排除高危诊断的问题（风险增益高）

4. **候选生成**（结合知识推理）：
   - 使用**模板A：主诉级候选集（2.2.1）**获得三层候选集合
   - 使用知识图谱（3.1）进行路径推理和概率计算
   - 结合**分层规则库（2.2.1）**确定每个候选属于哪一层（首要假设/主要备选/必须排除）

5. **分流路径推进**：
   - 使用**分流路径模板库（2.2.1）**和**关键分岔点清单（2.2.1）**进行分叉式问诊
   - 例如：第一个分叉问题"疼痛是急性还是慢性？" → 根据答案选择不同路径

6. **证据收集与概率更新**（结合知识推理）：
   - 使用**模板C：证据条目库（2.2.3）**收集证据
   - 使用知识图谱（3.1）进行贝叶斯更新，调整候选概率

7. **验证计划制定**：
   - 使用**验证计划库（2.2.2）**为必须排除的高危方向制定验证计划
   - 确定需要做什么检查、问什么问题、如何判定验证结果

8. **风险识别与分级**：
   - 使用**高危识别规则库（2.3.3）**识别高危情况
   - 使用**严重程度评估规则库（2.3.3）**评估严重程度
   - 使用**紧急程度分级规则库（2.3.3）**确定紧急程度（L1-L4）

9. **回填与重排**：
   - 当新信息出现（如检查结果、新症状），使用**回填与重排规则库（2.3.4）**重新排序诊断方向
   - 如果出现证据冲突，使用回退规则

10. **回退处理**：
    - 使用**回退条件清单（2.3.4）**判定是否需要回退
    - 例如：症状突然加重 → 回退到触发诊断或阶段1（健康状态判定）

11. **结论包生成**：
    - 使用**终点结论包模板库（2.3.1）**生成诊断结果输出
    - 包含：结论、必须排除项状态、关键依据、行动与随访

12. **复评与升级**：
    - 使用**复评与升级规则库（2.3.3）**设置复评时间窗
    - 监控升级触发条件，必要时建议就医

### 4.4 场景4：入口角度统一转换

**问题**：用户从家族史/既往史/体检异常入口，如何转换为主诉诊断流程。

**使用流程**：

1. **识别入口类型**：
   - 用户说"我父亲有糖尿病" → 识别为家族史入口
   - 用户说"我有高血压，最近感觉不太对" → 识别为既往史入口
   - 用户说"体检发现血压偏高" → 识别为体检异常入口
   - 用户说"我查出来了高血压" → 识别为已诊断疾病入口（使用**疾病名称归一化词表扩展（2.1.2）**）

2. **LLM推理可能主诉**：
   - 使用LLM从家族史/既往史/体检异常推理可能的主诉
   - 例如：家族史"糖尿病" → LLM推理可能主诉：["多饮", "多尿", "体重下降", "乏力"]

3. **映射表校验**：
   - 使用**家族史 → 可能主诉映射表（2.3.5）**校验LLM结果的合理性
   - 如果LLM推理的主诉不在映射表中 → 标记为低置信度，需要人工审核

4. **追问策略**：
   - 使用**家族史/既往史/体检异常入口追问策略库（2.3.5）**生成标准追问问题
   - LLM生成自然、口语化的追问问题，策略库用于校验问题质量

5. **转换为主诉入口**：
   - 根据追问结果，确定实际主诉
   - 转换为主诉诊断流程（B路径）或健康管理流程（A路径）
