# AI医生系统 - 表格文件结构与格式设计

> **设计目标**：为"知识内容混合存储方案"中所有表格文件设计详细的结构与格式  
> **创建日期**：2026-01-28  
> **文档版本**：v1.0

---

## 📋 文档总览

本文档详细设计了AI医生系统中所有表格文件的结构与格式，包括：
- **归一化词表**（7个文件）：症状、主诉、疾病、检查、指标、药物、体征
- **标准目录主数据**（4个文件）：症状、主诉、疾病、检验项目
- **医学概念本体与编码规范**（1个文件）：统一编码规范

每个表格文件都包含：
- 文件说明
- 字段定义
- 数据类型
- 约束条件
- 示例数据
- 使用说明

---

## 一、归一化词表（7个文件）

归一化词表用于将用户的各种表达方式映射到标准术语，支持同义词、别名、常用名等多种表达。

### 1.1 症状归一化词表

**文件名**：`symptom_normalization.csv`

**文件说明**：包含所有症状的同义词映射，将用户的口语化表达映射到标准症状术语。

**字段定义**：

| 字段名 | 数据类型 | 是否必填 | 说明 | 示例 |
|--------|---------|---------|------|------|
| standard_term | String | 是 | 标准症状术语（唯一） | 胸闷样不适 |
| standard_term_id | String | 是 | 标准术语ID（唯一标识符） | SYM_CHEST_DISCOMFORT_001 |
| synonym_1 | String | 否 | 同义词1 | 胸口闷 |
| synonym_2 | String | 否 | 同义词2 | 胸闷 |
| synonym_3 | String | 否 | 同义词3 | 胸憋气 |
| alias_1 | String | 否 | 别名1 | 胸闷感 |
| alias_2 | String | 否 | 别名2 | 胸部不适 |
| common_name_1 | String | 否 | 常用名1 | 憋气 |
| common_name_2 | String | 否 | 常用名2 | 气闷 |
| symptom_code | String | 是 | 症状编码（HPO/CUI等） | C1234567 |
| icd10_code | String | 否 | ICD-10编码 | R06.0 |
| snomed_code | String | 否 | SNOMED CT编码 | 29857009 |
| category | String | 是 | 症状分类 | 心血管系统 |
| subcategory | String | 否 | 症状子分类 | 胸部症状 |
| priority | Integer | 是 | 匹配优先级（1-10，数字越大优先级越高） | 5 |
| is_active | Boolean | 是 | 是否启用（true/false） | true |
| created_at | DateTime | 是 | 创建时间 | 2026-01-28T00:00:00Z |
| updated_at | DateTime | 是 | 更新时间 | 2026-01-28T00:00:00Z |
| version | String | 是 | 版本号 | v1.0 |
| notes | String | 否 | 备注说明 | 与胸痛区分 |

**约束条件**：
- `standard_term` 必须唯一
- `standard_term_id` 必须唯一，格式：`SYM_{分类}_{序号}`
- `priority` 范围：1-10
- 至少有一个同义词、别名或常用名

**示例数据**：


**使用说明**：
- 系统启动时加载到内存，构建倒排索引
- 支持精确匹配和模糊匹配
- 匹配时按priority排序，返回优先级最高的结果

## 四、通用字段说明

### 4.1 数据类型规范

| 数据类型 | 说明 | 格式示例 |
|---------|------|---------|
| String | 字符串类型 | "胸痛" |
| Integer | 整数类型 | 5 |
| Float | 浮点数类型 | 0.05 |
| Boolean | 布尔类型 | true / false |
| DateTime | 日期时间类型 | 2026-01-28T00:00:00Z (ISO 8601格式) |

### 4.2 编码规范

**ID命名规范**：
- 症状：`SYM_{分类}_{序号}`，如 `SYM_CHEST_PAIN_001`
- 主诉：`CC_{分类}_{序号}`，如 `CC_CHEST_PAIN_001`
- 疾病：`DIS_{分类}_{序号}`，如 `DIS_DVT`
- 检查：`EXAM_{分类}_{序号}`，如 `EXAM_LOWER_VEIN_US_001`
- 指标：`IND_{分类}_{序号}`，如 `IND_TROPONIN_I_001`
- 药物：`MED_{分类}_{序号}`，如 `MED_ASPIRIN_001`
- 体征：`SIGN_{分类}_{序号}`，如 `SIGN_LOWER_EDEMA_001`

**UUID规范**：
- 使用标准UUID格式：`xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx`
- 所有实体必须包含UUID作为唯一标识

### 4.3 文件格式规范

**文件格式**：CSV（逗号分隔值）

**编码**：UTF-8（带BOM可选）

**分隔符**：逗号（`,`）

**引号**：字段包含逗号、换行符或引号时，使用双引号包裹

**换行符**：Unix格式（`\n`）或Windows格式（`\r\n`）

**首行**：必须包含字段名（表头）

### 4.4 数据验证规则

1. **必填字段验证**：所有标记为"是"的字段必须填写
2. **唯一性验证**：所有标记为"唯一"的字段值不能重复
3. **格式验证**：
   - UUID必须符合UUID格式
   - DateTime必须符合ISO 8601格式
   - 编码必须符合相应编码规范
4. **范围验证**：
   - Integer/Float必须在指定范围内
   - Boolean必须是true或false
5. **关联验证**：
   - 编码字段必须与医学概念本体表中的编码对应
