# 用户问题、症状、主诉、疾病四个概念的区别与定位说明

> **文档目的**：明确用户问题、症状、主诉、疾病四个概念在问诊和循证医学过程中的区别与定位  
> **创建日期**：2026-02-03  
> **文档版本**：v2.0

---

## 一、四个核心概念的定义

| 概念 | 定义 | 在系统中的角色 | 示例 |
|------|------|---------------|------|
| **用户问题** | 用户用自然语言描述的身体不适或健康需求 | **输入层**：系统的原始输入，需要被理解和解析 | "我最近胸口闷，走几步就喘"<br>"我确诊了高血压，现在怎么办？" |
| **症状** | 经过归一化处理后的标准医学概念（CUI编码） | **中间层**：概念归一化的产物，用于知识图谱检索 | 胸闷样不适(C0232118)、活动后气促(C0030193) |
| **主诉** | 从症状组合中识别出的主要问题，是问诊的起点和诊断推理的入口 | **问诊层**：问诊流程的组织单位，决定问诊方向 | "胸痛"、"呼吸困难"、"水肿" |
| **疾病** | 诊断推理的目标（症状诊断路径），或用户咨询的起点（已确诊疾病咨询路径） | **诊断层/咨询层**：诊断结论的输出单位，或咨询服务的入口 | "心绞痛"、"急性心肌梗死"、"高血压病" |

## 二、四个概念在问诊过程中的定位

### 2.1 问诊过程：从用户问题到主诉

**问诊过程的目标**：将用户的自然语言描述转化为结构化的主诉信息，为诊断推理做准备。

```
用户问题（自然语言）
    ↓ [概念归一化]
症状（标准医学概念）
    ↓ [症状组合识别]
主诉（问诊入口）
    ↓ [主诉关键字段填充]
结构化问题清单（问诊输出）
```

**详细流程**：

1. **用户问题 → 症状（Step 1：识别问题）**
   - **任务**：概念归一化，将用户的口语化表达转换为标准医学概念
   - **方法**：使用归一化词表进行映射
   - **示例**：
     - 用户说："胸口闷，走几步就喘"
     - 系统识别为：`胸闷样不适(C0232118)` + `活动后气促(C0030193)`
   - **输出**：症状列表（带CUI编码）

2. **症状 → 主诉（Step 1：识别问题）**
   - **任务**：从症状组合中识别主诉候选，确定问诊入口
   - **方法**：使用症状到主诉映射规则（规则层第8项）
   - **示例**：
     - 症状组合：`胸闷样不适` + `活动后气促`
     - 系统识别主诉候选：`胸痛`、`呼吸困难`
     - 通过澄清规则确定最终主诉：`胸痛`
   - **输出**：主诉名称 + 主诉关键字段配置

3. **主诉 → 结构化问题清单（Step 1：识别问题）**
   - **任务**：根据主诉模板生成问诊问题清单
   - **方法**：使用主诉模板（核心层第5项）和结构化问题清单模板（基础层第4项）
   - **示例**：
     - 主诉：`胸痛`
     - 系统加载主诉关键字段配置：起病时间、部位、性质、严重度等
     - 生成问题清单：什么时候开始的？具体哪里不舒服？更像刺痛还是压着？
   - **输出**：结构化问题清单（包含主要问题、伴随问题、关键背景、信息缺口）

**问诊过程的特点**：
- **主诉是问诊的组织单位**：不同主诉对应不同的问诊模板和问题清单
- **主诉模板决定问诊方向**：主诉模板定义了需要收集哪些关键信息
- **症状是主诉的组成部分**：主诉可能包含多个症状，症状是主诉的细化

## 三、四个概念在循证医学过程中的定位

### 3.1 循证医学过程：从主诉到疾病（症状诊断路径）

**循证医学过程的目标**：基于结构化问题清单，通过知识图谱推理生成疾病候选集，并形成可追溯的证据链。

```
结构化问题清单（问诊输出）
    ↓ [知识图谱路径检索]
推理路径（症状→中间概念→疾病）
    ↓ [路径评分排序]
疾病候选集（诊断输出）
    ↓ [证据回填与验证]
最终诊断结论（疾病名称 + 证据链）
```

**详细流程**：

1. **结构化问题清单 → 推理路径（Step 2：构建候选集）**
   - **任务**：从知识图谱检索症状到疾病的推理路径
   - **方法**：使用DR.KNOWS方法，从Neo4j知识图谱检索路径
   - **输入**：症状CUI列表（来自结构化问题清单）
   - **示例**：
     - 症状：`胸痛(C0232118)` + `活动后气促(C0030193)`
     - 检索路径：
       - 路径1：`胸痛` → `心血管系统` → `心绞痛`
       - 路径2：`活动后气促` → `呼吸系统` → `慢性阻塞性肺疾病`
   - **输出**：推理路径列表（50-100条路径）

2. **推理路径 → 疾病候选集（Step 2：构建候选集）**
   - **任务**：从路径中提取疾病候选，进行三层分层
   - **方法**：路径评分排序 + 候选去重 + 三层分层
   - **示例**：
     - 从路径中提取疾病：`心绞痛`、`急性心肌梗死`、`慢性阻塞性肺疾病`
     - 三层分层：
       - 首要假设：`心绞痛`（路径数量最多）
       - 主要备选：`慢性阻塞性肺疾病`（路径数量较多）
       - 必须排除：`急性心肌梗死`（高危疾病，必须优先排除）
   - **输出**：三层候选集（每个候选包含入选依据、推理路径、信息缺口）

3. **疾病候选集 → 最终诊断结论（Step 4-5：证据采集与回填）**
   - **任务**：采集关键证据，验证疾病候选，形成最终诊断
   - **方法**：路径约束推理 + 证据回填 + 路径重评估
   - **示例**：
     - 采集证据：心电图ST段抬高、肌钙蛋白升高
     - 证据支持：`急性心肌梗死`（路径被强烈支持）
     - 证据反对：`心绞痛`（路径被反对）
     - 最终诊断：`急性心肌梗死`（可确证）+ 证据链（来自推理路径）
   - **输出**：终点结论包（结论、必须排除项状态、关键依据、行动与随访）

**循证医学过程的特点**：
- **疾病是诊断的目标**：疾病候选集是诊断推理的终点
- **疾病模板定义疾病特征**：疾病模板记录了疾病的典型症状、体征、检查、治疗等
- **推理路径连接主诉和疾病**：路径从主诉的症状出发，经过中间概念，到达疾病

## 四、疾病作为用户咨询起点的场景（已确诊疾病咨询路径）

### 4.1 疾病作为起点的场景

**场景描述**：用户直接咨询已确诊的疾病，例如：
- "我确诊了高血压，现在怎么办？"
- "我得了糖尿病，需要注意什么？"
- "我查出来有冠心病，该怎么治疗？"

**处理流程**：

```
用户问题（已确诊疾病）
    ↓ [疾病识别与归一化]
疾病（标准医学概念）
    ↓ [入口判定：已确诊疾病咨询]
已确诊疾病咨询路径
    ↓ [疾病模板查询]
疾病相关信息（治疗、随访、注意事项）
    ↓ [生成咨询建议]
咨询结论包（治疗建议、随访计划、注意事项）
```

### 4.2 已确诊疾病咨询的处理逻辑

1. **用户问题 → 疾病（入口判定）**
   - **任务**：识别用户是否在咨询已确诊的疾病
   - **方法**：使用归一化词表识别疾病名称，判断是否为已确诊表达
   - **示例**：
     - 用户说："我确诊了高血压"
     - 系统识别为：`高血压病(I10)` + 已确诊标记
   - **输出**：疾病名称 + 已确诊标记

2. **疾病 → 已确诊疾病咨询路径（路径选择）**
   - **任务**：根据已确诊疾病，选择咨询路径
   - **方法**：使用入口判定规则（规则层第14项）和入口角度统一转换规则（规则层第16项）
   - **处理策略**：
     - **策略1**：直接进入疾病咨询流程（治疗建议、随访管理）
     - **策略2**：转换为相关主诉，进入症状诊断路径（关注疾病相关症状和并发症）
   - **示例**：
     - 已确诊疾病：`高血压病`
     - 系统选择：转换为相关主诉（如"头痛"、"头晕"），进入症状诊断路径
     - 或：直接进入疾病咨询流程，提供治疗建议和随访计划
   - **输出**：咨询路径选择 + 相关主诉（如适用）

3. **疾病模板查询（疾病咨询流程）**
   - **任务**：查询疾病模板，获取疾病相关信息
   - **方法**：使用疾病模板（核心层第6项）查询疾病特征、治疗、随访等信息
   - **示例**：
     - 疾病：`高血压病`
     - 系统查询疾病模板：
       - 典型症状：头痛、头晕、心悸等
       - 治疗建议：生活方式干预、药物治疗等
       - 随访计划：定期监测血压、定期复查等
       - 注意事项：避免高盐饮食、规律运动等
   - **输出**：疾病相关信息（治疗、随访、注意事项）

4. **生成咨询建议（咨询结论包）**
   - **任务**：基于疾病模板生成咨询建议
   - **方法**：使用治疗引擎服务、随访计划服务等
   - **示例**：
     - 疾病：`高血压病`
     - 咨询建议：
       - 治疗建议：建议使用ACE抑制剂，起始剂量10mg/天
       - 随访计划：1周后复查血压，1个月后评估疗效
       - 注意事项：低盐饮食、规律运动、戒烟限酒
   - **输出**：咨询结论包（治疗建议、随访计划、注意事项）

### 4.3 疾病作为起点的特点

- **疾病是咨询的入口**：用户直接提供疾病名称，系统需要识别并处理
- **疾病模板提供咨询依据**：疾病模板记录了疾病的治疗、随访、注意事项等信息
- **可能转换为主诉**：根据咨询内容，可能转换为相关主诉，进入症状诊断路径
- **关注疾病管理**：已确诊疾病咨询更关注疾病管理、治疗建议、随访计划等

## 五、为什么需要从主诉和疾病分别填充？

### 5.1 主诉模板的作用（问诊阶段）

**主诉模板**（核心层第5项）用于**问诊阶段**，定义：
- **问诊入口**：用户说"胸痛"，系统知道这是主诉，需要启动问诊流程
- **问诊方向**：不同主诉对应不同的问诊模板和问题清单
- **关键字段**：每个主诉需要收集哪些关键信息（起病时间、部位、性质等）
- **候选疾病清单**：每个主诉对应的候选疾病集合（用于Step 2的候选生成）

**主诉模板的填充内容**：
- 主诉定义、包含范围、排除范围
- 适用人群、适用场景
- 最小关键字段配置（主诉表2）
- 三层候选集合（首要假设、主要备选、必须排除）
- 分流路径、关键差异点

**为什么需要主诉模板**：
- **问诊需要结构化**：不同主诉需要问不同的问题，主诉模板定义了问诊的结构
- **候选生成需要入口**：主诉是候选生成的起点，主诉模板提供了候选疾病的初始清单
- **分流路径需要组织**：主诉模板定义了如何通过分叉式问诊快速区分诊断方向

### 5.2 疾病模板的作用（诊断推理阶段 + 疾病咨询阶段）

**疾病模板**（核心层第6项）用于**诊断推理阶段**和**疾病咨询阶段**，定义：
- **疾病特征**：每个疾病的典型症状、典型体征、典型背景
- **疾病关系**：疾病与其他概念的关系（症状、检查、治疗、其他疾病）
- **疾病属性**：疾病ID、名称、患病率、先验概率等
- **证据条目**：支持该疾病的证据、反对该疾病的证据、差异点线索
- **治疗建议**：疾病的治疗方案、药物建议、生活方式干预等
- **随访计划**：疾病的随访频率、复查项目、监测指标等

**疾病模板的填充内容**：
- 疾病节点属性（ID、名称、患病率）
- 关系边（疾病→症状、疾病→检查、疾病→治疗、疾病→疾病）
- 可计算属性（先验概率、似然评分、后验概率）
- 治疗建议（治疗方案、药物建议、生活方式干预）
- 随访计划（随访频率、复查项目、监测指标）

**为什么需要疾病模板**：
- **诊断推理需要疾病知识**：疾病模板记录了疾病的完整知识，用于路径评分和证据评估
- **证据链需要疾病特征**：疾病模板定义了哪些证据支持该疾病，哪些证据反对该疾病
- **鉴别诊断需要疾病关系**：疾病模板记录了易混淆疾病的关系，用于鉴别诊断
- **疾病咨询需要治疗信息**：疾病模板记录了疾病的治疗、随访、注意事项等信息

### 5.3 两者的协作关系

```
场景1：症状诊断路径
问诊阶段（主诉模板）
    ↓
结构化问题清单
    ↓
诊断推理阶段（疾病模板）
    ↓
最终诊断结论

场景2：已确诊疾病咨询路径
用户问题（已确诊疾病）
    ↓
疾病识别（归一化词表）
    ↓
疾病咨询流程（疾病模板）
    ↓
咨询结论包
```

**协作流程**：
1. **主诉模板提供问诊结构**：用户说"胸痛"，主诉模板告诉系统需要问哪些问题
2. **主诉模板提供候选清单**：主诉模板提供初始候选疾病清单（首要假设、主要备选、必须排除）
3. **疾病模板提供推理依据**：疾病模板提供每个疾病的特征和证据，用于路径评分和证据评估
4. **疾病模板提供咨询信息**：疾病模板提供疾病的治疗、随访、注意事项等信息，用于疾病咨询
5. **两者共同形成诊断结论**：主诉模板提供候选方向，疾病模板提供推理依据，两者结合形成最终诊断

**为什么不能只用其中一个**：
- **只用主诉模板**：无法进行深入的诊断推理，无法评估证据强度，无法形成完整的证据链，无法提供疾病咨询
- **只用疾病模板**：无法组织问诊流程，无法确定问诊方向，无法生成结构化问题清单
- **两者结合**：主诉模板负责问诊组织，疾病模板负责诊断推理和疾病咨询，两者缺一不可

## 六、总结

### 6.1 四个概念的区别总结

| 概念 | 定位 | 作用 | 在系统中的位置 |
|------|------|------|---------------|
| **用户问题** | 输入层 | 系统的原始输入，需要被理解和解析 | Step 1：识别问题（输入） |
| **症状** | 中间层 | 概念归一化的产物，用于知识图谱检索 | Step 1：识别问题（输出）→ Step 2：构建候选集（输入） |
| **主诉** | 问诊层 | 问诊流程的组织单位，决定问诊方向 | Step 1：识别问题（输出）→ Step 2：构建候选集（输入） |
| **疾病** | 诊断层/咨询层 | 诊断推理的目标（症状诊断路径），或用户咨询的起点（已确诊疾病咨询路径） | Step 2：构建候选集（输出）→ Step 5：输出结论包（输出）<br>或：入口判定（输入）→ 疾病咨询流程（输出） |

### 6.2 主诉模板和疾病模板的协作关系

- **主诉模板**：负责问诊阶段，定义问诊结构、候选清单、分流路径
- **疾病模板**：负责诊断推理阶段和疾病咨询阶段，定义疾病特征、证据条目、推理依据、治疗建议、随访计划
- **两者结合**：主诉模板提供问诊组织和候选方向，疾病模板提供推理依据、证据链和咨询信息，两者缺一不可

### 6.3 疾病的双重角色

- **作为诊断目标**：在症状诊断路径中，疾病是诊断推理的终点，通过主诉→症状→推理路径→疾病候选集→最终诊断的流程得出
- **作为咨询起点**：在已确诊疾病咨询路径中，疾病是用户咨询的起点，系统直接识别疾病名称，提供治疗建议、随访计划、注意事项等咨询服务
