# 如何使用疾病模板搭建知识图谱

系统有两种工作方式（两条主线）：

- **健康管理态（A路径）**：面向“无症状或健康状态不确定”的人，输出筛查/健康管理建议、形成随访闭环，并在出现风险时升级处理。
- **临床诊疗态（B路径）**：面向“疑似/明确有病”的人，做鉴别诊断、制定下一步验证计划、输出可解释的结论与行动建议。

用户进入系统常见入口至少有两类：

- **从症状/诉求来问**：比如“胸痛、发热、腹痛、体检异常、想减脂”等（多数情况属于A路径或B路径的起点）。
- **从已确诊疾病来问**：比如“我已经确诊了XX病，怎么治疗/怎么处理/要不要复查/有什么风险”（需要“疾病知识 + 安全边界”）。

## 1. 需要"疾病模板+"：从一张表到知识图谱的必经之路

> **说明**：疾病模板是知识体系的核心基础，这一点毋庸置疑。但要让系统真正"活起来"、能够推理和决策，我们需要在疾病模板的基础上，补充一些"连接器"和"翻译器"。这就像建房子：疾病模板是砖块，但还需要钢筋（关系网络）、水泥（归一化标准）、图纸（流程规则）才能建成可用的房子。

### 1.1 疾病模板能建知识图谱，但还缺“能跑起来”的运行层

#### 现状：只有疾病模板时，会发生什么？

疾病模板非常重要，它能把“疾病”这类核心概念结构化。但如果**只交付疾病模板**，即使搭了知识图谱，系统也很难把“问诊→推理→决策→安全”完整跑通，常见会卡在 5 件事上（后文逐一展开）：

1. **候选太多、缺少排序**：从“胸痛”倒推可能得到 20+ 疾病，但不知道优先级与必须排除项（见1.3的“分流”与1.6的整体框架）
2. **证据不可计算**：同一个证据在不同疾病里写法不一，无法做概率更新（见1.2）
3. **问诊缺路径**：不知道先问哪个关键问题才能最快区分方向（见1.3）
4. **安全缺硬规则**：红旗信号/急症分级不能靠“模板自然覆盖”（见1.4）
5. **输入缺翻译**：用户口语表达无法稳定映射到标准概念（见1.5）

#### ❌既然有图谱，就从症状倒推疾病

这个思路**技术上没问题**：图数据库本身支持“沿关系反向遍历”，关系边是正向还是反向，更多是语义命名与建模习惯。

但关键问题在于：**倒推只能给出“有哪些候选”**，却解决不了上面 2~5 的“运行层”问题（证据、路径、安全、归一化），同时也无法保证倒推出来的候选能被正确排序、可解释、可评估、可迭代。

#### 结论：以疾病模板为核心，但必须补齐“运行层”

所以我们提出“疾病模板+”思路：在疾病模板基础上，补齐**模板C（证据条目库）**、**分流路径**、**红旗安全规则**、**归一化基础层**（以及主诉级候选集/排序框架），让系统从“能查到”变成“能跑起来”。

### 1.2 证据推理：为什么“把证据写在疾病模板里”不够

#### 问题：证据不统一，就无法计算

**场景**：患者说“胸痛，还出了很多汗”。系统真正要做的是：这个“胸痛伴大汗”对哪些疾病更支持？支持力度多大？出现/不出现时概率如何更新？

如果证据只写在疾病模板里，常见会出现：

- **同证据不同写法**：A病写“出汗”，B病写“冷汗”，C病写“汗出明显”，系统难以统一识别
- **无法落到可计算字段**：缺少敏感性/特异性/似然比等结构化数据，贝叶斯更新无法稳定落地
- **证据复用困难**：同一条证据要在多个疾病模板里重复维护，成本高、质量难控

#### ❌在图谱边上“加权重”，或直接在模板里写权重

常见做法是：

- 在 `Disease-HasSymptom-Symptom` 边上加权重，表示“相关性”
- 或在疾病模板里给症状/检查写一个“重要程度/权重”

#### 为什么不好：权重≠证据，且不可治理

这些做法最大的问题是：

- **权重口径不统一**：不同人写的权重不可比，难以解释“为什么这个更像”
- **无法区分证据类型**：症状、体征、检查结果、风险因子混在一起，推理链条会变成“拍脑袋加减分”
- **难评估难迭代**：当线上结果不准，你很难定位是哪个证据条目/哪个问法/哪个映射出了问题

#### 结论：模板C（证据条目库）把“证据”抽成标准资产

把证据从疾病卡片里抽出来，变成可复用条目（带统一字段与问法），再用关系表把证据与疾病连接：

- **证据条目**：证据ID、证据类型（症状组合/检查/体征/画像）、标准问法/获取方式、强度、敏感性/特异性（或可近似的LR）
- **证据→疾病关系**：支持/反对、作用方向（上移/下移/剔除）、适用人群、证据冲突处理

一句话：**没有可治理的“证据条目库”，知识图谱就很难从“查到”升级为“算得动”。**

### 1.3 分流问诊：为什么“倒推出候选”仍然走不通对话

#### 问题：候选有了，但不知道怎么问，效率会崩

**场景**：用户只说“胸痛”。系统要做的不是“问一堆”，而是**用最少的问题先排高危、再快速分流**。

只有疾病模板时常见后果：

- **问题顺序不可控**：先问的不是“最能区分方向”的关键问题
- **信息收集无闭环**：缺少“必问/重要/可选”分级，容易问不到关键字段
- **对话体验差**：问题太多、太散，用户容易中途退出

#### ❌把候选列出来，然后挨个匹配症状/逐条追问

典型做法：

- 候选疾病列表出来后，对每个候选的“典型症状”逐条问
- 或者让LLM自由发挥追问，图谱只当参考

#### 为什么不好：成本高、漏问风险大、无法保证先排高危

这会带来：

- **问诊轮次爆炸**：候选多→要问的症状更多→体验快速恶化
- **缺少“最优分流”**：没有明确的分岔点设计，信息增益低
- **安全靠运气**：如果红旗问题没被优先问到，就可能延误处理

#### 结论：分流路径模板 + 关键字段模板 + 信息缺口分级

用结构化的“路线图”把对话跑通：

- **分流路径模板**：定义关键分岔点（例如：急性/慢性、活动相关/静息、伴随呼吸困难/出汗等），按路径推进
- **主诉关键字段模板**：每个主诉必须采集哪些字段（起病方式、严重程度、诱因缓解等）
- **信息缺口分级**：必问项缺失就追问，达到阈值再进入推理与排序

一句话：**候选是“地图”，分流路径才是“导航”。**

### 1.4 安全机制：为什么必须“独立于疾病模板”

#### 问题：安全是“跨疾病的硬约束”，不是疾病属性

**场景**：用户说“胸痛+意识模糊”。系统首要目标不是“更像哪个病”，而是**立即建议急诊/呼叫急救**。

如果把安全逻辑散落在疾病模板里，会出现：

- **红旗分散**：每个疾病模板写一段“危险”，但系统无法统一触发与统一动作
- **优先级冲突**：推理模块还在排序，安全模块应该已经中断流程
- **难以审计**：上线后很难证明“所有红旗都覆盖、都能触发”

#### ❌靠倒推候选里“包含高危病”来提示

即：倒推出急性心梗/夹层等高危候选，就提示“可能严重，请就医”。

#### 为什么不好：高危提示不等于高危触发

关键区别：

- **高危提示**：给一个建议，可能被对话继续覆盖/稀释
- **高危触发**：直接进入安全动作（急诊建议、停止线上流程、明确时间窗与下一步）

#### 结论：红旗信号库 + 风险分级规则（独立规则层）

把安全做成“总开关”：

- **红旗信号库**：按主诉/场景维护高危组合（症状+体征+背景）
- **紧急度分级**：L1-L4 对应动作（立即急诊/尽快就医/观察复评等）
- **升级/回退机制**：新信息出现时触发升级，中断原流程

一句话：**安全是“先于推理”的控制层，必须独立建设。**

### 1.5 归一化：为什么不能只靠LLM“临时翻译”

#### 问题：不归一化，就没有稳定连接与稳定评估

**场景**：用户说“胸口闷”，知识库/图谱里是“胸闷样不适”。如果映射不稳定，就会出现“同一句话这次能匹配，下次匹配不到”的问题。

只有疾病模板时常见后果：

- **同义词/口语/缩写覆盖不足**：模板里写“胸闷”，用户说“憋得慌/闷得慌/胸前发紧”
- **多义歧义无法处理**：同一个词在不同语境下对应不同概念
- **无法测试**：没有确定性的映射表，就很难做回归测试与质量评估

#### ❌让LLM直接把用户话翻成标准术语

这能解决一部分体验问题，但会引入：

- **不稳定与不可控**：同一输入可能产生不同映射
- **不可审计**：难以证明“映射覆盖率”和“错误率”
- **难以持续治理**：一旦出错，不知道该修哪条规则/哪条词表

#### 结论：基础层“归一化词表 + 编码规范”做成可治理资产

把“翻译”变成可运营的资产：

- **归一化词表**：同义词→标准术语→概念ID（含人群/场景/歧义处理）
- **编码规范**：疾病/症状/检查/药物各自统一ID体系，便于跨服务复用
- **LLM做增量**：LLM可以做“召回”，但必须被词表/规则校验并可回填治理

一句话：**没有归一化，知识图谱就无法稳定连接，更无法规模化迭代。**

### 1.6 总结：疾病模板是"核心"，但不是"全部"

| 组件             | 作用                                       | 类比                     |
| ---------------- | ------------------------------------------ | ------------------------ |
| **疾病模板**     | 定义每个疾病的"身份证"（症状、检查、治疗） | 砖块（核心材料）         |
| **主诉级候选集** | 从症状入口找到候选疾病                     | 目录索引（入口导航）     |
| **证据条目库**   | 可计算的证据，支持概率推理                 | 标准度量衡（统一口径）   |
| **分流路径**     | 问诊流程的"路线图"                         | GPS导航（路径规划）      |
| **安全规则库**   | 高危识别和安全机制                         | 安全系统（独立保障）     |
| **归一化基础层** | 概念标准化和映射                           | 标准地名系统（连接前提） |

**核心观点**：

- 疾病模板是知识体系的**核心基础**，这一点非常重要
- 但要让系统真正"活起来"，需要在这些"砖块"之间架起"钢筋"（关系网络）和"水泥"（归一化标准），并配备"图纸"（流程规则）
- 这不是"替代"疾病模板，而是"增强"疾病模板，让它在知识图谱中发挥作用
