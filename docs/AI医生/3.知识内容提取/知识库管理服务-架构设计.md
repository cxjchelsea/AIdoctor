# 知识库管理服务 - 架构设计

> **设计目标**：为知识库的导入、清洗、管理设计完整的架构方案  
> **创建日期**：2026-01-28  
> **文档版本**：v1.0

---

## 📋 架构总览

### 推荐方案：独立后端服务 + 管理端界面

**架构组成**：
1. **knowledge-management-service**（后端服务）：负责知识库的导入、清洗、验证、管理
2. **frontend-admin**（管理端界面）：提供可视化的知识库管理界面
3. **数据存储**：知识图谱（Neo4j）、表格文件（CSV/Excel）、配置文件（YAML）

**架构优势**：
- ✅ **职责清晰**：后端专注业务逻辑，前端专注展示交互
- ✅ **独立部署**：知识库管理服务可独立部署和扩展
- ✅ **易于维护**：代码组织清晰，便于长期维护
- ✅ **可扩展性强**：后续可增加API接口供其他服务调用
- ✅ **统一管理**：在管理端统一管理所有知识内容

## 🏗️ 架构设计

### 1. 后端服务：knowledge-management-service

#### 1.1 服务定位

**服务职责**：
- 知识图谱数据导入、清洗、验证
- 表格文件解析、转换、导入
- 配置文件验证、管理
- 知识库版本管理
- 数据质量检查
- 导入任务调度和监控

**技术栈**：
- **框架**：FastAPI（与现有服务保持一致）
- **图数据库**：Neo4j（与diagnosis-engine-service共用）
- **文件处理**：pandas、openpyxl、PyYAML
- **任务调度**：Celery（可选，用于异步导入任务）

## 🔄 数据流转

### 导入流程

```
1. 用户上传文件（前端）
   ↓
2. 文件上传到后端（POST /api/v1/import/...）
   ↓
3. 后端保存文件到 data/source/
   ↓
4. 执行数据清洗（DataCleaner）
   ↓
5. 执行导入（Importer）
   ↓
6. 数据验证（Validator）
   ↓
7. 返回导入结果（前端显示）
```

### 版本管理流程

```
1. 创建版本快照（VersionService）
   ↓
2. 保存到版本库
   ↓
3. 版本对比（可选）
   ↓
4. 版本回滚（如需要）
```

## 📦 部署方案

### 1. Docker部署

在`docker-compose.yml`中新增服务：

```yaml
knowledge-management-service:
  build: ./knowledge-management-service
  container_name: knowledge-management-service
  ports:
    - "8094:8094"
  environment:
    - NEO4J_URI=bolt://neo4j:7687
    - NEO4J_USER=neo4j
    - NEO4J_PASSWORD=password
    - DATA_DIR=/app/data
  volumes:
    - ./knowledge-management-service/data:/app/data
    - ./knowledge-management-service/logs:/app/logs
  depends_on:
    - neo4j
  networks:
    - aidoctor-network
  restart: unless-stopped
```

### 2. 服务配置

**环境变量**：
- `NEO4J_URI`：Neo4j连接地址
- `NEO4J_USER`：Neo4j用户名
- `NEO4J_PASSWORD`：Neo4j密码
- `DATA_DIR`：数据目录路径
- `LOG_LEVEL`：日志级别

## 🔗 与其他服务的关系

### 1. 与diagnosis-engine-service的关系

- **共享Neo4j数据库**：两个服务连接同一个Neo4j实例
- **数据同步**：knowledge-management-service导入数据后，diagnosis-engine-service自动可用
- **版本控制**：导入新版本时，可通知diagnosis-engine-service重新加载

### 2. 与clinical-parsing-service的关系

- **词表同步**：归一化词表导入后，clinical-parsing-service需要重新加载词表
- **配置同步**：基础标准配置更新后，需要通知clinical-parsing-service

### 3. 与其他服务的关系

- **配置分发**：配置文件导入后，需要分发到对应的服务（diagnosis-engine-service、health-state-assessment-service等）
