# 知识内容提取 - 大规模结构化数据提取指南

---

## 一、提取方法

### 1.1 选定方案：半自动化（人机协作）

**核心工作流程**：

```
PDF/文档 → AI初步提取 → 人工审核 → 修正与补充 → 批量导入系统
```

---

## 二、七阶段架构框架（理论指导）

### 2.1 总体架构逻辑

将**医学书籍 PDF**中的疾病相关内容，按照**统一疾病结构模板**，批量转化为**结构一致、可追溯、可复用的疾病知识数据**。

> **核心原则**：这是**知识抽取（Knowledge Extraction）**，不是知识推理（Reasoning）。我们不做诊断结论生成，不做跨书推理融合，专注于从单书中准确提取结构化信息。

**实际执行顺序**（按逻辑流程）：

```
【前置】统一疾病结构模板定义
 → 【前置】疾病目录定义
 → 阶段一：书籍接入与版本治理（找书）
 → 阶段二：结构解析（粗解析，识别章节结构）
 → 阶段三：定位疾病章节（根据疾病目录确定范围）
 → 阶段四：精解析（只解析疾病相关章节）
 → 阶段五：文本分段与疾病内容聚合（切分）
 → 阶段六：结构化抽取（AI提取）
 → 阶段七：校验、审核与入库
```

**执行逻辑说明**：

1. **先定义模板**：确定要提取的结构标准（这是整个提取的目标）
2. **再定义疾病目录**：明确要提取哪些疾病（这是提取的范围）
3. **找书处理**：确定要处理的书籍
4. **结构解析**：粗解析整本书，仅识别章节结构、页码、目录（避免一次性解析整本书的幻觉问题）
5. **定位疾病章节**：根据疾病目录，确定每个疾病在哪些章节/页码
6. **精解析**：只详细解析疾病相关的章节，跳过无关章节（提高效率和准确性）
7. **切分聚合**：将精解析的文本按疾病切分聚合
8. **结构化抽取**：对每个疾病的文本进行AI提取
9. **校验入库**：最后进行质量校验和入库

### 2.2 【前置步骤】统一疾病结构模板定义

#### 2.2.1 模板设计原则

1. **结构稳定**（长期不变）
2. **字段语义清晰**
3. **允许缺失，不允许推断**
4. **每个大字段都可溯源**

**实现逻辑**：

- 定义标准化的JSON Schema结构
- 明确每个字段的含义和数据类型
- 规定哪些字段必填，哪些可选
- 要求每个字段都要标注来源位置

### 2.3 【前置步骤】疾病目录定义

#### 2.3.1 疾病目录的作用

- 定义"要抽取哪些疾病"
- 控制抽取边界
- 支撑任务拆分、进度管理、断点续跑

#### 2.3.3 每个疾病目录项至少包括

- 标准疾病名（主键）
- 别名（可选）
- 所属章节范围（如果已知）
- 书籍来源 ID

> **注意**：**疾病目录是人工或半人工确定的，不交给模型生成**

**实现逻辑**：

- 建立疾病目录管理系统
- 支持从多个来源（目录、索引、标准表）导入疾病列表
- 建立标准疾病名与别名的映射关系
- 记录疾病在书籍中的位置范围（如果已知）

### 2.4 阶段一：书籍接入与版本治理

#### 2.4.1 书籍基础信息管理

每一本书都必须有**唯一身份**：

- **书名**（中文/英文）
- **版本** / 出版年份
- **ISBN**（如有）
- **学科领域**（内科 / 外科 / 儿科等）
- **使用状态**（启用 / 停用 / 重跑中）

#### 2.4.2 核心原则

> 同一本书的不同版本 = 不同数据源  
> 抽取结果**不覆盖旧版本**

**实现逻辑**：

- 建立书籍注册表，为每本书分配唯一标识（书名_版本）
- 记录书籍的完整元数据信息
- 支持多版本并存，便于版本对比和历史追溯

### 2.5 阶段二：结构解析（粗解析）

#### 2.5.1 目标

**避免一次性解析整本书带来的幻觉问题**，先进行粗解析，仅识别书籍的基本结构。

#### 2.5.2 解析内容

- **章节结构**：识别所有章节标题、小节标题
- **页码信息**：建立页码与章节的对应关系
- **目录信息**：提取书籍目录（如果存在）
- **索引信息**：提取书籍索引（如果存在）

#### 2.5.3 输出形式

- 书籍 ID
- 章节列表（章节标题、起始页码、结束页码）
- 目录结构（层级关系）
- 索引信息（如果有）

#### 2.5.4 为什么先粗解析？

- **避免幻觉**：一次性解析整本书，PDF解析工具可能出现错误、格式混乱、信息丢失
- **提高效率**：只解析结构，速度快，资源消耗低
- **便于定位**：有了结构信息，才能准确找到疾病所在的章节范围

**实现逻辑**：

- 使用PDF解析工具，只提取标题、页码等结构信息
- 识别标题层级结构（章节标题、小节标题等）
- 建立章节与页码的映射关系
- 提取目录和索引信息（如果存在）

### 2.6 阶段三：定位疾病章节

#### 2.6.1 目标

根据疾病目录和书籍结构，确定每个疾病在书籍中的具体位置。

#### 2.6.2 定位方式

- **目录匹配**：如果疾病目录中已包含章节信息，直接使用
- **标题匹配**：根据疾病名称在章节标题中搜索匹配
- **索引匹配**：如果书籍有索引，通过索引查找疾病对应的页码
- **语义匹配**：使用关键词匹配或简单语义匹配定位相关章节

#### 2.6.3 输出形式

每个疾病对应一个章节范围：

- 疾病名称
- 相关章节列表（章节标题、起始页码、结束页码）
- 可能相关的章节（弱关联）
- 定位置信度

**实现逻辑**：

- 遍历疾病目录中的每个疾病
- 在结构解析结果中搜索匹配的章节
- 记录每个疾病对应的章节范围和页码范围
- 建立疾病与章节的映射关系

### 2.7 阶段四：精解析（只解析相关章节）

#### 2.7.1 目标

只详细解析疾病相关的章节，跳过无关章节，避免一次性解析整本书。

#### 2.7.2 解析范围

- **主章节**：疾病对应的主要章节（强关联）
- **相关章节**：鉴别诊断、并发症等涉及该疾病的章节（弱关联）
- **上下文保留**：解析时保留章节前后的少量上下文，确保语义完整

#### 2.7.3 统一要求

- 保留 **页码**
- 保留 **标题层级**
- 保留 **段落边界**

#### 2.7.4 输出形式

每一段文本都至少具备：

- 书籍 ID
- 页码区间
- 标题路径（第 X 章 → 第 Y 节）
- 段落序号
- 段落正文
- 所属疾病（关联的疾病列表）

#### 2.7.5 为什么只解析相关章节？

- **避免幻觉**：小范围解析更准确，减少PDF解析错误
- **提高效率**：跳过无关章节，节省计算资源
- **提高准确性**：只处理相关文本，减少上下文混乱
- **可控性强**：某个疾病解析有问题，不影响其他疾病

**实现逻辑**：

- 根据阶段三的定位结果，确定要解析的章节范围
- 只解析这些章节的详细文本内容
- 识别标题层级结构（章节标题、小节标题等）
- 维护文本段落与页码、章节的关联关系
- 标注每个段落与疾病的关联关系
- 标准化段落格式，去除无关字符，保留语义结构

### 2.8 阶段五：文本分段与疾病内容聚合（**关键切分步骤**）

#### 2.8.1 核心目标

将精解析的文本按疾病**切分并归并到"某一个疾病"**

> **这是整个流程中的关键切分环节**：精解析后的文本在这里被切分成多个独立的文本集合，每个疾病一个集合。

#### 2.8.2 切分的必要性

**为什么必须切分**：

- **精解析文本 → 多个疾病独立文本**：输入是精解析的文本（已标注疾病关联），输出是每个疾病独立的文本集合
- **避免混淆**：不同疾病的内容分开，避免AI在提取时混淆
- **聚焦处理**：每个疾病单独处理，AI可以专注于该疾病的信息
- **便于管理**：每个疾病的数据是独立的，便于后续的审核、更新、版本管理

#### 2.8.3 原则

- 一个段落 **可以属于多个疾病**（例如鉴别诊断部分）
- 允许"弱关联"和"强关联"标记
- **切分结果**：精解析的文本被切分成N个文本集合（N=疾病目录中的疾病数量）

#### 2.8.4 聚合后结果

对于每个疾病，最终得到的是：

- **一个独立的文本集合**（包含该疾病的所有相关段落）
- 一组与该疾病相关的文本段落
- 每段文本都有明确来源（页码 / 章节 / 段落）

**切分前后对比**：

| 切分前 | 切分后 |
|--------|--------|
| 精解析的文本（包含多个疾病的相关段落） | 疾病A的文本集合 |
| 已标注疾病关联，但混在一起 | 疾病B的文本集合 |
| 难以独立处理单个疾病 | 疾病C的文本集合 |
| | ... |
| | 每个疾病都是独立的文本集合 |

#### 2.8.5 实现逻辑

**切分流程**：

1. **输入**：精解析的文本（已标注疾病关联）+ 疾病目录
2. **切分过程**：
   - 根据精解析时标注的疾病关联信息，将段落分配到对应的疾病文本集合
   - 如果段落标注了多个疾病，则同时分配到多个疾病的集合中
   - 标记段落与疾病的关联强度（强关联/弱关联）
3. **输出**：N个独立的文本集合（N=疾病数量）
   - 每个集合包含该疾病的所有相关段落
   - 标记段落与疾病的关联强度（强关联/弱关联）
   - 保留段落的完整来源信息（页码、章节、段落序号）

**切分示例**：

假设一本书包含3个疾病：胸痛、头痛、发热

切分前（精解析后的文本）：
- 第2章胸痛相关段落（已标注：疾病=胸痛）
- 第3章头痛相关段落（已标注：疾病=头痛）
- 第4章发热相关段落（已标注：疾病=发热）
- 第5章鉴别诊断段落（已标注：疾病=[胸痛,头痛,发热]）

切分后：
- 疾病"胸痛"的文本集合：{第2章相关段落, 第5章鉴别诊断段落, ...}
- 疾病"头痛"的文本集合：{第3章相关段落, 第5章鉴别诊断段落, ...}
- 疾病"发热"的文本集合：{第4章相关段落, 第5章鉴别诊断段落, ...}

### 2.6 阶段五：统一疾病结构模板（Schema）

#### 2.6.1 模板设计原则

1. **结构稳定**（长期不变）
2. **字段语义清晰**
3. **允许缺失，不允许推断**
4. **每个大字段都可溯源**

#### 2.6.2 模板示意（结构层面）

- 疾病基本信息
- 定义与概述
- 流行病学
- 病因与发病机制
- 临床表现
- 诊断要点 / 标准
- 鉴别诊断
- 治疗原则
- 药物与禁忌
- 并发症
- 预后与随访
- 数据来源说明

> **注意**：模板一旦定版，**不要频繁修改**，否则会造成历史数据不可比。

**实现逻辑**：

- 定义标准化的JSON Schema结构
- 明确每个字段的含义和数据类型
- 规定哪些字段必填，哪些可选
- 要求每个字段都要标注来源位置

### 2.9 阶段六：结构化抽取（受控执行）

#### 2.7.1 本阶段的本质

不是"生成内容"，而是：

> **从已给文本中，按模板字段摘录信息**

#### 2.7.2 执行规则

- 逐疾病执行（而不是逐章节）
- 只允许使用已聚合的文本
- 严格按照模板字段填充
- 找不到内容 → 标记为空

#### 2.7.3 输出物

- 每个疾病一份完整结构化数据
- 每个字段附带来源定位

#### 2.7.4 **为什么AI提取也必须切分？**

**关键问题**：能否直接把整本书输入AI，让它一次性提取所有疾病的结构化信息？

**答案：不行，必须切分。原因如下：**

**1. 技术性切分：Token限制**

- **模型能力限制**：即使是最强大的GPT-4，单次处理也有token上限（128K-200K tokens）
- **书籍体量**：一本医学书籍通常有数百页、数十万字，远超单次token限制
- **即使未来模型能力增强**：书籍会越来越大，总会有上限

**2. 逻辑性切分：按疾病聚合（更重要）**

即使技术允许一次处理整本书，也必须按疾病切分：

- **输出粒度问题**：
  - 我们需要每个疾病单独的结构化数据
  - 整本书一次性提取，输出结构会非常复杂，难以管理
  - 无法保证每个疾病数据的完整性和独立性

- **上下文混乱问题**：
  - 一本书包含多个疾病，混在一起会让AI难以聚焦
  - AI可能混淆不同疾病的信息
  - 无法准确标注每条信息属于哪个疾病

- **质量保证问题**：
  - 无法验证AI是否正确识别了所有疾病
  - 无法保证每个疾病的信息都完整提取
  - 出错时无法精确定位是哪个疾病的问题

- **可追溯性问题**：
  - 无法准确标注每条信息来自哪一页、哪一章
  - 无法建立疾病与原始文本段落的精确映射

- **增量更新问题**：
  - 当书籍更新时，无法知道哪个疾病的信息发生了变化
  - 需要重新处理整本书，效率低

**3. 正确的切分方式**

我们采用**"按疾病聚合后再提取"**的方式：

1. **第一步（阶段四）**：按疾病目录将整本书的文本切分聚合
   - 每个疾病得到其相关的所有文本段落
   - 保留完整的来源信息（页码、章节）

2. **第二步（阶段六）**：对每个疾病的相关文本进行AI提取
   - 如果单个疾病的内容仍然超过token限制，再进行技术性切分
   - 如果单个疾病内容在token范围内，直接提取

**总结**：切分不是可选的，而是必需的。切分有两种：
- **逻辑性切分**（按疾病）：保证输出质量、可追溯性、可管理性
- **技术性切分**（按token）：处理超长文本的技术限制

**实现逻辑（AI辅助）**：

1. **准备提取上下文**：
   - 将某个疾病的所有聚合文本段落整理成完整上下文
   - 包含疾病名称、别名、相关段落内容
   - **重要**：这是已经切分好的疾病相关文本，不是整本书

2. **检查文本长度**：
   - 如果疾病相关文本超过模型token限制，进行技术性切分
   - 将长文本分成多个块，每块保留上下文重叠
   - 如果文本在token范围内，直接进入下一步

3. **构建提取Prompt**：
   - 明确告知模型要提取哪些字段
   - 提供统一的输出格式要求
   - 强调只能摘录原文内容，不能推断或生成
   - 明确这是关于"XX疾病"的提取（已切分好的上下文）

4. **调用大模型提取**：
   - 将疾病相关文本和提取要求发送给大模型
   - 模型按模板结构返回JSON格式的提取结果
   - 如果是分块提取，逐块调用

5. **合并提取结果**：
   - 如果一个疾病的内容被分成多块提取，需要合并结果
   - 去重相同信息，保留最完整的版本
   - 合并时保留所有来源信息

6. **错误处理**：
   - 处理JSON解析错误
   - 处理API调用失败
   - 记录提取过程中的所有错误信息

### 2.10 阶段七：校验、审核与入库

#### 2.8.1 三层质量保障

**1️⃣ 结构完整性**

- 模板字段是否齐全
- 数据类型是否正确

**2️⃣ 内容可信性**

- 是否引用了真实段落
- 是否存在明显"扩写 / 推断"

**3️⃣ 溯源完整性**

- 每条核心信息是否可追溯到：
  - 书籍
  - 章节
  - 页码 / 段落

**实现逻辑**：

1. **自动验证**：
   - 检查JSON结构是否符合模板
   - 验证必填字段是否存在
   - 检查数据类型是否正确
   - 验证风险等级、字段枚举值是否合法

2. **质量评分**：
   - 完整性评分：关键字段是否都有内容
   - 详细程度评分：内容的丰富程度
   - 结构化程度评分：字段是否完整标注

3. **人工审核**：
   - 提供Web审核界面或Excel模板
   - 审核人员对比原始文本和提取结果
   - 修正AI提取的错误
   - 补充缺失的内容
   - 标记需要重新提取的数据

4. **数据清洗**：
   - 去除空值和无效数据
   - 标准化疾病名称、主诉名称等
   - 去重相同疾病或线索
   - 按风险等级、优先级排序

5. **数据入库**：
   - 转换为系统所需格式
   - 导入到数据库
   - 建立索引便于查询
   - 记录导入时间和版本信息

### 2.9 最终数据形态

最终不是得到"一堆文本"，而是：

- 每个疾病一条**标准化知识实体**
- 可版本对比（不同书 / 不同版本）
- 可用于：
  - AI 问答（RAG）
  - 医生知识库
  - 系统规则与提示
  - 后续人工审校与发布

### 3.1 完整工作流程

**流程逻辑说明**：

1. **先定义模板**：在开始处理书籍之前，先确定要提取的结构模板，这是整个提取的目标和标准
2. **再定义疾病目录**：明确要提取哪些疾病，这是提取的范围
3. **找书处理**：确定要处理的书籍，进行版本管理
4. **结构解析（粗解析）**：只解析书籍结构，识别章节、页码、目录，避免一次性解析整本书的幻觉问题
5. **定位疾病章节**：根据疾病目录，确定每个疾病在哪些章节/页码
6. **精解析（只解析相关章节）**：只详细解析疾病相关的章节，跳过无关章节，避免幻觉，提高效率和准确性
7. **切分（关键步骤）**：将精解析的文本按疾病切分成多个独立的文本集合
8. **结构化抽取**：对每个疾病的独立文本使用AI进行结构化抽取
9. **校验入库**：最后对提取结果进行校验、审核，确保质量后入库

**关键说明**：

1. **模板和目录在前**：统一疾病结构模板和疾病目录应该在开始处理书籍之前就确定
2. **两阶段解析**：先粗解析结构，再精解析相关章节，避免一次性解析整本书的幻觉问题
3. **切分在精解析后**：必须在精解析完成后，才能进行切分
4. **切分是必需环节**：即使使用AI，也必须先切分，才能保证提取质量和可追溯性
5. **逐疾病处理**：结构化抽取是逐疾病进行的，不是处理整本书

### 3.2 AI提取环节详细流程

> **重要前提**：此阶段的输入是**阶段五已经切分好的疾病文本集合**，不再是整本书或精解析的混合文本。

**步骤1：文本准备（使用已切分的文本）**
- **输入**：某个疾病的独立文本集合（来自阶段五的切分结果）
- 整理成完整的上下文，包含疾病名称和别名
- **如果单个疾病的文本仍然超过token限制**，进行技术性分块（保留上下文连续性）
- **注意**：这是在疾病文本集合基础上进行的二次分块，不是整本书的分块

**步骤2：构建提取指令**
- 明确告知模型要提取的字段结构
- 提供示例格式要求
- 强调只摘录原文，不推断、不生成

**步骤3：调用AI提取**
- 发送文本和指令到大模型API
- 接收JSON格式的提取结果
- 处理可能的格式错误或解析失败

**步骤4：结果后处理**
- 解析返回的JSON数据
- 添加来源信息（页码、章节）
- 验证提取结果的完整性

**步骤5：批量处理**
- 对所有疾病目录项循环执行提取
- 记录进度和错误日志
- 支持断点续跑（跳过已完成的疾病）

## 五、实际应用策略

### 5.1 主诉识别策略

医学书籍通常按主诉组织内容，识别逻辑：

- 识别章节标题中的主诉关键词（胸痛、头痛、发热等）
- 匹配主诉常见模式（"主诉："、"主要症状："等）

### 5.2 诊断流程提取策略

- 识别编号模式（数字、字母、中文编号）
- 提取步骤描述
- 识别关键问诊问题
- 提取决策判断点

### 5.3 疾病名称提取策略

- 关键词匹配：使用疾病名称词典进行匹配
- 上下文提取：提取疾病名称周围的上下文信息
- NER模型：使用医学命名实体识别模型（如有）

### 5.4 处理长文本的策略

- **分块处理**：将超长文本分成多个块，每块不超过模型token限制
- **重叠策略**：相邻块之间保留重叠部分，避免信息丢失
- **智能合并**：提取完成后智能合并分块结果，去重和整合

## 六、为什么不能直接把书输给GPT就出来结果

### 6.1 技术限制

#### 6.1.1 Token限制问题

- **上下文窗口限制**：即使是GPT-4，单次处理的token数量也有限（通常128K-200K tokens）
- **完整书籍体量**：一本医学书籍通常有数百页、数十万字，远超单次处理的token限制
- **信息丢失风险**：如果将整本书压缩或分块，可能导致重要信息丢失或上下文断裂
- **未来限制依然存在**：即使未来模型token限制扩大，书籍也会越来越大，总会遇到边界

#### 6.1.2 输出粒度问题

- **输出结构过于复杂**：整本书一次性提取，输出会包含所有疾病的结构化数据，结构过于庞大复杂
- **难以管理**：无法对单个疾病的数据进行单独管理、更新、审核
- **缺乏独立性**：每个疾病的数据应该是一个独立的知识实体，不能混在一起

#### 6.1.3 输出格式不稳定

- **格式不一致**：直接让GPT提取，每次输出的格式可能略有差异，难以保证结构化的一致性
- **字段缺失**：GPT可能忽略某些不重要但必需的字段
- **嵌套结构复杂**：医学知识结构复杂，需要多层级嵌套，GPT难以稳定输出

### 6.2 质量问题

#### 6.2.1 内容准确性风险

- **推断与生成**：GPT可能基于训练数据"推断"出书籍中没有的内容，而不是严格摘录原文
- **医学专业术语**：可能误解或替换医学专业术语
- **上下文理解偏差**：可能因为上下文不足而错误理解医学概念之间的关系
- **多疾病混淆**：整本书一起提取时，GPT可能混淆不同疾病的信息，将A疾病的特征误判为B疾病的

#### 6.2.2 遗漏重要信息

- **关键信息识别**：GPT可能无法准确识别哪些信息是关键的，哪些是次要的
- **隐性知识**：可能遗漏需要专业判断才能识别的重要信息
- **关联信息断裂**：跨章节的关联信息可能被忽略
- **疾病遗漏**：整本书提取时，可能遗漏某些疾病的完整信息，难以发现和定位

#### 7.2.3 聚焦度问题

- **注意力分散**：处理整本书时，GPT的注意力分散在所有疾病上，无法对单个疾病进行深度聚焦
- **信息边界不清**：难以准确区分哪些内容属于哪个疾病，特别是鉴别诊断等跨疾病内容
- **质量控制困难**：无法针对单个疾病进行质量评估和优化

### 6.3 可追溯性问题

#### 6.3.1 来源信息缺失

- **无法溯源**：直接输入整本书，GPT无法准确标注每条信息来自哪一页、哪一章
- **版本管理困难**：无法区分不同版本书籍的差异
- **数据更新困难**：当书籍更新时，无法精确知道哪些内容发生了变化

#### 6.3.2 质量验证困难

- **无法核对**：无法验证GPT提取的内容是否真的在原文中存在
- **错误定位困难**：当发现问题时，难以定位错误的来源

### 6.4 业务需求不匹配

#### 6.4.1 结构化要求

- **标准模板**：我们需要严格按照标准化的疾病知识模板提取，而不是GPT自由发挥
- **字段完整性**：某些字段可能书籍中没有，但需要明确标记为"缺失"而非让GPT生成
- **数据一致性**：不同疾病的数据结构必须完全一致，便于后续系统使用

#### 6.4.2 质量控制要求

- **医学审核**：医学知识需要专业医生审核，而不是完全信任AI的输出
- **版本控制**：需要记录每个版本的数据状态，支持版本对比
- **增量更新**：需要支持在已有数据基础上增量更新，而不是每次都重新生成

### 6.5 七阶段架构的必要性

#### 6.5.1 阶段一（版本治理）的价值

直接输入整本书无法区分版本，无法追溯数据来源。而通过版本治理，我们可以：
- 准确记录每本书的版本信息
- 支持多版本并存和对比
- 建立完整的数据血缘关系

#### 6.5.2 阶段二+三+四（结构解析+定位+精解析）的价值

直接使用PDF或一次性解析整本书，会出现严重问题：

**通过两阶段解析（结构解析+精解析）**：
- **避免幻觉**：一次性解析整本书，PDF解析工具可能出现错误、格式混乱、信息丢失
- **提高效率**：只解析需要的章节，节省资源
- **提高准确性**：小范围解析更精确，减少上下文混乱
- **保留结构**：先粗解析结构，保留页码和章节信息
- **精确定位**：通过定位疾病章节，只解析相关内容
- **建立映射**：建立文本与来源的精确映射

#### 6.5.3 【前置步骤】疾病目录定义的价值

直接让GPT自己决定提取哪些疾病，可能遗漏或错误识别。通过疾病目录：
- 明确定义提取范围
- 控制抽取边界
- 支持任务拆分和进度管理

#### 6.5.4 阶段五（内容聚合/切分）的价值

GPT处理整本书时，无法精确地将内容按疾病归并。通过内容聚合：
- 确保每个疾病的内容完整
- 标记关联强度
- 保留精确的来源信息

#### 6.5.5 【前置步骤】模板定义的价值

没有统一模板，GPT的输出结构会不一致。通过模板定义：
- 确保数据结构标准化
- 便于后续系统使用
- 支持数据对比和分析

#### 6.5.6 阶段六（结构化抽取）的价值

这个阶段确实使用GPT，但是在受控环境下：
- 只处理已切分的、与特定疾病相关的文本
- 严格按照模板字段提取
- 强调只摘录不推断

#### 6.5.7 阶段七（校验入库）的价值

直接使用GPT结果无法保证质量。通过校验审核：
- 专业医生审核准确性
- 自动验证数据完整性
- 建立完整的质量保障体系

### 6.6 结论

**不能直接把书输给GPT的原因总结**：

1. **技术限制**：Token限制、输出粒度问题、格式不稳定
2. **质量问题**：可能推断生成、遗漏重要信息、多疾病混淆、注意力分散
3. **可追溯性**：无法标注来源、版本管理困难
4. **业务需求**：需要标准化结构、质量控制、版本管理、按疾病独立管理
5. **架构必要性**：七阶段架构每个环节都有其不可替代的价值

**关于切分的明确说明**：

即使使用AI提取，也**必须进行切分**，这是不可绕过的环节：

1. **技术性切分**：受token限制影响，必须将超长文本分块处理
2. **逻辑性切分**（更重要）：必须按疾病切分，因为：
   - 需要每个疾病独立的结构化数据
   - 避免多疾病信息混淆
   - 保证输出质量和可追溯性
   - 支持单个疾病的独立管理和更新

**正确的做法**：

- 采用优化的多阶段架构，将复杂的提取任务分解为可控制的步骤
- **先定义目标和范围**：定义模板和疾病目录，明确要提取什么
- **两阶段解析**：先粗解析结构，再精解析相关章节，避免一次性解析整本书的幻觉问题
- **必须先切分**：通过阶段五（内容聚合）按疾病切分文本，而不是整本书输入
- 在受控环境下使用GPT（阶段六），只处理已切分好的疾病相关文本
- 配合结构解析、定位、精解析等前期准备，确保切分的准确性
- 通过人工审核（阶段七）确保质量
- 建立完整的版本管理和溯源体系

**流程示意**：
```
定义模板和疾病目录
    ↓
找书 → 结构解析（粗解析，识别章节结构）
    ↓
定位疾病章节（确定每个疾病在哪些章节）
    ↓
精解析（只解析疾病相关章节，避免幻觉）
    ↓
按疾病切分聚合 → 逐个疾病AI提取 → 人工审核 → 入库
      ↓                    ↓
   每个疾病独立       避免混淆，保证
   文本集合          提取质量
```

只有这样，才能获得**高质量、可追溯、可复用的结构化医学知识数据**。
