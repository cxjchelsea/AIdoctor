# HPO数据中文翻译方案

## 📋 概述

HPO（Human Phenotype Ontology，人类表型本体）数据目前只有英文版本，没有官方的中英文对照表。本文档说明如何为HPO数据添加中文翻译。

## 🎯 翻译方案

### 方案优先级

根据项目文档《通用数据集中文翻译方案.md》，HPO数据的翻译应该遵循以下优先级：

**优先级1：下载官方/第三方翻译字典** ⭐⭐⭐（最优）✨ **推荐！**

**好消息！** 可以下载现成的HPO中文翻译字典！

#### 可下载的资源：

1. **HPO International 中文翻译（GitHub）** ⭐ 推荐
   - 来源：HPO官方国际化项目
   - 包含：标签、定义、同义词的中文翻译
   - 下载方式：使用脚本自动下载（见下方）

2. **CHPO（Chinese HPO）**
   - 来源：中国HPO协作组维护的中文HPO项目
   - 包含：完整的中文标签集
   - 获取方式：从CHPO官网或相关论文获取

#### 快速开始（推荐方式）：

```bash
# 1. 下载中文翻译字典
python download_hpo_chinese_dict.py

# 2. 自动合并翻译到HPO数据
python merge_hpo_chinese.py
```

就这么简单！脚本会自动下载字典并合并翻译。

**优先级2：建立标准术语库** ⭐⭐（次优）
- 逐步建立HPO术语的中文翻译库
- 使用标准医学术语，保持一致性
- 可以分批次翻译，优先翻译常用术语

**优先级3：AI翻译（仅作为补充）** ⭐（谨慎使用）
- 仅用于补充翻译，不能作为主要方式
- 所有AI翻译必须经过人工审核
- 需要建立翻译缓存，避免重复翻译

### 详细用法

#### 1. 下载中文翻译字典

```bash
python download_hpo_chinese_dict.py
```

**功能说明：**
- 自动从GitHub下载HPO官方中文翻译文件
- 解析并转换为标准CSV格式
- 保存为 `hpo_chinese_mapping.csv`（可直接用于合并）

**输出文件：**
- `提取结果/hpo/翻译字典/zh.babelon.tsv` - 原始翻译文件
- `提取结果/hpo/hpo_chinese_mapping.csv` - 标准格式的映射文件

#### 2. 合并翻译到HPO数据

```bash
python merge_hpo_chinese.py
```

脚本会自动：
- 加载HPO数据（`hpo_data.csv`）
- 加载中文翻译映射（`hpo_chinese_mapping.csv`，如果存在）
- 合并翻译到新文件（`hpo_data_with_chinese.csv`）

#### 3. 查看结果

打开 `hpo_data_with_chinese.csv`，您会看到新增了两列：
- `标准名称（中文）`：中文术语名称
- `定义（中文）`：中文定义（如果已翻译）

### 手动翻译方式（如果字典不完整）

如果下载的字典覆盖不全，可以手动补充翻译：

#### 1. 创建翻译模板

```bash
python merge_hpo_chinese.py --create-template 100
```

这会创建一个包含前100条记录的翻译模板文件：`hpo_translation_template.csv`

#### 2. 填写翻译

打开 `hpo_translation_template.csv`，填写"标准名称（中文）"和"定义（中文）"列。

**重要提示：**
- 使用标准医学术语
- 保持术语一致性（相同英文术语使用相同中文翻译）
- 可以参考医学词典、术语表等权威资源

#### 3. 合并翻译

将填写好的文件重命名为 `hpo_chinese_mapping.csv`，或使用 `--mapping` 参数指定：

```bash
python merge_hpo_chinese.py --mapping hpo_translation_template.csv
```

### 高级用法

#### 指定文件路径

```bash
# 指定HPO数据文件
python merge_hpo_chinese.py --hpo-data path/to/hpo_data.csv

# 指定翻译映射文件
python merge_hpo_chinese.py --mapping path/to/my_translation.csv

# 指定输出文件
python merge_hpo_chinese.py --output path/to/output.csv
```

#### 不使用内置翻译字典

```bash
python merge_hpo_chinese.py --no-builtin
```

## 📝 翻译映射文件格式

翻译映射文件（`hpo_chinese_mapping.csv`）应该包含以下列：

| 列名 | 说明 | 示例 |
|------|------|------|
| HPO编码 | HPO术语的唯一标识符 | HP:0000107 |
| 标准名称（中文） | 中文术语名称 | 肾囊肿 |
| 定义（中文） | 中文定义（可选） | 肾脏中的液性囊性结构 |

**注意：**
- 文件编码必须是 UTF-8（带BOM）或 UTF-8-sig
- HPO编码格式可以是 `HP:0000107` 或 `HP_0000107`（脚本会自动转换）
- 至少需要包含"HPO编码"和"标准名称（中文）"两列

## 🔄 逐步翻译流程

由于HPO术语数量庞大（超过1万条），建议采用逐步翻译的方式：

### 第一步：翻译核心术语

优先翻译最常用的术语（约100-500条），这些术语在临床诊断中最常使用。

### 第二步：按类别翻译

根据HPO的层次结构，按类别逐步翻译：
- 先翻译大类（如"异常肾脏形态"）
- 再翻译具体术语（如"肾囊肿"）

### 第三步：补充翻译

对于不常用的术语，可以：
- 暂时保留英文
- 在需要时再补充翻译
- 使用AI翻译作为辅助（但必须人工审核）

## ⚠️ 翻译注意事项

### 1. 使用标准医学术语

- 参考《医学名词》、《中国药典》等权威标准
- 避免使用非标准术语或口语化表达
- 保持与现有医学系统的一致性

### 2. 保持术语一致性

- 同一个英文术语在整个数据集中必须使用相同的中文翻译
- 建议建立术语库，统一管理所有翻译

### 3. 处理专业术语

- 缩写：如"UTI"应翻译为"尿路感染"，而不是保留英文
- 拉丁文：如"E.coli"应翻译为"大肠杆菌"
- 人名地名：如"Prader scale"应翻译为"Prader量表"或保留英文

### 4. 质量控制

- 所有翻译都应该经过专业医学人员审核
- 定期检查术语一致性
- 建立翻译版本管理机制

## 📊 翻译进度跟踪

## 💡 建议

1. **建立术语库**：创建一个标准HPO术语翻译库，逐步完善
2. **分批次翻译**：不要一次性翻译所有术语，按优先级分批进行

## ❓ 常见问题

### Q1: 可以直接使用AI翻译吗？

**A:** 不建议。AI翻译无法保证使用标准医学术语，且同一术语多次翻译可能产生不同结果。AI翻译只能作为辅助手段，且必须经过人工审核。

### Q2: 翻译文件格式不对怎么办？

**A:** 确保文件编码为UTF-8（带BOM），列名包含"HPO编码"和"标准名称（中文）"。脚本会自动识别列名，但建议使用标准列名。

### Q3: 如何知道哪些术语已经翻译了？

**A:** 运行脚本后，查看输出文件 `hpo_data_with_chinese.csv`，已翻译的术语会在"标准名称（中文）"列显示中文，未翻译的为空。

### Q4: 可以只翻译部分字段吗？

**A:** 可以。至少需要翻译"标准名称（中文）"，"定义（中文）"是可选的。

### Q5: 翻译后如何更新数据？

**A:** 每次添加新翻译后，重新运行脚本即可。脚本会合并所有翻译到新文件中。
