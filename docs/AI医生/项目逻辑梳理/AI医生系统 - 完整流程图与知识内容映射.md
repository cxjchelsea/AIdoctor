#### 2.1.1 A3-1分支：筛查建议分支

```
┌─────────────────────────────────────────────────────────────────┐
│  【A3-1｜筛查建议分支】（对应需求1）                             │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ 1. 补充追问（仅问会影响筛查决策的关键信息）               │  │
│  │    - 年龄、性别、既往史、家族史等关键信息                  │  │
│  │ 2. 规则化生成两张清单                                      │  │
│  │    - 推荐做的筛查清单                                      │  │
│  │    - 不建议做的筛查清单                                    │  │
│  │ 3. 输出分支结果                                            │  │
│  │    - 推荐筛查清单 + 频率/时机                              │  │
│  │    - 不建议筛查清单 + 理由                                 │  │
│  │    - 下次更新时间点                                        │  │
│  │    - 随访节奏（初步）                                      │  │
│  └──────────────────────────────────────────────────────────┘  │
│  📚 知识内容位置：                                               │
│  - 额外追问清单（仅筛查决策关键项）                             │
│  - 输出数量与排序规则（推荐/不推荐各输出多少条）                │
│  - 条件触发筛查规则库（screening_recommendation_rule）           │
│    * 什么条件 → 建议哪些筛查 → 大致频率/时机                    │
│  - 不推荐筛查清单（反过度筛查理由与替代建议）                    │
│  - 强烈要求检查时的标准回应话术                                 │
└────────────────────────┬────────────────────────────────────────┘
```

│  - 升级触发条件库                                               │
└────────────────────────┬────────────────────────────────────────┘
                         │ (进入临床诊疗态)
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│  【Step 1：识别问题】                                            │
│  【诊断服务】（diagnosis-service）编排                           │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ 目标：把用户自然语言转为可推理、可复用、可审计的结构化    │  │
│  │       "问题清单"，作为后续候选方向生成与分流问诊的唯一输入│  │
│  │                                                             │  │
│  │ 【临床理解服务】（clinical-parsing-service）- 脑区A        │  │
│  │ - 概念归一化：把"原话"翻译为医学可用的标准概念            │  │
│  │   * 医学概念识别与归一化（CUI/ICD/SNOMED）                 │  │
│  │   * 处理同义表达与歧义表达                                 │  │
│  │   * 多模态理解（文本/影像/检查报告）                       │  │
│  │                                                             │  │
│  │ 【对话管理服务】（dialog-service）- 脑区B                  │  │
│  │ - 问题清单构建与信息缺口识别                               │  │
│  │ - 形成完整问题清单：                                       │  │

│  │   * 伴随问题（同时间窗出现的关键症状/体征）               │  │

│  │   * 必填缺口：缺失则不能进入 Step 2                        │  │
│  │   * 重要缺口：可进入但必须提示不确定性与风险              │  │

│  └──────────────────────────────────────────────────────────┘  │
│  📚 知识内容位置：                                               │
│  【脑区A - clinical-parsing-service】                           │

│    normalization）                                              │
│  - 多模态理解规则库（multimodal_understanding_rule）            │
│  - 歧义表达判定与追问规则库（ambiguity_detection_rule）        │
│  【脑区B - dialog-service】                                     │
│  - 主诉关键字段模板（chief_complaint_key_field_template）        │
│    * 起病时间与过程（突然/渐进、持续/间歇）                     │
│    * 部位与放射（如适用）                                       │
│    * 性质与强度（例如0-10分）                                   │
│    * 诱因与缓解因素                                             │
│    * 伴随症状                                                   │
│    * 关键危险因素与既往相似发作                                 │
│  - 伴随症状清单（associated_symptom_list）                      │
│  - 关键背景字段（主诉特异+全局通用）                            │
│  - 信息缺口分级规则（information_gap_grading_rule）              │
│    * 必填缺口判定规则                                           │
│    * 重要缺口判定规则                                           │
│    * 可选缺口判定规则                                           │
│  - 问题清单输出模板（统一字段、顺序与语言风格）                 │
└────────────────────────┬────────────────────────────────────────┘
                         │
                         ▼
┌─────────────────────────────────────────────────────────────────┐
│  【Step 2：构建鉴别诊断候选集并分层】                            │
│  【诊断引擎服务】（diagnosis-engine-service）- 脑区C             │
│  ┌──────────────────────────────────────────────────────────┐  │
│  │ 目标：基于问题清单列出鉴别诊断全集，按首要假设、主要备选  │  │
│  │      与必须排除高危方向分层，为每个方向写清入选依据与缺口 │  │
│  │                                                             │  │
│  │ 【五引擎融合诊断 + 三层分层】                               │  │
│  │ - 生成鉴别诊断全集（先"列全"）：                          │  │
│  │   * 常见原因                                                │  │
│  │   * 易混淆原因                                              │  │
│  │   * 严重但不能漏诊的原因（先放入，不等待证据完善）        │  │
│  │ - 五引擎融合诊断：                                         │  │
│  │   * 规则引擎（rule_engine）：症状组合规则库                │  │
│  │   * 知识图谱引擎（kg_engine）：Neo4j知识图谱（DR.KNOWS）   │  │
│  │   * 统计模型引擎（statistical_engine）：历史诊断数据        │  │
│  │   * 大模型引擎（llm_engine）：提示词模板 + 路径注入         │  │
│  │   * 鉴别诊断引擎（differential_engine）：鉴别诊断规则库     │  │
│  │ - 三层分层（把"可能"变成"可推进"）：                       │  │
