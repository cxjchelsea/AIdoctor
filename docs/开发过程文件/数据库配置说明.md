## 概述

AI医生系统使用**Oracle作为主开发环境**：
- **Oracle**：主开发环境（公司部署，默认使用）
- **MySQL**：可选本地测试环境（用于快速本地开发，可选）

### 设计原则

- **主环境**：Oracle（`dev` profile）- 日常开发使用
- **可选环境**：MySQL（`mysql` profile）- 本地快速测试，可选配置
- **表结构管理**：使用Flyway迁移脚本管理，包含完整的表结构定义

## 数据库架构

### Oracle架构（主环境）

```
Oracle实例 (公司服务器)
└── Schema: AI_DOCTOR
    ├── 诊断服务相关表
    │   ├── cdp
    │   ├── cdp_version
    │   ├── diagnosis_record
    │   ├── examination_record
    │   ├── examination_plan
    │   ├── follow_up_plan
    │   ├── health_state_assessment_record
    │   └── wellness_screening_record
    └── 执行追踪服务相关表
        └── execution_trace
```

### MySQL架构（可选本地测试环境）

```
MySQL实例 (本地，可选)
├── 数据库: aidoctor
│   └── (所有诊断服务相关表)
└── 数据库: aidoctor_trace
    └── execution_trace
```

**注意**：
- Oracle中所有表都在同一个Schema中，MySQL中分为两个数据库
- MySQL配置是可选的，如果以后只用Oracle，可以删除MySQL相关配置

## 环境配置

### 配置文件结构

每个服务都有以下配置文件：

```
服务目录/src/main/resources/
├── application.yml          # 主配置（设置默认profile）
├── application-dev.yml     # Oracle配置（主开发环境）
└── application-mysql.yml   # MySQL配置（本地备用）
```

### 默认配置

**所有服务的 `application.yml` 默认使用 `dev` profile（Oracle）：**

```yaml
spring:
  profiles:
    # 主开发环境: dev (Oracle - 公司部署)
    # 可选本地测试: mysql (MySQL - 本地快速测试，可选)
    active: dev
```

### 切换环境

#### 方式1：修改配置文件（临时）

```yaml
# application.yml
spring:
  profiles:
    active: mysql  # 切换到MySQL
```

#### 方式2：启动时指定（推荐）

```bash
# 使用Oracle（默认）
mvn spring-boot:run

# 使用MySQL
mvn spring-boot:run -Dspring-boot.run.profiles=mysql
```

#### 方式3：使用环境变量

```bash
# Windows
set SPRING_PROFILES_ACTIVE=dev  # 或 mysql

# Linux/Mac
export SPRING_PROFILES_ACTIVE=dev  # 或 mysql
```

### Oracle配置（application-dev.yml）

```yaml
spring:
  datasource:
    driver-class-name: oracle.jdbc.driver.OracleDriver
    url: jdbc:oracle:thin:@${DB_HOST:192.168.3.25}:${DB_PORT:1521}/${DB_SERVICE:XE}
    username: ${DB_USERNAME:AI_DOCTOR}
    password: ${DB_PASSWORD:your_password}
```

**配置说明：**
- 使用环境变量或默认值
- 可通过环境变量覆盖连接信息
- 支持Service Name连接方式

### MySQL配置（application-mysql.yml）

```yaml
spring:
  datasource:
    driver-class-name: com.mysql.cj.jdbc.Driver
    url: jdbc:mysql://localhost:3306/aidoctor?useUnicode=true&characterEncoding=utf8&useSSL=false&serverTimezone=Asia/Shanghai&allowPublicKeyRetrieval=true
    username: root
    password: root
```

## IDEA数据库连接配置

### 配置Oracle连接

1. **打开Database工具窗口**
   - `View` → `Tool Windows` → `Database`

2. **添加Oracle数据源**
   - 点击 `+` → `Data Source` → `Oracle`

3. **配置连接信息**
   ```
   名称: AI_DOCTOR
   连接类型: Service name
   主机: 192.168.3.25
   端口: 1521
   Service name: XE (或根据实际情况)
   用户: AI_DOCTOR
   密码: your_password
   ```

4. **测试连接**
   - 点击 "测试连接"
   - 如果失败，尝试将Service name改为 `XEPDB1` 或 `ORCL`

### 配置MySQL连接

1. **添加MySQL数据源**
   - 点击 `+` → `Data Source` → `MySQL`

2. **配置连接信息**
   ```
   名称: aidoctor@localhost
   主机: localhost
   端口: 3306
   用户: root
   密码: root
   数据库: aidoctor
   ```

3. **测试连接**

### 使用建议

- **Oracle连接**：主开发时使用（必需）
- **MySQL连接**：本地快速测试时使用（可选）

## 表结构管理

### Flyway迁移脚本

项目使用**Flyway**管理数据库表结构，所有表结构定义都保存在迁移脚本中。

### 迁移脚本位置

```
diagnosis-service/src/main/resources/db/migration-oracle/
└── V1__init_diagnosis_tables.sql  ← 诊断服务所有表结构

execution-trace-service/src/main/resources/db/migration-oracle/
└── V1__init_execution_trace_table.sql  ← 执行追踪表结构
```

### 包含的内容

迁移脚本包含完整的表结构定义：
- ✅ 表结构定义（CREATE TABLE）
- ✅ 索引定义（CREATE INDEX）
- ✅ 触发器定义（CREATE TRIGGER）
- ✅ 表注释和字段注释（COMMENT）

### 自动执行

当服务启动时，Flyway会自动：
1. 检测数据库中的表结构
2. 对比迁移脚本
3. 自动执行未执行的迁移脚本
4. 创建或更新表结构

### 以后使用自己的数据库

**场景**：离开公司后，使用自己的Oracle数据库

**步骤：**

1. **修改连接信息**
   ```yaml
   # application-dev.yml
   spring:
     datasource:
       url: jdbc:oracle:thin:@你的Oracle地址:1521/你的服务名
       username: 你的用户名
       password: 你的密码
   ```

2. **启动服务**
   ```bash
   mvn spring-boot:run
   ```

3. **Flyway自动执行**
   - 检测到新数据库
   - 自动执行迁移脚本
   - 创建所有表结构
   - 完成初始化

**优势：**
- ✅ 不需要手动执行SQL脚本
- ✅ 表结构版本化管理
- ✅ 自动检测和执行
- ✅ 只创建表结构，不包含数据

## 常见问题

### 1. Oracle连接失败

**错误：`ORA-12514: 无法连接到数据库。服务 XE 未注册到监听程序`**

**解决方案：**
- 检查Service Name是否正确（尝试 `XEPDB1` 或 `ORCL`）
- 确认连接类型选择为 `Service name` 而不是 `SID`
- 联系DBA确认正确的连接信息

### 2. 如何临时使用MySQL

**场景**：需要本地快速测试（不需要安装Oracle）

**步骤：**
1. 修改 `application.yml`：`active: mysql`
2. 启动服务，Flyway会自动执行MySQL迁移脚本创建表结构
3. 使用本地MySQL进行开发测试

**注意**：MySQL配置是可选的，如果以后只用Oracle，可以删除MySQL相关配置。

### 3. 如何查看表结构

**在IDEA中：**
- 展开Oracle连接 → `AI_DOCTOR` → `Tables`
- 展开MySQL连接 → `aidoctor` → `Tables`

**在命令行中：**
```sql
-- Oracle
SELECT table_name FROM user_tables ORDER BY table_name;

-- MySQL
SHOW TABLES;
```

### 4. Flyway迁移失败

**错误：`FlywayException: Validate failed`**

**解决方案：**
- 检查迁移脚本语法是否正确
- 确认数据库连接正常
- 查看Flyway日志了解具体错误

### 5. 如何查看表结构定义

**查看迁移脚本：**
- 诊断服务：`diagnosis-service/src/main/resources/db/migration-oracle/V1__init_diagnosis_tables.sql`
- 执行追踪：`execution-trace-service/src/main/resources/db/migration-oracle/V1__init_execution_trace_table.sql`

**在IDEA中：**
- 直接打开SQL文件查看
- 或在Database工具窗口中查看表结构

## 总结

### 日常开发流程

1. **默认使用Oracle**（`active: dev`）
   - 日常开发、测试、提交代码
   - 数据写入Oracle

2. **可选使用MySQL**（`active: mysql`）
   - 本地快速测试时使用
   - 不需要安装Oracle客户端
   - 表结构由Flyway自动创建

### 配置文件位置

- **主配置**：各服务的 `application.yml`
- **Oracle配置**：各服务的 `application-dev.yml`（主环境）
- **MySQL配置**：各服务的 `application-mysql.yml`（可选）
- **表结构脚本**：
  - `diagnosis-service/src/main/resources/db/migration-oracle/V1__init_diagnosis_tables.sql`
  - `execution-trace-service/src/main/resources/db/migration-oracle/V1__init_execution_trace_table.sql`

### 重要提醒

- ✅ **默认使用Oracle**（主开发环境）
- ✅ **表结构已完整保留**（Flyway迁移脚本）
- ✅ **MySQL配置可选**（如果以后只用Oracle，可以删除）
- ✅ **以后使用自己的数据库**：只需修改连接信息，Flyway会自动创建表结构
- ✅ **不包含数据**：迁移脚本只包含表结构，不包含业务数据
