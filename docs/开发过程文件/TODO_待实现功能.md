## 🔄 工作态切换功能

### 问题描述

**问题ID**: `FEATURE-001`  
**创建日期**: 2026-01-16  
**优先级**: 中等（Medium）  
**状态**: 🔴 待实现

#### 问题背景

当前系统的健康状态判定逻辑如下：
1. 用户首次输入症状后，系统会进行健康状态判定（脑区0）
2. 根据判定结果，设置工作态为 `wellness_mode`（健康管理态）或 `clinical_mode`（临床诊疗态）
3. 如果判定为临床诊疗态，系统会自动开始诊断流程

#### 当前行为

- ✅ **健康管理态 → 临床诊疗态**：用户可以通过继续输入症状自动进入诊断流程
- ❌ **临床诊疗态 → 健康管理态**：无法自动切换

**具体场景**：
- 用户先描述了严重症状（如"胸痛、恶心"），系统判定为临床诊疗态，开始诊断
- 用户接着询问轻微问题（如"偶尔头疼"），系统会继续在临床诊疗态中处理，而不是重新进行健康状态判定
- 这导致轻微问题也被当作临床诊疗态处理，可能不符合用户期望

#### 技术细节

**相关文件**：
- `frontend/src/stores/diagnosisStore.ts` - `sendMessage` 方法（第121-208行）
- `frontend/src/components/diagnosis/DiagnosisInfoPanel.tsx` - "开始新诊断"按钮

**当前实现逻辑**：
```typescript
sendMessage: async (content: string) => {
  // ...
  
  // 如果还没有进行健康状态判定，先进行判定
  if (!state.healthAssessmentDone) {
    await get().performHealthAssessment(content)
    return
  }

  // 如果已经完成健康状态判定，但没有诊断ID，开始诊断
  if (!state.diagnosisId) {
    await get().startDiagnosis({...})
    return
  }

  // 如果已有诊断ID，发送回答（不会重新判定）
  await get().answerQuestion(content)
}
```

**问题点**：
- 一旦 `healthAssessmentDone = true` 且 `diagnosisId` 存在，系统就不会重新进行健康状态判定
- 用户可以通过"开始新诊断"按钮手动重置状态，但这需要用户主动操作

#### 解决方案建议

**方案1：智能识别新问题（推荐）**
- 在 `sendMessage` 方法中检测是否为新问题
- 当检测到新问题关键词（如"还有"、"另外"、"还想问"等）时，提示用户选择：
  - "继续当前诊断"
  - "开始新咨询"（重新进行健康状态判定）
- **优点**：智能、用户体验好
- **缺点**：需要实现新问题识别逻辑

**方案2：提供明确的"咨询新问题"入口**
- 在对话界面中添加"咨询新问题"按钮
- 点击后自动重置状态并重新进行健康状态判定
- **优点**：实现简单、用户意图明确
- **缺点**：需要用户手动操作

**方案3：混合方案**
- 方案1 + 方案2的组合
- 智能识别 + 明确入口
- **优点**：灵活、覆盖多种场景
- **缺点**：实现复杂度中等
