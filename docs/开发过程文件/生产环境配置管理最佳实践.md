# 生产环境配置管理最佳实践

## 概述

生产环境配置管理是系统安全性和可维护性的关键。本文档介绍不同场景下的配置管理方案。

## 配置管理方案对比

| 方案 | 适用场景 | 优点 | 缺点 | 推荐度 |
|------|---------|------|------|--------|
| **配置中心** | 微服务、多环境 | 集中管理、动态更新、版本控制 | 需要额外基础设施 | ⭐⭐⭐⭐⭐ |
| **环境变量** | 容器化部署、简单项目 | 简单、标准化、安全 | 难以管理大量配置 | ⭐⭐⭐⭐ |
| **外部配置文件** | 传统部署、单机应用 | 灵活、易维护 | 需要文件系统访问 | ⭐⭐⭐ |
| **密钥管理服务** | 高安全要求 | 加密存储、审计日志 | 成本较高 | ⭐⭐⭐⭐⭐ |
| **K8s ConfigMap/Secret** | Kubernetes环境 | 原生支持、版本管理 | 仅限K8s环境 | ⭐⭐⭐⭐ |

## 方案1：配置中心（推荐 - 微服务场景）

### 1.1 Nacos配置中心

**适用场景**：Spring Cloud微服务、多环境管理

#### 配置结构

```
Nacos配置中心
├── 命名空间（Namespace）
│   ├── dev（开发环境）
│   ├── test（测试环境）
│   └── prod（生产环境）
└── 配置组（Group）
    ├── DEFAULT_GROUP（默认组）
    └── 应用配置
        ├── diagnosis-service-dev.yml
        ├── diagnosis-service-prod.yml
        └── shared-config.yml（共享配置）
```

#### 实现方式

**1. 在Nacos中创建配置**

```yaml
# Data ID: diagnosis-service-prod.yml
# Group: DEFAULT_GROUP
# 命名空间: prod

spring:
  datasource:
    driver-class-name: oracle.jdbc.driver.OracleDriver
    url: jdbc:oracle:thin:@${DB_HOST}:${DB_PORT}/${DB_SERVICE}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}
  
  redis:
    host: ${REDIS_HOST}
    port: ${REDIS_PORT}
    password: ${REDIS_PASSWORD}
```

**2. 应用配置**

```yaml
# application.yml
spring:
  application:
    name: diagnosis-service
  profiles:
    active: prod
  cloud:
    nacos:
      config:
        server-addr: ${NACOS_SERVER:localhost:8848}
        namespace: ${NACOS_NAMESPACE:prod}  # 生产环境命名空间
        group: DEFAULT_GROUP
        file-extension: yml
        shared-configs:  # 共享配置
          - data-id: shared-config.yml
            group: DEFAULT_GROUP
            refresh: true
```

**3. 敏感信息处理**

敏感信息（密码、密钥）建议使用：
- Nacos的加密配置功能
- 或通过环境变量注入

```yaml
# Nacos配置（不包含密码）
spring:
  datasource:
    url: jdbc:oracle:thin:@${DB_HOST}:${DB_PORT}/${DB_SERVICE}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}  # 从环境变量读取
```

#### 优点

- ✅ 集中管理，统一修改
- ✅ 支持动态刷新（`@RefreshScope`）
- ✅ 版本控制和回滚
- ✅ 多环境隔离（命名空间）
- ✅ 配置共享和继承

#### 缺点

- ❌ 需要部署Nacos服务
- ❌ 增加系统复杂度
- ❌ 需要网络访问

### 1.2 Apollo配置中心

**适用场景**：大型企业、多团队协作

特点：
- 更强大的权限管理
- 配置变更审计
- 灰度发布配置

### 1.3 Consul配置中心

**适用场景**：服务发现 + 配置管理一体化

## 方案2：环境变量（推荐 - 容器化场景）

### 2.1 Docker/Kubernetes环境

**适用场景**：容器化部署、CI/CD流水线

#### Docker Compose方式

```yaml
# docker-compose.prod.yml
version: '3.8'

services:
  diagnosis-service:
    image: aidoctor/diagnosis-service:latest
    environment:
      - SPRING_PROFILES_ACTIVE=prod
      - DB_HOST=${DB_HOST}
      - DB_PORT=${DB_PORT}
      - DB_SERVICE=${DB_SERVICE}
      - DB_USERNAME=${DB_USERNAME}
      - DB_PASSWORD=${DB_PASSWORD}
      - REDIS_HOST=${REDIS_HOST}
      - REDIS_PORT=${REDIS_PORT}
    env_file:
      - .env.prod  # 生产环境变量文件
    volumes:
      - ./logs:/app/logs
```

#### Kubernetes方式

```yaml
# deployment.yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: diagnosis-service
spec:
  template:
    spec:
      containers:
      - name: diagnosis-service
        image: aidoctor/diagnosis-service:latest
        env:
        - name: SPRING_PROFILES_ACTIVE
          value: "prod"
        - name: DB_HOST
          valueFrom:
            configMapKeyRef:
              name: app-config
              key: db.host
        - name: DB_PASSWORD
          valueFrom:
            secretKeyRef:
              name: app-secrets
              key: db.password
        envFrom:
        - configMapRef:
            name: app-config
```

**ConfigMap示例：**

```yaml
# configmap.yaml
apiVersion: v1
kind: ConfigMap
metadata:
  name: app-config
data:
  DB_HOST: "192.168.1.100"
  DB_PORT: "1521"
  DB_SERVICE: "ORCL"
  DB_USERNAME: "AI_DOCTOR"
  REDIS_HOST: "redis-service"
  REDIS_PORT: "6379"
```

**Secret示例：**

```yaml
# secret.yaml
apiVersion: v1
kind: Secret
metadata:
  name: app-secrets
type: Opaque
stringData:
  DB_PASSWORD: "your-secure-password"
  REDIS_PASSWORD: "redis-password"
```

### 2.2 系统环境变量

**适用场景**：传统服务器部署、systemd服务

#### systemd服务配置

```ini
# /etc/systemd/system/diagnosis-service.service
[Unit]
Description=AI Doctor Diagnosis Service
After=network.target

[Service]
Type=simple
User=appuser
WorkingDirectory=/opt/aidoctor/diagnosis-service
EnvironmentFile=/etc/aidoctor/prod.env
ExecStart=/usr/bin/java -jar diagnosis-service.jar
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

**环境变量文件：**

```bash
# /etc/aidoctor/prod.env
SPRING_PROFILES_ACTIVE=prod
DB_HOST=192.168.1.100
DB_PORT=1521
DB_SERVICE=ORCL
DB_USERNAME=AI_DOCTOR
DB_PASSWORD=secure_password_here
REDIS_HOST=192.168.1.101
REDIS_PORT=6379
REDIS_PASSWORD=redis_password
```

**文件权限：**

```bash
# 设置文件权限（仅root可读写）
chmod 600 /etc/aidoctor/prod.env
chown root:root /etc/aidoctor/prod.env
```

## 方案3：外部配置文件

### 3.1 配置文件外置

**适用场景**：传统部署、需要频繁修改配置

#### Spring Boot外置配置

```bash
# 启动命令
java -jar diagnosis-service.jar \
  --spring.config.location=file:/etc/aidoctor/application-prod.yml \
  --spring.profiles.active=prod
```

**配置文件位置：**

```
/etc/aidoctor/
├── application-prod.yml
├── application-test.yml
└── secrets/
    └── db-credentials.yml  # 敏感信息单独文件
```

#### 配置文件内容

```yaml
# /etc/aidoctor/application-prod.yml
spring:
  datasource:
    driver-class-name: oracle.jdbc.driver.OracleDriver
    url: jdbc:oracle:thin:@192.168.1.100:1521/ORCL
    username: ${DB_USERNAME}  # 仍可从环境变量读取
    password: ${DB_PASSWORD}
  
  redis:
    host: 192.168.1.101
    port: 6379
    password: ${REDIS_PASSWORD}
```

**文件权限：**

```bash
chmod 640 /etc/aidoctor/application-prod.yml
chown appuser:appgroup /etc/aidoctor/application-prod.yml
```

## 方案4：密钥管理服务（高安全场景）

### 4.1 HashiCorp Vault

**适用场景**：高安全要求、多团队、合规要求

#### 配置示例

```java
// 从Vault读取配置
@Configuration
public class VaultConfig {
    @Value("${vault.uri}")
    private String vaultUri;
    
    @Bean
    public VaultTemplate vaultTemplate() {
        VaultEndpoint endpoint = VaultEndpoint.create(vaultUri);
        return new VaultTemplate(endpoint, new TokenAuthentication("your-token"));
    }
}
```

#### Vault存储结构

```
secret/
├── aidoctor/
│   ├── prod/
│   │   ├── database
│   │   │   ├── username
│   │   │   └── password
│   │   └── redis
│   │       └── password
│   └── test/
│       └── ...
```

## 方案5：混合方案（推荐）

### 5.1 配置分层策略

```
配置优先级（从高到低）：
1. 环境变量（最高优先级）
2. 配置中心（Nacos/Apollo）
3. 外部配置文件
4. 应用内配置文件（application.yml）
```

### 5.2 实际配置结构

```yaml
# application.yml（基础配置，提交到Git）
spring:
  application:
    name: diagnosis-service
  profiles:
    active: ${SPRING_PROFILES_ACTIVE:dev}
  cloud:
    nacos:
      config:
        enabled: ${NACOS_ENABLED:true}
        server-addr: ${NACOS_SERVER:localhost:8848}
        namespace: ${NACOS_NAMESPACE:dev}

# application-prod.yml（生产环境模板，不包含敏感信息）
spring:
  datasource:
    url: jdbc:oracle:thin:@${DB_HOST}:${DB_PORT}/${DB_SERVICE}
    username: ${DB_USERNAME}
    password: ${DB_PASSWORD}  # 从环境变量或密钥服务读取
```

## 生产环境配置最佳实践

### 1. 敏感信息处理

✅ **推荐做法：**

- 密码、密钥等敏感信息**永远不要**提交到代码仓库
- 使用环境变量或密钥管理服务
- 配置文件使用占位符：`${DB_PASSWORD}`

❌ **错误做法：**

```yaml
# ❌ 不要这样做！
spring:
  datasource:
    password: mypassword123  # 明文密码
```

### 2. 配置分离

```
✅ 推荐结构：
├── application.yml          # 基础配置（提交Git）
├── application-dev.yml     # 开发环境（提交Git）
├── application-prod.yml    # 生产环境模板（提交Git，不含敏感信息）
└── .env.prod              # 生产环境变量（不提交Git，服务器上配置）
```

### 3. 配置版本管理

- 使用配置中心的版本控制功能
- 重要配置变更前备份
- 支持快速回滚

### 4. 配置验证

```yaml
# 启动时验证必需配置
spring:
  config:
    import:
      - optional:file:.env[.properties]
    validate:
      enabled: true
```

### 5. 配置监控

- 监控配置变更
- 记录配置访问日志
- 告警异常配置

## 不同部署场景推荐方案

### 场景1：传统服务器部署

**推荐方案：**
- 环境变量 + 外部配置文件
- systemd服务 + `/etc/aidoctor/prod.env`

### 场景2：Docker容器部署

**推荐方案：**
- 环境变量 + Docker Secrets
- `.env.prod` 文件（不提交Git）

### 场景3：Kubernetes部署

**推荐方案：**
- ConfigMap + Secret
- 或配置中心（Nacos/Apollo）

### 场景4：微服务架构

**推荐方案：**
- 配置中心（Nacos/Apollo）
- 环境变量作为补充

### 场景5：高安全要求

**推荐方案：**
- 密钥管理服务（Vault/AWS Secrets Manager）
- 配置中心 + 密钥服务

## 总结

| 场景 | 推荐方案 | 优先级 |
|------|---------|--------|
| 微服务、多环境 | 配置中心（Nacos） | ⭐⭐⭐⭐⭐ |
| 容器化部署 | 环境变量 + ConfigMap/Secret | ⭐⭐⭐⭐⭐ |
| 传统服务器 | 环境变量 + 外部配置文件 | ⭐⭐⭐⭐ |
| 高安全要求 | 密钥管理服务（Vault） | ⭐⭐⭐⭐⭐ |
| 简单项目 | 环境变量 | ⭐⭐⭐⭐ |

**核心原则：**
1. 敏感信息永远不提交到代码仓库
2. 配置与代码分离
3. 支持多环境管理
4. 配置变更可追溯
5. 支持快速回滚
