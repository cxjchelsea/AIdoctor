## 2. 总体蓝图补充

总体架构增加以下稳定公式：

```text
Stable Clinical Platform
+ Versioned Capability Package
= New Supported Clinical Scenario
```

`adult_respiratory_v1` 是第一个用于验证平台的场景坍缩，不是系统永久只能处理呼吸道疾病。

新增场景必须交付完整 Capability Package，而不是只替换 Prompt 或知识文档。Package 至少包含：

- Scope/Population；
- Terminology Pack；
- Observation Profile；
- Safety Pack；
- Question Pack；
- Hypothesis Pack；
- Knowledge Policy/Release；
- Tool/Skill Allowlist；
- Prompt Releases；
- Model Route Releases；
- Delivery Policy；
- Eval Suite。

## 3. 企业级临床 Agent 主方案补充

主方案中的 Agent 动态性仍只存在于批准的 NextAction 范围。

新增约束：

1. Capability Router 必须先加载明确的 Capability Release；
2. Safety、Question、Hypothesis、Tool、Prompt、Model 和 Knowledge 均受该 Release 限制；
3. 业务节点不得直接选择供应商模型或任意知识索引；
4. 高风险任务没有已验证模型时，切确定性安全路径、固定 Workflow 或医生审核；
5. 新 Capability 必须独立完成临床评估和放量审批。

完整调用链：

```text
Encounter / Thread
→ Capability Release
→ Context Assembly
→ Deterministic Safety Skeleton
→ Approved Clinical/Model/Tool Action
→ Validation
→ State Committer
→ Checkpoint
→ Delivery / Review
```

## 4. 临床数据与循证智能补充

Evidence Intelligence 的生产基线明确为：

```text
Source Registry
+ Licensed/Reviewed Source
+ Structure-aware Chunking
+ PostgreSQL Metadata
+ BM25
+ pgvector
+ Reranker
+ Claim-Level Citation
+ EvidencePack
+ Knowledge Release
```

### 4.1 Patient RAG 与 Medical RAG

两者必须隔离：

- Patient RAG：患者/租户/Consent/时间范围，结构化查询优先；
- Medical RAG：白名单来源、版本、人群、地区、证据和 Citation。

两者不得使用无权限隔离的同一索引或 collection。

### 4.2 知识图谱

Knowledge Graph 只作为：

- 术语归一化；
- Query Expansion；
- 症状—疾病—检查多跳关系；
- must-not-miss 扩展。

它不能替代指南、证据等级、适用性和 Citation。生产启用必须经过 provenance 治理和无图/有图对照实验，并绑定 `graph_release_id`。

### 4.3 Knowledge Release

每次检索和 EvidencePack 必须记录：

- `knowledge_release_id`；
- embedding version；
- BM25/index version；
- reranker version；
- graph release（若启用）；
- source filters；
- rejected items 和 reason codes。

## 5. Agent Runtime Foundations 补充

原 Model Router 扩展为统一 Model Runtime：

```text
Prompt Registry
→ Prompt Loader
→ Prompt Builder
→ Model Router
→ Model Gateway
→ Provider Adapter
→ Structured Output Validator
```

### 5.1 统一入口

所有模型调用必须经过 Model Gateway。业务模块只能引用稳定 `route_id`，不得：

- 直接调用 OpenAI/Qwen/Claude/本地模型 SDK；
- 在节点内写死模型名称；
- 自行加载未发布 Prompt；
- 自行实现不一致的重试、JSON 修复和 Fallback；
- 将模型输出直接写数据库。

### 5.2 Prompt Runtime

Prompt 必须拥有：

- `prompt_id/version`；
- task/capability/language/risk；
- input/output Schema；
- allowed route；
- owner/reviewer；
- Eval；
- release/rollback。

ContextEnvelope 不是 Prompt；Prompt Builder 依据节点、模型和 Schema 渲染本次调用。

### 5.3 确定性边界

以下保持确定性：State Committer、最终 Safety/Triage、权限、Consent、Checkpoint/Resume、幂等、Outbox/Inbox 和 Audit。

## 6. Durable Execution 与可观测性补充

Checkpoint、AgentEvent、ClinicalDecisionRecord 和 Release Audit 必须能够关联：

```text
capability_release_id
prompt_release_id
model_route_release_id
selected_model_id
knowledge_release_id
embedding_version
reranker_version
graph_release_id
context_hash
contract_version
graph_version
cdp_version
checkpoint_id
```

### 6.1 恢复

恢复时不得自动切换到“最新” Prompt、Model 或 Knowledge。应：

1. 使用原版本恢复；
2. 若原版本不可用，执行显式 MigrationDecision；
3. 高风险迁移失败则进入固定 Workflow 或人工审核；
4. 记录版本变化和原因。

### 6.2 Replay

Replay 默认使用历史版本快照，且禁止重复不可逆动作。对比实验可显式指定新 Prompt、Model 或 Knowledge Release，但结果只能进入 Evaluation，不修改历史临床状态。

## 8. 统一发布单元

生产发布不再只由应用版本表示：

```text
Application
+ Contracts / Schema
+ Graph Runtime
+ Capability Release
+ Safety Policy
+ Prompt Releases
+ Model Route Releases
+ Knowledge Release
+ Tool/Skill Releases
+ Eval Report
```

这些版本必须形成统一 Release Manifest，并可独立禁用和回滚。

## 9. 统一扩场景流程

```text
新场景立项
→ Capability Scope 与排除项
→ Terminology / Observation / Safety / Question / Hypothesis Pack
→ Knowledge Source Manifest 与 Release
→ Prompt / Model Route
→ Tool/Skill Allowlist
→ Clinical + Safety + RAG + Model Eval
→ Shadow
→ Clinician Assist
→ Restricted Rollout
→ Production Release
```

平台代码只在通用契约或 Runtime 能力确实不足时修改；临床差异优先进入 Capability Package。
