# AIdoctor 外部产品参考与架构抽象矩阵

> 文档状态：`FUTURE_EXTENSION_DESIGN`  
> 用途：记录外部医疗健康产品对 AIdoctor 的可迁移设计思想，避免直接复制产品功能或反复修改核心架构  
> 当前 Runtime 影响：`NONE`  
> 实现授权：`NOT_AUTHORIZED`

---

## 1. 使用原则

本矩阵关注的不是“这个产品有哪些功能”，而是：

```text
外部产品观察
→ 它解决的系统性问题
→ AIdoctor 已有/缺失抽象
→ 可吸收设计思想
→ 是否需要未来 Extension
```

任何外部产品都不是 AIdoctor 的规范 Source of Truth。

产品能力、接口、许可和商业策略可能变化；真正进入实施前必须重新验证外部事实、API、License、Region 和 Privacy 条款。

## 4. 对当前 AIdoctor 的 Gap 判断

### 4.1 已经存在，不应重构

| 能力 | 当前判断 |
|---|---|
| Constrained Agent Runtime | 已有目标设计，不因外部插件改变 |
| State Committer | 已有，不允许 Connector/Provider 绕过 |
| Capability Package | 已有，应扩展而不是替换 |
| Medical RAG | 已有，继续负责长文本循证知识 |
| Knowledge Graph | 已有可选增强定位，不升级为总知识库 |
| EvidencePack | 已有，应作为未来 Provider 证据归一化出口 |
| ToolContext / ToolResult | 已有，未来设备和 Provider Tool 应复用其边界思想 |
| Model Runtime | 正在重构，不因这些外部产品插入 Scope |

### 4.2 当前没有正式落地、值得作为 Future Extension

```text
Connector Registry
ExternalHealthSourceConnection
Device Adapter Contract
Measurement / Biosignal / Image Artifact vNext
Structured Medical Provider Registry
ProviderResult / Evidence Normalizer
Temporal Capability Policy
Multimodal Capability Policy
```

这些属于下一版本候选，不修改当前 `contracts/v1`。

## 5. 对数字脉诊和舌象项目的直接影响

### 数字脉诊

借鉴链：

```text
freddy / Fitness AI Connector
↓
Connector + Narrow Tool Surface
↓
digital-pulse-diagnosis 独立服务
↓
PulseDeviceAdapter
↓
ToolResult / ObservationCandidate
↓
AIdoctor State Committer
```

不做：

```text
AIdoctor 直接依赖设备驱动
AIdoctor 直接运行全部信号处理算法
Pulse 模型直接写 Clinical State
```

### 舌象分析

借鉴链：

```text
Device Connector Pattern
↓
独立 Tongue Analysis Service
↓
Image Artifact + Quality Metadata
↓
Tongue Tool
↓
ObservationCandidate
↓
State Committer
```

必须特别保留 camera / lighting / calibration / model version provenance。

## 6. 对 RAG / KG 的直接影响

这些外部产品不要求重做 RAG/KG，而是帮助明确知识边界：

```text
RAG
= 长文本、指南、研究、患者教育

KG
= 术语、关系、Query Expansion、受控多跳

Structured Provider
= 药物、监管、器械等天然结构化权威事实

Patient Evidence
= 患者历史、设备数据、EHR、报告
```

四类数据不应塞进同一个 Vector Store 或 Neo4j 后统一交给 LLM。

## 8. 升级为正式 Extension 的条件

当某个外部模式同时满足以下条件时，才从本矩阵升级为独立设计或正式 ADR：

1. 解决的是平台级问题，而非单个产品功能；
2. 当前 Stable Platform 无法优雅表达；
3. 至少有一个明确业务场景需要；
4. 不引入新的临床真值旁路；
5. Contract / Security / Privacy / Evidence 影响可定义；
6. 能建立独立评估标准。

---

## 9. 当前结论

当前外部产品研究对 AIdoctor 的主要价值已经收敛为四个 Future Extension Pattern：

```text
1. External Health Connector
2. Device Adapter / Narrow Tool Surface
3. Structured Medical Provider
4. Advanced Capability Template
```

这些模式应被沉淀、评估和版本化，但当前不修改正在执行的重构路线。
