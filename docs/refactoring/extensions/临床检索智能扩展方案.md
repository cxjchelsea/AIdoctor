# AIdoctor 临床检索智能扩展方案

> 文档状态：`FUTURE_EXTENSION_DESIGN`  
> 设计主题：`Clinical Retrieval Intelligence`  
> 适用基线：`agent/enterprise-agent-refactoring-plan` 当前冻结/冻结候选架构之上的未来扩展  
> 当前 Runtime 影响：`NONE`  
> Shared Contracts v1 影响：`NONE`  
> 当前 Capability 影响：`NONE`  
> 当前 Production 影响：`NONE`  
> 实现授权：`NOT_AUTHORIZED`  
> 设计目标：在不破坏现有 Constrained Agentic Workflow、Evidence Intelligence、Knowledge Graph、Medical RAG、Structured Medical Provider、Evidence Ledger 与 Safety Governance 的前提下，为未来版本预设计“临床意图理解 → 多路召回 → 临床价值重排 → 证据充分性判断 → 定向再检索”的受约束检索智能层。

---

## 1. 文档目的

AIdoctor 当前重构已经重点解决：

- 临床状态如何被结构化、版本化和审计；
- Agent 如何在受约束工作流中运行；
- Safety、Consent、Permission、Human Review 如何成为强制边界；
- Medical RAG、Knowledge Graph、Structured Medical Provider 如何提供不同类型的医学知识；
- EvidencePack、Evidence Ledger 如何保存来源、支持关系、冲突和局限；
- Capability 如何决定允许执行的临床范围。

但在“信息如何进入临床推理”这一层，未来仍存在一个平台级问题：

> **相关信息很多，但系统如何判断当前应该检索什么、从哪里检索、哪些结果真正具有临床决策价值，以及何时需要继续寻找缺失证据？**

普通 RAG 往往只完成：

```text
User Query
→ Embedding
→ Vector Top-K
→ LLM
```

这不足以覆盖复杂临床决策中的以下情况：

- 患者输入模糊、口语化或缺乏医学术语；
- 一个临床问题同时涉及症状、鉴别诊断、指南、检查、风险和患者历史；
- 最高语义相似度的文档并不一定最有临床决策价值；
- must-not-miss 疾病可能与当前 Query 字面相似度较低；
- 不同来源之间可能冲突；
- 当前证据可能不足以区分多个诊断假设；
- 系统需要根据 Evidence Gap 发起第二轮定向检索，而不是一次性生成结论。

因此，本方案提出未来候选扩展：

> **Clinical Retrieval Intelligence（临床检索智能层）**

它不是新的自由 Agent，也不是新的临床真值源，而是一组受治理的检索规划、候选生成、临床排序和证据充分性评估能力。

---

## 2. 核心判断

本方案吸收现代搜索、推荐、RAG 和 Agentic Retrieval 中可泛化的系统思想，但不复制互联网推荐系统目标。

互联网内容系统常见目标：

```text
相关性
+ 兴趣匹配
+ Engagement
+ Exploration
```

医疗系统不能采用同样目标。

AIdoctor 未来允许的对应抽象必须变成：

```text
Clinical Relevance
+ Patient Applicability
+ Evidence Authority
+ Diagnostic Discriminability
+ Must-not-miss Coverage
+ Safety
+ Traceability
```

因此：

```text
Interest Exploration
≠
Clinical Hypothesis Expansion
```

未来系统只允许进行：

> `Clinically Necessary Hypothesis Expansion`

即基于 Capability、临床状态、医学关系、must-not-miss policy 和证据缺口进行有限候选扩展。

禁止：

- 因 embedding 相似度自由联想疾病；
- 为提高“覆盖率”无限扩展诊断候选；
- 将推荐系统中的探索策略直接映射为疾病探索；
- 以用户停留、点击、情绪反馈优化诊断输出；
- 让无来源的 LLM 联想结果进入 Clinical Truth；
- 让 Retrieval Intelligence 绕过 Safety、Capability、Permission、State Committer 或 Clinician Review。

## 3. 与现有架构的关系

Clinical Retrieval Intelligence 不替代现有任何核心层。

### 3.1 与 Evidence Intelligence 的关系

现有 Evidence Intelligence 负责：

- Clinical Question Parsing；
- PICO Builder；
- Source Retrieval；
- Evidence Ranking；
- Applicability Evaluation；
- Citation Validation；
- Conflict Detection。

Clinical Retrieval Intelligence 是其未来增强层，重点解决：

```text
检索什么
→ 从哪些路径检索
→ 如何构造不同检索目标
→ 如何融合候选
→ 如何按临床决策价值重排
→ 当前证据是否足够
→ 还缺什么
→ 是否允许定向再检索
```

它应优先作为 Evidence Intelligence 内部可组合能力演进，而不是新建一个平行微服务或新 Agent。

### 3.2 与 Medical RAG 的关系

Medical RAG 继续负责：

- 指南；
- 系统综述；
- 研究；
- 患者教育；
- 需要保留原文语境的医学文本。

Clinical Retrieval Intelligence 只决定：

- 当前是否需要 Medical RAG；
- 应构造什么检索目标；
- 哪类来源优先；
- 候选如何参与统一排序。

### 3.3 与 Knowledge Graph 的关系

Knowledge Graph 继续用于：

- Terminology；
- Concept Relation；
- Query Expansion；
- must-not-miss 扩展；
- Controlled Multi-hop。

Clinical Retrieval Intelligence 不允许自由图遍历。

未来 KG 扩展必须满足：

```text
Clinical Intent
+ Capability Allowlist
+ Relation Allowlist
+ Hop Limit
+ Source Provenance
+ Expansion Budget
```

### 3.4 与 Structured Medical Provider 的关系

Structured Provider 继续负责确定性、结构化、权威数据库访问，例如：

- 药物；
- 监管；
- 器械；
- 其他权威结构化数据库。

Clinical Retrieval Intelligence 只负责在需要时选择对应 Provider Tool，并将返回结果归一到候选证据池。

### 3.5 与 Evidence Ledger / Encounter CDP 的关系

Retrieval Intelligence 不拥有患者状态。

它只读取：

- Encounter observations；
- hypotheses；
- uncertainty；
- triage；
- existing EvidencePack；
- longitudinal patient context（在授权范围内）。

任何结果都不能直接写入长期 Patient Truth。

候选证据只能进入受治理的：

```text
Retrieved Evidence
→ Evidence Normalization
→ EvidencePack / Candidate
→ Clinical Reasoning
→ State Committer
```

## 5. 核心组件设计

## 5.1 Clinical Query Understanding

### 5.1.1 目的

将自然语言 Query 转换为受约束的临床检索意图，而不是直接生成最终搜索字符串。

患者可能输入：

```text
“咳了好几天，昨晚开始喘，今天有点发热。”
```

系统不应只做一次 embedding。

未来可生成：

```text
Symptom Intent
- cough
- dyspnea
- fever

Temporal Intent
- several days
- worsening last night

Risk Intent
- acute respiratory deterioration

Diagnostic Intent
- likely differential
- must-not-miss differential

Evidence Intent
- adult acute respiratory guidance
```

### 5.1.2 候选数据结构

以下为 vNext Candidate，不修改当前 `contracts/v1`：

```python
class ClinicalRetrievalIntent(BaseModel):
    intent_id: str
    encounter_id: str
    capability_id: str

    normalized_concepts: list[str]
    temporal_context: dict[str, str]
    patient_context_refs: list[str]

    retrieval_goals: list[Literal[
        "symptom_context",
        "diagnostic_differential",
        "must_not_miss",
        "guideline_recommendation",
        "workup_discrimination",
        "contraindication",
        "patient_history",
        "structured_fact",
        "evidence_gap_resolution",
    ]]

    prohibited_goals: list[str]
    confidence: float
    source_observation_ids: list[str]
```

### 5.1.3 约束

Query Understanding 只能：

- 归一化；
- 分类；
- 拆解检索目标；
- 提取上下文；
- 生成检索候选意图。

不能：

- 宣告诊断；
- 修改 CDP；
- 创建长期患者事实；
- 无边界添加疾病标签。

---

## 5.2 Clinical State Contextualization

检索不能只看当前一句话。

未来检索上下文应至少考虑：

```text
Current Encounter Observations
+ Known Negatives
+ Unknowns
+ Diagnostic Hypotheses
+ Uncertainty
+ Triage State
+ Age / Sex / Pregnancy / Major Risk Context（在 Capability 与 Consent 允许时）
+ Relevant Longitudinal Facts
```

必须明确区分：

- patient-confirmed；
- artifact-confirmed；
- clinician-confirmed；
- model-inferred；
- unknown。

低可信模型推断不能与已确认事实同权参与 Query Expansion。

---

## 5.3 Retrieval Intent Planner

### 5.3.1 目标

把一个临床问题拆成有限数量、可解释、可审计的检索任务。

例如：

```text
Goal 1: 当前最可能解释症状的常见疾病证据
Goal 2: must-not-miss 严重疾病排查证据
Goal 3: 区分候选 A / B 所需的关键检查或问诊信息
Goal 4: 当前患者是否存在改变处置的风险因素
```

### 5.3.2 Retrieval Plan Candidate

```python
class RetrievalTask(BaseModel):
    task_id: str
    goal: str
    route_type: Literal[
        "medical_rag",
        "knowledge_graph",
        "structured_provider",
        "encounter_ledger",
        "longitudinal_record",
        "capability_reference",
    ]

    query: str | None
    concept_ids: list[str]
    filters: dict[str, str]

    priority: Literal["mandatory", "high", "normal", "optional"]
    reason: str

    max_candidates: int
    timeout_ms: int | None
```

### 5.3.3 Budget

任何一次检索计划必须存在：

- route budget；
- candidate budget；
- latency budget；
- token budget；
- re-retrieval budget。

禁止“多路召回”退化为“所有系统全部查一遍”。

---

## 5.4 Multi-Route Candidate Retrieval

未来允许以下受控路径。

### A. Medical RAG

适合：

- 指南；
- 推荐条款；
- 研究；
- 系统综述；
- 需要上下文的医学证据。

候选生成可组合：

```text
Lexical Retrieval
+ Dense Retrieval
+ Metadata Filtering
+ Source Tier Filtering
```

但是否采用 BM25、Dense、Hybrid、ColBERT 或其他技术属于未来实现决策，不在本设计中冻结。

### B. Knowledge Graph

适合：

- concept normalization；
- synonym expansion；
- symptom-disease relation；
- disease-test relation；
- must-not-miss expansion；
- controlled relation traversal。

禁止无界图搜索。

### C. Structured Medical Provider

适合：

- drug fact；
- interaction；
- contraindication；
- regulatory fact；
- device fact。

结构化精确查询优先于把数据库文本化再做 embedding。

### D. Encounter Evidence Ledger

适合：

- 当前已经掌握什么；
- 某观察是否存在；
- 某信息是否已经确认；
- 是否重复提问；
- 当前未知项是什么。

### E. Longitudinal Patient Record

只在 Consent、Permission 与 Capability 允许时访问。

用于：

- 既往疾病；
- 既往检查；
- 长期用药；
- 过敏；
- 长期风险因素；
- 历史相同/相关 Encounter。

### F. Capability Reference

用于：

- Capability 内部受控临床路径；
- Mandatory Safety Rule；
- allowed question / workup / escalation references。

它不等价于互联网检索。

原则：

> 原始召回分数不得直接被解释为临床可信度。

## 5.6 Clinical Evidence Reranker

这是本扩展的核心候选能力。

### 5.6.1 为什么需要临床重排

最高 semantic similarity 不等于最高 clinical utility。

例如：

| 候选 | 语义相似度 | 临床价值 |
|---|---:|---:|
| 普通疾病百科 | 高 | 中 |
| 最新权威指南 | 中高 | 很高 |
| 能排除 must-not-miss 的关键证据 | 中 | 极高 |
| 不适用于当前年龄/人群的研究 | 高 | 低 |

未来排序目标应从：

```text
Similarity Score
```

演进到：

```text
Clinical Utility Score
```

### 5.6.2 候选评分维度

建议未来评估以下维度：

```text
Semantic Relevance
Clinical Relevance
Patient Applicability
Evidence Authority
Evidence Quality
Diagnostic Discriminability
Must-not-miss Importance
Recency / Freshness
Jurisdiction Match
Source Diversity
Redundancy Penalty
Conflict Signal
Safety Relevance
Traceability Completeness
```

### 5.6.3 不建议冻结为简单加权公式

早期原型可以用显式权重：

```text
score =
  w1 * semantic_relevance
+ w2 * clinical_relevance
+ w3 * authority
+ w4 * applicability
+ w5 * discriminability
+ w6 * safety_relevance
- w7 * redundancy
- w8 * population_mismatch
```

但该公式只能作为研究基线。

长期实现可以评估：

- rule-based reranking；
- learning-to-rank；
- cross-encoder；
- LLM judge with structured rubric；
- hybrid reranking。

任何学习型排序器必须独立评估，不能直接因离线指标提升进入生产。

---

## 5.7 Source Diversity / Redundancy Control

互联网推荐的“打散”思想可以被有限吸收，但医疗版目标不是内容多样性，而是：

> **避免同一来源、同一结论、同一证据链重复占据候选池，从而掩盖真正不同的临床证据。**

未来可控制：

- 同来源重复；
- 同一指南不同 chunk 重复；
- 同一观点重复；
- 低质量二手来源挤占权威来源；
- 单一检索 route 垄断 Top-K。

但禁止为了“多样性”主动加入低相关或低质量医学信息。

---

## 5.8 Evidence Sufficiency Evaluator

### 5.8.1 核心问题

系统在完成一轮检索和推理后，应判断：

> **现有证据是否足以支持当前下一步临床动作？**

注意不是：

> “有没有搜到足够多文档？”

### 5.8.2 候选状态

```python
class EvidenceSufficiencyState(BaseModel):
    status: Literal[
        "sufficient",
        "insufficient",
        "conflicting",
        "population_mismatch",
        "stale_evidence",
        "unsafe_to_conclude",
    ]

    supported_hypotheses: list[str]
    unresolved_hypotheses: list[str]
    unresolved_questions: list[str]
    missing_evidence_types: list[str]
    must_not_miss_gaps: list[str]

    reason_codes: list[str]
```

### 5.8.3 充分性必须与动作绑定

不能定义全局“证据充分”。

应问：

```text
是否足以继续问诊？
是否足以建议常规就医？
是否足以触发升级？
是否足以推荐某项检查？
是否足以向医生展示某个鉴别诊断？
```

不同动作需要不同 Evidence Threshold。

---

## 5.9 Evidence Gap Detection

Evidence Gap 是本设计与普通 RAG 的关键区别。

未来需要识别：

```text
Missing Observation
Missing Negative Evidence
Missing Guideline Support
Missing Patient Applicability
Unresolved Conflict
Unresolved Must-not-miss
Missing Temporal Information
Missing Workup Discriminator
Missing Contraindication Check
```

例如：

```text
Hypothesis A: 支持证据充分
Hypothesis B: 部分支持
Hypothesis C: must-not-miss，但关键排除信息缺失
```

则系统不应继续扩展更多疾病，而应优先产生：

```text
Gap = 缺少排除 C 的关键证据
```

然后决定：

```text
Ask User
OR
Retrieve Guideline
OR
Check Existing Record
OR
Structured Provider Query
OR
Escalate
```

---

## 5.10 Targeted Re-retrieval

第二轮检索必须是“针对缺口”，不是重复第一轮 Query。

错误模式：

```text
第一轮结果不好
→ 把原 Query 再搜一次
```

正确候选：

```text
Evidence Gap
→ Specific Retrieval Goal
→ Route Selection
→ Bounded Query
→ Candidate Merge
→ Re-rank
```

### 5.10.1 强制停止条件

未来 Runtime 必须限制：

```text
max_retrieval_rounds
max_total_candidates
max_route_calls
max_external_calls
max_latency
max_cost
```

达到边界后进入：

- uncertainty disclosure；
- ask user；
- clinician review；
- safe escalation；
- stop。

禁止无限 Agentic Retrieval。

## 6. 临床候选扩展策略

未来诊断候选扩展建议分层，而不是普通“相关推荐”。

```text
Likely
Must-not-miss
Alternative
Rule-out
Context-dependent
```

### 6.1 Likely

基于当前 observation、流行病学和 Capability 知识形成的高概率候选。

### 6.2 Must-not-miss

即使概率较低，只要漏诊代价显著，也应进入受控检索。

### 6.3 Alternative

用于解释当前证据但不是首选的合理候选。

### 6.4 Rule-out

用于获得排除性信息。

### 6.5 禁止行为

禁止：

```text
embedding nearest diseases
→ 全部加入 differential
```

任何候选必须带：

```text
expansion_reason
source
clinical_relation
priority
safety_role
```

---

## 7. 与 Question Policy 的联动

Evidence Gap 不一定通过继续检索解决。

系统应在以下动作中选择：

```text
Retrieve
Ask
Use Existing Record
Request Artifact
Escalate
Stop
```

因此，Clinical Retrieval Intelligence 必须与 Question Policy 协作。

例如：

```text
缺少“是否胸痛”
```

通常应：

```text
Ask Patient
```

而不是检索文献。

例如：

```text
缺少“当前指南是否建议某项检查”
```

应：

```text
Retrieve Guideline
```

例如：

```text
缺少“患者当前是否使用某药”
```

优先：

```text
Existing Record / Ask Patient
```

而不是让 LLM 猜测。

## 8. 安全与治理要求

Clinical Retrieval Intelligence 属于高风险临床信息入口，未来实现必须至少满足以下要求。

### 8.1 Capability Boundary

每个 Capability 必须声明：

- allowed retrieval goals；
- allowed knowledge routes；
- allowed provider tools；
- allowed KG relations；
- allowed re-retrieval depth；
- mandatory must-not-miss coverage；
- prohibited domains。

### 8.2 Source Governance

Medical RAG 来源必须具有：

- source identity；
- source tier；
- version；
- published/update time；
- jurisdiction；
- license status；
- ingestion provenance。

### 8.3 External Retrieval

默认禁止 unrestricted medical web retrieval。

任何未来外部医学检索必须：

```text
Provider / Source Allowlist
+ Tool Governance
+ Citation Capture
+ Freshness Policy
+ License Policy
+ Audit
```

### 8.4 No Direct State Mutation

Retrieval result 永远只是 evidence candidate。

禁止：

```text
retrieval result
→ direct diagnosis
→ direct longitudinal record write
```

必须经过现有 Clinical Reasoning 与 State Committer。

### 8.5 Prompt Injection / Retrieved Content Attack

未来需将 retrieved content 视为不可信输入。

必须评估：

- prompt injection；
- poisoned documents；
- hidden instructions；
- malformed metadata；
- provider response spoofing；
- citation mismatch。

### 8.6 Safety Dominance

任何排序优化都不得降低：

- must-not-miss recall；
- emergency escalation recall；
- contraindication detection；
- high-risk population safeguards。

若 relevance 与 safety 冲突，以 safety 为优先。

## 11. 建议研究阶段

本方案不授权实施。未来若当前重构正式冻结后启动，可按以下阶段推进。

### E0 — Read-only Baseline Assessment

目标：

- inventory 当前所有 retrieval path；
- 定义 query taxonomy；
- 定义 evidence taxonomy；
- 建立离线 benchmark；
- 记录当前 Dense / RAG baseline。

退出条件：

```text
Baseline Frozen
+ Eval Set Defined
+ No Production Change
```

### E1 — Clinical Query Understanding

只实现：

- query normalization；
- retrieval intent classification；
- structured retrieval goals。

不改变线上 retrieval。

### E2 — Multi-route Retrieval

验证：

```text
Medical RAG
+ KG
+ Encounter Evidence
+ Structured Provider（如有授权测试源）
```

是否提高 Evidence Recall 和 must-not-miss coverage。

### E3 — Clinical Evidence Reranking

优先级最高。

验证：

> 临床价值排序是否优于原始 similarity ranking。

需要冻结：

- ranking rubric；
- source authority mapping；
- applicability labels；
- safety constraints。

### E4 — Evidence Sufficiency / Gap Detection

验证系统能否正确判断：

- sufficient；
- insufficient；
- conflict；
- missing discriminator；
- missing must-not-miss evidence。

### E5 — Targeted Re-retrieval

只允许有限轮次。

验证：

- gap resolution；
- cost；
- latency；
- loop safety；
- stop correctness。

### E6 — Retrieval Policy Learning / Feedback

属于后期研究候选。

可探索：

- learning-to-rank；
- route selection policy；
- retrieval budget allocation；
- clinician feedback learning。

禁止直接使用用户 engagement 作为临床排序奖励。

任何反馈学习必须区分：

```text
Clinician Relevance Feedback
Evidence Quality Feedback
Retrieval Failure Feedback
Safety Event Feedback
```

并经过独立 Governance。

## 12. 推荐的第一研究问题

未来若只选择一个问题启动，不建议直接做完整 Agentic RAG。

建议首先验证：

> **在受约束临床 Agent 中，基于临床决策价值的多路召回与证据重排，是否能够比单一语义相似度 RAG 提高 Evidence Recall、must-not-miss recall、Claim Support、Citation Precision 和 Diagnostic Discriminability，同时保持可接受的 latency 与 cost？**

原因：

1. 排序层不需要立即改变 Agent Runtime；
2. 可以离线评估；
3. 风险低于直接引入循环式自主检索；
4. 能直接判断“最相似 ≠ 最有用”是否是当前系统真实瓶颈；
5. 若 E3 无显著收益，则没有必要继续扩大 E4/E5。

## 15. 失败模式与风险

### 15.1 Semantic Over-expansion

症状语义扩展过宽导致疾病候选爆炸。

控制：

- Capability scope；
- KG relation allowlist；
- candidate budget；
- clinical reason required。

### 15.2 Authority Blindness

低质量高相似内容超过权威指南。

控制：

- source tier；
- authority feature；
- source policy gate。

### 15.3 Population Mismatch

儿童、孕妇、老年人或特殊人群证据错误迁移。

控制：

- applicability evaluator；
- population metadata；
- mismatch state。

### 15.4 Must-not-miss Suppression

排序器过度优化平均相关性，压低低概率高风险证据。

控制：

- mandatory safety slots；
- must-not-miss recall gate；
- safety dominance。

### 15.5 Retrieval Loop

Evidence Gap 导致无限再检索。

控制：

- round limit；
- budget；
- stop policy；
- explicit escalation。

### 15.6 False Sufficiency

模型错误认为证据已经足够。

控制：

- action-specific thresholds；
- mandatory gap checklist；
- clinician adjudication；
- conservative stop policy。

### 15.7 Feedback Bias

未来反馈优化把“医生常点的内容”误当成“医学上正确的内容”。

控制：

- feedback type separation；
- no engagement reward；
- safety metrics hard constraint。

### 15.8 Knowledge Drift

指南更新但向量库未更新。

控制：

- knowledge snapshot version；
- freshness policy；
- stale evidence state；
- citation validation。

## 19. 是否值得作为当前重构之后的高优先级扩展

当前判断：`YES_AS_FUTURE_CANDIDATE`。

理由：

1. 当前架构已经具备 Medical RAG、KG、Structured Provider、Evidence Ledger、Evidence Intelligence 等基础；
2. 本方案可以复用现有状态和治理，不要求推翻重构；

4. 可先离线研究，不必直接进入 Clinical Runtime；
5. 其收益可以通过独立检索指标和临床证据指标验证；
6. 若无收益，可以在 E3 前后停止，不形成长期架构负债。

## 22. 最终定位

Clinical Retrieval Intelligence 的长期目标不是让 AIdoctor“搜索更多内容”，而是让系统做到：

```text
知道当前真正需要回答什么
↓
知道应该从哪里找
↓
知道哪些证据对当前患者真正重要
↓
知道哪些关键信息仍然缺失
↓
知道下一步应该继续检索、提问、请求资料、升级还是停止
```

因此，它治理的核心不是：

> **“模型能搜到什么。”**

而是：

> **“模型为什么看这些证据、这些证据是否足够，以及缺失证据时系统如何安全地继续。”**

该能力如果未来通过验证，应作为 Evidence Intelligence 的高级检索策略层进入平台，而不是作为自由搜索 Agent 或新的临床真值源。
