## 1. 权威语义

按当前 Phase 7 / Phase 8：

```text
raw user input
→ C01 candidate extraction
→ typed Capability Result
→ U01 Business Owner / D10
→ formal Subject / Problem / Scope decision
```

必须保持：

```text
Capability Result != Clinical Truth
ScopeCandidate != ScopeDecision
EarlySafetySignalCandidate != Clinical Risk
Capability failure != negative clinical result
Candidate != Decision != Proposal != Commit
```

C01-U01 只产生 Subject / Problem / Scope / early-safety 候选及 source / provenance / uncertainty / binding metadata。

## 3. 已实现内容

### 3.1 Typed C01-U01 Contract

新增 typed request/result，显式区分：

- `SubjectCandidate`
- `ProblemCandidate`
- `ScopeCandidate`
- `EarlySafetySignalCandidate`
- `EvidenceSpan`
- `businessStatus / reasonCode / retryable`
- `sourceAttribution / provenance`
- `bindingId / capabilityVersion / capabilitySetVersion / scopeVersion / contractVersion`

不包含 `suggested_writes`、`StateChangeProposal` 或 CDP 写入字段。

### 3.2 C01-U01 最小能力

新增 C01-U01 service：

- SELF / OTHER / UNKNOWN Subject 候选；
- OTHER 关系词不伪造正式 `subjectReferenceId`；
- Problem 候选与 evidence span；
- `SYMPTOM / EXAMINATION / CLINICAL_CONSULTATION / OUTSIDE_V1_INTENT / MIXED / UNKNOWN` Scope 候选；
- MIXED 不掩盖临床不适；
- early safety clue 只做候选透传；
- 空输入、未知输入、binding mismatch 使用一等 failure / insufficiency 语义；
- C01 不直接产生业务真值。

### 3.3 Governed Route / Java Gateway

新增 typed route：

`POST /api/v1/capabilities/c01/u01/interpret`

Diagnosis 侧新增 typed client / DTO / gateway：

- 默认 `aidoctor.capability.c01-u01.enabled=false`；
- 未启用时禁止调用；
- 即使启用，也必须先通过 Foundation-1 `CapabilityInvocationGuard`；
- authoritative binding 缺失、禁用、过期或上下文不兼容时，在调用 C01 前 fail-closed；
- request 的 binding / capability-set / scope / contract 信息来自本次已授权 binding；
- capability 返回的 BindingRef 必须与已授权 binding 完全一致；
- dependency failure 显式映射为 `DEPENDENCY_FAILURE`，不得伪装为 UNKNOWN / negative clinical result；
- `INSUFFICIENT_INFORMATION` 是合法候选结果，不等于依赖失败。

这里已经复用 Foundation-1 最小 P06 binding governance，但并不意味着 C01-U01 已完成生产 binding 注册或激活。当前 composition 仍 default-off，且生产激活未授权。

### 3.4 C01 → U01 内部接入

新增 `U01NaturalLanguageStartService`：

```text
raw text
→ governed C01 invocation
→ C01 candidates
→ U01StartCommand
→ U01SemanticPolicy / D10
→ U01 Consultation state
```

保持：

- C01 inferred OTHER 不产生正式 Subject Reference；
- 已有正式 Subject Reference 只在 OTHER candidate 时透传；
- canonical replay 不重新执行 C01 candidate extraction；
- raw input 使用 source fingerprint 稳定 canonical event identity，避免未来 C01 算法变化改变同一原始输入的 replay identity。

该服务是内部业务适配，不是 Phase 10 外部 HTTP cutover。

### 3.5 PHI 日志边界

C01 不复用会记录原始临床文本的 legacy orchestration；底层 `ConceptRecognizer` 日志改为仅记录长度/计数，不写原始临床文本。

## 5. 独立实现审查与整改

### C01-R01 — 初始 service 文件截断

状态：CLOSED。

### C01-R02 — 新能力回流 legacy orchestration / PHI logging 风险

初版复用了旧 parsing orchestration，会继承 raw clinical text INFO logging。整改为只复用低层 `VocabularyLoader / ConceptRecognizer / AmbiguityDetector`，并移除底层 raw clinical text debug logging。

状态：CLOSED。

### C01-R03 — Canonical replay identity 依赖派生 candidate

若 event digest 基于 C01 派生结果，未来 capability implementation 改变可能导致同一 raw event replay 被误判 payload drift。整改为 raw path 使用原始输入 fingerprint；历史 committed Consultation replay 不再次调用 C01。

状态：CLOSED。

### C01-R04 — legacy async regression verification harness 不完整

旧 `test_service.py` 使用裸 async test；验证环境补充 `pytest-asyncio` 并显式使用 `--asyncio-mode=auto`。没有删除或弱化旧测试。

状态：CLOSED。

### C01-R05 — architecture guard 注释误报

初版 guard 通过源码 substring 检查 legacy 类名，注释文本触发 false positive。整改为检查 executable `co_names` + direct-write / legacy member references。

状态：CLOSED。

### C01-R06 — Capability activation / production authority

Foundation-1 现已提供最小 authoritative capability binding registry / resolver / invocation guard，C01-U01 gateway 也已接入该 guard。但当前没有因此自动创建或激活生产 C01 binding；composition 仍 default-off，生产 activation 未授权。

状态：`MINIMAL_P06_GOVERNANCE_AVAILABLE / C01_PRODUCTION_ACTIVATION_NOT_AUTHORIZED`。

### C01-R07 — Runtime ingress ordering / Trace

当前 C01→U01 是内部自然语言适配层，尚未替换外部 `/diagnosis/start`。Foundation-1 已提供 P05 capability-call/governance trace baseline，但 C01-U01 当前内部适配层尚无完整正式 Run/Thread/Event runtime context，因此未伪造 ID 强行 wiring `CapabilityTraceService`。

状态：`P05_BASELINE_AVAILABLE / C01_RUNTIME_TRACE_WIRING_DEFERRED_TO_FORMAL_RUNTIME_CONSUMER / NOT_A_COMPONENT_VERIFICATION_BLOCKER`。

### C01-R08 — Foundation-1 合入后仍存在第二套硬编码 binding 治理

Foundation-1 进入 `main` 后，旧 C01-U01 gateway 仍仅靠本地常量验证 `ACTIVE/version/scope/contract`，会形成与 P06 authoritative registry 并行的第二套治理路径。

整改：

```text
latest main
→ standard merge commit sync into feature branch
→ C01U01CapabilityGateway uses CapabilityInvocationGuard
→ authoritative binding first
→ only then invoke C01
→ returned BindingRef must match authorized binding
```

状态：CLOSED。
