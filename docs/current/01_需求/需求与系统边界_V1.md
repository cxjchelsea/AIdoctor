# AIdoctor V1 需求与系统边界

> 状态：FROZEN / V1
> 来源：`docs/current/00_现状与治理/Current_State_Baseline_V1.md` + 已确认产品边界 + `docs/AI医生/项目文档` 有效业务设计 + `docs/refactoring` 有效治理设计。
> 本文件是产品/业务边界当前权威；不绑定具体微服务、框架或旧 Agent 实现。

## 1. 产品定位

AIdoctor V1 是一个受正式医学知识、规则、安全约束和状态治理控制的多轮智能问诊系统。系统通过持续收集和判断临床信息，为用户提供可追溯的疾病鉴别方向、风险提示、必要的信息或检查补充建议及就医引导。

V1 不承担自动确诊、自动处方、自动治疗管理、完整健康管理、正式医生审核闭环或跨天检查结果自动恢复诊断。

## 2. V1 核心业务目标

- 自然语言开始问诊；
- 明确问诊对象与当前健康问题；
- 识别并结构化患者提供的临床事实；
- 主动发现信息缺口并进行最小必要追问；
- 持续进行红旗、急症和高危安全判断；
- 在证据允许时形成疾病方向与鉴别分析；
- 对必须排除的高风险方向维护明确排除状态；
- 在线证据不足时说明还缺什么，并给出有正式依据的进一步检查/信息建议；
- 输出可解释、可追溯且不越界的患者侧结果；
- 支持多轮等待、普通中断恢复、重复事件防护和用户更正。

## 3. 关键临床语义

### 3.1 未知不能投射为阴性

```text
UNKNOWN != NO
UNMEASURED != NORMAL
NOT_ASKED != NEGATIVE
SERVICE_FAILURE != NEGATIVE
NO_RESULT != LOW_RISK
```

### 3.2 信息缺口必须具有决策影响

系统不仅要记录“缺什么”，还必须能表达缺失信息对当前临床决策的影响，例如：

- 缺失则阻断进一步分析；
- 缺失会提高不确定性但可继续；
- 可以延后获取；
- 只能线下获得。

具体枚举在状态/契约阶段定义，不在需求层冻结旧“必填/重要/可选”字段名。

### 3.3 必须排除项

对于进入“必须排除”集合的高风险疾病方向，系统必须维护其排除状态，至少能表达：

- 已有充分依据排除；
- 尚未排除；
- 需要线下检查/专业评估才能排除。

证据不足不得等价于“已排除”。

### 3.4 证据关系

正式临床结论必须能够追溯到证据。证据至少需要保留：

- 来源；
- 支持 / 反对 / 未知关系；
- 作用对象；
- 重要性或强度；
- 当前有效性。

不采用“必须凑够固定条数”作为结论合法性的机械条件。

### 3.5 新证据允许回退

新的患者事实、检查信息或用户更正如果改变既有判断，系统必须允许撤销、降级、失效或重新计算已有风险、疾病方向、证据结论和进一步建议。系统不能只允许单向向前推进。

## 4. 入口与混合诉求

用户可以以自然语言表达模糊或混合诉求。系统应通过最小必要澄清确定当前主要健康问题。

若用户同时存在体检/健康管理诉求和临床不适，临床症状与安全风险不能被非临床意图掩盖。

完整 Wellness / 长期健康管理不属于 V1 核心范围。

## 5. 风险与安全边界

风险识别贯穿整个问诊过程，新事实到达后可以重新触发。

高风险或红旗命中时，普通问诊推进必须受到限制、暂停或结束，并给出适当的就医/急诊引导。

关键安全能力自身失败时：

```text
SAFETY_FAILURE != SAFE
```

不得静默进入普通临床结论路径。

## 6. 疾病方向分析边界

系统可以提供疾病方向、候选方向和需要进一步鉴别的方向，但不得将其表达为自动确诊。

正式方向分析必须基于：

```text
当前患者证据
+ 已批准医学知识
+ 已批准规则
+ 当前适用场景
```

模型的先验知识、Prompt 文本或未登记知识不能单独成为临床真值。

## 7. 临床支持范围

系统支持的临床范围必须是显式、版本化且可判断的。

“模型可能知道某疾病”不等价于“系统支持该疾病”。

超出当前正式支持范围时，应明确进入 Unsupported / Safe Exit，而不是自由扩展医学关系。

## 8. 临床事实来源

Clinical State 不能只保存值，还必须能够区分事实/推断来源。至少需要在后续契约中区分：

- 患者陈述；
- 外部测量/设备数据；
- OCR/自动提取；
- 模型推断；
- 规则推导；
- 医学知识证据；
- 医生确认（未来扩展）。

模型推断不能直接冒充患者事实或医生确认事实。

## 9. 最小授权上下文

任何 Capability、模型或工具都不得默认读取整个 CDP。它只能获得完成当前任务所需、且由系统授权的最小上下文。

## 10. 主动问诊

主动问诊目标是获取当前业务决策所必需的最少关键证据，不是最大化轮次或 completeness 分数。

问题必须具有明确目的，如安全、鉴别、条件判断、背景、数据质量或澄清；应避免重复询问、无价值追问和对不可获得信息的无限追问。

## 11. 检查建议边界

V1 允许给出有正式医学知识/规则支持的检查方向或具体检查项目建议，但其性质是“进一步完善信息/与医生沟通的建议”，不是自动医嘱或检查下单。

V1 不要求完成“数小时/数天后外部检查结果自动恢复原问诊并重新诊断”的闭环。

## 12. Treatment / Medication 边界

V1 不建设自动治疗方案、自动处方、具体药品+剂量决策或长期疾病管理。

患者侧可以提供安全相关行动建议、就医建议和必要的信息/检查补充建议。

## 13. 连续性、更正与恢复

V1 必须支持：

- 等待用户回答；
- 页面刷新/网络中断后的普通问诊恢复；
- 重复提交不产生重复临床效果；
- 过期回答不能污染新状态；
- 用户更正和补充；
- 上游事实变化后使依赖的下游结果失效。

具体状态名称、Checkpoint 和 Resume 协议由后续状态阶段定义。

## 14. 输出边界

患者侧正式结果可以包含：

- 系统对当前问题的理解；
- 已确认关键事实；
- 未知/缺失信息；
- 疾病鉴别方向；
- 必须排除项及其当前状态；
- 支持/反对证据；
- 风险提示；
- 进一步信息或检查建议；
- 就医建议；
- 当前能力范围和不确定性。

前端不得在后端缺失临床结果时自行创造疾病、风险、行动或随访结论。

## 15. 医学知识与证据边界

模型不是医学事实源。正式医学知识、规则、阈值和临床路径必须具有来源、版本、适用范围和发布状态。

患者证据、确定性安全规则依据与医学文献 Citation 必须在语义上区分。图谱路径本身不自动等价于医学 Citation。

## 16. AI 能力质量

概率性 AI Capability 进入正式业务链前必须逐步具备：

```text
Version
EvalSet
Baseline
Metrics
Threshold / PASS
Regression
```

并能绑定 Model、Prompt、Knowledge、Tool、Configuration 版本。

能力独立 Eval 通过不等于业务闭环正确，仍需验证接入真实状态转换后的结果。

## 17. V1 非目标

- 自动确诊；
- 自动治疗和处方；
- 完整医生 HITL 业务闭环；
- 完整 Wellness / 健康管理；
- 长期个人记忆；
- 自由自治多 Agent；
- 全疾病/全人群覆盖；
- 外部检查跨天自动恢复诊断；
- 自动修改生产 Prompt、Skill、规则或医学知识；
- 一次性重写整个系统。

## 18. 系统级不变量

```text
INV-01 UNKNOWN != NEGATIVE
INV-02 NO_DDX != LOW_RISK
INV-03 SAFETY_FAILURE != SAFE
INV-04 MODEL_OUTPUT != CLINICAL_TRUTH
INV-05 NO_EVIDENCE -> NO_ASSERTION
INV-06 Capability cannot bypass State Governance
INV-07 Agent cannot bypass Safety Governance
INV-08 Frontend cannot create Clinical Truth
INV-09 Same event cannot produce duplicate clinical effects
INV-10 Changed upstream facts invalidate dependent downstream results
INV-11 Critical safety capability unavailable -> ordinary clinical continuation prohibited
INV-12 Formal clinical direction -> traceable basis required
```

## 19. 已关闭产品决策

| 决策 | V1 结论 |
|---|---|
| DEC-01 医生 HITL | 不建设完整闭环，仅预留架构扩展点 |
| DEC-02 检查建议粒度 | 允许正式规则/知识支持的具体检查建议，但不是医嘱 |
| DEC-03 管理建议 | 独立治疗/健康管理后置；V1 仅安全、信息补充与就医引导 |
| DEC-04A 普通问诊 Resume | V1 必须 |
| DEC-04B 外部检查跨时段恢复 | 后置 |
