## 一、真实用户主链现在可以进一步还原

上一轮我们只确认到：

```text
Frontend
→ DiagnosisController
→ DiagnosisOrchestrationService
→ DiagnosisWorkflowOrchestrator
→ Python Services
```

现在前端也追进去了。

当前 `DiagnosisPage` 使用 `DiagnosisChatPanel + diagnosisStore` 驱动会话。

`diagnosisStore.sendMessage()` 的真实逻辑是：

```text
用户第一次发送文本
        ↓
healthAssessmentDone == false
        ↓
performHealthAssessment(content)
        ↓
实际上调用 diagnosisApi.start()
        ↓
POST /diagnosis/start
        ↓
Java DiagnosisOrchestrationService
        ↓
HealthStateAssessmentClient
        ↓
创建 CDP + 完成入口判定
        ↓
前端获得 diagnosisId / cdpId
        ↓
回到 sendMessage()
        ↓
发现 diagnosisId 已存在
        ↓
answerQuestion(content)
        ↓
POST /diagnosis/{id}/answer
        ↓
再次把同一条 content 作为用户回答提交
```

这不是推测，是由当前 store 控制流直接推导出来的。`performHealthAssessment()` 自己调用 `/diagnosis/start`，而返回以后 `sendMessage()` 又会根据刚获得的 diagnosisId 调用 `answerQuestion(content)`。

因此现在有一个新的高可信缺陷：

```text
CSA-FLOW-001
首轮用户输入可能被消费两次
CONFIRMED BY CODE FLOW
```

也就是说：

```text
“我最近胸痛三天”
```

可能先作为 `/start` 输入一次，再立刻作为 `/answer` 输入一次。

这会污染：

- userAnswers；
- conversation history；
- completeness；
- 症状抽取；
- 后续追问判断。

这比“架构不好看”重要得多。

# 三、Health State Assessment 服务：确实是真实现，但质量声明不可信

服务入口是标准 FastAPI：

```text
health-state-assessment-service/app/main.py
```

并挂载：

```text
/api/v1/health-state-assessment/assess
```

以及统一 Tool 接口：

```text
/api/v1/tools/tool_0/invoke
```

所以这个服务不是 Stub。

但这里出现了非常典型的“代码看起来有质量指标，实际上没有 Eval”的问题。

它构造 `ToolResult` 时直接写：

```text
confidence   = 0.9
completeness = 0.85
accuracy     = 0.88
```

这三个数字是固定常量，不是从本次结果计算，也不是来自 Eval。

因此当前状态必须拆开写：

| 维度                           | 判断       |
| ------------------------------ | ---------- |
| 服务存在                       | YES        |
| API 存在                       | YES        |
| Java 主链调用                  | YES        |
| 业务逻辑存在                   | YES        |
| ToolContext/ToolResult 适配    | YES        |
| 能力质量有真实量化             | **NO**     |
| 有版本化临床 Eval 证明         | **未发现** |
| `0.9/0.85/0.88` 可作为能力指标 | **NO**     |

所以它是：

```text
IMPLEMENTED
+ WIRED
+ QUALITY_UNVERIFIED
```

而不是“已验证健康状态判定能力”。

# 二十四、对这个项目当前真实成熟度，我现在会比上一轮更保守

```text
工程基础明显更成熟
```

换句话说，现在不是单纯：


```text

+
修复危险业务语义
+
逐个接入新的状态/Runtime/Contract治理
```

这与“全部重写”是完全不同的路线。
