### 1. 当前 `main` 上 Diagnosis Engine 的五引擎入口实际上存在确定性的断路

链路已经可以完整串起来：

```text
DiagnosisWorkflowOrchestrator Step 2
→ DiagnosisEngineClient.generateDDxCandidates()
→ /engine/generate-ddx-candidates
→ get_fusion_engine()
→ get_llm_client()
→ LangChainLLMClient(config)
```

而当前 `common/aidoctor_llm/llm_client.py` 对 `LangChainLLMClient` 的定义不是“旧实现”，而是 Enterprise 冻结后的兼容壳：

```text
执行语义：FAIL_CLOSED_NO_ENABLE_PATH
```

其构造函数本身就直接：

```python
_raise_disabled()
```

也就是说，甚至还没到真正调用模型，就已经禁止实例化。

Diagnosis Engine 的代理 `app/utils/llm_client.py` 又明确只是把这个公共类重新导出，并不存在另外一套可用实现。

而 `get_llm_client()` 确实直接实例化它：

```python
_llm_client_singleton = LangChainLLMClient(config=llm_config)
```

`get_fusion_engine()` 又首先调用这个函数，之后才建立 FusionEngine。

因此这是一个可以从代码路径确定的结果：

```text
当前 main
↓
第一次调用需要 FusionEngine 的诊断接口
↓
构造 Legacy LangChainLLMClient
↓
LegacyLLMDisabledError
↓
Diagnosis Engine HTTP 请求失败
```

这已经不仅是此前的：

```text
CSA-MODEL-001
临床 LLM 绕过 Model Runtime
```

而应该新增：

```text
CSA-INTEGRATION-001
Enterprise Legacy-LLM freeze breaks the surviving clinical Diagnosis Engine path

Severity: CRITICAL
Evidence: CONFIRMED BY CODE PATH
```

# 7. Trace 的 PHI 策略目前反而有一个值得保留的设计


> Trace 默认最小化数据，而不是为了 Debug 把完整临床内容全塞进日志。
