## 1. 冻结目标

U03 的正式语义保持：

```text
Current Clinical State Version
+
Risk Assessment = NOT_ASSESSED / STALE
↓
C02 candidate/evidence
↓
Evidence Acceptance
↓
D09 deterministic Clinical Risk Disposition
↓
VALID + exactly one of:
  NO_HIGH_RISK_SIGNAL
  CAUTION
  HIGH_RISK
or
FAILED
↓
K09 typed proposal
↓
P01 / StateCommitter
↓
version-bound Risk Assessment state
↓
后续仅作为 U04 Safety Gate 输入
```

必须保持：

```text
Risk FAILED != NO_HIGH_RISK_SIGNAL
NO_HIGH_RISK_SIGNAL != SAFE
Capability Result != Clinical Truth
Candidate != Decision != Proposal != Commit
Risk Capability != Clinical Risk Disposition Owner
Risk Capability != Safety Gate Owner
```

U03 不实现 U04 Safety Gate，也不并发分叉 U14。

## 3. 关键实现边界

### 3.1 C02 只产生 Candidate

```text
U03CandidateProvider
→ U03RiskAssessmentCandidate
```

Candidate 不拥有正式 Risk Disposition，不直接生成 K09，不写 Clinical State。

### 3.2 VALID 与 FAILED 不共用“假完整”版本证据

VALID：

```text
exact Clinical State Version
+
authorized Capability Binding
+
active/effective Rule Release
+
active/effective Knowledge Release
↓
Evidence Acceptance PASS
```

FAILED：

```text
Capability / Release / Provider failure
↓
Risk Assessment FAILED
↓
formal failure Decision
↓
formal failure Proposal / Commit
```

如果 failure 发生在 release 被解析前，只保留真实存在的 attempted Capability Binding ref；不得填充虚假的 Rule/Knowledge Release。

### 3.3 D09 Owner 边界

```text
C02 candidate
!=
Clinical Risk Disposition
```

VALID outcome vocabulary 被限制为：

```text
NO_HIGH_RISK_SIGNAL
CAUTION
HIGH_RISK
```

但这些结果如何由医学证据/规则得出，不由本次工程实现自行发明；必须由后续受治理、可审查、版本化的 D09 / Safety-critical Rule Pack 提供。

### 3.4 U04 未实现

U03 只形成并提交正式 Risk Assessment。尤其：

```text
Risk Assessment FAILED
→ future U04 Safety Gate input
```

当前 slice 没有实现 Safety Gate、恢复/降级或 U14 路由，因此不能声称业务闭环已闭合。

## 4. P04 / P06 最小增量

本轮没有新建 Foundation-2，也没有重构完整平台。

实现的是 U03 首个消费者需要的最小增量：

```text
U03ReleaseBinding
- capability binding ref
- rule release id/version
- knowledge release id/version
- population/region/language/channel scope
- effective_from/effective_until
- provenance refs
- active

U03ReleaseRegistry
- immutable registration per binding id
- active/effective checks
- no silent overwrite

U03GovernedCandidateGateway
- Foundation-1 capability authorization
- release lookup
- release/capability scope compatibility
- provider invocation
```

生产 release 注册、完整审批流、完整 P04 durable registry、发布/回滚工具链均不在本 slice 内。

## 5. P05 Trace 增量

`CapabilityCallTraceRecord` / `CapabilityTraceService` 增加：

```text
rule_release_ref
knowledge_release_ref
bindReleases(...)
failWithOutcome(...)
```

`failWithOutcome` 的语义是：

```text
Capability call = FAILED
但该 failure 已被正式转换为
Risk Assessment FAILED Decision/Proposal/Commit
```

因此 call status 仍为 FAILED，不得因为 failure 被安全处理而改成 SUCCEEDED。

DB migration：

```text
V5__extend_capability_trace.sql
```
