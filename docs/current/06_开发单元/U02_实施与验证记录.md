## 1. 权威业务链与边界

本轮实现遵循：

```text
accepted NEW_CLINICAL_INPUT
↓
C01-U02 candidate-only Clinical Understanding
↓
U02 Business Owner / deterministic interpretation
↓
K09 typed Clinical Fact StateChangeProposal
↓
P01 / StateCommitter governed commit
↓
Clinical State Version n+1
↓
minimum D05 invalidation hook
```

强制保持：

```text
UNKNOWN != NO
UNMEASURED != NORMAL
MODEL_INFERRED != PATIENT_REPORTED
Capability Result != Clinical Truth
Candidate != Decision != Proposal != Commit
Trace != Clinical State
```

Patient Fact 与 Derived Clinical Assertion 保持分离：

- `PATIENT_REPORTED / EXTERNAL_MEASUREMENT / OCR_EXTRACTED / CLINICIAN_CONFIRMED` 可形成 patient-fact 类 typed operation；
- `MODEL_INFERRED / RULE_DERIVED` 进入 `derived_clinical_assertion_*` 路径，不伪装成患者报告事实；
- P01 operation.source 保留冻结 K03 `source_type`，不统一改写为 `PATIENT_FACT`。

## 3. C01-U02 实现

### 3.1 Observation Candidate

候选结构覆盖：

```text
observation_id
concept_id
concept_display
raw_text_ref
normalized_value
value_semantics
unit
negation
temporality
severity_or_degree
source_type
lifecycle
confidence_or_uncertainty
provenance
ambiguity_flags[]
contradiction_refs[]
```

值语义：

```text
YES / NO / UNKNOWN / UNMEASURED / NOT_ASKED / NOT_APPLICABLE
```

生命周期：

```text
EXTRACTED / NORMALIZED / CONFIRMED / UNCERTAIN / CONTRADICTED / INVALIDATED
```

C01-U02 只产生候选，不直接产生 Clinical Truth、K09 Proposal 或 State write。

### 3.2 Local-clause metadata binding

否定、数值/单位、时间、程度等 metadata 按 concept 所在局部 clinical clause 绑定，不再把整句中另一个 concept 的属性复制给所有候选。

示例回归：

```text
没有头晕，今天体温38.5℃
```

期望：

```text
头晕 → NO；无 38.5℃；无 CURRENT
体温 → YES；38.5℃；CURRENT
```

### 3.3 Frozen source semantics

两侧边界均显式支持且只支持：

```text
PATIENT_REPORTED
EXTERNAL_MEASUREMENT
OCR_EXTRACTED
MODEL_INFERRED
RULE_DERIVED
CLINICIAN_CONFIRMED
```

Java Gateway 要求 Capability 返回候选的 `source_type` 必须与本次请求来源一致，禁止 silent provenance relabel。

## 4. Governance / P01 / D05 / Trace

### 4.1 Foundation-1 binding governance

C01-U02 invocation 必经 `CapabilityInvocationGuard`；binding 缺失、禁用、过期或上下文不兼容时 fail closed。返回 BindingRef 必须与 authoritative binding 一致。

### 4.2 U02 Business Owner

Capability Result 先进入 U02 Business Owner；未解析 concept 进入 clarification 语义，不创建正式 proposal/commit。已接受 observation 才能进入 K09 proposal。

### 4.3 P01 typed commit

U02 proposal 保留：

```text
proposal / consultation / decision refs
base clinical state version
idempotency key
capability binding refs
typed structured operations
source / provenance
```

仍通过既有 `StateCommitter`、field permission、source validation、base-version、idempotency、atomic commit 边界；没有恢复 `CDPManager.updateCDP` 或 direct Map write。

`StatePatchBoundaryValidator` 只在现有 v1 root 不变的前提下增加冻结 K03 source class；没有开放任意 state root。

### 4.4 Minimum D05

当前只形成最小 invalidation hook：

```text
RISK     → STALE
DDX      → INVALIDATED
WORKUP   → SUPERSEDED
DELIVERY → SUPERSEDED
```

没有下游 artifact 时安全 no-op；未知 artifact type fail closed，禁止自行发明状态效果。完整 dependency engine 仍 deferred。

### 4.5 P05 Trace

当前 trace 记录 capability call 与 downstream result/decision/proposal/commit-result/version 的关联。

必须注意：

```text
Trace SUCCEEDED != Clinical State committed
Trace != Clinical State
```

Capability 正常返回后，即使后续 P01 commit 未应用，也不能把它伪装成 capability invocation failure；实际 commit outcome 仍由 CommitResult / U02 result 表达。

## 5. 独立实现审查与整改

### U02-R01 — P01 测试夹具来源权限不匹配

首次 U02 Java verification 中 typed fact commit test 预期 `COMMITTED`，实际 `REJECTED`。定位为共享 `StateCommitterTestHarness` 默认只授权 synthetic source，U02 测试没有授权本场景来源。

整改：只修测试 fixture，显式授权 U02 测试所需 frozen source；没有放宽 production policy。

状态：CLOSED。

### U02-R02 — mixed input metadata 跨 concept 泄漏

初版 C01-U02 以整句计算 negation/value/unit/temporality/severity，可能把其他 clinical clause 的属性复制到无关 concept。

整改：按 concept-local clause 提取 metadata，并增加 mixed-input 回归。

状态：CLOSED。

### U02-R03 — source_type 仅做非空校验

初版 source semantics 过松，不能保证 `MODEL_INFERRED != PATIENT_REPORTED`。

整改：Python 与 Java Gateway 均冻结为 Phase 8 六类来源；unsupported source fail closed；Gateway 强制返回 source 与请求 source 一致。

状态：CLOSED。

### U02-R04 — Proposal 层把所有来源折叠成 PATIENT_FACT

初版 ProposalFactory 无论来源均写 `operation.source=PATIENT_FACT` 且统一落 `clinical_fact_*`，会让 model/rule derived assertion 冒充 patient fact。

整改：保留 K03 source type；`MODEL_INFERRED / RULE_DERIVED` 使用 `derived_clinical_assertion_*`，patient/external/OCR/clinician-confirmed 使用 `clinical_fact_*`；P01 boundary 增加 exact K03 source 支持。

状态：CLOSED。

### U02-R05 — D05 未知 artifact type 默认 INVALIDATED

初版 minimum D05 对未知类型默认返回 `INVALIDATED`，超出冻结范围。

整改：只允许 Risk/DDx/Workup/Delivery 四类映射；未知类型抛出异常 fail closed，并增加回归测试。

状态：CLOSED。

### U02-R06 — Implementation branch 缺少 Pre-Implementation 审计证据

PR #82 的 Readiness/LIA 已完成，但实现分支并非从 prep branch 派生，导致 PR #85 最初缺少这两份证据。

整改：将最终 Readiness 与 Legacy Impact Assessment 按已审定状态带入 implementation branch；未合并 PR #82，也未把其视为 Implementation Authorization。

状态：CLOSED。
