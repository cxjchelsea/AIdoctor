## 1. 权威语义来源

U01 按冻结 Phase 6/7 语义实现：

```text
START_CONSULTATION
→ Consultation 建立
→ Subject Resolution
→ Problem Framing
→ D10 Scope Adjudication
→ ACTIVE
→ 路由 U02 / U06 / U11
```

保持：

- `CLARIFICATION_REQUIRED != WAITING_USER`
- 对象未确认不得猜测为本人
- `OUTSIDE_V1_INTENT != 系统故障`
- 早期风险线索不得因 framing 未完成而丢失
- Scope 最终裁决由 deterministic policy 完成，不由模型直接拥有
- Runtime routing 不是 Consultation Business Truth

## 2. 已实现内容

### 2.1 U01 Internal Contract

新增 `U01StartCommand`，明确要求：

- `eventId`
- `idempotencyKey`
- `userId`
- `subjectType`
- `subjectReferenceId`（OTHER 时需要）
- `problemText`
- `scopeIntentCandidate`
- `earlySafetySignalPresent`

该 Command 是 U01 内部 Contract，不复用 legacy `DiagnosisRequest` 作为新业务 Contract。

### 2.2 Deterministic U01 Policy

新增 `U01SemanticPolicy`：

- `SELF` → Subject 可解析；
- `OTHER + subjectReferenceId` → Subject 可解析；
- 主体不足 → clarification；
- Problem 为空 → clarification；
- Scope ambiguity / mixed / unknown → clarification；
- V1 in-scope → route `U02`；
- `OUTSIDE_V1_INTENT` → route `U11`；
- clarification → route `U06`；
- U01 从不创建 `WAITING_USER`。

### 2.3 Consultation Business State

新增 `clinical_consultation`：

- Consultation ID
- optimistic `row_version`
- CDP reference
- user reference
- lifecycle status
- subject status/type/reference
- problem status/text
- scope decision
- clarification reason
- early safety signal passthrough
- canonical START event reference
- created timestamp

`nextUnit` 没有持久化。路由从已提交的 Subject / Problem / Scope 状态确定性推导，避免把 Runtime routing cursor 变成业务真值。

### 2.4 Foundation-0 integration

U01 使用：

- Canonical Business Event Ledger
- Runtime Binding / P06 version binding skeleton
- `CLINICAL_RUNTIME_V1`
- minimal Clinical Run
- legacy `CDPManager.createCDP()` 仅作为 CDP 初始化持久化资产

U01 不调用：

- `DiagnosisOrchestrationService`
- `DiagnosisWorkflowOrchestrator`
- `HealthStateAssessmentClient`
- `CDPManager.updateCDP()`
- fixed five-step workflow
- legacy completeness threshold

### 2.5 Canonical replay

同一 canonical `START_CONSULTATION` replay：

- 解析到同一 Consultation ID；
- 不创建第二个 CDP；
- 不创建第二个 Runtime Binding；
- 不创建第二个 Run；
- 返回原始 Run correlation；
- 路由重新从已提交 Business State 推导。

## 4. 实施/独立审查发现

### U01-R01 — OTHER 主体误标 RESOLVED

初版 shared clarification helper 仅按 `subjectType=OTHER` 判断 resolved，未要求 `subjectReferenceId`。

处理：clarification helper 显式接收 `subjectResolved`，OTHER 无 reference 时保持 `SUBJECT_CLARIFICATION_REQUIRED`。

状态：CLOSED。

### U01-R02 — nextUnit 被错误持久化

初版把 `next_unit` 存在 `clinical_consultation` 中，会把执行路由 cursor 混入 Business Truth。

处理：删除持久化 `next_unit`；路由只从 committed Subject / Problem / Scope state 确定性推导。

状态：CLOSED。

### U01-R03 — canonical replay 未返回原 Run

初版 replay 虽然不重复副作用，但 `runId=null`，不符合 replay 返回原 outcome/correlation 的语义。

处理：ClinicalRunRepository 增加 consultation+event 原始 Run 查询；replay 返回 original run，不新建 run。

状态：CLOSED。

### U01-R04 — Consultation 缺少并发版本保护

初版 Consultation 只有主键，没有 lifecycle 更新所需的行版本控制。

处理：新增 JPA `@Version row_version`，MySQL / Oracle migration 同步。

状态：CLOSED。
