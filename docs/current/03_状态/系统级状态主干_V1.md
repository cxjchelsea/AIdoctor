# AIdoctor V1 系统级状态主干

> 文档状态：FROZEN / V1  
> 所属阶段：复杂业务软件开发 SOP — Phase 3 系统级状态主干  
> 上游权威：`01_需求/需求与系统边界_V1.md`、`02_功能/功能模块划分_V1.md`  
> 本文只定义系统级状态对象、一级状态语义、状态关系和全局约束；不定义模块内部细状态、API、数据库表、开发单元或具体框架实现。

---

## 1. Phase 3 要解决的问题

AIdoctor 不能继续用一个模糊的 `completed / not completed` 或一个大 JSON 中的若干字段，同时表达：

- 一次问诊是否仍有效；
- Runtime 当前是否正在执行；
- 是否正在等待用户；
- 患者当前临床风险是什么；
- 系统当前是否允许继续普通临床路径；
- 信息是否足够；
- 是否已经形成可正式交付结果；
- 是否因失败而停止。

因此 V1 的系统级状态采用：

```text
一个业务主生命周期
+
四个正交系统状态维度
+
一个版本化临床事实聚合
+
一个独立执行恢复对象
```

具体为：

```text
Consultation Lifecycle       一次问诊在业务上处于什么生命周期
Clinical Risk Disposition    患者当前临床风险语义
Safety Gate                  系统当前是否允许继续普通临床流程
Clinical Readiness           当前信息是否允许继续问、分析或结束
Delivery Readiness           当前结果是否允许正式交付
Clinical State / CDP         当前版本化临床事实与临床推理产物
Execution Thread             Runtime 执行、暂停、恢复、重试
```

核心原则：这些状态互相关联，但不能互相替代，也不能由多个对象竞争同一事实的最终解释权。

## 2. 系统级核心对象

### 2.1 Consultation：业务生命周期主对象

`Consultation` 表示一次完整的智能问诊业务事件。

它回答：

> 这次问诊在业务上处于什么生命周期阶段？

它不是聊天窗口，不等于 HTTP Session，也不等于一次 Runtime Run。

V1 原则：

```text
一个独立健康问题
→ 一个 Consultation
→ 一个当前 Clinical State / CDP
→ 一个主要 Execution Thread
→ 多个 Turn
→ 多个 Run
→ 多个 Clinical State Version
```

如果用户提出明显独立的新主诉，原则上创建新的 Consultation，而不是无限累积进旧 Consultation。

### 2.2 Clinical State / CDP：临床事实聚合

CDP 延续旧设计中最有价值的定位：

> 本次 Consultation 的版本化临床事实与临床推理聚合视图。

CDP 负责承载或引用：

- 当前患者事实；
- 事实来源与确定性；
- 当前信息缺口；
- 当前风险判断；
- 当前疾病方向与 Must-Exclude 状态；
- 当前支持/反对/未知证据；
- 检查或进一步信息建议；
- 当前不确定性；
- 当前可交付结果引用；
- 使用的知识、规则、模型和能力版本引用。

CDP 必须版本化。上游事实变化时，不允许静默覆盖旧结果，而应产生新版本，并使依赖结果失效、重新计算或重新审核。

V1 不允许所有 Capability、Tool、Agent 或前端自由读写整个 CDP。

### 2.3 Execution Thread：执行恢复对象

Execution Thread 负责回答：

> Runtime 执行到哪里？为什么暂停？如何安全恢复？

它不保存临床真值。

必须明确：

```text
Clinical State / CDP
!=
Execution Checkpoint
```

Checkpoint 可以引用或缓存执行上下文，但 Resume 时必须重新验证当前 Clinical State Version，不能假设旧 checkpoint 中的临床快照仍然有效。

## 3. Consultation Lifecycle — 业务主状态

V1 一级生命周期：

```text
CREATED
ACTIVE
WAITING_USER
SAFETY_ESCALATED
COMPLETED
SAFE_EXIT
CANCELLED
EXPIRED
FAILED_TERMINAL
```

### 3.1 CREATED

含义：Consultation 已建立，但尚未进入稳定的多轮临床推进。

允许：接收首条输入、确认患者主体、做入口澄清、建立初始 Clinical State。

禁止：在临床事实尚未建立前直接形成正式疾病方向。

### 3.2 ACTIVE

含义：当前问诊仍可继续推进，可以进行信息理解、风险评估、主动问诊、鉴别分析、证据评估或结果准备。

```text
Consultation ACTIVE
!=
Thread RUNNING
```

业务可处于 ACTIVE，而 Runtime 此刻未必正在执行。

### 3.3 WAITING_USER

含义：当前继续问诊所需的下一关键事件是用户回答；系统已经产生合法问题或澄清请求，执行应暂停等待。

必须关联：

- 当前等待的问题/请求；
- 关联 Clinical State Version；
- 可接受事件类型；
- 过期策略；
- 幂等 / Resume 语义。

用户关闭页面不改变这一业务状态。

### 3.4 SAFETY_ESCALATED

含义：已经识别高风险或红旗情况，普通问诊推进受到 Safety Policy 限制。

进入后必须：

- 保留风险依据；
- 给出相应安全/就医引导；
- 阻止普通 Planner 静默降低风险；
- 只允许不会延误安全处置的必要动作。

V1 不要求完整医生 HITL，因此该状态的正常后继为：

```text
SAFETY_ESCALATED
→ SAFE_EXIT
```

未来可扩展 `WAITING_CLINICIAN / UNDER_REVIEW`，但不属于 V1 正式状态。

### 3.5 COMPLETED

含义：

> 本次 Consultation 已完成 V1 的正常智能问诊目标，并成功形成符合产品边界、证据要求和安全要求的正式临床交付结果。

至少要求：

- Safety Gate 不阻断正常交付；
- 输出未越过确诊、处方、治疗边界；
- 正式疾病方向具有可追溯依据；
- 关键不确定性没有被伪装成阴性或正常；
- Delivery 已正式完成。

```text
workflow reached end
!=
COMPLETED
```

以下场景不进入 `COMPLETED`：

- `OUT_OF_SCOPE`；
- 无法继续线上获得关键证据；
- `NO_RELIABLE_DIRECTION` 且无法进一步在线推进；
- 高风险导致普通问诊停止；
- 必要安全能力不可用。

这些场景应进入 `SAFE_EXIT` 或在真正不可恢复的系统故障下进入 `FAILED_TERMINAL`。

### 3.6 SAFE_EXIT

含义：

> 系统没有完成正常临床分析目标，但正确识别了范围、安全、证据或能力边界，并向用户完成了符合边界的安全退出交付。

典型原因：

- 超出 Clinical Capability Scope；
- 必要安全能力不可用；
- 关键输入无法可靠确认；
- 证据不足且无法继续线上获得；
- 当前场景需要线下进一步评估；
- 高风险状态要求停止普通在线问诊。

`SAFE_EXIT` 不是系统故障，也不等同 `FAILED_TERMINAL`。

### 3.7 CANCELLED

用户或授权业务方明确取消本次问诊；不再接受普通 Resume，也不允许继续产生新的临床副作用。

### 3.8 EXPIRED

Consultation 因超过生命周期或等待有效期而关闭。旧回答不能再直接写入当前 Clinical State；继续咨询应创建新 Consultation 或经过未来明确的恢复策略。

### 3.9 FAILED_TERMINAL

含义：

> 因系统级不可恢复故障，本次 Consultation 无法继续，也无法形成符合要求的正常或安全交付。

必须记录失败原因、最后有效 Clinical State Version、是否已提供最低限度安全提示以及是否允许重新发起新 Consultation。

`FAILED_TERMINAL` 不允许伪装成 `COMPLETED` 或 `SAFE_EXIT`。

## 4. Consultation 主状态转换

```text
CREATED
  ↓
ACTIVE
  ├─→ WAITING_USER ──有效回答/Resume──→ ACTIVE
  ├─→ SAFETY_ESCALATED ───────────────→ SAFE_EXIT
  ├─→ COMPLETED
  ├─→ SAFE_EXIT
  ├─→ CANCELLED
  ├─→ EXPIRED
  └─→ FAILED_TERMINAL
```

V1 终止态：

```text
COMPLETED
SAFE_EXIT
CANCELLED
EXPIRED
FAILED_TERMINAL
```

终止态默认禁止普通 Resume。

## 5. Clinical Risk Disposition — 患者临床风险维度

该维度回答：

> 基于当前已知临床事实，患者当前风险语义是什么？

V1 一级语义：

```text
NOT_EVALUATED
NO_HIGH_RISK_SIGNAL
CAUTION
HIGH_RISK
```

说明：

- `NOT_EVALUATED`：当前版本尚未形成所需临床风险判断；
- `NO_HIGH_RISK_SIGNAL`：当前已知信息未命中需要升级处置的高风险信号，不表示“患者安全/无病”；
- `CAUTION`：存在需要持续关注但尚未达到强制中止普通路径的风险；
- `HIGH_RISK`：命中需要优先安全处置的红旗或高风险条件。

风险状态描述患者，不描述系统是否允许继续。

---

## 6. Safety Gate — 系统继续权限维度

该维度回答：

> 在当前风险、能力可用性和安全策略下，系统是否允许继续普通临床流程？

V1 一级语义：

```text
NOT_EVALUATED
ALLOW
RESTRICTED
BLOCKED
UNAVAILABLE
```

说明：

- `NOT_EVALUATED`：当前版本尚未完成必要 Safety Gate；
- `ALLOW`：允许继续普通临床路径；
- `RESTRICTED`：只允许受限动作，例如补充不会延误处置的必要信息；
- `BLOCKED`：明确禁止继续普通临床路径；
- `UNAVAILABLE`：必要安全能力无法可靠执行，因此普通临床路径不得继续。

典型组合：

```text
Risk = HIGH_RISK
SafetyGate = BLOCKED
```

以及：

```text
Risk = NOT_EVALUATED
SafetyGate = UNAVAILABLE
```

后者表示“无法形成可靠安全判断”，不能被错误解释成患者低风险。

全局约束：

```text
SafetyGate UNAVAILABLE
!= ALLOW

Risk HIGH_RISK
→ SafetyGate 不得保持普通 ALLOW
```

## 7. Clinical Readiness — 临床推进状态维度

该维度回答：

> 根据当前临床事实，下一步在业务上允许做什么？

V1 一级语义：

```text
NEEDS_CLARIFICATION
CAN_ASK_MORE
READY_FOR_CLINICAL_ANALYSIS
NEEDS_OFFLINE_EVIDENCE
OUT_OF_SCOPE
NO_RELIABLE_DIRECTION
```

说明：

- `NEEDS_CLARIFICATION`：问题主体、主诉或关键表达尚不明确，必须先澄清；
- `CAN_ASK_MORE`：存在可在线获得且具有临床价值的关键缺口；
- `READY_FOR_CLINICAL_ANALYSIS`：当前证据达到进入疾病方向/鉴别分析的最低条件；
- `NEEDS_OFFLINE_EVIDENCE`：关键缺口无法通过当前在线问诊获取，需要线下检查、测量或专业评估；
- `OUT_OF_SCOPE`：当前问题不属于已版本化 Clinical Capability Scope；
- `NO_RELIABLE_DIRECTION`：现有证据不足以形成可靠疾病方向，且当前没有足够的进一步线上获取路径。

```text
READY_FOR_CLINICAL_ANALYSIS
!= READY_TO_COMPLETE
```

分析后仍可能重新产生信息缺口并回到 `CAN_ASK_MORE`。

## 8. Delivery Readiness — 正式交付状态维度

Phase 3 只保留系统级交付语义，不提前规定 F7 内部的 drafting / validation 工作流。

V1 一级语义：

```text
NOT_READY
READY
BLOCKED
DELIVERED
```

说明：

- `NOT_READY`：当前尚不允许形成正式患者侧交付；
- `READY`：已经满足正式交付前提；
- `BLOCKED`：当前存在安全、证据、范围或失败原因，禁止正常临床交付；
- `DELIVERED`：已经形成并交付正式结果包，包括正常完成结果或安全退出结果。

关键约束：

```text
Consultation COMPLETED
→ Delivery = DELIVERED
```

```text
Consultation SAFE_EXIT
→ 必须存在合法的安全退出交付
→ Delivery = DELIVERED
```

```text
Delivery BLOCKED
→ Consultation 不得进入 COMPLETED
```

F7 内部的 `DRAFTING / VALIDATING / VALIDATION_FAILED` 等细状态留到 Phase 4。

---

## 9. Execution Thread — Runtime 执行状态

V1 只冻结执行状态的一级语义，不绑定具体 Runtime 框架。

建议：

```text
CREATED
RUNNING
AWAITING_USER
RETRY_SCHEDULED
SUSPENDED
DEGRADED
COMPLETED
CANCELLED
EXPIRED
FAILED_TERMINAL
```

约束：

- Thread `AWAITING_USER` 必须与 Consultation `WAITING_USER` 的业务语义一致；
- Thread `RUNNING` 不决定 Consultation 是否 ACTIVE；
- Thread `FAILED_TERMINAL` 不必然等于 Consultation `FAILED_TERMINAL`，若仍可重建执行上下文或安全退出，业务层可继续处理；
- Thread `COMPLETED` 只表示当前执行线程结束，不证明 Consultation 业务完成；
- V1 不包含正式 `AWAITING_CLINICIAN`，但未来允许扩展。

## 10. Run 与 Checkpoint

一个 Thread 可以有多个 Run。

Run 表示：

> 从一次开始/恢复，到下一次暂停、等待或结束的一段实际执行。

Checkpoint 表示：

> 某个可验证的执行恢复点。

关系：

```text
Consultation
  └─ Thread
      ├─ Run 1
      │   ├─ Checkpoint 1
      │   └─ Checkpoint 2
      ├─ Run 2
      │   └─ Checkpoint 3
      └─ ...

Consultation
  └─ CDP v1 → v2 → v3 → ...
```

Checkpoint 与 Clinical State Version 必须建立引用关系，但不能替代 CDP。

Resume 时至少验证：

- Consultation 是否仍允许恢复；
- Thread 是否有效；
- Resume Event 是否重复或过期；
- Checkpoint 是否与当前 Runtime 兼容；
- 关联 Clinical State Version 是否仍是可接受基线；
- 当前 Safety / Capability / Consent 等关键约束是否仍成立。

## 11. Clinical State Version 与失效传播

V1 必须把临床状态视为版本化状态，而不是任意覆盖的 Map。

基本规则：

```text
用户新回答 / 更正
→ Patient Fact Change
→ 新 Clinical State Version
→ 标记依赖旧事实的派生结果可能失效
→ 必要时重新 Risk
→ 必要时重新 Safety Gate
→ 必要时重新 Information Gap
→ 必要时重新 DDx / Must-Exclude
→ 必要时重新 Delivery
```

Phase 3 不规定具体字段级依赖图，但冻结：

```text
Upstream Fact Changed
→ Dependent Derived State must be invalidatable
```

---

## 12. Must-Exclude 与 Information Gap 不进入系统一级生命周期

单个 Must-Exclude 候选未来可以具有：

```text
UNASSESSED
NOT_EXCLUDED
EXCLUDED
NEEDS_OFFLINE_EXCLUSION
```

但一个 Consultation 可以同时存在多个候选，因此它属于 F5 模块级状态，不应压缩成 Consultation 主状态。

同理，单个 Information Gap 需要表达是否阻断、是否可在线获取、是否已询问、用户是否未知、是否只能线下获取、是否已失效等语义，属于 F3/F6 模块级状态。

Phase 3 只通过 `Clinical Readiness` 表达这些细状态对全局推进的综合影响。

---

## 13. 为什么不采用固定五步 current_step 作为系统主状态

旧 AgentState 的 `current_step = 1..5` 不作为 V1 系统状态真值，因为：

1. 新证据可能要求回退或重算；
2. Safety 可以在任意轮触发；
3. 主动问诊和鉴别分析可能循环；
4. 用户更正会让旧结果失效；
5. 到达某个技术步骤不等于业务完成。

```text
固定步骤
可以成为某种 Workflow 实现
但不能成为系统唯一状态真值
```

---

## 14. AgentState 的重新归属

旧 AgentState 中有价值的部分继续保留，但归入 Execution / Runtime State：

```text
budget
retry / backoff
tried actions / tools
runtime stop guard
```

以下内容属于 Clinical State / CDP：

```text
patient facts
risk
DDx
Evidence
information gaps
```

目标设计不允许：

```text
CDP.work_mode
AgentState.work_mode
Frontend.work_mode
Dialog.work_mode
```

多个对象同时解释同一个临床业务事实。

## 15. 典型合法状态组合

### 正常追问

```text
Consultation = WAITING_USER
Risk = NO_HIGH_RISK_SIGNAL / CAUTION
SafetyGate = ALLOW / RESTRICTED
ClinicalReadiness = CAN_ASK_MORE
Delivery = NOT_READY
Thread = AWAITING_USER
```

### 可以进入疾病方向分析

```text
Consultation = ACTIVE
Risk = NO_HIGH_RISK_SIGNAL / CAUTION
SafetyGate = ALLOW
ClinicalReadiness = READY_FOR_CLINICAL_ANALYSIS
Delivery = NOT_READY
Thread = CREATED / RUNNING
```

### 高风险安全退出

```text
Consultation = SAFETY_ESCALATED
Risk = HIGH_RISK
SafetyGate = BLOCKED / RESTRICTED
Delivery = NOT_READY / READY
```

完成安全交付后：

```text
Consultation = SAFE_EXIT
Delivery = DELIVERED
```

### 安全能力不可用

```text
Risk = NOT_EVALUATED
SafetyGate = UNAVAILABLE
→ 普通临床推进禁止
→ 形成安全退出交付
→ Consultation = SAFE_EXIT
```

若系统连最低限度安全退出都无法完成，才进入 `FAILED_TERMINAL`。

### 当前范围外

```text
Consultation = ACTIVE
ClinicalReadiness = OUT_OF_SCOPE
→ 形成范围说明与安全指引
→ Delivery = READY → DELIVERED
→ Consultation = SAFE_EXIT
```

### 正常完成

```text
Consultation = ACTIVE
Risk = NO_HIGH_RISK_SIGNAL / CAUTION
SafetyGate = ALLOW
ClinicalReadiness = READY_FOR_CLINICAL_ANALYSIS
→ 合法形成患者侧结果
→ Delivery = DELIVERED
→ Consultation = COMPLETED
```

## 16. V1 全局状态不变量

```text
STATE-INV-01  COMPLETED != workflow reached end
STATE-INV-02  Clinical State / CDP != Runtime Checkpoint
STATE-INV-03  Thread RUNNING != Consultation ACTIVE 的唯一条件
STATE-INV-04  UNKNOWN / UNMEASURED 不得自动变成 NEGATIVE / NORMAL
STATE-INV-05  SafetyGate UNAVAILABLE != ALLOW
STATE-INV-06  Risk HIGH_RISK → 普通临床路径不得无条件继续
STATE-INV-07  Terminal Consultation 不得普通 Resume
STATE-INV-08  相同业务事件重复到达不得产生重复临床效果
STATE-INV-09  Upstream Fact Changed → Dependent Derived State must be invalidatable
STATE-INV-10  Delivery BLOCKED → Consultation cannot COMPLETED
STATE-INV-11  Thread COMPLETED != Consultation COMPLETED
STATE-INV-12  Capability Failure 不得通过空对象被解释为正常业务状态
STATE-INV-13  OUT_OF_SCOPE / NEEDS_OFFLINE_EVIDENCE / NO_RELIABLE_DIRECTION 的终止路径不得伪装为 COMPLETED
STATE-INV-14  Risk Disposition != Safety Gate；患者风险与系统继续权限必须分别表达
```

## 17. 与 F1-F8 的一级关系

| 功能域 | 主要影响的系统级状态 |
|---|---|
| F1 问诊建立与对象确认 | Consultation CREATED → ACTIVE；Clinical Readiness |

## 18. 与 G1-G6 的一级关系

| 横向能力 | 状态职责 |
|---|---|
| G1 临床范围、医学知识与规则治理 | 决定 Scope / Knowledge / Rule Version 是否有效 |
| G2 临床状态治理 | Clinical State Version、合法状态写入、失效、幂等 |
| G3 AI 能力与模型治理 | Capability / Model / Prompt 运行状态与失败语义 |
| G4 安全与权限治理 | Safety Gate、授权、Fail Closed |
| G5 Trace / Audit / Eval / Observability | 记录状态变化依据，不作为恢复真值 |
| G6 临床证据与来源治理 | Evidence 来源、极性、适用性、冲突和版本 |

其中 F4 负责患者临床风险语义，G4 负责系统安全继续权限；二者在 Phase 3 中通过 `Clinical Risk Disposition` 与 `Safety Gate` 明确分离。

## 19. 从历史设计正式继承与拒绝继承

### 保留

- CDP 作为病例临床聚合视图；
- CDP 版本化、历史不可变、Copy-on-Write / 可回放思想；
- Capability / Tool 不应直接任意修改临床事实；
- AgentState 中预算、重试、尝试、停止保护思想；
- Durable Execution 中 Thread / Run / Checkpoint / Resume / Idempotency 分离；
- Checkpoint 与 Clinical State 分离；
- 中断恢复、重复提交、服务故障恢复思想。

### 不原样继承

- `current_step = 1..5` 作为系统主状态；
- AgentState 作为第二套临床状态；
- Redis 作为唯一恢复事实源；
- `completed` 表示流程代码已跑到底；
- Tool / Agent 直接决定 CDP 最终写入；
- 完整健康管理态作为 V1 核心状态；
- V1 正式 `AWAITING_CLINICIAN`；
- Treatment / Medication 生命周期进入 V1 主状态。

## 20. Phase 3 审查结论与完成状态

本版已完成 Phase 3 专项审查，并关闭以下问题：

```text
REVIEW-03-01  COMPLETED 与 SAFE_EXIT 终态语义重叠

REVIEW-03-02  患者风险与系统继续权限混在同一 Safety Disposition

REVIEW-03-03  Delivery Readiness 粒度过细
→ CLOSED：Phase 3 仅保留 NOT_READY / READY / BLOCKED / DELIVERED
```

Phase 3 当前能够回答：

> 系统从一次问诊开始到结束，最关键的一级业务状态是什么？临床真值、患者风险、系统安全继续权限、临床推进条件、正式输出条件和 Runtime 执行恢复分别由什么对象表达？

```text
业务生命周期：Consultation Lifecycle
临床事实真值：Versioned Clinical State / CDP
患者临床风险：Clinical Risk Disposition
系统继续权限：Safety Gate
临床推进条件：Clinical Readiness
正式输出条件：Delivery Readiness
执行恢复状态：Execution Thread / Run / Checkpoint
```

因此：

```text
SOP Phase 3
= FROZEN / V1
```

下一阶段：

```text
SOP Phase 4
模块级状态细化与状态所有权
```

进入 Phase 4 后，才进一步定义 F1-F8 内部状态、状态所有者、合法转移和写入责任；仍不得提前拆开发单元。
