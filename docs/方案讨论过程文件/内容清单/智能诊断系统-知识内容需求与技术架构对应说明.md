# 知识内容需求与技术架构对应说明

## 一、总体说明

### 1.1 知识内容的作用与定位

**核心定位**：知识内容是智能诊断系统的**核心资产**，主要为**AI服务层**提供知识支撑。

知识内容为系统提供：
- ✅ **AI推理依据**：症状组合规则、鉴别诊断逻辑、证据判定标准（支撑诊断引擎）
- ✅ **对话生成能力**：问题模板、追问策略、概念归一化（支撑对话服务）
- ✅ **知识沉淀体系**：可复用、可审计、可迭代的知识库
- ✅ **临床诊断思维**：三层分层逻辑、必须排除机制、复评回退规则

### 1.2 AI服务层架构概览

- **使用**：在诊断流程开始前，先进行门控判断，命中红旗条件则升级处理，未命中则进入阶段1


## 三、知识内容在诊断流程中的使用（补充说明）

### 3.1 诊断流程概览

```
触发诊断（门控）
  ↓ 使用：主诉级红旗条件、升级动作规则
阶段1：主动询问
  ↓ 使用：症状归一化词表、主诉关键字段模板、信息缺口分级规则
阶段2：信息补全
  ↓ 使用：主诉关键字段模板、信息缺口分级规则、数据冲突检测规则
阶段3：可能性分析（五引擎融合）
  ↓ 使用：规则库、知识图谱、统计模型、大模型提示词、鉴别规则库
  ↓ 输出：三层分层（使用：主诉级鉴别诊断模板库、分层规则、关键分岔点清单）
阶段4：鉴别诊断
  ↓ 使用：分流路径模板、证据条目库、验证计划库、关键分岔点清单
阶段5：结果输出
  ↓ 使用：终点结论包模板、复评规则库、回退条件
```
