# 智能诊断系统-知识内容需求目录

---

## 一、分诊服务（triage-service）

**服务说明**：在患者进入诊断流程前，先判断是否有高危情况，如果有就立即建议就医，如果没有才进入正常诊断流程。

| 序号 | 知识内容名称 | 作用说明 |
|-----|------------|---------|
| 1.1 | 主诉级红旗条件（高危触发项） | **作用**：定义每个主诉（如胸痛、发热）下，出现哪些症状组合时必须立即就医，不能继续在线诊断。<br>**举例**：对于"胸痛"这个主诉，如果同时出现"意识模糊"或"生命体征异常"（如血压很低、心率很快），就触发红旗条件，系统会立即建议患者去急诊。<br>**内容组需要准备**：为每个常见主诉列出高危症状组合清单，比如"胸痛+意识改变"、"发热+呼吸困难"等。 |
| 1.2 | 升级动作规则 | **作用**：定义当检测到高危情况后，系统应该给出什么建议和动作。<br>**举例**：如果检测到极高危险，系统会说"建议立即到急诊科就诊，必要时拨打120"；如果是中等危险，系统会说"建议尽快到相关科室就诊"。<br>**内容组需要准备**：定义不同危险等级对应的建议话术和处理方式。 |

## 二、对话服务（dialog-service）

**服务说明**：让AI像医生一样主动询问患者，收集症状信息，理解患者说的自然语言，并生成合适的追问问题。

| 序号 | 知识内容名称 | 作用说明 |
|-----|------------|---------|
| 2.1 | 症状归一化词表 | **作用**：将患者说的各种口语化表达转换成医学标准术语，让系统能理解患者的意思。<br>**举例**：患者说"胸口闷"、"走几步就喘"，系统要能识别出这是"胸闷样不适"和"活动后气促"。如果患者说"胸痛"这种模糊词，系统要知道需要进一步追问疼痛的性质。<br>**内容组需要准备**：整理常见症状的口语化表达和标准医学术语的对应关系，比如"胸口闷"→"胸闷样不适"，"走几步就喘"→"活动后气促"等。 |
| 2.2 | 主诉关键字段模板 | **作用**：定义每个主诉（如胸痛、发热）需要收集哪些关键信息，以及如何问这些问题。<br>**举例**：对于"胸痛"，必须收集的信息包括：起病时间（"疼痛持续多久了？"）、起病方式（"是突然出现的还是慢慢加重的？"）、严重程度（"0-10分，您觉得疼痛是几分？"）、症状性质（"疼痛是什么性质的？是钝痛、刺痛还是压榨感？"）等。<br>**内容组需要准备**：为每个常见主诉列出必须收集的字段清单，以及每个字段的标准问法。 |
| 2.3 | 伴随症状清单（主诉特异） | **作用**：定义与主诉相关的、最能帮助判断疾病方向的伴随症状，以及如何询问这些症状。<br>**举例**：对于"胸痛"，需要询问是否伴有"出汗"、"恶心"、"呼吸困难"、"咳血"等。如果患者说"胸痛伴出汗"，这提示可能是心血管疾病（如心梗、心绞痛）。<br>**内容组需要准备**：为每个主诉列出重要的伴随症状清单，每个症状的标准问法，以及这个症状对诊断方向的影响（支持哪些疾病方向）。 |
| 2.4 | 智能追问题库（按缺口映射） | **作用**：当发现患者信息不完整时，系统知道如何追问，以及如何处理患者说"不知道"、"记不清"等不确定回答。<br>**举例**：如果患者没有说疼痛持续多久，系统会问"疼痛持续多久了？"；如果患者说"记不清"，系统会标记为不确定，但继续问其他必填项；如果患者拒绝回答，系统会提示风险并建议线下就医。<br>**内容组需要准备**：定义每个必填/重要字段的标准问法（引用主诉关键字段模板），以及处理不确定回答的方式。 |
| 2.5 | 信息缺口分级规则 | **作用**：定义哪些信息是必须的（缺失就不能诊断），哪些是重要的（缺失会影响准确性），哪些是可选的（后续补充即可）。<br>**举例**：对于所有主诉，"主诉"、"起病时间"、"严重程度"都是必填的；"伴随症状"、"既往史"是重要的；"详细生活方式信息"是可选的。<br>**内容组需要准备**：定义通用必填项、主诉特定必填项、重要项、可选项的清单。 |
| 2.6 | 关键背景字段（主诉特异 + 全局通用） | **作用**：定义需要收集的患者背景信息，包括年龄、性别、既往史、用药史、过敏史、暴露史、家族史等，以及如何询问这些信息。<br>**举例**：对于"胸痛"，需要询问年龄（"您今年多大年纪？"）、性别、既往史（"您有没有高血压、冠心病、糖尿病等疾病？"）、用药史（"您最近在吃什么药？"）、暴露史（"最近有没有旅行、接触过感染病人、做过手术、长时间坐着或躺着、受过外伤？"）等。<br>**内容组需要准备**：列出全局通用字段（年龄、性别）和主诉特定字段（既往史、用药史等）的标准问法，以及这些信息对诊断的影响。 |
| 2.7 | 健康档案相关归一化词表 | **作用**：将患者说的疾病名称、药物名称、过敏源等转换成标准术语，确保系统能正确理解。<br>**举例**：患者说"血压高"、"血糖高"，系统要识别为"高血压病"、"2型糖尿病"；患者说"降压药"，系统要知道这是"抗高血压药物"，并可能需要追问具体是什么药；患者说"青霉素"、"盘尼西林"，系统要识别为"青霉素类抗生素"。<br>**内容组需要准备**：整理疾病名称、药物名称、过敏源的常见表达和标准术语的对应关系，包括同义词、别名、商品名等。 |
| 2.8 | 生命体征正常值范围库 | **作用**：定义血压、心率、体温、血氧饱和度等生命体征的正常值范围，用于判断患者体征是否异常。<br>**举例**：成人血压正常范围是收缩压90-140mmHg、舒张压60-90mmHg；心率正常范围是60-100次/分；体温正常范围是36.0-37.2℃；血氧饱和度正常范围是95-100%。<br>**内容组需要准备**：整理各种生命体征在不同年龄、性别下的正常值范围，以及异常判定标准。 |
| 2.9 | 数据冲突检测规则 | **作用**：检测患者输入中的矛盾信息，比如时间描述不一致、肯定和否定同时存在、逻辑上互相排斥的症状组合，并规定如何处理这些冲突。<br>**举例**：患者先说"昨天开始胸痛"，后说"一个月了"，这是时间轴冲突，系统需要重新询问；患者先说"不发烧"，后说"寒战发热"，这是否定冲突，系统需要澄清；患者同时说"持续疼痛"和"间歇性疼痛"，这是逻辑冲突，系统需要询问哪个更准确。<br>**内容组需要准备**：定义各种冲突类型的检测规则和处理方式，包括时间轴冲突、否定冲突、逻辑冲突等。 |

## 三、诊断引擎服务（diagnosis-engine-service）

**服务说明**：使用五种不同的方法（规则引擎、知识图谱、统计模型、大模型、鉴别诊断）综合分析患者信息，给出可能的疾病方向。

| 序号 | 知识内容名称 | 作用说明 |
|-----|------------|---------|
| 3.1 | 规则引擎 - 症状组合规则库 | **作用**：定义"出现哪些症状组合，可能是什么疾病"的规则，让系统能快速匹配可能的疾病方向。<br>**举例**：如果患者有"胸痛+出汗+气短"这个症状组合，系统会匹配到"急性心肌梗死"这个疾病方向，置信度0.9；如果患者有"胸痛+活动后加重"，系统会匹配到"心绞痛"，置信度0.7。<br>**内容组需要准备**：整理常见症状组合与疾病的对应关系，包括症状组合、疾病名称、置信度、典型体征、典型背景等。 |
| 3.2 | 知识图谱引擎 - Neo4j知识图谱 | **作用**：建立症状、疾病、检查、体征、药物等医学概念之间的关系网络，让系统能通过关系推理发现可能的疾病。<br>**举例**：在知识图谱中，"胸痛"这个症状节点与"心绞痛"、"急性心肌梗死"、"胃食管反流"等疾病节点有"引起"关系，权重和置信度不同。系统可以根据这些关系推理出可能的疾病方向。<br>**内容组需要准备**：整理症状、疾病、检查、体征、药物等概念之间的关系，包括关系类型（引起、诊断、治疗、相关等）、权重、置信度等。 |
| 3.3 | 统计模型引擎 - 历史诊断数据 | **作用**：基于大量历史诊断数据训练统计模型，当输入患者症状、体征、背景信息时，模型能预测可能的疾病及其概率。<br>**举例**：如果历史数据中，有1000个"55岁男性+胸痛+出汗+气短+高血压史"的案例，其中800个最终诊断为"心绞痛"，那么当遇到类似患者时，模型会预测"心绞痛"的概率较高。<br>**内容组需要准备**：提供历史诊断数据，包括症状、体征、检查结果、最终诊断、患者画像（年龄、性别、既往史）等，数据量建议≥10000条，需要经过医学专家审核。 |
| 3.4 | 大模型引擎 - 提示词模板 | **作用**：定义如何向医学大模型提问，让大模型根据患者信息进行深度推理分析，给出可能的疾病方向、支持证据、反对证据等。<br>**举例**：系统会把患者信息（年龄、性别、症状、体征、既往史等）填入提示词模板，然后问大模型："根据这些信息，分析可能的疾病方向、每个方向的支持证据和反对证据、还需要哪些信息、建议做哪些检查"。<br>**内容组需要准备**：设计提示词模板，包括如何组织患者信息、如何提问、期望的输出格式等。 |
| 3.5 | 鉴别诊断引擎 - 鉴别诊断规则库 | **作用**：定义如何区分相似的疾病，提供鉴别诊断的要点，帮助系统区分容易混淆的疾病。<br>**举例**：对于"心绞痛"和"急性心肌梗死"这对容易混淆的疾病，鉴别要点包括：疼痛持续时间（心绞痛<30分钟，心梗>30分钟）、严重程度（心绞痛中等，心梗剧烈）、伴随症状（心绞痛出汗气短轻度，心梗大汗恶心气短重度）、心电图（心绞痛ST段压低或正常，心梗ST段抬高）等。<br>**内容组需要准备**：整理常见疾病对的鉴别要点，包括每个要点在两个疾病中的不同特征，以及每个要点的权重。 |

## 四、OCR服务（ocr-service）

**服务说明**：识别患者上传的检查报告图片，提取报告中的指标数值，判断指标是否异常。

| 序号 | 知识内容名称 | 作用说明 |
|-----|------------|---------|
| 4.1 | 检查报告模板库 | **作用**：定义不同医院、不同检查类型的报告格式，告诉系统如何从报告中找到各项指标的位置和数值。<br>**举例**：对于"血常规"报告，系统需要知道"白细胞"可能在报告中用"白细胞"、"WBC"、"White Blood Cell"等关键词表示，数值通常在关键词后面，单位可能是"10^9/L"或"×10^9/L"。<br>**内容组需要准备**：整理常见检查报告（血常规、心电图、肝功能等）的格式，包括标题关键词、指标位置、数值提取规则、单位等。 |
| 4.2 | 指标名称归一化词表 | **作用**：将不同医院使用的不同指标名称统一成标准名称，确保系统能正确识别。<br>**举例**：不同医院可能用"白细胞"、"白细胞计数"、"WBC"、"White Blood Cell"、"白細胞"（繁体）、"白血球"（台湾用法）等不同名称，系统都要能识别为"白细胞"这个标准名称。<br>**内容组需要准备**：整理每个检查指标的标准名称、标准编码、同义名称（包括不同医院、不同地区的用法），以及单位映射关系。 |
| 4.3 | 正常值范围库 | **作用**：定义各种检查指标的正常值范围，用于判断患者检查结果是否正常。<br>**举例**：成人白细胞正常范围是3.5-9.5×10^9/L，但0-1岁儿童是6.0-17.5×10^9/L；成人男性血红蛋白正常范围是120-160g/L，女性是110-150g/L。<br>**内容组需要准备**：整理各种检查指标在不同年龄、性别下的正常值范围，包括下限、上限、参考来源等。 |
| 4.4 | 异常判定规则 | **作用**：定义什么值算正常、什么值算异常，以及异常的程度（轻度、中度、重度），并说明异常的临床意义。<br>**举例**：对于白细胞，3.5-9.5是正常，3.0-3.5是轻度偏低（可能提示感染、营养不良），<3.0是明显偏低（需要进一步检查，排除血液系统疾病），9.5-12.0是轻度偏高（可能提示感染、炎症），>12.0是明显偏高（需要进一步检查，排除严重感染、血液系统疾病）。<br>**内容组需要准备**：为每个检查指标定义正常、轻度异常、中度异常、重度异常的判定条件和临床意义。 |

## 五、业务服务层

**服务说明**：这些知识内容用于支撑整个诊断流程，包括如何分层诊断方向、如何验证诊断、如何生成结论等。

| 序号 | 知识内容名称 | 作用说明 |
|-----|------------|---------|
| 5.1 | 主诉级鉴别诊断模板库 | **作用**：为常见主诉（如胸痛、发热）预先定义三层诊断方向：最可能的疾病（首要假设）、其他可能的疾病（主要备选）、必须排除的高危疾病（必须排除）。<br>**举例**：对于"胸痛"，首要假设可能是"心绞痛"（如果症状典型），主要备选可能是"焦虑症"（如果症状不典型），必须排除的是"急性心肌梗死"（即使概率不高，但一旦漏诊后果严重，必须优先排除）。<br>**内容组需要准备**：为每个常见主诉整理三层诊断方向的候选集合，包括每个疾病的入选依据、典型症状组合、典型体征、典型背景等。 |
| 5.2 | 分层规则 | **作用**：定义什么情况下一个疾病可以进入"首要假设"（最可能方向），什么情况下必须进入"必须排除"（高危方向）。<br>**举例**：一个疾病要成为"首要假设"，需要满足：可能性分数最高、症状组合匹配度≥70%、支持证据数量≥3、关键背景匹配。一个疾病要进入"必须排除"，需要满足：一旦漏诊后果严重、即使概率不高（≥0.1）也必须纳入、存在高危线索或高危背景。<br>**内容组需要准备**：定义首要假设规则、主要备选诊断规则、必须排除的高危诊断规则的具体条件。 |
| 5.3 | 分流路径模板（Routing Path） | **作用**：定义如何通过分叉式问诊快速区分诊断方向，逐步缩小候选疾病范围。<br>**举例**：对于"胸痛"，第一个分叉问题是"疼痛是急性还是慢性？"（<1周为急性，≥1周为慢性）。如果答案是"急性"，系统会继续问"疼痛是否活动后加重？"；如果答案是"慢性"，系统会问"疼痛是否与进食有关？"。通过这样的分叉问题，系统能快速区分是心血管疾病还是消化系统疾病等。<br>**内容组需要准备**：为每个主诉设计分叉问诊路径，包括第一层分叉问题、后续收缩步骤、每个分叉结果对应的诊断方向等。 |
| 5.4 | 主诉关键线索库 | **作用**：定义哪些线索是阳性线索（能显著支持某一疾病方向）、哪些是关键阴性线索（能显著削弱某一疾病方向），用于采集关键证据。<br>**举例**：对于"胸痛"和"急性心肌梗死"这个方向，"胸痛伴大汗"是强阳性线索（权重1.0），出现这个线索应该推动心梗方向前移；"无明显出汗"是中等阴性线索（权重0.7），出现这个线索应该推动心梗方向后移；"症状持续时间短（<5分钟）"是强阴性线索（权重1.0），因为心梗通常持续时间>30分钟。<br>**内容组需要准备**：为每个主诉和疾病方向整理阳性线索和关键阴性线索，包括线索名称、线索描述、症状组合、线索强度、权重、推动方向等。 |
| 5.5 | 证据条目库 | **作用**：定义支持某个疾病的证据、反对某个疾病的证据，以及证据的强度分级，用于进行支持/反对证据分析。<br>**举例**：对于"急性心肌梗死"，支持证据包括"胸痛伴出汗"（强证据，权重1.0，特异性高）、"心电图ST段抬高"（强证据，权重1.0，特异性极高）、"老年男性"（弱证据，权重0.4，非特异性）；反对证据包括"无出汗"（中证据，权重0.7）、"症状持续时间短"（强证据，权重1.0）、"心电图正常"（中证据，权重0.7）。<br>**内容组需要准备**：为每个疾病整理支持证据和反对证据清单，包括证据名称、证据类型、证据内容、证据强度、权重、特异性等。 |
| 5.6 | 验证计划库 | **作用**：定义如何验证某个疾病方向，包括是否需要验证、需要做什么检查、需要问什么问题、如何判定验证结果。<br>**举例**：对于"急性心肌梗死"这个必须排除的方向，验证计划包括：优先检查"心电图"和"心肌酶"，关键问题"疼痛是否持续不缓解？"、"是否伴有大汗、恶心？"。如果心电图显示ST段抬高或心肌酶升高，则支持心梗诊断，必须升级处理；如果心电图正常且心肌酶正常且症状已缓解，则不支持心梗诊断，可以排除。<br>**内容组需要准备**：为每个疾病方向（特别是最可能方向和必须排除方向）设计验证计划，包括查不查、查什么（检查、问题）、判定标准（支持/不支持/不确定）等。 |
| 5.7 | 复评与升级规则库 | **作用**：定义建议患者多久后复评，以及什么情况下需要立即升级处理（建议就医）。<br>**举例**：对于"心绞痛"，默认复评时间窗是"3天后"；但如果症状加重或出现新症状（如出汗、气短），需要立即复评；如果症状完全缓解，可以延迟到1周后复评。升级触发条件包括：症状突然加重、出现高危症状（大汗、恶心、气短等）、处理无效等，一旦触发需要立即就医。<br>**内容组需要准备**：为每个疾病方向定义复评时间窗、提前复评条件、延迟复评条件、升级触发条件、升级处理方式等。 |
| 5.8 | 回退条件清单 | **作用**：定义什么情况下需要回退到之前的诊断阶段，重新收集信息或重新分析。<br>**举例**：如果新证据与原有证据冲突（如症状说发热，但体温测量正常），需要回退到阶段4（重新采集证据）；如果症状发生变化（如疼痛性质从钝痛变为刺痛），需要回退到阶段3（重新组织分流路径）；如果按照建议处理后症状未改善或加重，需要回退到阶段4（重新采集证据）。<br>**内容组需要准备**：定义各种回退条件，包括证据冲突、症状演变、处理无效、必须排除项未完成排除等，以及每种情况对应的回退目标阶段和回退原因。 |
| 5.9 | 关键分岔点（Pivotal Points）清单 | **作用**：定义保证"任何主诉都能分流推进"的关键分岔点，这些分岔点是互斥的（如急性vs慢性），用于快速分流诊断方向。<br>**举例**：对于"胸痛"，关键分岔点包括："急性vs慢性"（<1周为急性，≥1周为慢性）、"活动诱发vs静息也发生"、"单侧vs双侧"、"发热vs无发热"、"进行性加重vs稳定/波动"等。如果患者是"急性胸痛"，系统会优先考虑急性心血管事件；如果是"慢性胸痛"，系统会优先考虑非急性疾病。<br>**内容组需要准备**：为每个主诉整理关键分岔点清单，包括分岔点名称、互斥对、判定条件、标准问法、命中后推动的方向等。 |
| 5.10 | 回填与重排规则（Re-rank Rule） | **作用**：定义当新信息出现后，如何重新排序诊断方向（哪些方向上移、哪些下移、哪些剔除、哪些保留），以及如何处理证据冲突。<br>**举例**：如果新检查结果显示"心电图ST段抬高"，这是急性心肌梗死的典型表现，系统会将"急性心肌梗死"方向上移（权重+0.3），将"心绞痛"方向下移（权重-0.2）。如果新证据与原有证据明显冲突（如症状说胸痛剧烈，但心电图正常且持续正常），系统会标记为不确定并回退到阶段4重新分析。<br>**内容组需要准备**：定义新信息出现后的重排规则，包括不同新信息类型对应的重排动作和权重调整，以及证据冲突时的回退规则。 |
| 5.11 | 终点结论包模板 | **作用**：定义诊断结果输出的统一格式，确保所有主诉的诊断结果都包含四个要素：结论、必须排除项状态、关键证据链、行动与随访。<br>**举例**：如果证据充分可以确证诊断，输出"可确证结论"，包括具体诊断名称、已排除的高危诊断列表、至少3条关键证据链、立即行动建议、复评时间窗、升级触发条件。如果证据不充分，输出"不可确证结论"，包括最可能方向、需线下排除的高危诊断、支持/反对/缺失证据、下一步验证建议等。<br>**内容组需要准备**：设计终点结论包模板，定义可确证结论和不可确证结论的输出格式，包括每个要素的具体要求和示例。 |
