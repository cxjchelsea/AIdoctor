# AI医生系统 - 知识内容需求

| 交付物名称 | 通俗解释 | 具体包含什么 |
|-----------|---------|------------|
| **医学概念本体与编码规范** | **给每个医学概念起一个标准名字和唯一编号**<br>就像给每个人发身份证号一样，确保系统内部每个疾病、症状、检查、药物都有唯一标识 | • 疾病：标准名称 + ICD/SNOMED编码<br>• 症状：标准术语 + HPO/CUI编码<br>• 检查：标准名称 + LOINC编码<br>• 药物：标准名称 + ATC编码<br>• 体征、指标：标准术语 + 编码 |
| **归一化词表** | **把用户的各种说法翻译成标准术语**<br>用户说"胸口闷"，系统要知道这是"胸闷样不适"；用户说"血压高"，系统要知道这是"高血压病" | • 症状归一化：口语化表达 → 标准术语<br>（如"胸口闷"→"胸闷样不适"）<br>• 疾病归一化：常见表达 → 标准术语<br>（如"血压高"→"高血压病"）<br>• 药物归一化：商品名/别名 → 标准名称<br>（如"拜阿司匹灵"→"阿司匹林"）<br>• 检查/指标归一化：不同医院的说法 → 标准名称 |
| **基础标准配置** | **定义系统内部使用的统一标准**<br>就像规定"急性"是指<1周，"慢性"是指≥1周，确保所有知识内容都用同一套标准 | • 紧急程度分级：L1（极紧急）/L2（紧急）/L3（一般）/L4（非紧急）<br>• 时间标准：急性（<1周）/慢性（≥1周）<br>• 严重程度：轻度/中度/重度<br>• 生命体征正常值：血压、心率、体温等在不同年龄/性别下的正常范围<br>• 人群字段标准：年龄段分组、性别、既往史类型等 |

### 2 三模板核心层（核心知识内容）

| 交付物名称 | 通俗解释 | 具体包含什么 |
|-----------|---------|------------|
| **模板A：主诉级候选集** | **每个主诉对应的候选疾病清单**<br>用户说"胸痛"，系统要知道：最可能是哪1-2个病，常见备选是哪2-5个病，必须排除的高危病是哪1-3个 | • 主诉名称（如"胸痛"）<br>• 三层候选集合及其分层规则：<br>  - 首要假设（1-2个疾病）<br>  - 主要备选（2-5个疾病）<br>  - 必须排除（1-3个高危疾病）<br>• 每个候选疾病的：入选依据、典型症状、典型体征、典型背景、当前缺口<br>• 分流路径：通过分叉式问诊快速区分诊断方向的关键问题序列<br>• 候选方向的子组组织（按系统来源/病程/诱因等维度组织）<br/>• 主诉关键字段模板：每个主诉需要收集哪些关键信息<br/>伴随症状清单<br/>信息缺口分级规则：哪些信息是必须的、重要的、可选的 |
| **模板B：疾病模板** | **每个疾病在知识图谱里的样子**<br>就像给每个疾病建一张"身份证"，记录它有哪些症状、需要做什么检查、怎么治疗、容易和哪些病混淆 | • 疾病节点属性：<br>  - 疾病ID、名称、患病率<br>  - 典型症状组合、典型体征、典型背景<br>• 关系边（疾病与其他概念的关系）：<br>  - 疾病→症状（引起关系）<br>  - 疾病→检查（需要检查关系）<br>  - 疾病→治疗（需要治疗关系）<br>  - 疾病→疾病（易混淆关系）<br>• 可计算属性：先验概率、似然评分、后验概率 |
| **模板C：证据条目库** | **把"证据"从疾病卡片里抽出来，做成可复用的条目**<br>就像把"胸痛伴大汗"这个证据做成一个标准条目，记录它支持哪些疾病、不支持哪些疾病、如何获取、强度如何 | • 证据条目属性：<br>  - 证据名称（如"胸痛伴大汗"、"心电图ST段抬高"）<br>  - 证据类型（症状组合/检查结果/体征/用户画像）<br>  - 证据强度（极高/高/中/低）<br>  - 特异性（仅见于该疾病/多见于该疾病/多个疾病都可能出现）<br>  - 如何获取（标准问法/检查项目/测量方法）<br>  - 影响对象（推动哪个疾病方向上移/下移）<br>• 证据分类：<br>  - 支持证据清单（能支持该疾病的证据）<br>  - 反对证据清单（能削弱或排除该疾病的证据）<br>  - 差异点线索（能最快区分诊断方向的证据） |

### 3 规则层（流程和安全保障）

| 交付物名称 | 通俗解释 | 具体包含什么 |
|-----------|---------|------------|
| **入口判定与工作态切换** | **判断用户想干什么，选择走A路径还是B路径**<br>用户说"我想体检"→走A路径；用户说"我胸痛"→走B路径；用户说"胸痛+意识模糊"→立即建议急诊 | • 红旗信号库：每个主诉下的高危症状组合清单<br>• 工作态判定规则：什么情况走A路径，什么情况走B路径<br>• 症状/困扰识别规则：如何识别用户是否有症状<br>• 方向澄清模板：对模糊诉求进行澄清的问题模板<br>• 信息缺口分级规则：哪些信息是必须的、重要的、可选的<br>• 智能追问题库：按缺口映射的标准追问问题 |
| **A路径（健康管理态）** | **健康管理态的完整流程规则**<br>从需求分类（筛查/体检解读/健康目标/计划性需求）到结果输出、随访闭环、升级条件 | • 需求分类规则（A1）：四类需求的识别规则<br>• 健康档案字段清单（A2）：需要采集的字段<br>• 筛查建议规则（A3-1）：按年龄段/性别/风险因素推荐筛查<br>• 体检异常分级规则（A3-2）：轻度/中度/重度的判定标准<br>• 健康目标管理模板（A3-3）：目标类型、行动计划模板<br>• 计划性健康需求场景库（A3-4）：备孕/疫苗/差旅等场景清单<br>• 统一结果页模板（A4）：结果页输出格式<br>• 随访规则（A5）：随访节奏规则<br>• 升级条件库：A路径升级到B路径的触发条件<br/>健康管理态随访规则库（A5） |
| **风险与急症识别** | **识别高危情况，评估紧急程度**<br>判断什么情况需要立即就医，什么情况可以观察，建议多久后复评 | • 高危识别规则库：需要立即就医的高危症状组合<br>• 严重程度评估规则：每个疾病的严重程度判定标准<br>• 紧急程度分级规则：L1-L4的判定标准<br>• 复评与升级规则：复评时间窗、升级触发条件 |
| **回填/重排/回退** | **当新信息出现后，如何重新排序诊断方向**<br>比如新检查结果显示"心电图ST段抬高"，系统要知道把"急性心肌梗死"方向上移 | • 回填与重排规则：新信息出现后的重排规则（哪些方向上移/下移/剔除）<br>• 回退条件清单：什么情况需要回退到之前的诊断阶段<br> |
| **入口角度统一转换** | **把用户从不同角度的问题转换成标准流程**<br>用户说"我父亲有糖尿病，我担心自己也会得"→转换成"多饮、多尿"等主诉，走B路径 | • 家族史→可能主诉映射表<br>• 既往疾病→可能主诉映射表<br>• 异常指标→可能主诉映射表<br>• 生命体征异常→可能主诉映射表<br>• 追问策略库：标准追问问题模板<br> |
| 输出 | 诊断结果输出的统一格式（属于输出模板） | 终点结论包模板库 |
