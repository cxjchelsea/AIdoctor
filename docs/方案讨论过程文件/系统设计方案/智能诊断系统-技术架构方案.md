# 智能诊断系统 - 技术架构方案

> **文档定位**：本文档是智能诊断系统的**技术架构方案**，专注于技术实现、系统架构、服务设计、技术选型、部署方案等技术层面的设计。  
> **业务逻辑**：请参考《智能诊断系统-系统设计方案.md》  
> **核心理念**：智能诊断是**医学判断引擎**，与智能家庭医生（照护执行引擎）协作，整合所有模块，实现主动引导。

### 1.2 技术栈选型

#### 1.2.1 语言选型：Java vs Python

**推荐方案：混合架构（Java + Python）**

**后端业务服务（推荐Java）**：
- **语言**：Java 8
- **框架**：Spring Boot 2.7.8
- **服务治理**：Spring Cloud Gateway + Nacos
- **数据库访问**：MyBatis Plus / JPA
- **服务调用**：OpenFeign

**优势**：
- 企业级稳定性：Spring Boot生态成熟，适合高并发、高可用场景
- 性能优势：JVM优化好，适合大量CRUD操作、事务处理
- 团队技能：如果团队Java经验丰富，开发效率高
- 服务治理：Spring Cloud生态完善，服务注册发现、配置管理成熟

**适用场景**：
- 诊断服务（diagnosis-service）：诊断流程编排、记录管理、业务逻辑处理
- 检查服务（examination-service）：检查方案设计、报告管理、业务逻辑处理
- 用户管理、权限管理
- 任务调度、消息队列处理
- 与现有Java系统集成（如有）

**注意**：对话管理功能已独立为dialog-service（Python），diagnosis-service通过HTTP/WebSocket调用

**后端AI服务（推荐Python）**：
- **语言**：Python 3.10+
- **框架**：FastAPI
- **异步处理**：asyncio
- **HTTP客户端**：httpx / aiohttp

**优势**：
- AI模型集成便利：scikit-learn、XGBoost、TensorFlow/PyTorch生态成熟
- 特征工程高效：pandas、numpy处理数据更便捷
- 快速迭代：规则引擎、预测模型开发速度快
- NLP处理：spaCy、transformers用于报告识别、对话理解
- 科学计算：statsmodels、Prophet用于时序预测、统计分析

**适用场景**：
- 对话服务（dialog-service）：自然语言理解、生成、对话管理、智能追问
- 诊断引擎服务（diagnosis-engine-service）：五引擎融合诊断
- OCR服务（ocr-service）：报告图片识别、结构化提取
- AI/ML模型服务
- 特征工程服务

**混合架构建议**：
```
┌─────────────────────────────────────┐
│   Java服务层（Spring Boot）          │
│   - 诊断服务、检查服务                │
│   - 用户管理、权限、认证              │
│   - 任务调度、消息队列                │
│   - API网关、统一接口                │
└─────────────────────────────────────┘
              ↓ HTTP/gRPC
┌─────────────────────────────────────┐
│   Python服务层（FastAPI）            │
│   - 诊断引擎（规则/知识图谱/模型）   │
│   - OCR服务                          │
│   - 对话服务                         │
│   - AI/ML模型服务                    │
└─────────────────────────────────────┘
```

**如果只能选一种语言**：
- **优先选Python**：因为系统核心价值在AI/ML能力，Python生态更适合
- **但需要加强**：性能优化（异步框架、缓存策略）、并发处理（多进程/协程）

#### 1.2.2 技术栈详细选型

**Java技术栈（业务服务）**：
- **Web框架**：Spring Boot 2.7.8

- **异步处理**：Spring WebFlux（响应式编程，可选）

  * pandas：数据清洗、特征工程

- **对象存储**：MinIO（私有）或 阿里云OSS/腾讯云COS

**前端**：

- **状态管理**：Zustand / Redux

**数据库**：

**AI/ML**：

### 1.3 层间调用关系图

#### 1.3.1 详细调用关系

```
【前端层】
    │
    │ ① HTTP请求：POST /api/diagnosis/start
    │   请求体：{ "userId": "user123", "symptom": "我最近胸痛" }
    ↓
【API网关层】
    │
    │ ② 路由转发、认证授权、限流
    ↓
【业务服务层 - 诊断服务】
    │
    │ ③ 调用：diagnosisService.startDiagnosis(request)
    │   内部调用核心引擎层
    ↓
【AI服务层】
    │
    ├─→ ④ 对话服务：dialogService.generateQuestion(context)
    │     读取：健康档案库（用户画像）
    │     返回：{ "question": "疼痛持续多久了？", "missing_info": "duration" }
    │
    ├─→ ⑤ 诊断引擎服务：diagnosisEngineService.diagnose(engineRequest)
    │     ├─→ 规则引擎：ruleEngine.diagnose(request)
    │     │     读取：规则库（MySQL）
    │     │     返回：{ "possibilities": {"心绞痛": 0.8}, ... }
    │     │
    │     ├─→ 知识图谱引擎：kgEngine.diagnose(request)
    │     │     读取：知识图谱（Neo4j）
    │     │     返回：{ "possibilities": {"心绞痛": 0.75}, ... }
    │     │
    │     ├─→ 统计模型引擎：statisticalEngine.diagnose(request)
    │     │     读取：模型库（文件/Redis）
    │     │     返回：{ "possibilities": {"心绞痛": 0.7}, ... }
    │     │
    │     ├─→ 大模型引擎：llmEngine.diagnose(request)
    │     │     调用：LLM API
    │     │     返回：{ "possibilities": {"心绞痛": 0.8}, ... }
    │     │
    │     └─→ 鉴别诊断引擎：differentialEngine.diagnose(request)
      │          读取：鉴别规则库（MySQL）
    │          返回：{ "differential_points": {...}, ... }
    │
    └─→ ⑥ OCR服务（如上传报告）：ocrService.recognize(imageFile)
         返回：{ "raw_text": "...", "structured_data": {...} }
    │
    ↓ ⑦ 返回结果给业务服务层
【业务服务层】
    │
    │ ⑧ 融合诊断结果：fuseResults(engineResults)
    │   生成诊断报告
    │
    │ ⑨ 写入：诊断记录库（diagnosis_record表）
    │
    ↓ ⑩ 返回完整结果
【前端层】
    │
    │ ⑪ 展示：诊断结果卡片 + 可能性列表 + 建议检查
    │
```

#### 1.3.2 层间接口规范

| 层间调用 | 调用方式 | 接口类型 | 示例 |
|---------|---------|---------|------|
| **前端层 → 业务服务层** | HTTP REST API | 外部接口 | `POST /api/diagnosis/start` |
| **业务服务层 → AI服务层** | HTTP/gRPC | 服务间接口 | `POST /api/engine/diagnose` |
| **AI服务层 → 数据层** | ORM查询 / SQL / 图查询 | 数据访问接口 | `db.query(DiagnosisRecord).filter(...)` |
| **业务服务层 → 业务服务层** | HTTP/gRPC（OpenFeign） | 服务间接口 | `healthCenterService.getHealthProfile(userId)` |
| **AI服务层 → AI服务层** | Python函数调用 | 引擎间接口 | `ruleEngine.diagnose(request)` |

**接口设计原则**：
- **前端层 ↔ 业务服务层**：RESTful API，标准化HTTP接口，支持版本控制
- **业务服务层 ↔ AI服务层**：HTTP/gRPC，支持异步调用，超时控制
- **AI服务层 ↔ 数据层**：ORM/SQL/图查询，统一数据访问层，支持缓存
- **异步处理**：大模型推理、复杂知识图谱查询等异步场景使用消息队列

### 1.5 典型业务场景流程

#### 场景1：用户说"我头痛"的完整诊断流程

**步骤1：前端层 → 业务服务层**
```
用户输入："我头痛"
    ↓
前端层：
  - 对话界面接收用户输入
  - 语音识别（如语音输入）
  - 文本理解（提取主诉）
    ↓
业务服务层（诊断服务）：
  - 接收主诉："头痛"
  - 创建诊断记录
  - 启动诊断流程
```

**步骤2：业务服务层 → AI服务层（对话服务）**
```
诊断服务调用对话服务：
    ↓
对话服务：
  - 检查信息完整度（当前：只有主诉，完整度=20%）
  - 识别缺失信息：起病时间、严重度、伴随症状
  - 生成追问问题："头痛持续多久了？"
    ↓
返回给业务服务层：
  - { "question": "头痛持续多久了？", "completeness": 0.2 }
```

**步骤3：用户回答 → 继续追问**
```
用户回答："2天了"
    ↓
业务服务层：
  - 更新诊断记录（起病时间=2天）
  - 检查信息完整度（当前：主诉+起病时间，完整度=40%）
  - 继续追问："疼痛程度0-10分，您打几分？"
    ↓
用户回答："6分"
    ↓
业务服务层：
  - 更新诊断记录（严重度=6分）
  - 检查信息完整度（当前：主诉+起病时间+严重度，完整度=60%）
  - 继续追问："除了头痛，还有没有其他不舒服？"
```

**步骤4：信息足够 → 调用诊断引擎**
```
用户回答："有点头晕"
    ↓
业务服务层：
  - 更新诊断记录（伴随症状=头晕）
  - 检查信息完整度（当前：完整度=70%，达到阈值）
  - 调用诊断引擎服务
    ↓
AI服务层（诊断引擎服务）：
  ├─→ 规则引擎：执行头痛诊断规则
  │     读取：规则库（头痛诊断规则）
  │     返回：{ "possibilities": {"偏头痛": 0.6, "紧张性头痛": 0.5} }
  │
  ├─→ 知识图谱引擎：查询症状-疾病关系
  │     读取：知识图谱（Neo4j）
  │     返回：{ "possibilities": {"偏头痛": 0.65, "紧张性头痛": 0.55} }
  │
  ├─→ 统计模型引擎：基于模型预测
  │     读取：模型库
  │     返回：{ "possibilities": {"偏头痛": 0.7, "紧张性头痛": 0.6} }
  │
  ├─→ 大模型引擎：专业分析
  │     调用：LLM API
  │     返回：{ "possibilities": {"偏头痛": 0.75, "紧张性头痛": 0.65} }
  │
  └─→ 鉴别诊断引擎：区分相似疾病
       读取：鉴别规则库
       返回：{ "differential_points": {...} }
    ↓
融合结果：
  - 加权融合五个引擎的结果
  - 输出Top 3-5可能性列表（代码实现返回Top 5候选，根据可能性筛选Top 3-5展示）
```

**步骤5：业务服务层 → 前端层**
```
业务服务层：
  - 接收诊断引擎结果
  - 生成诊断报告
  - 生成建议检查
  - 生成就医建议
    ↓
前端层展示：
  - 诊断结果卡片："根据您的描述，我考虑以下几个可能的方向"
  - 可能性列表（Top 3-5）
  - 支持证据
  - 建议检查
  - 就医建议
```

#### 场景2：用户上传检查报告的完整流程

**步骤1：用户上传报告**
```
用户上传：血常规检查报告（图片）
```

```java
        DiagnosisRecord record = diagnosisRecordRepository.findById(diagnosisId);
        
        // 2. 调用对话服务，理解用户输入
        UserInputRequest inputRequest = UserInputRequest.builder()
            .diagnosisId(diagnosisId)
            .userInput(answer.getAnswer())
            .context(getContext(diagnosisId))
            .build();
        
        UnderstandingResponse understanding = dialogServiceClient.understand(inputRequest);
        
        // 3. 更新诊断记录（使用对话服务提取的信息）
        updateDiagnosisRecord(record, understanding.getExtractedInfo());
        
        // 4. 调用对话服务，生成下一个问题

            .diagnosisId(diagnosisId)
            .context(buildContext(record, profile))
            .build();
        
        QuestionResponse questionResponse = dialogServiceClient.generateQuestion(questionRequest);
        
        // 5. 如果信息足够，开始分析
        // 信息完整度阈值说明（与系统设计方案保持一致）：
        // - ≥60%：最低要求，可以开始诊断分析
        // - ≥70%：停止追问阈值，达到此阈值后停止追问，开始诊断分析
        // - ≥80%：理想状态，诊断准确性更高
        if (questionResponse.getCompleteness() >= 0.7) {
            return analyze(record, profile);
```

```python
from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from typing import Dict, List
import redis
import json

app = FastAPI()

class DialogService:
    """对话服务"""
    
    def __init__(self):
        self.redis_client = redis.Redis(host='localhost', port=6379, db=0)
        self.nlu = NaturalLanguageUnderstanding()
        self.nlg = NaturalLanguageGenerator()
        self.adaptive_questioning = AdaptiveQuestioningStrategy()
    
    @app.post("/api/v1/dialog/generate-question")
    async def generate_question(self, request: QuestionRequest) -> Dict:
        """生成追问问题"""
        # 1. 获取对话上下文
        context = self.get_context(request.diagnosis_id)
        
        # 2. 分析信息完整度
        completeness = self.calculate_completeness(context)
        
        # 3. 识别缺失信息
        missing_info = self.identify_missing_info(context)
        
        # 4. 生成追问问题
        question = await self.adaptive_questioning.generate_question(
            context=context,
            missing_info=missing_info,
            completeness=completeness
        )
        
        # 5. 转换为自然语言
        natural_question = self.nlg.generate_question(question)
        
        return {
            "question": natural_question,
            "question_type": question["type"],
            "missing_info": missing_info,
            "completeness": completeness
        }
    
    @app.post("/api/v1/dialog/understand")
    async def understand(self, request: UserInputRequest) -> Dict:
        """理解用户输入"""
        # 1. 自然语言理解
        understood_info = await self.nlu.understand(
            text=request.user_input,
            context=request.context
        )
        
        # 2. 提取关键信息
        extracted_info = {
            "symptom_duration": understood_info.get("duration"),
            "symptom_severity": understood_info.get("severity"),
            "accompanying_symptoms": understood_info.get("accompanying"),
            # ...
        }
        
        return {
            "extracted_info": extracted_info,
            "confidence": understood_info.get("confidence", 0.8)
        }
    
    @app.websocket("/ws/dialog/{diagnosis_id}")
    async def websocket_dialog(self, websocket: WebSocket, diagnosis_id: str):
        """WebSocket实时对话"""
        await websocket.accept()
        
        try:
            while True:
                # 接收用户消息
                data = await websocket.receive_text()
                user_input = json.loads(data)
                
                # 理解用户输入
                understood = await self.understand(user_input)
                
                # 更新上下文
                self.update_context(diagnosis_id, understood["extracted_info"])
                
                # 生成回复
                response = await self.generate_response(
                    diagnosis_id=diagnosis_id,
                    user_input=user_input,
                    understood_info=understood
                )
                
                # 发送回复
                await websocket.send_json(response)
                
        except WebSocketDisconnect:
            # 清理上下文
            self.cleanup_context(diagnosis_id)
    
    def get_context(self, diagnosis_id: str) -> Dict:
        """获取对话上下文"""
        context_key = f"dialog:context:{diagnosis_id}"
        context_json = self.redis_client.get(context_key)
        if context_json:
            return json.loads(context_json)
        return {}
    
    def update_context(self, diagnosis_id: str, info: Dict):
        """更新对话上下文"""
        context_key = f"dialog:context:{diagnosis_id}"
        context = self.get_context(diagnosis_id)
        context.update(info)
        self.redis_client.setex(
            context_key,
            1800,  # 30分钟过期
            json.dumps(context)
        )
```

```python
            'kg': 0.25,
            'statistical': 0.20,
            'llm': 0.25,
            'differential': 0.05
```

```python
    def __init__(self):
        self.rules = self._load_rules()
    
    def _load_rules(self) -> List[Dict]:
        """加载规则库"""
        # 从文件或数据库加载规则
        # 规则格式：{symptoms: [...], diseases: {...}, confidence: 0.8}
        pass
    
    async def diagnose(self, request: DiagnosisEngineRequest) -> Dict:
        """规则引擎诊断"""
        symptoms = request.symptom_info.get('symptoms', [])
        vital_signs = request.vital_signs
        
        matches = []
        for rule in self.rules:
            score = self._calculate_match_score(rule, symptoms, vital_signs)
            if score > 0.7:  # 匹配阈值
                matches.append({
                    'disease': rule['disease'],
                    'confidence': score,
                    'supporting_symptoms': rule['symptoms']
                })
        
        return {
            'possibilities': {m['disease']: m['confidence'] for m in matches},
            'engine_type': 'rule'
        }
    
    def _calculate_match_score(self, rule: Dict, symptoms: List, vital_signs: Dict) -> float:
        """计算匹配分数"""
        rule_symptoms = set(rule['symptoms'])
        user_symptoms = set(symptoms)
        
        # 完全匹配
        if rule_symptoms.issubset(user_symptoms):
            return 1.0
        
        # 部分匹配
        intersection = rule_symptoms.intersection(user_symptoms)
        if len(intersection) / len(rule_symptoms) >= 0.7:
            return len(intersection) / len(rule_symptoms)
        
        return 0.0
```

```python
from neo4j import GraphDatabase

class KnowledgeGraphEngine:
    """知识图谱引擎"""
    
    def __init__(self):
        self.driver = GraphDatabase.driver(
            "bolt://neo4j:7687",
            auth=("neo4j", "password")
        )
    
    async def diagnose(self, request: DiagnosisEngineRequest) -> Dict:
        """知识图谱查询"""
        symptoms = request.symptom_info.get('symptoms', [])
        
        query = """
        MATCH (s:Symptom)-[r:CAUSES]->(d:Disease)
        WHERE s.name IN $symptoms
        WITH d, count(r) as symptom_count, avg(r.probability) as avg_prob
        RETURN d.name as disease, d.category, symptom_count, avg_prob
        ORDER BY symptom_count DESC, avg_prob DESC
        LIMIT 5
        """
        
        with self.driver.session() as session:
            result = session.run(query, symptoms=symptoms)
            diseases = {}
            for record in result:
                disease = record['disease']
                confidence = record['avg_prob'] * (record['symptom_count'] / len(symptoms))
                diseases[disease] = confidence
        
        return {
            'possibilities': diseases,
            'engine_type': 'knowledge_graph'
        }
```

```java
@Service
public class CompletenessCalculator {
    
    /**
     * 计算信息完整度
     * 完整度 = (已有信息项数 / 总信息项数) × 100%
     */
    public double calculateCompleteness(StructuredQuestionList questionList) {
        int totalItems = getTotalItemCount();
        int existingItems = countExistingItems(questionList);
        
        double completeness = (double) existingItems / totalItems;
        
        // 检查必填缺口
        InformationGaps gaps = questionList.getInformationGaps();
        if (!gaps.getRequiredGaps().isEmpty()) {
            // 如果有必填缺口，完整度不能超过60%
            completeness = Math.min(completeness, 0.6);
        }
        
        return completeness;
    }
    
    private int getTotalItemCount() {
        // 总信息项包括：
        // - 主要问题（主诉、起病时间、严重度、症状特征）：4项
        // - 伴随问题（关键伴随症状）：1项
        // - 关键背景（年龄、性别、既往史、用药史、家族史）：5项
        // - 生命体征（血压、心率、体温）：3项
        // - 检查结果（如果有）：1项
        return 14;  // 4 + 1 + 5 + 3 + 1
    }
    
    private int countExistingItems(StructuredQuestionList questionList) {
        int count = 0;
        
        // 主要问题计数
        ChiefComplaint chiefComplaint = questionList.getChiefComplaint();
        if (chiefComplaint != null) {
            if (chiefComplaint.getName() != null) count++;
            if (chiefComplaint.getDuration() != null) count++;
            if (chiefComplaint.getSeverity() != null) count++;
            if (chiefComplaint.getFeatures() != null && !chiefComplaint.getFeatures().isEmpty()) count++;
        }
        
        // 伴随问题计数
        if (questionList.getAccompanyingSymptoms() != null && 
            !questionList.getAccompanyingSymptoms().isEmpty()) {
            count++;
        }
        
        // 关键背景计数
        KeyBackground background = questionList.getKeyBackground();
        if (background != null) {
            if (background.getAge() != null) count++;
            if (background.getGender() != null) count++;
            if (background.getMedicalHistory() != null && !background.getMedicalHistory().isEmpty()) count++;
            if (background.getMedicationHistory() != null && !background.getMedicationHistory().isEmpty()) count++;
            if (background.getFamilyHistory() != null && !background.getFamilyHistory().isEmpty()) count++;
        }
        
        // 生命体征计数
        VitalSigns vitalSigns = questionList.getVitalSigns();
        if (vitalSigns != null) {
            if (vitalSigns.getBloodPressure() != null) count++;
            if (vitalSigns.getHeartRate() != null) count++;
            if (vitalSigns.getTemperature() != null) count++;
        }
        
        // 检查结果计数
        if (questionList.getExaminationResults() != null && 
            !questionList.getExaminationResults().isEmpty()) {
            count++;
        }
        
        return count;
    }
```

```python
class AdaptiveQuestioningStrategy:
    """智能追问策略（按信息缺口等级优先级排序）"""
    
    async def generate_question(
        self,
        context: Dict,
        gaps: InformationGaps,
        completeness: float
    ) -> Dict:
        """生成追问问题"""
        
        # 优先级1：必填缺口（必须先补齐）
        if gaps.required_gaps:
            question_type = gaps.required_gaps[0]
            question = self.generate_required_question(question_type, context)
            return {
                "question": question,
                "question_type": question_type,
                "priority": "required",
                "completeness": completeness
            }
        
        # 优先级2：重要缺口（尽量补齐，影响诊断准确性）
        if gaps.important_gaps and completeness < 0.8:
            question_type = gaps.important_gaps[0]
            question = self.generate_important_question(question_type, context)
            return {
                "question": question,
                "question_type": question_type,
                "priority": "important",
                "completeness": completeness
            }
        
        # 优先级3：可选缺口（可后续补充）
        if gaps.optional_gaps and completeness < 0.9:
            question_type = gaps.optional_gaps[0]
            question = self.generate_optional_question(question_type, context)
            return {
                "question": question,
                "question_type": question_type,
                "priority": "optional",
                "completeness": completeness
            }
        
        # 无需继续追问
        return None
```

**技术实现**（在诊断引擎服务中）：
```python
class ThreeLayerClassifier:
    """三层分层分类器"""
    
    def classify(self, engine_results: Dict) -> Dict:
        """将候选疾病分为三层"""
        
        # 1. 获取五引擎融合结果（Top 5候选）
        fused_result = self.fuse_engine_results(engine_results)
        candidates = fused_result.get('possibilities', {})
        
        # 2. 识别高危诊断
        high_risk_diseases = self.identify_high_risk_diseases(candidates)
        
        # 3. 三层分层
        primary_hypothesis = self.select_primary_hypothesis(candidates, high_risk_diseases)
        main_alternatives = self.select_main_alternatives(candidates, primary_hypothesis, high_risk_diseases)
        must_exclude = self.select_must_exclude(candidates, high_risk_diseases)
        
        return {
            "primary_hypothesis": primary_hypothesis,  # 1个
            "main_alternatives": main_alternatives,  # 1-2个
            "must_exclude": must_exclude,  # 0-1个
            "all_candidates": candidates
        }
    
    def identify_high_risk_diseases(self, candidates: Dict) -> List[str]:
        """识别高危诊断（一旦漏诊后果严重）"""
        high_risk_keywords = [
            "心肌梗死", "脑梗死", "肺栓塞", "主动脉夹层",
            "急性心肌梗死", "急性脑梗死", "急性肺栓塞"
        ]
        
        high_risk_diseases = []
        for disease, score in candidates.items():
            for keyword in high_risk_keywords:
                if keyword in disease:
                    high_risk_diseases.append(disease)
                    break
        
        return high_risk_diseases
    
    def select_primary_hypothesis(self, candidates: Dict, high_risk: List[str]) -> Dict:
        """选择首要假设（1个）"""
        # 排除高危诊断（高危诊断单独处理）
        filtered_candidates = {
            d: s for d, s in candidates.items() 
            if d not in high_risk
        }
        
        if not filtered_candidates:
            return None
        
        # 选择可能性最高的
        top_disease = max(filtered_candidates.items(), key=lambda x: x[1])
        return {
            "disease": top_disease[0],
            "score": top_disease[1],
            "layer": "primary_hypothesis"
        }
    
    def select_main_alternatives(self, candidates: Dict, primary: Dict, high_risk: List[str]) -> List[Dict]:
        """选择主要备选诊断（1-2个）"""
        # 排除首要假设和高危诊断
        filtered_candidates = {
            d: s for d, s in candidates.items() 
            if d != primary["disease"] and d not in high_risk
        }
        
        # 选择可能性较高的1-2个
        sorted_candidates = sorted(
            filtered_candidates.items(), 
            key=lambda x: x[1], 
            reverse=True
        )[:2]
        
        return [
            {"disease": d, "score": s, "layer": "main_alternative"}
            for d, s in sorted_candidates
        ]
    
    def select_must_exclude(self, candidates: Dict, high_risk: List[str]) -> Dict:
        """选择必须排除的高危诊断（0-1个）"""
        if not high_risk:
            return None
        
        # 即使可能性不高，也必须纳入并优先排除
        high_risk_candidates = {
            d: s for d, s in candidates.items() 
            if d in high_risk
        }
        
        if not high_risk_candidates:
            return None
        
        # 选择可能性最高的高危诊断（即使不高也要排除）
        top_high_risk = max(high_risk_candidates.items(), key=lambda x: x[1])
        return {
            "disease": top_high_risk[0],
            "score": top_high_risk[1],
            "layer": "must_exclude",
            "reason": "高危诊断，必须排除，即使可能性不高"
        }
```

```python
class EvidenceTracer:
    """证据追踪器（记录每个方向的入选依据）"""
    
    def trace_evidence(self, disease: str, engine_results: Dict) -> Dict:
        """追踪疾病方向的入选依据"""
        evidence = {
            "disease": disease,
            "triggers": [],  # 由问题清单中的哪条线索触发
            "engine_sources": [],  # 对应五引擎中哪个引擎的结果
            "confidence": 0.0
        }
        
        # 追踪每个引擎的结果
        for engine_type, result in engine_results.items():
            if disease in result.get('possibilities', {}):
                score = result['possibilities'][disease]
                evidence["engine_sources"].append({
                    "engine": engine_type,
                    "score": score
                })
                evidence["confidence"] += score * self.get_engine_weight(engine_type)
        
        return evidence
    
    def get_engine_weight(self, engine_type: str) -> float:
        """获取引擎权重"""
        weights = {
            'rule': 0.25,
            'kg': 0.25,
            'statistical': 0.20,
            'llm': 0.25,
            'differential': 0.05
        }
        return weights.get(engine_type, 0.0)
```

```python
class ReasoningGroupOrganizer:
    """推理子组组织器"""
    
    def organize(self, three_layer_result: Dict) -> Dict:
        """组织推理子组"""
        groups = {
            "by_system": {},  # 按系统来源组织（心血管/呼吸/代谢等）
            "by_onset": {},  # 按起病与病程组织（急性/亚急/慢性）
            "by_trigger": {},  # 按诱因与触发场景组织
            "differential_paths": []  # 分流路径
        }
        
        # 按系统来源组织
        all_diseases = (
            [three_layer_result["primary_hypothesis"]] +
            three_layer_result["main_alternatives"] +
            ([three_layer_result["must_exclude"]] if three_layer_result["must_exclude"] else [])
        )
        
        for disease_info in all_diseases:
            if disease_info:
                disease = disease_info["disease"]
                system = self.get_disease_system(disease)
                if system not in groups["by_system"]:
                    groups["by_system"][system] = []
                groups["by_system"][system].append(disease_info)
        
        # 提炼关键差异点
        groups["differential_paths"] = self.build_differential_paths(three_layer_result)
        
        return groups
    
    def build_differential_paths(self, three_layer_result: Dict) -> List[Dict]:
        """构建分流路径"""
        paths = []
        
        primary = three_layer_result["primary_hypothesis"]
        alternatives = three_layer_result["main_alternatives"]
        
        # 为首要假设和主要备选构建分流路径
        if primary and alternatives:
            for alt in alternatives:
                differential_points = self.extract_differential_points(
                    primary["disease"],
                    alt["disease"]
                )
                paths.append({
                    "disease_pair": [primary["disease"], alt["disease"]],
                    "differential_points": differential_points,
                    "priority": "high"
                })
        
        # 高危路径优先
        must_exclude = three_layer_result["must_exclude"]
        if must_exclude:
            paths.insert(0, {
                "disease": must_exclude["disease"],
                "priority": "highest",
                "reason": "高危诊断，必须优先处理"
            })
        
        return paths
```

```java
    private Conclusion buildConclusion(
        ThreeLayerResult threeLayerResult,
        EvidenceAnalysis evidenceAnalysis
    ) {

        PrimaryHypothesis primary = threeLayerResult.getPrimaryHypothesis();
        
        // 判断是否可确证
        boolean canConfirm = canConfirmDiagnosis(primary, evidenceAnalysis);
        
        if (canConfirm) {
            // 可确证终点
            conclusion.setType(ConclusionType.CONFIRMED);
            conclusion.setDiagnosis(primary.getDisease());
            conclusion.setConfidence(primary.getScore());
        } else {
            // 不可确证终点
            conclusion.setType(ConclusionType.PROBABLE);
            conclusion.setDiagnosis(primary.getDisease());
            conclusion.setConfidence(primary.getScore());
            conclusion.setUncertaintyReason(
                "当前证据不足以确证，需要进一步检查"
            );
            conclusion.setReviewWindow("3天后复评");
            conclusion.setUpgradeTriggers(
                Arrays.asList("症状加重", "出现新症状", "检查结果异常")
            );
        }
        
        return conclusion;
    }
    
    private MustExcludeStatus buildMustExcludeStatus(
        MustExcludeDiagnosis mustExclude
    ) {
        if (mustExclude == null) {
            return MustExcludeStatus.builder()
                .status(ExcludeStatus.NONE)
                .build();
        }
        
        MustExcludeStatus status = new MustExcludeStatus();
        
        // 判断是否已排除

        if (excluded) {

                status.setStatus(ExcludeStatus.NEED_OFFLINE_EXCLUDE);

            } else {
                status.setStatus(ExcludeStatus.NOT_EXCLUDED);
                status.setExcludeReason("仍需保留，需要进一步验证");
            }
        }
        
        return status;
```

## 四、诊断引擎详细设计

### 3.1 引擎架构概述

智能诊断系统采用**五引擎融合架构**，五个引擎并行工作，最终融合结果：

```
诊断引擎服务（diagnosis-engine-service）
    ├─→ 引擎1：专科规则引擎（权重25%）
    ├─→ 引擎2：深度知识图谱推理引擎（权重25%）
    ├─→ 引擎3：专科统计模型预测引擎（权重20%）
    ├─→ 引擎4：专业大模型分析引擎（权重25%）
    └─→ 引擎5：鉴别诊断规则引擎（权重5%）
            ↓
        结果融合算法
            ↓
        最终诊断结果（Top 5可能性列表）
```

### 3.2 引擎1：专科规则引擎

#### 3.2.1 职责
- 执行预定义的专科诊断规则（症状组合 → 疾病方向）
- 支持规则版本管理、A/B测试
- 规则优先级调度
- 规则匹配度计算

#### 3.2.2 输入/输出

**输入**：
- 症状信息：主诉、伴随症状、症状特征
- 体征数据：血压、心率、体温等
- 健康档案：年龄、性别、既往史
- 检查结果：异常指标（如有）

**输出**：
- 规则触发结果：匹配的疾病方向及置信度
- 支持证据：哪些症状/体征支持该疾病
- 规则匹配度：0-1之间的分数

#### 3.2.3 核心逻辑

**规则库结构**：
```python
rule = {
    "id": "rule_001",
    "disease": "心绞痛",
    "symptoms": ["胸痛", "气短", "出汗"],
    "vital_signs": {"heart_rate": ">100"},
    "age_range": [40, 80],
    "gender": ["male", "female"],
    "medical_history": ["hypertension"],
    "confidence": 0.8,
    "priority": "high"
}
```

**匹配算法**：
1. **完全匹配**：所有症状都匹配 → 置信度 = 1.0
2. **部分匹配**：70%以上症状匹配 → 置信度 = 匹配度
3. **体征匹配**：体征数据符合规则条件 → 提高置信度
4. **用户画像匹配**：年龄、性别、既往史匹配 → 提高置信度

**规则优先级**：
- **高优先级**：症状组合 + 体征组合 + 用户画像匹配
- **中优先级**：症状组合 + 体征组合
- **低优先级**：单个症状匹配

#### 3.2.4 技术组件
- 规则库（MySQL）：存储诊断规则
- 规则匹配引擎：执行规则匹配算法
- 规则版本管理：支持规则A/B测试、版本回滚

### 3.3 引擎2：深度知识图谱推理引擎

#### 3.3.1 职责
- 基于知识图谱进行深度推理
- 多跳关系查询（症状 → 疾病 → 检查 → 治疗）
- 路径权重计算
- 关系强度评估

#### 3.3.2 输入/输出

**输入**：
- 症状列表：用户描述的症状
- 健康档案：年龄、性别、既往史
- 检查结果：异常指标（如有）

**输出**：
- 疾病可能性列表：基于知识图谱推理的疾病方向
- 推理路径：从症状到疾病的推理路径
- 关系强度：症状-疾病关系的强度

#### 3.3.3 核心逻辑

**知识图谱结构**（Neo4j）：
```
节点类型：
- Symptom（症状）
- Disease（疾病）
- Examination（检查）
- Treatment（治疗）
- Sign（体征）

关系类型：
- CAUSES（引起）：Symptom → Disease
- DIAGNOSES（诊断）：Examination → Disease
- TREATS（治疗）：Treatment → Disease
- INDICATES（指示）：Sign → Disease
```

**推理算法**：
1. **单跳查询**：从症状节点直接找到相关疾病
2. **多跳查询**：通过中间节点（如检查、体征）找到疾病
3. **路径权重计算**：根据路径长度和关系强度计算权重
4. **用户画像过滤**：根据年龄、性别、既往史过滤疾病

**查询示例**：
```cypher
MATCH (s:Symptom)-[r1:CAUSES]->(d:Disease)
WHERE s.name IN $symptoms
WITH d, count(r1) as symptom_count, avg(r1.probability) as avg_prob
MATCH (d)<-[r2:INDICATES]-(sign:Sign)
WHERE sign.name IN $vital_signs
WITH d, symptom_count, avg_prob, count(r2) as sign_count
RETURN d.name as disease, 
       (avg_prob * 0.7 + sign_count * 0.3) as confidence
ORDER BY confidence DESC
LIMIT 5
```

#### 3.3.4 技术组件
- Neo4j图数据库：存储知识图谱
- Cypher查询引擎：执行图查询
- 路径权重计算算法：计算推理路径权重

### 3.7 引擎协作关系

#### 3.7.1 引擎调用链

```
用户输入症状
    ↓
诊断引擎服务接收请求
    ↓
并行执行五个引擎：
    ├─→ 规则引擎（快速，规则匹配）
    ├─→ 知识图谱引擎（中等，图查询）
    ├─→ 统计模型引擎（中等，模型推理）
    ├─→ 大模型引擎（慢速，LLM推理）
    └─→ 鉴别诊断引擎（快速，规则匹配）
    ↓
等待所有引擎完成（或超时）
    ↓
结果融合算法
    ├─→ 加权融合（根据引擎权重）
    ├─→ 冲突解决（不同引擎结果差异大时）
    └─→ 排序输出（Top 5）
    ↓
返回最终诊断结果
```

#### 3.7.2 引擎并行协作

**并行执行策略**：
- 使用 `asyncio.gather()` 并行执行五个引擎
- 设置超时时间（例如：5秒）
- 如果某个引擎超时，使用其他引擎的结果

**冲突解决**：
- 如果不同引擎结果差异很大，降低置信度
- 如果多个引擎指向同一方向，提高置信度
- 如果规则引擎匹配度很高（> 0.8），优先使用规则引擎结果

### 3.8 结果融合算法

#### 3.8.1 加权融合公式

```python
最终可能性分数 = 
    规则引擎分数 × 0.25 +
    知识图谱分数 × 0.25 +
    统计模型分数 × 0.20 +
    大模型分数 × 0.25 +
    鉴别诊断分数 × 0.05
```

#### 3.8.2 融合逻辑

```python
def fuse_results(engine_results):
    weights = {
        'rule': 0.25,
        'kg': 0.25,
        'statistical': 0.20,
        'llm': 0.25,
        'differential': 0.05
    }
    
    fused = {}
    for engine_type, result in engine_results.items():
        if result is None or isinstance(result, Exception):
            continue
        weight = weights[engine_type]
        for disease, score in result.get('possibilities', {}).items():
            if disease not in fused:
                fused[disease] = 0
            fused[disease] += score * weight
    
    # 排序，返回Top 5（作为候选，最终展示Top 3-5，与系统设计方案保持一致）
    sorted_diseases = sorted(fused.items(), key=lambda x: x[1], reverse=True)[:5]
    return dict(sorted_diseases)
```

## 五、主动对话实现（技术实现）

### 5.1 智能追问实现

**复用智能家庭医生的自适应追问能力**：

```python
from core.dialogue.adaptive_questioning import AdaptiveQuestioningStrategy

class DiagnosisDialogueService:
    """诊断对话服务（像医生一样）"""
    
    def __init__(self):
        self.adaptive_questioning = AdaptiveQuestioningStrategy()
        self.nlg = NaturalLanguageGenerator()
    
    async def start_diagnosis_dialogue(self, user_id: str, initial_symptom: str) -> Dict:
        """开始诊断对话"""
        # 1. 创建诊断记录
        diagnosis_record = self.create_diagnosis_record(user_id)
        
        # 2. 收集初始症状
        self.collect_symptom(diagnosis_record, initial_symptom)
        
        # 3. 检查信息完整度
        completeness = self.calculate_completeness(diagnosis_record)
        
        # 4. 如果信息不足，主动追问
        if completeness < 0.7:
            context = self.build_context(diagnosis_record)
            questioning_result = await self.adaptive_questioning.should_ask_follow_up(
                context, ""
            )
            
            if questioning_result.get("should_ask"):
                follow_up_question = questioning_result.get("question")
                # 转换为自然语言
                natural_question = self.nlg.generate_question(
                    questioning_result.get("missing_info_type")
                )
                
                return {
                    "status": "collecting",
                    "diagnosis_id": diagnosis_record.id,
                    "question": natural_question,
                    "completeness": completeness
                }
        
        # 5. 信息足够，开始分析
        return await self.analyze(diagnosis_record)
    
    async def continue_dialogue(self, diagnosis_id: str, user_answer: str) -> Dict:
        """继续对话，收集用户回答"""
        # 1. 获取诊断记录
        diagnosis_record = self.get_diagnosis_record(diagnosis_id)
        
        # 2. 提取信息（从用户回答中提取）
        extracted_info = self.extract_info_from_answer(user_answer)
        
        # 3. 更新诊断记录
        self.update_diagnosis_record(diagnosis_record, extracted_info)
        
        # 4. 检查信息完整度
        completeness = self.calculate_completeness(diagnosis_record)
        
        # 5. 如果信息足够，开始分析
        # 信息完整度阈值说明（与系统设计方案保持一致）：
        # - ≥60%：最低要求，可以开始诊断分析
        # - ≥70%：停止追问阈值，达到此阈值后停止追问，开始诊断分析
        # - ≥80%：理想状态，诊断准确性更高
        if completeness >= 0.7:
            return await self.analyze(diagnosis_record)
        
        # 6. 如果信息不足，继续追问
        context = self.build_context(diagnosis_record)
        questioning_result = await self.adaptive_questioning.should_ask_follow_up(
            context, user_answer
        )
        
        if questioning_result.get("should_ask"):
            follow_up_question = questioning_result.get("question")
            natural_question = self.nlg.generate_question(
                questioning_result.get("missing_info_type")
            )
            
            return {
                "status": "collecting",
                "diagnosis_id": diagnosis_record.id,
                "question": natural_question,
                "completeness": completeness
            }
        
        # 7. 信息足够或追问次数超限，开始分析
        return await self.analyze(diagnosis_record)
```

```python
class NaturalLanguageGenerator:
    """自然语言生成器（像医生一样说话）"""
    
    def generate_question(self, missing_info_type: str) -> str:
        """生成追问问题（像医生一样）"""
        questions = {
            "duration": "您这个症状出现多久了？",
            "severity": "症状严重程度如何？0-10分打几分？",
            "frequency": "症状是持续的还是阵发性的？",
            "location": "症状具体在哪个位置？",
            "trigger": "什么情况下出现的？",
            "accompanying": "除了这个症状，还有没有其他不舒服？",
            "history": "您之前有没有类似的症状？",
            "medication": "您最近有没有吃什么药？"
        }
        return questions.get(missing_info_type, "能详细描述一下吗？")
    
    def generate_diagnosis_explanation(self, diagnosis_result: Dict) -> str:
        """生成诊断解释（像医生一样）"""
        possibilities = diagnosis_result.get("possibilities", [])
        
        explanation = "根据您的描述和健康档案，我考虑以下几个可能的方向：\n\n"
        
        for i, possibility in enumerate(possibilities[:3], 1):
            disease = possibility.get("disease")
            confidence = possibility.get("confidence")
            evidence = possibility.get("supporting_evidence", [])
            
            # 像医生一样解释
            if confidence >= 0.7:
                level = "可能性较高"
            elif confidence >= 0.5:
                level = "可能性中等"
            else:
                level = "可能性较低"
            
            explanation += f"{i}. {disease}（{level}）\n"
            explanation += f"   - 支持证据：{', '.join(evidence)}\n\n"
        
        explanation += "建议您进一步检查确认。"
        
        return explanation
```

## 十、性能优化

### 8.1 缓存策略

**缓存内容**：
- 健康档案数据（用户信息变化不频繁）
- 基线数据（计算成本高）
- 常见症状组合的诊断结果（规则匹配结果）
- 知识图谱查询结果（症状-疾病关系）

**缓存更新**：
- 健康档案更新时，清除相关缓存
- 诊断规则更新时，清除规则匹配缓存
- 设置缓存过期时间（例如：24小时）

### 8.2 异步处理

**异步任务**：
- 大模型分析（耗时较长，可以异步）
- 知识图谱查询（如果查询复杂）
- 统计模型预测（如果模型较大）

**用户体验**：
- 先返回快速结果（规则引擎、简单知识图谱查询）
- 异步获取大模型结果后，更新诊断结果
- 通过WebSocket推送更新

### 8.3 结果分级

**快速路径**：
- 如果规则引擎匹配度高（> 0.8），直接返回规则引擎结果
- 跳过其他引擎，减少计算时间

**完整路径**：
- 如果规则引擎匹配度不高，走完整的多引擎融合流程

### 10.2 典型协作场景

#### 场景1：症状评估完成后触发诊断

**协作流程**：
```
1. 用户在智能家庭医生模块描述症状："我头痛"
   ↓
2. 智能家庭医生模块（模块4：症状评估与分诊）：
   - 执行分诊评估
   - 输出分诊等级：L3（非急）
   - 症状信息完整度：60%
   ↓
3. 智能诊断系统检测到触发条件：
   - 分诊等级：L3（非急）✅
   - 症状信息足够：≥3个关键信息 ✅
   - 健康档案完整度：> 60% ✅
   ↓
4. 自动触发诊断：
   - 调用诊断服务：POST /api/diagnosis/start
   - 传递症状信息、健康档案
   ↓
5. 智能诊断系统执行诊断：
   - 主动追问补充信息
   - 调用诊断引擎
   - 生成诊断结果
   ↓
6. 返回诊断结果给智能家庭医生模块：
   - 可能性列表
   - 建议检查
   - 就医建议
   ↓
7. 智能家庭医生模块整合结果：
   - 展示分诊结果 + 诊断结果
   - 生成行动清单
```

**技术实现**：
```java
// 智能家庭医生模块完成分诊后
@Service
public class SymptomAssessmentService {
    
    @Autowired
    private DiagnosisServiceClient diagnosisServiceClient;
    
    public AssessmentResult completeAssessment(AssessmentRequest request) {
        // 1. 执行分诊评估
        TriageResult triageResult = performTriage(request);
        
        // 2. 检查是否触发诊断
        if (shouldTriggerDiagnosis(triageResult)) {
            // 3. 调用智能诊断系统
            DiagnosisRequest diagnosisRequest = DiagnosisRequest.builder()
                .userId(request.getUserId())
                .symptomInfo(triageResult.getSymptomInfo())
                .healthProfile(getHealthProfile(request.getUserId()))
                .build();
            
            DiagnosisResult diagnosisResult = diagnosisServiceClient
                .startDiagnosis(diagnosisRequest);
            
            // 4. 整合结果
            return AssessmentResult.builder()
                .triageResult(triageResult)
                .diagnosisResult(diagnosisResult)
                .build();
        }
        
        return AssessmentResult.builder()
            .triageResult(triageResult)
            .build();
    }
    
    private boolean shouldTriggerDiagnosis(TriageResult triageResult) {
        // 触发条件：
        // 1. 分诊等级L3或L4
        // 2. 症状信息足够（≥3个关键信息）
        // 3. 健康档案完整度 > 60%
        return (triageResult.getLevel() == TriageLevel.L3 || 
                triageResult.getLevel() == TriageLevel.L4) &&
               triageResult.getSymptomInfoCount() >= 3 &&
               getHealthProfileCompleteness(triageResult.getUserId()) > 0.6;
    }
}
```

#### 场景2：诊断时获取健康档案

**协作流程**：
```
1. 智能诊断系统开始诊断
   ↓
2. 调用健康中心模块获取健康档案：
   - GET /api/profile/{userId}
   ↓
3. 健康中心模块返回：
   - 基本信息：年龄、性别、身高、体重
   - 既往史：慢病、手术史
   - 用药史：当前用药、过敏史
   - 家族史：遗传性疾病
   ↓
4. 智能诊断系统使用健康档案：
   - 诊断引擎考虑用户画像
   - 规则引擎匹配年龄、性别、既往史
   - 知识图谱过滤不符合用户画像的疾病
   ↓
5. 生成个性化诊断结果
```

**技术实现**：
```java
// 智能诊断系统获取健康档案
@Service
public class DiagnosisService {
    
    @Autowired
    @FeignClient(name = "health-center-service")
    private HealthCenterService healthCenterService;
    
    public DiagnosisResponse startDiagnosis(DiagnosisRequest request) {
        // 1. 获取健康档案
        HealthProfile profile = healthCenterService.getHealthProfile(
            request.getUserId()
        );
        
        // 2. 创建诊断记录
        DiagnosisRecord record = createDiagnosisRecord(request, profile);
        
        // 3. 调用诊断引擎（传递健康档案）
        DiagnosisEngineRequest engineRequest = DiagnosisEngineRequest.builder()
            .symptomInfo(record.getSymptomInfo())
            .healthProfile(profile)  // 传递健康档案
            .build();
        
        DiagnosisEngineResult engineResult = diagnosisEngineService
            .diagnose(engineRequest);
        
        // 4. 保存诊断结果
        record.setDiagnosisResult(engineResult);
        diagnosisRecordRepository.save(record);
        
        // 5. 更新健康档案（同步诊断记录）
        healthCenterService.updateDiagnosisRecord(
            request.getUserId(),
            record.getId()
        );
        
        return DiagnosisResponse.builder()
            .diagnosisId(record.getId())
            .result(engineResult)
            .build();
    }
}
```

### 11.1 数据存储结构

#### 11.1.1 诊断记录库

**诊断记录表（diagnosis_record）**：
- **用途**：存储诊断记录和诊断结果

  * 症状信息：chief_complaint、symptom_duration、symptom_severity等
  * 体征数据：vital_signs（JSONB）
  * 检查结果：examination_results（JSONB）
  * 诊断结果：diagnosis_result（JSONB）
  * 对话记录：dialogue_history（JSONB）
  * 元数据：created_at、updated_at、completed_at

**检查记录表（examination_record）**：
- **用途**：存储检查报告和解读结果
- **字段**：
  * 基本信息：id、user_id、family_id、examination_type
  * 检查方案：plan_id、plan_name、plan_items（JSONB）
  * 报告信息：report_type、report_file_path、report_ocr_result（JSONB）
  * 解读结果：interpretation_result（JSONB）

**检查方案表（examination_plan）**：
- **用途**：存储检查方案设计
- **字段**：
  * 基本信息：id、user_id、plan_name、plan_type
  * 方案内容：plan_items（JSONB）、target_conditions（JSONB）
  * 元数据：created_at、updated_at

#### 11.1.2 知识库

**规则库（diagnosis_rules）**：
- **用途**：存储诊断规则
- **字段**：
  * 规则信息：id、disease、symptoms（JSONB）、vital_signs（JSONB）
  * 规则条件：age_range、gender、medical_history（JSONB）
  * 规则属性：confidence、priority、version
  * 元数据：created_at、updated_at

**知识图谱（Neo4j）**：
- **节点类型**：Symptom、Disease、Examination、Treatment、Sign
- **关系类型**：CAUSES、DIAGNOSES、TREATS、INDICATES
- **属性**：name、category、probability等

**鉴别规则库（differential_rules）**：
- **用途**：存储鉴别诊断规则
- **字段**：
  * 疾病对：disease_pair（JSONB）
  * 鉴别要点：key_points（JSONB）
  * 元数据：created_at、updated_at

#### 11.1.3 模型库

**模型文件存储**：
- **位置**：对象存储（MinIO/OSS/COS）或文件系统
- **模型类型**：
  * 统计模型：XGBoost、LightGBM模型文件（.pkl/.joblib）
  * 深度学习模型：TensorFlow/PyTorch模型文件
- **版本管理**：模型版本号、训练时间、训练数据版本

**模型元数据表（model_metadata）**：
- **用途**：存储模型元数据
- **字段**：
  * 模型信息：id、model_name、model_type、model_version
  * 模型文件：model_file_path、model_file_size
  * 训练信息：training_date、training_data_version、accuracy
  * 元数据：created_at、updated_at

#### 11.1.4 缓存库（Redis）

**缓存内容**：
- 健康档案缓存（key: `profile:{userId}`, TTL: 24小时）
- 规则库缓存（key: `rules:{ruleId}`, TTL: 1小时）
- 知识图谱查询结果缓存（key: `kg:{query_hash}`, TTL: 1小时）
- 常见症状组合的诊断结果缓存（key: `diagnosis:{symptoms_hash}`, TTL: 6小时）
- 会话状态缓存（key: `session:{sessionId}`, TTL: 30分钟）

### 11.2 数据流向总结

**数据自下而上流动**：
```
用户输入（症状描述/报告上传）
    ↓ 数据采集
数据层（Oracle/Neo4j/Redis）
    ↓ 数据读取
AI服务层（诊断引擎、OCR服务）
    ↓ 计算结果
业务服务层（诊断服务、检查服务）
    ↓ 业务处理
前端层（展示结果）
```

**数据共享机制**：
- **健康档案共享**：智能诊断系统读取健康中心模块的健康档案数据
- **诊断结果共享**：智能诊断系统的诊断结果同步到健康中心模块
- **症状信息共享**：智能家庭医生模块的症状评估结果传递给智能诊断系统

## 十五、KPI与护栏

### 13.1 北极星指标

- **诊断有用性**：用户对诊断结果的满意度评分（目标：> 4.0/5.0）

**用户体验指标**：
- **诊断完成率**：开始诊断到完成诊断的用户比例（目标：> 80%）
