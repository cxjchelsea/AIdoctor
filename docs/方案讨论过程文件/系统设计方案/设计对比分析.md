# AI医生系统设计对比分析

> **文档定位**：本文档对比分析三个设计方案的异同点、优缺点，以及如何融合。  
> **对比对象**：
> 1. 智能诊断A路径：AI循证诊断流程（原有设计）
> 2. 智能诊断系统-系统设计方案（原有设计）
> 3. AI医生系统-系统功能设计（基于DR.KNOWS的新设计）

---

## 一、设计理念对比

### 1.1 核心定位对比

| 维度 | 智能诊断A路径 | 智能诊断系统 | AI医生系统（新设计） |
|------|-------------|------------|-------------------|
| **定位** | AI循证诊断流程 | 医学判断引擎 | 完整的AI医生能力 |
| **核心问题** | 如何诊断疾病 | "是不是病？是否安全？" | "这个人需要被当成病人对待吗？" |
| **面向对象** | 默认有病的患者 | 有病+没病的人 | 健康状态不确定的人 |
| **第一职责** | 诊断疾病 | 医学判断 | 判断要不要下诊断 |

### 1.2 设计原则对比

**智能诊断A路径**：
- 核心：5步循证诊断流程（识别问题→构建候选集→组织分流→采集证据→回填输出）
- 特点：流程化、结构化、可审计
- 假设：用户是患者，需要诊断

**智能诊断系统**：
- 核心：医学判断引擎，回答"是不是病？是否安全？"
- 特点：像医生一样主动对话、专业分析
- 假设：用户可能是患者，也可能不是

**AI医生系统（新设计）**：
- 核心：健康状态判定 → 分叉 → 两种工作态
- 特点：从"健康状态不确定"出发，先判断是否需要进入诊疗流程
- 假设：用户是"健康状态不确定"的人，不是默认的患者

## 二、流程设计对比

### 2.1 流程步骤对比

#### 智能诊断A路径（5步流程）

```
Step 1: 识别问题
  → 概念归一化、形成问题清单、标记信息缺口

Step 2: 构建鉴别诊断候选集并分层
  → 生成候选集、三层分层（首要假设/主要备选/必须排除）

Step 3: 组织候选集并建立分流路径
  → 组织推理子组、提炼关键差异点、形成分流问题清单

Step 4: 采集关键证据并形成排序与验证计划
  → 采集证据、固化三层排序、制定验证计划

Step 5: 回填证据并输出终点结论包
  → 证据回填、更新排序、输出结论包
```

#### 智能诊断系统（5阶段流程）

```
阶段1: 主动询问
  → 形成结构化问题清单、标记信息缺口

阶段2: 信息补全
  → 智能追问、数据冲突检测

阶段3: 可能性分析
  → 五引擎融合、三层分层

阶段4: 鉴别诊断
  → 组织推理结构、采集关键证据、形成三层排序

阶段4.5: 疾病状态判断（关键节点）
  → 判断是否有病 → 分叉到有病/没病/不确定路径

阶段5: 结果输出
  → 根据路径输出不同的结论包（诊断/排除/检查）
```

#### AI医生系统（新设计，8工具流程）

```
阶段0: 健康状态判定（工具0）
  → 判断是否需要进入诊疗流程 → 分叉

    ├─ 健康管理态（wellness_mode）
    │   → 工具A：病例理解
    │   → 生成健康管理计划
    │   → 持续监控、动态升级
    │
    └─ 临床诊疗态（clinical_mode）
        → 工具A：病例理解
        → 工具B：主动问诊
        → 工具C：鉴别诊断
        → 工具D：检查建议
        → 工具E：治疗建议
        → 工具F：风险评估
        → 工具G：证据链
```

### 2.2 关键差异点

| 维度 | 智能诊断A路径 | 智能诊断系统 | AI医生系统（新设计） |
|------|-------------|------------|-------------------|
| **流程起点** | 识别问题（默认患者） | 主动询问（可能患者） | 健康状态判定（不确定） |
| **分叉点** | 无分叉，直接诊断 | 阶段4.5分叉（有病/没病/不确定） | 阶段0分叉（健康管理态/临床诊疗态） |
| **"没病"处理** | 无明确处理 | 阶段4.5的"没病路径" | 健康管理态（完整流程） |
| **流程步骤** | 5步（固定） | 5阶段+1分叉节点 | 8工具（模块化） |

## 三、数据结构对比

### 3.1 核心数据结构

#### 智能诊断A路径
- **问题清单**：结构化问题清单（主要问题、伴随问题、关键背景、信息缺口）
- **鉴别诊断分层清单**：三层分层（首要假设/主要备选/必须排除）
- **证据清单**：结构化证据（证据项、来源、方向、影响对象）
- **终点结论包**：四要素（结论、必须排除项状态、关键依据、行动与随访）

**特点**：流程化数据结构，每个步骤有明确的输入输出

#### 智能诊断系统
- **诊断记录**：诊断记录表（symptom、vital_signs、examination_results、diagnosis_result）
- **三层排序**：最可能方向、必须排除方向、积极备选方向
- **结论包**：根据路径不同（诊断结论包/排除结论包/检查结论包）

**特点**：数据库表结构，面向存储和查询

#### AI医生系统（新设计）
- **CDP（Clinical Decision Package）**：统一的核心数据结构
  - `health_state_assessment`：健康状态判定
  - `wellness_plan`：健康管理计划
  - `patient_state`：患者状态
  - `ddx`：鉴别诊断列表
  - `evidence_graph`：证据图
  - `workup_plan`：检查计划
  - `management_plan`：治疗方案
  - `triage`：风险评估
  - `uncertainty`：不确定性
  - `audit`：审计信息

**特点**：统一的数据中心，所有推理围绕CDP，支持可回放、可追溯

### 3.2 数据结构对比表

| 维度 | 智能诊断A路径 | 智能诊断系统 | AI医生系统（新设计） |
|------|-------------|------------|-------------------|
| **数据结构** | 流程化数据结构（问题清单、证据清单等） | 数据库表结构 | CDP统一数据结构 |
| **数据流转** | 步骤间传递 | 数据库存储 | CDP读/写操作 |
| **可追溯性** | 流程可追溯 | 记录可查询 | CDP版本管理、可回放 |
| **支持"没病"** | 无 | 排除结论包 | wellness_plan字段 |

## 五、技术架构对比

### 5.1 推理架构对比

#### 智能诊断A路径
- **架构**：流程化架构，5步顺序执行
- **推理方式**：规则+知识图谱（未明确多引擎融合）
- **特点**：结构化、可审计

#### 智能诊断系统
- **架构**：五引擎融合架构
  - 规则引擎（25%）
  - 知识图谱引擎（25%）
  - 统计模型引擎（20%）
  - 大模型引擎（25%）
  - 鉴别诊断引擎（5%）
- **特点**：多引擎融合，权重可调

#### AI医生系统（新设计）
- **架构**：双通道推理架构
  - **通道1：结构化推理通道**（决定"该往哪想"）
    - 规则引擎
    - 知识图谱引擎（DR.KNOWS方法）
    - 统计模型引擎
    - 大模型引擎（路径约束）
    - 鉴别诊断引擎
  - **通道2：语言与策略通道**（决定"怎么说、怎么问"）
    - 问诊对话生成
    - 解释与沟通
    - 生成处置方案
- **特点**：职责清晰，结构化推理与语言表达分离

### 5.2 知识图谱使用对比

| 维度 | 智能诊断A路径 | 智能诊断系统 | AI医生系统（新设计） |
|------|-------------|------------|-------------------|
| **知识图谱** | 未明确说明 | Neo4j知识图谱 | Neo4j + DR.KNOWS方法 |
| **路径检索** | 未明确 | 症状→疾病路径 | 多跳推理路径检索（DR.KNOWS） |
| **路径评分** | 未明确 | 未明确 | 三层评分体系（相关性+证据强度+信息增益） |
| **路径注入LLM** | 未明确 | 未明确 | ✅ 路径注入LLM（DR.KNOWS核心） |

## 六、关键创新点对比

### 6.1 智能诊断A路径的创新点

1. **5步循证诊断流程**：结构化、可审计的诊断流程
2. **三层分层**：首要假设/主要备选/必须排除
3. **分流路径设计**：组织推理子组，提炼关键差异点
4. **验证计划**：查不查、查什么、怎么判定

**优势**：
- 流程清晰，易于理解和实现
- 结构化程度高，可审计性强
- 符合临床思维

**局限**：
- 默认用户是患者，没有"健康状态判定"
- 没有明确的多引擎融合
- 没有统一的数据结构（CDP）

### 6.2 智能诊断系统的创新点

1. **疾病状态判断（阶段4.5）**：判断是否有病，分叉到不同路径
2. **五引擎融合**：规则+知识图谱+统计模型+大模型+鉴别诊断
3. **三种结论包**：诊断结论包/排除结论包/检查结论包
4. **像医生一样的对话**：主动询问、自然语言、智能追问

**优势**：
- 考虑了"没病的人"的处理
- 多引擎融合，准确性更高
- 对话体验好

**局限**：
- 疾病状态判断在流程后期（阶段4.5），应该在更早
- 没有统一的数据结构（CDP）
- 没有明确的知识图谱路径推理

### 6.3 AI医生系统（新设计）的创新点

1. **健康状态判定（阶段0）**：医生的第一职责，关键分叉点
2. **两种工作态**：健康管理态 + 临床诊疗态
3. **CDP核心数据结构**：统一的数据中心，支持可回放、可追溯
4. **双通道推理架构**：结构化推理 + 语言表达
5. **DR.KNOWS方法**：知识图谱路径推理 + 路径注入LLM
6. **三层评分体系**：路径相关性 + 证据强度 + 信息增益
7. **八大临床工具**：模块化设计，每个工具可独立训练和评测

**优势**：
- 真正的医生视角：从"健康状态不确定"出发
- 架构清晰：双通道、模块化
- 可追溯性强：CDP版本管理
- 技术先进：DR.KNOWS方法

**局限**：
- 设计复杂度较高
- 需要更多技术实现工作

```
  │   └─ 鉴别诊断引擎

  ├─ 三层分层（智能诊断A路径 + 智能诊断系统）
  │   ├─ 首要假设
  │   ├─ 主要备选
  │   └─ 必须排除
  │
  └─ 分流路径设计（智能诊断A路径）
      ├─ 组织推理子组
      ├─ 提炼关键差异点
      └─ 形成分流问题清单

通道2：语言与策略通道
  ├─ 问诊对话生成（智能诊断系统）
  ├─ 解释与沟通（智能诊断系统）
  └─ 生成处置方案（智能诊断系统）
```

## 八、优势互补分析

### 8.1 智能诊断A路径的优势

1. **流程清晰**：5步流程，易于理解和实现
2. **结构化程度高**：每个步骤有明确的输入输出
3. **分流路径设计**：组织推理子组，提炼关键差异点
4. **验证计划**：查不查、查什么、怎么判定

**可借鉴**：
- 分流路径设计方法
- 验证计划的制定规则
- 推理子组的组织方式

### 8.2 智能诊断系统的优势

1. **五引擎融合**：多引擎融合，准确性更高
2. **疾病状态判断**：考虑了"没病的人"的处理
3. **对话体验**：像医生一样的对话
4. **三种结论包**：根据路径输出不同的结论包

**可借鉴**：
- 五引擎融合的权重设计
- 疾病状态判断的逻辑（但应该在更早）
- 对话体验的设计

### 8.3 AI医生系统（新设计）的优势

1. **健康状态判定**：医生的第一职责，关键分叉点
2. **CDP数据结构**：统一的数据中心，支持可回放
3. **双通道架构**：职责清晰
4. **DR.KNOWS方法**：知识图谱路径推理

**可借鉴**：
- 健康状态判定的设计理念
- CDP数据结构的设计
- 双通道架构的设计

## 十、总结

### 10.1 三个设计的核心特点

| 设计 | 核心特点 | 适用场景 |
|------|---------|---------|
| **智能诊断A路径** | 5步循证诊断流程，结构化、可审计 | 需要结构化诊断流程的场景 |
| **智能诊断系统** | 医学判断引擎，五引擎融合，考虑"没病的人" | 需要专业诊断分析的场景 |
| **AI医生系统（新设计）** | 完整的AI医生能力，健康状态判定，CDP数据结构 | 需要完整医生能力的场景 |

### 10.2 融合建议

**推荐采用AI医生系统（新设计）作为主架构**，原因：

1. **最符合"定位.md"的理念**：从"健康状态不确定"出发，先判断是否需要进入诊疗流程
2. **技术最先进**：DR.KNOWS方法、双通道架构、三层评分体系
3. **数据结构最完善**：CDP统一数据结构，支持可回放、可追溯
4. **功能最完整**：八大临床工具，覆盖完整的医生能力

**融合其他两个设计的优点**：

1. **智能诊断A路径**：分流路径设计、验证计划、推理子组组织
2. **智能诊断系统**：五引擎融合、疾病状态判断逻辑、对话体验

### 10.3 实施建议

1. **第一阶段**：实现AI医生系统的核心架构（健康状态判定、CDP、双通道）
2. **第二阶段**：融合智能诊断A路径的分流路径设计
3. **第三阶段**：融合智能诊断系统的五引擎融合
4. **第四阶段**：优化和迭代
