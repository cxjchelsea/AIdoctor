## 系统架构

```
业务服务
  ├── 日志输出 → logs/app.log（文件）
  └── Promtail → Loki → Grafana（日志查看）
```

### 组件说明

- **业务服务**：输出日志到文件（`logs/app.log`）
- **Promtail**：收集日志文件，发送到Loki
- **Loki**：日志聚合和存储系统
- **Grafana**：可视化查看日志（复用已有的Grafana）

## 日志文件位置

### Python服务

所有Python服务的日志文件位于：
```
{服务目录}/logs/app.log
```

例如：
- `health-state-assessment-service/logs/app.log`
- `diagnosis-engine-service/logs/app.log`
- `clinical-parsing-service/logs/app.log`
- 等等...

### Java服务

所有Java服务的日志文件位于：
```
{服务目录}/logs/app.log
```

例如：
- `diagnosis-service/logs/app.log`
- `examination-service/logs/app.log`
- `execution-trace-service/logs/app.log`

### 日志轮转

- **最大文件大小**：10MB
- **备份文件数**：5个
- **自动轮转**：文件达到10MB时自动创建新文件

## 启动日志系统

### 1. 启动所有服务

确保所有业务服务已启动，并开始生成日志文件。

### 2. 启动监控服务（包含Loki和Promtail）

```bash
cd monitoring
docker-compose up -d
```

这将启动：
- Prometheus（指标监控）
- Loki（日志聚合）
- Promtail（日志收集）
- Grafana（可视化）

### 3. 验证日志收集

```bash
# 查看Promtail日志
docker logs promtail

# 查看Loki日志
docker logs loki

# 检查Promtail是否正在收集日志
docker exec promtail wc -l /var/log/aidoctor/*/logs/*.log
```

## 在Grafana中查看日志

### 1. 添加Loki数据源

1. 登录Grafana: http://localhost:3001
2. 进入 **Configuration** -> **Data Sources**
3. 点击 **Add data source**
4. 选择 **Loki**
5. 配置：
   - **URL**: `http://loki:3100`
   - **Access**: Server (default)
6. 点击 **Save & Test**

### 2. 查看日志

1. 进入 **Explore**（左侧菜单）
2. 选择 **Loki** 数据源
3. 在查询框中输入LogQL查询（见下方）
4. 点击 **Run query**

### 3. 常用查询

#### 查看所有日志

```logql
{job=~".+"}
```

#### 查看特定服务的日志

```logql
{service="diagnosis-engine"}
```

#### 查看错误日志

```logql
{job=~".+"} |= "ERROR"
```

#### 查看特定时间段的日志

```logql
{job=~".+"} [5m]
```

#### 按服务过滤

```logql
{service="diagnosis-engine"} |= "诊断失败"
```

## 日志查询语法

### LogQL基础语法

#### 标签选择器

```logql
# 选择特定服务
{service="diagnosis-engine"}

# 选择多个服务
{service=~"diagnosis-engine|health-state-assessment"}

# 选择所有Python服务
{language="python"}

# 选择所有Java服务
{language="java"}
```

#### 过滤器

```logql
# 包含特定文本
{job=~".+"} |= "ERROR"

# 不包含特定文本
{job=~".+"} != "DEBUG"

# 正则匹配
{job=~".+"} |~ "error|exception"

# 不匹配正则
{job=~".+"} !~ "debug|trace"
```

#### 时间范围

```logql
# 最近5分钟
{job=~".+"} [5m]

# 最近1小时
{job=~".+"} [1h]

# 最近24小时
{job=~".+"} [24h]
```

### 高级查询

#### 统计错误数量

```logql
sum(count_over_time({job=~".+"} |= "ERROR" [5m]))
```

#### 按服务统计日志行数

```logql
sum by (service) (count_over_time({job=~".+"} [5m]))
```

## 常见问题

### 1. Promtail无法收集日志

**症状**：Grafana中看不到日志

**排查步骤**：

1. **检查日志文件是否存在**：
   ```bash
   ls -la health-state-assessment-service/logs/app.log
   ```

2. **检查Promtail配置**：
   ```bash
   docker exec promtail cat /etc/promtail/config.yml
   ```

3. **检查Promtail日志**：
   ```bash
   docker logs promtail
   ```

4. **检查文件权限**：
   - 确保日志文件可读
   - 确保Promtail有权限访问日志目录

5. **Windows路径问题**：
   - 如果使用Windows，可能需要调整docker-compose.yml中的路径映射
   - 使用绝对路径：`E:/pycharmProject/AIdoctor/health-state-assessment-service/logs:/var/log/aidoctor/health-state-assessment-service/logs:ro`

### 2. Loki无法接收日志

**症状**：Promtail日志显示连接失败

**排查步骤**：

1. **检查Loki是否运行**：
   ```bash
   docker ps | grep loki
   ```

2. **检查Loki日志**：
   ```bash
   docker logs loki
   ```

3. **检查网络连接**：
   - 确保Promtail和Loki在同一网络中
   - 检查docker-compose.yml中的网络配置

### 3. Grafana无法连接Loki

**症状**：Grafana显示"Data source is not working"

**排查步骤**：

1. **检查Loki URL**：
   - 在Grafana中，数据源URL应为：`http://loki:3100`
   - 不要使用`localhost`，因为Grafana在Docker容器中

2. **测试连接**：
   - 在Grafana数据源配置页面点击"Save & Test"
   - 查看错误信息

3. **检查网络**：
   - 确保Grafana和Loki在同一网络中

### 4. 日志文件路径问题（Windows）

**问题**：Windows下Docker路径映射可能失败

**解决方案**：

1. **使用绝对路径**：
   修改`docker-compose.yml`中的volumes配置，使用绝对路径：
   ```yaml
   volumes:
     - E:/pycharmProject/AIdoctor/health-state-assessment-service/logs:/var/log/aidoctor/health-state-assessment-service/logs:ro
   ```

2. **使用Docker Desktop设置**：
   - 在Docker Desktop中，Settings -> Resources -> File Sharing
   - 添加项目目录到共享列表

3. **使用符号链接**：
   - 创建符号链接到统一目录
   - 在docker-compose中挂载统一目录

### 5. 日志文件过大

**问题**：日志文件占用磁盘空间过大

**解决方案**：

1. **调整日志级别**：
   - 将日志级别从DEBUG改为INFO
   - 减少不必要的日志输出

2. **调整轮转配置**：
   - 减少备份文件数量
   - 减少单个文件大小

3. **定期清理**：
   - 手动删除旧的日志文件
   - 或配置自动清理策略

## 最佳实践

1. **日志级别**：
   - 生产环境：INFO
   - 开发环境：DEBUG
   - 错误：ERROR

2. **日志内容**：
   - 记录关键操作
   - 记录错误详情
   - 避免记录敏感信息（密码、token等）

3. **日志查询**：
   - 使用标签过滤，提高查询效率
   - 使用时间范围限制，避免查询过多数据

4. **日志保留**：
   - 根据需求设置保留时间
   - 定期清理旧日志
