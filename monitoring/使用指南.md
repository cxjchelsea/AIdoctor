## 启动监控服务

### 前置条件

- 已安装Docker和Docker Compose
- 所有业务服务已启动

### 启动步骤

```bash
# 1. 进入monitoring目录
cd monitoring

# 2. 启动Prometheus和Grafana
docker-compose up -d

# 3. 查看服务状态
docker-compose ps

# 4. 查看日志
docker-compose logs -f prometheus
docker-compose logs -f grafana
```

### 停止服务

```bash
cd monitoring
docker-compose down
```

### 重启服务

```bash
cd monitoring
docker-compose restart
```

## 访问监控界面

### Prometheus Web UI

**地址**: http://localhost:9090

**功能**：
- 查看所有收集的指标
- 执行PromQL查询
- 查看告警规则
- 查看目标服务状态

**常用操作**：

1. **查看目标状态**：
   - 点击顶部菜单 "Status" -> "Targets"

2. **执行查询**：
   - 在顶部搜索框输入PromQL查询

3. **查看指标**：
   - 点击顶部菜单 "Graph"
   - 输入指标名称，如：`http_requests_total`

**地址**: http://localhost:3001

**默认登录**：
- 用户名: `admin`

## 配置Grafana

### 1. 添加Prometheus数据源

1. 登录Grafana
2. 点击左侧菜单 "Configuration" -> "Data Sources"
3. 点击 "Add data source"
4. 选择 "Prometheus"
5. 配置：
   - **URL**: `http://prometheus:9090`
   - **Access**: Server (default)
6. 点击 "Save & Test"

### 2. 查看预配置的仪表板

系统已自动配置了以下仪表板，无需手动导入：

1. 点击左侧菜单 **Dashboards** -> **Browse**
2. 可以看到以下仪表板：
   - **系统资源监控** - 显示CPU、内存、磁盘、网络等系统级指标
   - **服务资源监控** - 显示各服务的QPS、响应时间、JVM内存等应用级指标

### 3. 导入其他仪表板（可选）

#### 方法A：使用官方模板

1. 点击左侧菜单 "Dashboards" -> "Import"
2. 输入模板ID：
   - **Spring Boot**: `11378`
   - **Node Exporter**: `11074`
3. 选择Prometheus数据源
4. 点击 "Import"

#### 方法B：创建自定义仪表板

1. 点击左侧菜单 "Dashboards" -> "New" -> "New Dashboard"
2. 添加面板（Panel）
3. 配置查询（使用PromQL）

### 4. 常用仪表板配置

#### QPS（每秒请求数）

```promql
sum(rate(http_requests_total[5m])) by (service)
```

#### 响应时间（P95）

```promql
histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[5m])) by (le, service))
```

#### 错误率

```promql
sum(rate(http_request_errors_total[5m])) by (service) / 
sum(rate(http_requests_total[5m])) by (service) * 100
```

#### CPU使用率（Java服务）

```promql
100 - (avg by(instance) (rate(process_cpu_seconds_total[5m])) * 100)
```

#### 内存使用（Java服务）

```promql
process_resident_memory_bytes / 1024 / 1024 / 1024
```

## 系统资源监控

### 概述

系统资源监控功能可以实时查看服务器的CPU、内存、磁盘、网络等资源使用情况。通过 Node Exporter 收集系统指标，并在 Grafana 中可视化展示。

### 查看系统资源

#### 方法1：使用预配置的仪表板（推荐）

1. 登录 Grafana: http://localhost:3001
2. 点击左侧菜单 **Dashboards** -> **Browse**
3. 找到以下预配置的仪表板：
   - **系统资源监控** - 显示CPU、内存、磁盘、网络等系统级指标
   - **服务资源监控** - 显示各服务的QPS、响应时间、JVM内存等应用级指标
4. 点击仪表板名称即可查看

#### 方法2：在 Prometheus 中查询

访问 http://localhost:9090，使用以下 PromQL 查询：

**CPU使用率**：
```promql
100 - (avg by(instance) (rate(node_cpu_seconds_total{mode="idle"}[5m])) * 100)
```

**内存使用率**：
```promql
(node_memory_MemTotal_bytes - node_memory_MemAvailable_bytes) / node_memory_MemTotal_bytes * 100
```

**内存使用量（GB）**：
```promql
(node_memory_MemTotal_bytes - node_memory_MemAvailable_bytes) / 1024 / 1024 / 1024
```

**磁盘使用率**：
```promql
(node_filesystem_size_bytes{fstype!="rootfs"} - node_filesystem_avail_bytes{fstype!="rootfs"}) / node_filesystem_size_bytes{fstype!="rootfs"} * 100
```

**网络接收速率**：
```promql
rate(node_network_receive_bytes_total{device!="lo"}[5m])
```

**网络发送速率**：
```promql
rate(node_network_transmit_bytes_total{device!="lo"}[5m])
```

**磁盘读取速率**：
```promql
rate(node_disk_read_bytes_total[5m])
```

**磁盘写入速率**：
```promql
rate(node_disk_written_bytes_total[5m])
```

### 查看各服务的资源占用

#### Java服务的JVM堆内存

```promql
jvm_memory_used_bytes{area="heap"} / 1024 / 1024 / 1024
```

#### Java服务的进程CPU使用率

```promql
rate(process_cpu_seconds_total[5m]) * 100
```

#### Java服务的进程内存使用

```promql
process_resident_memory_bytes / 1024 / 1024 / 1024
```

### 验证 Node Exporter 是否正常工作

1. 访问 Prometheus: http://localhost:9090
2. 点击顶部菜单 **Status** -> **Targets**
3. 查找 `node_exporter` 目标，状态应为 **UP**
4. 如果状态为 **DOWN**，检查：
   - Node Exporter 容器是否运行：`docker ps | grep node_exporter`
   - 查看日志：`docker logs node_exporter`

### Windows 系统注意事项

在 Windows 上，Node Exporter 在 Docker 容器中可能无法完全访问主机的系统资源（因为需要访问 Linux 的 `/proc` 和 `/sys` 文件系统）。

**解决方案**：
1. 如果 Node Exporter 无法正常工作，可以查看各服务自身的资源指标（Java服务的JVM指标、Python服务的进程指标）
2. 或者使用 Windows 任务管理器查看系统资源
3. 对于生产环境，建议在 Linux 服务器上部署 Node Exporter

## 查看日志

### 1. 添加Loki数据源

1. 登录Grafana: http://localhost:3001
2. 进入 **Configuration** -> **Data Sources**
3. 点击 **Add data source**
4. 选择 **Loki**
5. 配置：
   - **URL**: `http://loki:3100`
   - **Access**: Server (default)
6. 点击 **Save & Test**

### 2. 在Grafana中查看日志

1. 进入 **Explore**（左侧菜单）
2. 选择 **Loki** 数据源
3. 输入LogQL查询，例如：
   ```logql
   {service="diagnosis-engine"} |= "ERROR"
   ```
4. 点击 **Run query**

### 3. 常用日志查询

#### 查看所有日志
```logql
{job=~".+"}
```

#### 查看特定服务日志
```logql
{service="diagnosis-engine"}
```

#### 查看错误日志
```logql
{job=~".+"} |= "ERROR"
```

#### 查看最近5分钟的日志
```logql
{job=~".+"} [5m]
```

### 4. 日志文件位置

所有服务的日志文件位于：
- Python服务: `{服务目录}/logs/app.log`
- Java服务: `{服务目录}/logs/app.log`

**详细日志使用说明请查看**: [日志系统使用说明.md](./日志系统使用说明.md)

## 告警配置

### 查看告警规则

告警规则定义在 `monitoring/alert_rules.yml` 中，包括：

- **慢请求告警**：P95响应时间 > 2秒
- **错误率告警**：错误率 > 5%
- **CPU使用率告警**：CPU > 80%
- **内存使用率告警**：内存 > 12GB
- **服务不可用告警**：服务下线 > 1分钟
- **JVM堆内存告警**：堆内存 > 85%
- **数据库连接池告警**：连接池 > 80%

### 查看告警状态

1. 访问 Prometheus: http://localhost:9090
2. 点击 "Alerts" 查看告警状态
3. 查看告警规则和当前状态

### 配置告警通知（可选）

如需配置邮件、钉钉等通知，需要配置AlertManager（当前未包含在docker-compose中）。

## 故障排查

### Prometheus无法拉取指标

**症状**：在Prometheus的Targets页面看到服务状态为DOWN

**排查步骤**：

1. **检查服务是否运行**：
   ```bash
   # 检查Python服务
   curl http://localhost:8086/health
   
   # 检查Java服务
   curl http://localhost:8084/actuator/health
   ```

2. **检查指标端点**：
   ```bash
   # Python服务
   curl http://localhost:8086/metrics
   
   # Java服务
   curl http://localhost:8084/actuator/prometheus
   ```

3. **检查网络连接**：
   - Windows: 确保使用 `host.docker.internal`
   - Linux/Mac: 可以使用 `localhost` 或 `host.docker.internal`

4. **查看Prometheus日志**：
   ```bash
   docker logs prometheus
   ```

5. **检查Prometheus配置**：
   - 确认 `monitoring/prometheus.yml` 中的端口正确
   - 确认服务名称和标签正确

### Grafana无法连接Prometheus

**症状**：Grafana显示"Data source is not working"

**排查步骤**：

1. **检查Prometheus是否运行**：
   ```bash
   docker ps | grep prometheus
   ```

2. **检查数据源URL**：
   - 在Grafana中，数据源URL应为：`http://prometheus:9090`
   - 不要使用 `localhost`，因为Grafana在Docker容器中

3. **测试连接**：
   - 在Grafana数据源配置页面点击 "Save & Test"
   - 查看错误信息

### 指标数据不更新

**症状**：Prometheus中看不到最新数据

**排查步骤**：

1. **检查拉取间隔**：
   - Prometheus默认每15秒拉取一次
   - 等待一段时间后再查看

2. **检查服务是否正常**：
   - 确保业务服务正在处理请求
   - 没有请求时，指标不会变化

3. **查看Prometheus目标状态**：
   - 访问 http://localhost:9090/targets
   - 确认所有服务状态为UP

### Windows特殊问题

**问题**：`host.docker.internal` 无法访问

**解决方案**：

1. **使用localhost**：
   修改 `monitoring/prometheus.yml`，将 `host.docker.internal` 改为 `localhost`

2. **使用Docker Desktop网络**：
   确保Docker Desktop的网络设置允许访问宿主机

3. **使用IP地址**：
   使用 `192.168.x.x` 等实际IP地址

## 常用PromQL查询

### 服务QPS

```promql
sum(rate(http_requests_total[5m])) by (service)
```

### 服务响应时间（P50/P95/P99）

```promql
# P50
histogram_quantile(0.50, sum(rate(http_request_duration_seconds_bucket[5m])) by (le, service))

# P95
histogram_quantile(0.95, sum(rate(http_request_duration_seconds_bucket[5m])) by (le, service))

# P99
histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket[5m])) by (le, service))
```

### 服务错误率

```promql
sum(rate(http_request_errors_total[5m])) by (service) / 
sum(rate(http_requests_total[5m])) by (service) * 100
```

### 按路径查看请求数

```promql
sum(rate(http_requests_total[5m])) by (path, service)
```

### 按状态码查看请求数

```promql
sum(rate(http_requests_total[5m])) by (status, service)
```

### Java服务JVM堆内存

```promql
jvm_memory_used_bytes{area="heap"} / jvm_memory_max_bytes{area="heap"} * 100
```

### Java服务GC次数

```promql
rate(jvm_gc_pause_seconds_count[5m])
```

## 性能影响

### 监控开销

- **客户端库内存**: <10MB/服务
- **CPU开销**: <0.1%
- **请求延迟**: <0.01ms（内存操作）

### 网络开销

- **Prometheus拉取**: 每15秒一次，数据量约几KB
- **总体影响**: 几乎可以忽略
