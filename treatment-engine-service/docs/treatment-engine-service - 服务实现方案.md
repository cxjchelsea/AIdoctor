## 一、服务概述

> **参考文档**：《AI医生系统-业务逻辑详细设计.md》第1.6节

### 1.1 服务定位

- **对应脑区**：脑区E（治疗推理引擎）
- **在架构中的位置**：诊断流程的后续环节，位于检查建议服务之后，提供治疗建议
- **服务职责**：
  1. 治疗方案推理（基于诊断结果和患者情况，推理合适的治疗方案）
  2. 药物推荐（推荐合适的药物，研发阶段不涉及具体剂量）
  3. 非药物治疗建议（提供生活方式、康复训练等非药物治疗建议）
  4. 治疗计划构建（构建完整的治疗计划）

### 1.2 输入输出

#### 1.2.1 输入数据格式和来源

**输入来源**：diagnosis-service（流程编排服务）调用

**输入数据格式**（参考《AI医生系统-数据模型设计.md》）：
```json
{
  "cdpId": "cdp-123456",
  "cdp": {
    "ddx": [
      {
        "disease": "急性心肌梗死",
        "probability": 0.75,
        "layer": "primary_hypothesis"
      }
    ],
    "patient_state": {
      "symptoms": ["胸痛", "气短"],
      "vital_signs": {
        "bp": {"systolic": 150, "diastolic": 95},
        "heart_rate": 100
      },
      "allergies": ["青霉素"],
      "current_medications": ["阿司匹林"]
    },
    "risk_level": "L2"
  }
}
```

**字段说明**：
- `cdpId`：CDP ID（必填）
- `cdp`：临床决策包（可选，如果提供则从CDP中读取数据）
- `ddx`：鉴别诊断候选集（从CDP读取）
- `patient_state`：患者状态（从CDP读取，包含过敏史、当前用药等）
- `risk_level`：风险等级（从CDP读取）

#### 1.2.2 输出数据格式和目标

**输出目标**：diagnosis-service（流程编排服务）、前端

**输出数据格式**（参考《AI医生系统-最终输出格式规范.md》）：

**字段说明**：
- `treatmentPlan`：治疗计划
  - `primaryTreatment`：主要治疗方案
  - `alternativeTreatments`：备选治疗方案
- `medicationAdvice`：药物推荐列表
  - `name`：药物名称
  - `indication`：适应症
  - `contraindications`：禁忌症
  - `drugInteractions`：药物相互作用
  - `note`：注意事项（研发阶段不涉及具体剂量）
- `nonMedicationAdvice`：非药物治疗建议
  - `type`：建议类型（lifestyle/rehabilitation/other）
  - `content`：建议内容
  - `priority`：优先级

#### 1.2.3 数据流转关系

**数据流转**（参考《AI医生系统-技术架构设计-CDP数据与状态管理.md》）：
```
diagnosis-service → treatment-engine-service → 返回治疗建议
                                      ↓
                              更新CDP的management_plan字段
```

**CDP数据更新**：
- 更新CDP的`management_plan`字段，包含治疗方案、药物推荐、非药物治疗建议

### 1.3 业务价值

- **个性化治疗**：基于诊断结果和患者情况，提供个性化的治疗方案
- **药物安全**：考虑过敏史、药物相互作用，确保用药安全
- **综合治疗**：不仅提供药物治疗，还提供非药物治疗建议
- **治疗优化**：根据风险等级和患者状态，优化治疗方案

### 2.2 核心算法/方法

#### 2.2.1 治疗方案推理算法

**算法描述**：基于诊断结果和患者情况，推理合适的治疗方案。

**实现思路**：

1. **诊断匹配**
   - 从诊断候选集中选择主要诊断（primary_hypothesis）
   - 考虑备选诊断（main_alternatives）

2. **治疗方案检索**
   - 使用治疗方案推理规则库（5.1）
   - 根据诊断匹配治疗方案模板
   - 考虑患者风险等级

3. **个性化调整**
   - 根据患者状态调整治疗方案
   - 考虑过敏史、当前用药、合并症等
   - 生成个性化治疗方案

**算法复杂度**：O(n)，n为治疗方案规则数

#### 2.2.2 药物推荐算法

**算法描述**：基于诊断和患者情况，推荐合适的药物。

**实现思路**：

1. **适应症匹配**
   - 根据诊断匹配药物适应症
   - 使用药物知识库检索相关药物

2. **禁忌症检查**
   - 检查患者过敏史
   - 检查药物禁忌症
   - 排除不适用药物

3. **药物相互作用检查**
   - 检查与当前用药的相互作用
   - 评估相互作用风险
   - 必要时调整推荐

4. **药物推荐排序**
   - 根据适应症匹配度、安全性、有效性排序
   - 优先推荐一线药物

**算法复杂度**：O(n*m)，n为药物数，m为检查项数

#### 2.2.3 非药物治疗建议生成算法

**算法描述**：生成生活方式、康复训练等非药物治疗建议。

**实现思路**：

1. **建议类型识别**
   - 根据诊断识别需要的建议类型
   - 生活方式建议（饮食、运动、作息等）
   - 康复训练建议
   - 其他建议

2. **建议内容生成**
   - 使用建议模板库
   - 根据患者情况个性化调整
   - 生成具体建议内容

3. **优先级排序**
   - 根据重要性和紧急性排序
   - 高优先级建议优先展示

**算法复杂度**：O(n)，n为建议模板数

### 2.3 性能要求

> **参考文档**：《AI医生系统-技术架构设计-性能与评估.md》

#### 2.3.1 响应时间要求

- **治疗建议生成**：< 3秒
- **药物推荐**：< 2秒
- **目标**：< 2秒（优化后）

#### 2.3.2 并发处理能力

- **支持并发请求**：50+ 并发
- **目标**：200+ 并发（优化后）

#### 2.3.3 资源消耗限制

- **内存消耗**：< 512MB（单实例）
- **CPU消耗**：< 50%（正常负载）

### 2.4 关键技术点

#### 2.4.1 关键技术难点

1. **治疗方案推理**
   - 难点：需要全面的治疗方案知识库
   - 解决方案：
     - 维护治疗方案推理规则库
     - 使用医学知识图谱
     - 可选：集成LLM生成治疗方案

2. **药物推荐安全性**
   - 难点：确保用药安全，避免禁忌症和严重相互作用
   - 解决方案：
     - 维护完整的药物知识库（适应症、禁忌症、相互作用）
     - 严格检查过敏史和禁忌症
     - 检查药物相互作用
     - 研发阶段不涉及具体剂量，降低风险

3. **个性化治疗**
   - 难点：根据患者情况个性化调整治疗方案
   - 解决方案：
     - 考虑患者状态、风险等级、合并症等
     - 使用规则引擎进行个性化调整

#### 2.4.2 技术风险及应对

| 风险 | 风险等级 | 应对措施 |
|------|---------|---------|
| 知识库不完整 | 高 | 逐步完善治疗方案规则库和药物知识库 |
| 药物推荐不安全 | 高 | 严格检查禁忌症和相互作用，研发阶段不涉及剂量 |
| 性能瓶颈 | 中 | 使用缓存，优化算法，异步处理 |
| 治疗方案不合理 | 高 | 增加专家审核机制，定期评估推荐质量 |

### 3.2 请求/响应模型

#### 3.2.1 请求模型定义

**参考文档**：《AI医生系统-数据模型设计.md》

```python
class TreatmentPlanRequest(BaseModel):
    """治疗建议请求"""
    cdpId: str  # CDP ID（必填）
    cdp: Optional[Dict[str, Any]] = None  # 临床决策包（可选）

class MedicationRecommendationRequest(BaseModel):
    """药物推荐请求"""
    cdpId: str  # CDP ID（必填）
    diagnosis: Dict[str, Any]  # 诊断信息
    patientState: Dict[str, Any]  # 患者状态
```

#### 3.2.2 响应模型定义

```python
class Treatment(BaseModel):
    """治疗方案"""
    name: str  # 治疗方案名称
    description: str  # 治疗方案描述
    priority: str  # 优先级（high/medium/low）

class TreatmentPlan(BaseModel):
    """治疗计划"""
    primaryTreatment: Treatment  # 主要治疗方案
    alternativeTreatments: List[Treatment] = []  # 备选治疗方案

class MedicationAdvice(BaseModel):
    """药物建议"""
    name: str  # 药物名称
    indication: str  # 适应症
    contraindications: List[str] = []  # 禁忌症
    drugInteractions: List[str] = []  # 药物相互作用
    note: Optional[str] = None  # 注意事项（研发阶段不涉及具体剂量）

class NonMedicationAdvice(BaseModel):
    """非药物治疗建议"""
    type: str  # 建议类型（lifestyle/rehabilitation/other）
    content: str  # 建议内容
    priority: str  # 优先级

class TreatmentPlanResponse(BaseModel):
    """治疗建议响应"""
    cdpId: str
    treatmentPlan: TreatmentPlan
    medicationAdvice: List[MedicationAdvice]
    nonMedicationAdvice: List[NonMedicationAdvice]
```

#### 3.2.3 数据验证规则

**遵循API接口规范**：
- 使用Pydantic进行数据验证
- `cdpId`：必填，字符串，长度1-100
- `medicationAdvice`：列表，每个项必须包含name、indication等字段
- `note`字段明确说明：研发阶段不涉及具体剂量

### 4.1 数据输入来源

**数据获取方式**：

- 请求体包含CDP ID或完整的CDP数据

### 4.2 数据处理流程

**数据处理步骤**（参考业务逻辑详细设计）：

1. **接收请求**
   - 验证请求参数
   - 提取CDP ID和CDP数据

2. **获取诊断信息**
   - 从CDP中读取DDx（鉴别诊断候选集）
   - 从CDP中读取患者状态（包含过敏史、当前用药等）
   - 从CDP中读取风险等级

3. **治疗方案推理**
   - 选择主要诊断
   - 使用治疗方案推理规则库
   - 生成治疗方案

4. **药物推荐**
   - 根据诊断匹配药物适应症
   - 检查禁忌症和药物相互作用
   - 生成药物推荐列表

5. **非药物治疗建议生成**
   - 识别建议类型
   - 生成建议内容
   - 排序优先级

6. **构建响应**
   - 组装响应数据
   - 返回统一格式响应

**数据转换逻辑**：
- 诊断结果 → 治疗方案推理 → 治疗计划
- 诊断结果 + 患者状态 → 药物推荐
- 诊断结果 → 非药物治疗建议

**数据验证规则**（参考数据模型设计）：
- 使用Pydantic进行数据验证
- 验证CDP数据格式
- 验证诊断信息格式
- 验证患者状态格式（特别是过敏史、当前用药）

### 4.3 数据输出格式

**输出数据结构**（参考数据模型设计）：
- JSON格式
- 字段使用camelCase（对外API）

**数据格式规范**（遵循最终输出格式规范）：
- 统一响应格式：`{code, message, data, timestamp}`
- 数据字段：`{cdpId, treatmentPlan, medicationAdvice, nonMedicationAdvice}`

**数据存储方式**（参考CDP数据与状态管理）：
- 治疗建议数据写入CDP的`management_plan`字段
- CDP字段使用snake_case（内部存储）
