## 一、服务概述

> **参考文档**：《AI医生系统-业务逻辑详细设计.md》第1.5节

### 1.1 服务定位

- **对应脑区**：脑区D（检查建议引擎）
- **在架构中的位置**：诊断流程中的检查建议环节，位于诊断引擎服务之后，治疗推理服务之前
- **服务职责**：
  1. 检查价值评估（评估各项检查对诊断的价值和必要性）
  2. 信息增益计算（计算检查结果对诊断的信息增益）
  3. 检查优先级排序（根据价值和信息增益对检查进行排序）
  4. 验证计划构建（制定验证诊断假设的检查计划）

### 1.2 输入输出

#### 1.2.1 输入数据格式和来源

**输入来源**：diagnosis-service（流程编排服务）调用

**输入数据格式**（参考《AI医生系统-数据模型设计.md》）：
```json
{
  "cdpId": "cdp-123456",
  "cdp": {
    "ddx": [
      {
        "disease": "急性心肌梗死",
        "probability": 0.75,
        "layer": "primary_hypothesis"
      },
      {
        "disease": "不稳定心绞痛",
        "probability": 0.20,
        "layer": "main_alternatives"
      }
    ],
    "patient_state": {
      "symptoms": ["胸痛", "气短"],
      "vital_signs": {
        "bp": {"systolic": 150, "diastolic": 95},
        "heart_rate": 100
      }
    },
    "must_exclude": [
      {
        "disease": "主动脉夹层",
        "reason": "高危诊断，必须排除"
      }
    ]
  }
}
```

**字段说明**：
- `cdpId`：CDP ID（必填）
- `cdp`：临床决策包（可选，如果提供则从CDP中读取数据）
- `ddx`：鉴别诊断候选集（从CDP读取）
- `patient_state`：患者状态（从CDP读取）
- `must_exclude`：必须排除的高危诊断（从CDP读取）

#### 1.2.2 输出数据格式和目标

**输出目标**：diagnosis-service（流程编排服务）、前端

**输出数据格式**（参考《AI医生系统-最终输出格式规范.md》）：
```json
{
  "code": 200,
  "message": "success",

          "testName": "胸部CT血管造影",
```

**字段说明**：
- `workupItems`：检查建议列表
  - `testName`：检查名称
  - `testCode`：检查编码（LOINC/SNOMED）
  - `priority`：优先级（high/medium/low）
  - `informationGain`：信息增益（0-1）
  - `purpose`：检查目的（区分哪些诊断）
  - `urgency`：紧急程度（emergency/urgent/routine）
- `verificationPlan`：验证计划（针对必须排除的高危诊断）

#### 1.2.3 数据流转关系

**数据流转**（参考《AI医生系统-技术架构设计-CDP数据与状态管理.md》）：
```
diagnosis-service → workup-planner-service → 返回检查建议
                                      ↓
                              更新CDP的workup_plan字段
```

**CDP数据更新**：
- 更新CDP的`workup_plan`字段，包含检查建议和验证计划

### 1.3 业务价值

- **优化检查流程**：基于诊断候选集，智能推荐最有价值的检查
- **提高诊断效率**：通过信息增益计算，优先推荐能最大程度区分诊断的检查
- **安全验证**：针对必须排除的高危诊断，制定专门的验证计划
- **成本控制**：避免不必要的检查，降低医疗成本

### 2.2 核心算法/方法

#### 2.2.1 检查价值评估算法

**算法描述**：基于诊断候选集和患者状态，评估各项检查对诊断的价值。

**实现思路**：

1. **检查-诊断关联度评估**
   - 使用检查价值评估规则库（4.1）
   - 评估检查对每个诊断候选的支持度
   - 计算检查的区分能力（能区分哪些诊断）

2. **检查必要性评估**
   - 评估检查是否为确诊必需
   - 评估检查是否为排除必需
   - 考虑患者状态和已有检查结果

3. **检查价值评分**
   - 综合关联度、区分能力、必要性
   - 生成检查价值评分（0-1）

**算法复杂度**：O(n*m)，n为诊断候选数，m为检查项数

#### 2.2.2 信息增益计算算法

**算法描述**：计算检查结果对诊断的信息增益，优先推荐信息增益高的检查。

**实现思路**：

1. **信息熵计算**
   - 计算当前诊断候选集的信息熵
   - H(X) = -Σ P(x) * log2(P(x))

2. **条件熵计算**
   - 计算检查结果已知后的条件熵
   - H(X|Y) = -Σ P(y) * Σ P(x|y) * log2(P(x|y))

3. **信息增益计算**
   - IG(X,Y) = H(X) - H(X|Y)
   - 信息增益越大，检查价值越高

**算法复杂度**：O(n*m)，n为诊断候选数，m为检查结果可能数

#### 2.2.3 检查优先级排序算法

**算法描述**：根据检查价值、信息增益、紧急程度等，对检查进行优先级排序。

**实现思路**：

1. **综合评分计算**
   - 检查价值评分 * 权重1
   - 信息增益 * 权重2
   - 紧急程度评分 * 权重3
   - 综合评分 = 加权求和

2. **优先级排序**
   - 按综合评分降序排序
   - 高优先级检查优先推荐

**算法复杂度**：O(m*log(m))，m为检查项数

#### 2.2.4 验证计划构建算法

**算法描述**：针对必须排除的高危诊断，制定专门的验证计划。

**实现思路**：

1. **目标诊断识别**
   - 从CDP中获取必须排除的高危诊断列表
   - 识别关键鉴别点

2. **验证检查选择**
   - 使用验证计划规则库（4.3）
   - 选择能有效排除/确认目标诊断的检查
   - 优先选择特异性高的检查

3. **验证计划构建**
   - 构建验证计划结构
   - 设置验证优先级

**算法复杂度**：O(k*m)，k为必须排除的诊断数，m为检查项数

### 2.3 性能要求

> **参考文档**：《AI医生系统-技术架构设计-性能与评估.md》

#### 2.3.1 响应时间要求

- **检查建议生成**：< 2秒
- **信息增益计算**：< 1秒
- **目标**：< 1秒（优化后）

#### 2.3.2 并发处理能力

- **支持并发请求**：50+ 并发
- **目标**：200+ 并发（优化后）

#### 2.3.3 资源消耗限制

- **内存消耗**：< 512MB（单实例）
- **CPU消耗**：< 50%（正常负载）

### 2.4 关键技术点

#### 2.4.1 关键技术难点

1. **信息增益计算**
   - 难点：需要准确的概率分布数据
   - 解决方案：
     - 使用诊断概率作为先验概率
     - 使用检查-诊断关联规则库计算条件概率
     - 可选：使用机器学习模型预测概率分布

2. **检查价值评估**
   - 难点：需要全面的检查-诊断关联知识库
   - 解决方案：
     - 维护检查价值评估规则库
     - 使用医学知识图谱
     - 定期更新规则库

3. **验证计划构建**
   - 难点：针对高危诊断，需要高特异性的检查
   - 解决方案：
     - 维护验证计划规则库
     - 优先选择金标准检查
     - 考虑检查的可及性和成本

#### 2.4.2 技术风险及应对

| 风险 | 风险等级 | 应对措施 |
|------|---------|---------|
| 知识库不完整 | 高 | 逐步完善检查价值评估规则库，使用医学知识图谱补充 |
| 信息增益计算不准确 | 中 | 使用多种方法验证，结合专家经验 |
| 性能瓶颈 | 中 | 使用缓存，优化算法，异步处理 |
| 检查推荐不合理 | 高 | 增加专家审核机制，定期评估推荐质量 |

### 3.2 请求/响应模型

#### 3.2.1 请求模型定义

**参考文档**：《AI医生系统-数据模型设计.md》

```python
class WorkupPlanRequest(BaseModel):
    """检查建议请求"""
    cdpId: str  # CDP ID（必填）
    cdp: Optional[Dict[str, Any]] = None  # 临床决策包（可选）

class VerificationPlanRequest(BaseModel):
    """验证计划请求"""
    cdpId: str  # CDP ID（必填）
    mustExclude: List[Dict[str, Any]]  # 必须排除的高危诊断
    keyDifferentiatingPoints: Optional[List[str]] = None  # 关键鉴别点
```

#### 3.2.2 响应模型定义

```python
class WorkupItem(BaseModel):
    """检查项"""
    testName: str  # 检查名称
    testCode: str  # 检查编码
    priority: str  # 优先级（high/medium/low）
    informationGain: float  # 信息增益（0-1）
    purpose: str  # 检查目的
    urgency: str  # 紧急程度
    reason: Optional[str] = None  # 推荐理由

class VerificationPlan(BaseModel):
    """验证计划"""
    targetDisease: Optional[str] = None  # 目标诊断
    verificationItems: List[WorkupItem]  # 验证检查项
    priority: str  # 优先级

class WorkupPlanResponse(BaseModel):
    """检查建议响应"""
    cdpId: str
    workupItems: List[WorkupItem]
    verificationPlan: Optional[VerificationPlan] = None
```

### 4.2 数据处理流程

**数据处理步骤**（参考业务逻辑详细设计）：

1. **接收请求**
   - 验证请求参数
   - 提取CDP ID和CDP数据

2. **获取诊断候选集**
   - 从CDP中读取DDx（鉴别诊断候选集）

   - 计算检查结果的条件熵
   - 计算信息增益

5. **检查优先级排序**
   - 综合检查价值、信息增益、紧急程度
   - 对检查进行优先级排序

6. **验证计划构建**

   - 构建验证计划

7. **构建响应**
   - 组装响应数据
   - 返回统一格式响应

**数据转换逻辑**：
- 诊断候选集 → 检查价值评估 → 检查建议
- 必须排除的诊断 → 验证计划

**数据验证规则**（参考数据模型设计）：
- 使用Pydantic进行数据验证
- 验证CDP数据格式
- 验证诊断候选集格式

### 4.3 数据输出格式

**输出数据结构**（参考数据模型设计）：
- JSON格式
- 字段使用camelCase（对外API）

**数据格式规范**（遵循最终输出格式规范）：
- 统一响应格式：`{code, message, data, timestamp}`
- 数据字段：`{cdpId, workupItems, verificationPlan}`

**数据存储方式**（参考CDP数据与状态管理）：
- 检查建议数据写入CDP的`workup_plan`字段
- CDP字段使用snake_case（内部存储）
